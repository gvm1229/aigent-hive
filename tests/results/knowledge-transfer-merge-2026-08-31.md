# 여러 지식 묶음 통합 측정

- 실행 환경: Windows 11 x64, 현재 debug CLI, 합성 Markdown·한글·공백 사용자 루트
- 방식: A·B 묶음의 일부 중복 원문과 서로 다른 원문을 C에서 `merge preview`·`merge apply`
- 측정 범위: 두 묶음 생성·통합 미리 보기·정본 적용과 FTS 생성
- 제외: 벡터 모델 설치·임베딩 생성, 실제 사용자 자료, 다른 운영체제 성능

| 최종 원문 수 | 두 묶음 생성 | 통합 미리 보기 | 통합 적용·FTS | 최대 메모리 | 자동 중복 정리 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 100 | 0.439초 | 0.108초 | 1.423초 | 22.00MiB | 11개 |
| 1,000 | 1.506초 | 0.716초 | 11.445초 | 32.31MiB | 101개 |
| 5,000 | 6.256초 | 3.446초 | 57.876초 | 93.33MiB | 501개 |

- 세 조건: 원문 합집합 100·1,000·5,000개, FTS 대표 조회 통과
- 결과: 두 묶음의 같은 바이트 원문은 한 번만 활성 지식으로 처리, 원문 누락 0건
- 1회 측정 결과. p95·모든 장치 성능 보장 자료 제외
- 원본 실행 기록: `tests/work/merge-transfer-*-produce/receipt.json`, `tests/work/merge-transfer-*-consume/receipt.json`
