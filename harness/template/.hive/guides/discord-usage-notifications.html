Discord usage notifications

Aigent Hive can send an outbound Discord message when the usage guard stops a workflow. It cannot read Discord replies or continue a Codex session from Discord.

1. Create a webhook

  1. Open the Discord channel settings, then Integrations.
  2. Create an incoming webhook and copy its URL.
  3. Store that URL only in a local environment variable, for example HIVE_DISCORD_WEBHOOK_URL.

2. Configure Hive

Ask Hive to configure global preferences. Enable the usage guard, choose Discord notifications, provide only the environment-variable name, choose the message fields and their order, and send a test message.

3. Verify the result

The test message has the same language, fields, and order as a real stop message. Only its first line identifies it as a test. A real message can show remaining usage, the project, a canonical run title, completed checklist count, host, resume guidance, time, and verification reference.

Privacy

Webhook URLs, raw prompts, session identifiers, and absolute paths stay local. If no canonical run is available, Hive explicitly reports that request and progress details are unavailable.
