# Writing checklist

Read only when the target is a document, README, release note or other prose. This file covers
structure. Rewriting Korean sentences goes to `humanize-kor`; rewriting English sentences stays
here only when the user asked for it.

## Keep fixed

Meaning, numbers, units, conditions, commands, links, names and sources. A cleanup never adds a
claim.

## Smells and examples

| Class | Look for |
| --- | --- |
| Repetition | the same point in the intro, body and summary; paragraphs that restate a table |
| Padding | "In this section we will…", empty conclusions, throat-clearing openers |
| Needless layers | headings for one line, nested bullets that hold one item, a summary of a summary |
| Generic defaults | bold on every other phrase, emoji section markers, lists where one sentence reads better |
| Unsupported claims | "significantly", "seamless", invented figures, benefits with no source |

## Check

Compare before and after for every number, link and condition. Run the project's document checks
if it has them.
