# Independent directive transplantation

Use this procedure only for a user-requested transfer between identified source and target projects.
The active host reads and adapts the rules; Hive does not call a provider, watch file copies, or
launch an extra model. An explicit request for an exact archival copy keeps its requested bytes.

1. Read the selected source directive and the target's canonical entrypoint and relevant rules.
   Inventory durable rules, names, roles, links, commands, authority and required companion text.
   Never expand inspection to credentials, private material or unrelated repositories.
2. Write independent target rules. Resolve names, paths, roles, commands and linked documents
   against the target. Use an existing target equivalent or include the necessary rule locally.
   Do not blindly import other files, infrastructure or source-specific assumptions.
3. Remove operational copied-from prefaces, transfer commentary and instructions that require
   the original project. Preserve the rule's meaning. Keep required legal notices; put optional
   provenance in a separate change record only when needed and within the authorized scope.
4. Follow target authority and precedence. Source-session approvals, release permission and
   permission to change another repository never transfer. Show unresolved mappings or rule
   conflicts before applying their affected changes; continue independent resolved work.
5. Preview and apply only the requested target files or exact marker blocks. Preserve source
   files and unrelated target bytes. User-authored imported directives remain target-owned;
   never add them to Hive's generated-file ownership manifest or modify a signed cache.
6. Validate all target-relative links, commands and scope statements. Review the whole directive
   for source dependence, not just its heading. It must work when the source project is absent.
   Report concrete checks and any unresolved dependency; file presence alone is not validation.
