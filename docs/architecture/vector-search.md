# 선택형 벡터 검색 구현 계약

## 목적과 기준

- 표현이 다른 비슷한 지식의 후보 검색. Markdown 정본과 기존 FTS 검색 유지
- 기본 사실 검색은 FTS. 명시적 의미 검색은 제목 문맥 벡터와 FTS 점수의 질문별 최소·최대 정규화 결합 사용
- 벡터 비중 0.75·FTS 비중 0.25. 같은 점수만 있는 경로는 1로 정규화. 결과는 질문 안의 상대 순위이며 사실 확률이 아님
- 벡터를 사용할 수 없을 때 검증된 FTS로 대체. 결합 방법·비중·인용·검색 경로를 함께 반환
- `0.10.0` 전용 구현. 이전 조사 실패는 유효 기록으로 보존하고 새 측정으로 채택 판정
- 기존 품질·속도·보안 기준 유지. 조사용 코드의 작동과 제품 수용 완료 구분
- engine 우선 후보: `sqlite-vec 0.1.9`; 임베딩 후보: MiniLM·검색 학습형 E5·다국어 정적 임베딩
- 선택 조건: 동일 고정 자료의 품질·고유 5만 청크 실제 생성·전체 요청 시간·세 운영체제 검증
- 비벡터 `test.4` 후보의 제품 트리와 분리. 벡터 제품 변경 뒤 다음 번호 시험 사용

## 실행 경계

- 생성형 모델·Agent 실행: 활성 구독 host 소유, Hive의 제공자 API·자격 증명 접근 금지
- 로컬 임베딩: 별도 동의된 비생성형 색인 계산으로만 허용. 프롬프트 생성·대화·추론 작업 실행 금지
- 보조 환경: 고정 Python 패키지와 모델 digest, Python 실행 파일 정체성, 보조 코드 digest 결합
- Python 자동 설치·전역 pip·서버·감시 프로세스·Git hook·자동 MCP 등록 없음
- 배포 구성: 고정 wheel 7개의 파일 기반 실행 환경. 원본 METADATA·RECORD 보존, 전체 pip 의존성 충족 주장 금지
- `tokenizers`의 선언된 `huggingface-hub` 의존성은 제한된 `Tokenizer.from_file` 구성에서 의도적으로 생략. `from_pretrained`·HF 제공자 SDK 기능 미지원
- 설치 전 정확한 다운로드·설치 경로와 용량을 preview로 제시, 동의 digest 확인 후 staging 설치
- 실행 시 환경 허용 목록과 `-I -S -B`, `.pth`·bytecode 쓰기 없음. 네트워크·telemetry·query log 기능 미사용
- Windows native DLL·모델 로더는 검증된 절대 경로에 확장 표기 적용. SQLite URI·정본·소유권 경로 불변
- Windows 혼합 CPU: 임베딩 보조 프로세스만 최고 `EfficiencyClass`로 제한. 기존 affinity·명시적 CPU Set의 교집합만 사용하며 부모·전역 설정 불변
- 허용된 최고 성능 코어 부재·혼합 다중 processor group은 벡터 실행 거부와 FTS 유지. 같은 종류의 CPU·다른 운영체제는 기존 배치 유지
- CPU 정책은 설치 동의·보조 코드 지문에 포함. 기존 실행 환경의 묵시적 교체 금지, 새 동의·재생성 필요
- 조회는 실행 환경·승인 영수증 검증 뒤 같은 보조 프로세스에서 수행. 검증을 생략하지 않고 중복 프로세스 시작을 줄임
- 결합 실행은 조회만 허용하고, 검증한 보조 코드 바이트만 실행. 생성·설치 권한으로 확대 금지
- 위 격리는 운영체제 수준의 네트워크·파일 접근 차단 증명 아님. 고정 신뢰 코드의 검사와 실제 관찰 범위 별도 기록
- 제한 시간·출력 상한·사용자 취소 시 하위 프로세스 전체 종료
- CLI 자체 강제 종료: Windows Job Object 유지, Unix 보조 프로세스는 정확한 부모 PID 변경을 감지해 스스로 종료
- Unix 감시는 현재 보조 프로세스 내부의 종료용 스레드이며 영구 서버·파일 감시 아님. Python 스케줄링을 막는 네이티브 교착의 커널 강제 종료 보장은 별도

## 정본과 권한

- 기존 RAG의 범위 해석·공개 범위 판정·인용 식별자 재사용
- 소비자: `<user-root>/.hive/index/vector/` 아래 collection·공개 범위별 분리
- Source: `.agents/work/vector/` 아래 독립 저장, 소비자 저장소로 우회 금지
- 기밀 검색: 기존 일회성 검색 승인 1회 소비 후 같은 요청의 FTS·벡터에만 적용
- 기밀 색인 생성: 별도 작업 종류·정본 세대·collection·현재 작업 승인. 검색 승인에서 추론 금지
- 다른 범위의 이름·건수·존재 여부 반환 금지
- 벡터 결과의 청크 ID와 digest를 현재 정본·권한으로 다시 검증한 뒤 인용 반환

## 세대와 복구

- 재사용 키: 내용 digest와 모델·토크나이저·분할·길이 제한·pooling·정규화·차원·보조 코드의 전체 계약 지문
- MiniLM의 고정 설정에 맞춘 128-token 구간 처리. 제목 문맥을 각 구간에 붙이고, 모든 본문 token을 명시적으로 나눈 뒤 가중 평균
- 토크나이저의 overflow 목록에 의존하지 않고 긴 본문 꼬리 차이 회귀 검사 필수
- 시간 제한 배치와 checkpoint. 중단된 세대의 활성화 금지
- 모델 한 벌을 공유하는 CPU 스레드 묶음 사용. 기본 동시 수는 허용 CPU 수와 12 중 작은 값, 명시적 `--workers` 상한 16
- 재개 전 SQLite 밖 신뢰 제어 기록의 DB digest와 대조. DB 안의 checksum만으로 캐시 연결 관계 인증 금지
- 정상 종료의 검증된 checkpoint만 보존. 강제 종료 시 수정 중인 DB를 신뢰하지 않고 이전 인증 snapshot 복구, 최대 한 배치 작업 손실
- 최종 조립은 별도 30초 예산과 행 cursor로 재개. 호출부의 전체 하위 프로세스 강제 종료 기한 필수
- staging·게시 DB의 하드링크 거부와 파일 정체성 재확인. 기존 사용자 파일을 덮어쓰는 설치 복사 금지
- 파일·실행 환경은 매 시도마다 새 식별자로 배타 생성. 디렉터리 이름 교체·하드링크 게시 없이 검증 뒤 제어 포인터만 원자 변경
- 실패·강제 종료된 복사본은 미게시 상태로 보존하고 새 식별자로 재시도. 수정 중인 staging은 격리 후 인증 snapshot에서 복구
- 게시 직전 정본·등록부·공개 범위 재확인과 비교 후 교체. 검사 도중 변경되면 게시 거부
- 벡터 최신성은 collection·공개 범위별 입력 지문으로 판정. 다른 collection 수정만으로 모든 벡터의 재생성 요구 금지
- 생성·게시의 정본 검증은 해당 collection만, 조회의 실제 파일 검증은 반환 후보만 수행. 전역 등록부·SQLite 무결성 검증은 유지
- 같은 최종 검색 세대는 FTS·의미 후보가 한 번의 검증·적재를 공유. 조회 도중 현재 디스크 손상 검사와 최종 정본 검증은 유지
- 생성 입력의 모음 지문·본문도 한 SQLite 적재를 공유. 요청 검사·승인 후 본문 추출·게시 시 새 파일 읽기와 정본 검사는 유지
- 모음별 입력 지문은 인증된 SQLite의 파생 테이블에 저장. 전체 권한 record 지문이 달라지면 기존 계산으로 복귀하며, 이전 색인의 테이블 부재도 지원
- CLI 밖의 Markdown 편집 뒤에는 기존 FTS 갱신과 해당 벡터 재생성 필요. 조회의 새 문서 자동 발견·정본 자동 수정 없음
- 정본 세대 변경·모델 부재·차원 불일치·손상 시 벡터 사용 중지, FTS 자체 검증을 유지한 대체 검색
- 갱신 실패 시 이전 정상 세대 유지. rollback 대상도 읽기 전에 재검증
- 저장량 보강: 완성본의 중복 캐시 제거, 갱신 시 검증된 검색 벡터를 512행씩 복원. 저장된 cursor로 이어서 처리
- `auto_vacuum=INCREMENTAL` 고정, 256쪽 단위 공간 회수. 중단 시 회수된 쪽을 유지하며 남은 공간만 처리
- 오래된 복사본은 이전 제어 기록의 정확한 경로·digest로만 정리. 현재·이전 정상 세대·최신 checkpoint 제외, 실패는 지속 목록에서 재시도
- 삭제 권한은 동의된 Hive 전용 폐기 가능 cache에만 적용. 고정 부모·생성된 경로·비재귀 unlink로 경로 밖 자료 보호
- 검사 때 오염·링크·예상 밖 파일 종류는 보존. 동일 UID가 검사 뒤 전용 cache 이름을 교체하는 경우의 원자적 inode 비교 삭제는 보장하지 않음
- 보존된 중간·실패 자료도 실제 용량 측정에 포함. 현재 구현의 누적 저장량을 활성 색인 하나의 크기로 대체 보고 금지
- 정상 설치 검증 뒤 고정 지문의 다운로드 복사본만 정리. 게시 뒤 같은 불변 복구본이 검증된 작업 DB만 제거
- 정상 fresh 생성의 중복 격리 파일 방지. 오염·미확인 파일과 기존 실패 자료는 자동 정리하지 않음
- 원문·등록부·프로젝트 설정 변경 없음. `.hivekb`에 모델·벡터·검색 기록 포함 금지

## 다중 모음 증분 구현 계획

- 명시적인 shared 모음 목록만 유한한 한 실행으로 처리. 같은 승인 실행 환경·사용자 루트, 모음별 물리 DB 유지
- RAG 검증·모델 시작은 최대 16개 모음 구간 안에서 공유. 새 게시 시 현재 자료·권한 재확인과 구간 내 제어 기록 복구 필수
- 전역 잠금 밖에서 모델 계산, 기존 scope→정본 잠금 순서 유지. source·비공개·기밀은 기존 단일 경로 유지
- 상세 범위·상한·검증: [증분 반복 비용 축소 계획](../research/vector-product-integration-2026-08-28.md#증분-처리의-반복-비용-축소-계획)

## 시험

- 결정적 단위 검사와 실제 CLI의 설치·동의·검색·중단 재개·증분·오염·복구 검사 분리
- 고정 과거 성능 자료와 새 자료를 구분하고, 모델 선택에 쓰지 않은 질문으로 과도한 맞춤 여부 검토
- 물리 범위 누출·현재 작업 승인 재사용·경로 탈출·잘못된 모델·미완료 활성화 반례 포함
- 검사 실패·환경 미지원·관찰하지 못한 경계는 통과로 합산 금지
- `qualify-vector-runtime.py`: 명시적 설치 승인 뒤 새 `tests/work/`에서 실제 패키지·검색·복구 검사. 성능·기밀 시험 대체 금지
- 수동 native 검사와 동일 공개 시험판 설치 검사를 구분. Python 최적화 모드의 검사 생략 거부, 실패·시간 제한도 영수증 보존
- 실제 수용에는 긴 DLL 경로·지식 묶음의 파생 파일 제외·새 루트의 별도 동의/재생성·소스 검색 포함. 다른 물리 기기 검증과 구분
