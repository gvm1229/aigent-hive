# Aigent Hive 0.16.0

## English

### Scope

- [SCOPE-01] `hive msg send` and `hive msg inbox` move role messages through one file inbox with sender, sequence, idempotency key, body digest and receipt.
- [SCOPE-02] Project hooks record official host events. A Stop hook returns `queued` at once, and a later hook event or host `/loop` returns the result.
- [SCOPE-03] Builder, reviewer and advisor work uses envelopes and receipts. The status screen shows role, god, provider, model and step from Hive records.
- [SCOPE-04] Worker limits, `max_workers`, read-only score files and `hive stop` cancel events limit the effect of worker runs.
- [SCOPE-05] A local decision queue keeps open decisions. Discord notices name the task, result, roles and time, with a separator line.
- [SCOPE-06] Built-in Skills are merged into fewer names. The new Skill descriptions list the old names.
- [SCOPE-07] `hive stop` stops new messages, and `hive route` and `hive prompt` move under `hive advanced`.
- [SCOPE-08] When Hive cannot read usage, work continues with a warning that names the missing limit, its cause and the fix.
- [SCOPE-09] After approval, `hive setup --scope user --section usage --claude-statusline preview` connects the Claude Code status line, keeps the existing status line and supports revert.
- [SCOPE-10] `hive update` from public 0.15.x keeps Claude and Antigravity installs. A needed reinstall keeps the project list, runtime state and backups.
- [SCOPE-11] `hive usage threshold --host` takes used percent for Claude and remaining percent for Codex and Antigravity.
- [SCOPE-12] `hive msg flow start --reviewer-provider <provider>` sets the reviewer provider. `--target .` works on Windows.
- [SCOPE-13] Usage screens and Discord show Claude usage as percent used. A stop caused by unreadable usage no longer promises recovery.
- [SCOPE-14] Install, update and uninstall first copy settings, the project list and changed files to `~/hive-backups`. `hive storage backup` restores them.
- [SCOPE-15] A Claude Code plugin hook adds matching Hive knowledge to each prompt. Guidance requires lookup before every task except small talk.

### Compatibility

- [COMPAT-01] Upgrade from public 0.15.3 and earlier supported versions keeps user answers, knowledge and project files.
- [COMPAT-02] An old `max_panes` value moves to `max_workers`. A conflict between the two values stops the change.
- [COMPAT-03] Skills merge into `knowledge-manage`, `run` and `judge`. Guidance keeps old names. Claude Code owns `/plugin:skill` resolution; Hive cannot redirect those commands. Changed files stay.
- [COMPAT-04] Message hooks and flows stay experimental. Codex hook, worker and cross-review checks on this version are not verified. Gemini hooks stay preview only.
- [COMPAT-05] Status-line use in the Claude desktop app Code tab is not confirmed. If Claude usage does not appear there, use Claude Code in a terminal.
- [COMPAT-06] After apply, trust the Codex project hooks in Codex. Claude automatic mode sometimes blocks `hive msg`. A project permission rule is optional.
- [COMPAT-07] Hook status does not prove host loading or execution.
- [COMPAT-08] Before a downgrade to 0.15.x, revert the status line. A 0.15.x reinstall deletes `~/.hive/backups` and the project list.
- [COMPAT-09] Antigravity 1.x callbacks after 1.1.18 are accepted only with the same data shape. Version 1.2 is not verified on a real host.
- [COMPAT-10] Backups include `~/.claude/settings.json` and are never deleted automatically. They exclude unchanged knowledge, history and `hive setup` edits.

### Verification

- [VERIFY-01] Rust and Python tests with fake host runners cover the inbox, duplicate claims, lost receipts, hook events, worker limits, decisions and Skill moves.
- [VERIFY-02] Public 0.16.0 test acceptance on three operating systems and real host checks on the maintainer PC are recorded in the release evidence.

### Publication

- [PUB-01] Stable 0.16.0 promotes the accepted 0.16.0 public test product.

## 한국어

### 범위

- [SCOPE-01] `hive msg send`·`hive msg inbox`로 역할 사이 메시지를 하나의 파일 수신 상자로 전달. 발신자·순번·중복 방지 키·본문 지문·크기 한도·확인증 결합.
- [SCOPE-02] 프로젝트 훅이 공식 호스트 사건을 Hive 사건 파일로 기록. Stop 훅은 즉시 `queued` 반환, 결과는 뒤의 훅 사건이나 호스트 `/loop` 조회로 전달.
- [SCOPE-03] 작성·검토·자문 작업의 봉투·확인증 흐름, 상태 화면에 Hive 기록만으로 역할·신·제공자·모델·단계 표시.
- [SCOPE-04] 작업자 권한 한도·`max_workers`·읽기 전용 점수표·`hive stop` 취소 사건으로 작업자 실행의 피해 범위 통제.
- [SCOPE-05] 로컬 결정 대기열과 기존 Discord 발신 경로의 결정 요청·완료 알림. 알림마다 구분선, 작업·결과·역할·걸린 시간·확인 명령 표시.
- [SCOPE-06] 내장 Skill 이름 통합, 새 Skill 설명에 옛 이름 표기.
- [SCOPE-07] `hive stop`의 새 메시지 중지, `hive route`·`hive prompt`의 `hive advanced` 하위 이동.
- [SCOPE-08] 사용량을 읽지 못해도 빠진 한도·원인·해결 방법을 알리는 경고 뒤 작업 계속. 측정한 사용량이 기준 이하이면 기존처럼 중단.
- [SCOPE-09] 승인 뒤 `hive setup --scope user --section usage --claude-statusline preview`로 Claude Code 상태 표시줄 연결, 기존 상태 표시줄 유지, 되돌리기 가능.
- [SCOPE-10] 공개 0.15.x에서 `hive update` 시 기존 Claude·Antigravity 설치 인식, 재설치 불필요. 재설치가 필요한 경우에도 프로젝트 목록·실행 상태·백업·claims 보존.
- [SCOPE-11] `hive usage threshold --host <호스트> --window <창>`에 Claude는 사용한 비율 `--stop-used-percent`, Codex·Antigravity는 남은 비율 `--stop-remaining-percent` 입력.
- [SCOPE-12] `hive msg flow start --reviewer-provider <공급자>`로 검토자 공급자 지정. Windows의 `--target .` 지원.
- [SCOPE-13] 사용량 화면과 Discord의 Claude 사용량을 사용한 비율로 표시. 사용량을 읽지 못해 멈춘 경우의 잘못된 회복 안내 제거.
- [SCOPE-14] 설치·갱신·제거 전 설정·프로젝트 목록·바뀌거나 지워질 파일을 `~/hive-backups`에 복사. `hive storage backup`으로 목록 확인과 복원.
- [SCOPE-15] Claude Code에서 플러그인 훅이 요청마다 Hive 지식을 찾아 상위 결과를 함께 전달. 사용자 지침의 조회 조건을 잡담 외 모든 작업으로 명확화, 읽기 전용 작업도 포함.

### 호환성

- [COMPAT-01] 공개 0.15.3·이전 지원 버전에서 사용자 답변·지식·프로젝트 파일 보존 갱신.
- [COMPAT-02] 옛 `max_panes` 값의 `max_workers` 이전. 두 값이 충돌하면 변경 중지.
- [COMPAT-03] Skill의 `knowledge-manage`·`run`·`judge` 통합. 옛 이름 안내 유지. `/plugin:skill` 처리 권한은 Claude Code 소유, Hive의 옛 슬래시 명령 전환 미지원. 바꾼 파일 보존.
- [COMPAT-04] 메시지 훅·흐름은 실험 단계. 이 버전의 Codex 훅·작업자·교차 검토는 실제 호스트 미검증. Gemini 훅은 미리보기만.
- [COMPAT-05] Claude 데스크톱 앱 Code 탭의 상태 표시줄 실행은 미확인. 그곳에서 Claude 사용량이 보이지 않으면 터미널의 Claude Code 사용, 작업은 사용량 미확인 경고와 함께 계속.
- [COMPAT-06] 적용 뒤 Codex에서 프로젝트 훅 신뢰 승인. Claude 자동 모드의 `hive msg` 차단 가능성, 프로젝트 권한 규칙은 사용자 선택.
- [COMPAT-07] 훅 상태와 호스트의 실제 로드·실행 증거 구분.
- [COMPAT-08] 0.15.x로 내리기 전 상태 표시줄 연결 되돌리기 필요. 0.15.x의 `~/.hive/backups`·프로젝트 목록 삭제 가능성.
- [COMPAT-09] Antigravity 1.1.18 뒤 1.x 콜백은 같은 자료 구조일 때만 수용. 1.2 실제 호스트는 미검증.
- [COMPAT-10] 백업에는 `~/.claude/settings.json` 포함, 자동 삭제 없음. 지식 전체·기록·`hive setup` 변경은 백업 범위 밖.

### 검증

- [VERIFY-01] 가짜 호스트 실행기로 수신 상자, 중복·동시 소비, 확인증 유실, 훅 사건, 작업자 한도, 결정 대기열, Skill 이름 이전의 Rust·Python 시험.
- [VERIFY-02] 공개 0.16.0 시험판의 세 운영체제 수용과 유지관리자 PC 실제 호스트 확인의 출시 근거 기록.

### 게시

- [PUB-01] 공개 시험 수용 제품의 정식 0.16.0 승격.
