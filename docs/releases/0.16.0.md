# Aigent Hive 0.16.0

## English

### Scope

- [SCOPE-01] `hive msg send` and `hive msg inbox` move role messages through one file inbox with sender, sequence, idempotency key, body digest and receipt.
- [SCOPE-02] Project hooks record official host events. A Stop hook returns `queued` at once, and a later hook event or host `/loop` returns the result.
- [SCOPE-03] Builder, reviewer and advisor work uses envelopes and receipts. The status screen shows role, god, provider, model and step from Hive records.
- [SCOPE-04] Worker limits, `max_workers`, read-only score files and `hive stop` cancel events limit the effect of worker runs.
- [SCOPE-05] A local decision queue keeps open decisions. The existing Discord sender reports decision requests and completed work.
- [SCOPE-06] Built-in Skills are merged into fewer names, and old names point to the new names.
- [SCOPE-07] `hive stop` stops new messages, and `hive route` and `hive prompt` move under `hive advanced`.
- [SCOPE-08] When Hive cannot read usage, work continues with a warning that names the missing limit, the cause and the fix command. Work still stops when measured usage is at or below your limit. With your approval, `hive setup --scope user --section usage --claude-statusline preview` connects the Claude Code status line so that Hive can read Claude usage, keeps your existing status line, and can be reverted.

### Compatibility

- [COMPAT-01] Upgrade from public 0.15.3 and earlier supported versions keeps user answers, knowledge and project files.
- [COMPAT-02] An old `max_panes` value moves to `max_workers`. A conflict between the two values stops the change.
- [COMPAT-03] Built-in Skills merge into `knowledge-manage`, `run` and `judge`. Old names point to the new names, and changed files are kept.
- [COMPAT-04] Message hooks and flows stay experimental until real Claude and Codex checks pass. Gemini hooks stay preview only.
- [COMPAT-05] It is not yet confirmed that the Claude desktop app Code tab runs the status line. If Claude usage does not appear there, use Claude Code in a terminal; work continues with the missing-usage warning.

### Verification

- [VERIFY-01] Rust and Python tests with fake host runners cover the inbox, duplicate claims, lost receipts, hook events, worker limits, decisions and Skill moves.
- [VERIFY-02] Public 0.16.0 test acceptance on three operating systems and real host checks on the maintainer PC are recorded in the release evidence.

### Publication

- [PUB-01] Stable 0.16.0 promotes the accepted 0.16.0 public test product.

## 한국어

### 범위

- [SCOPE-01] `hive msg send`·`hive msg inbox`로 역할 사이 메시지를 하나의 파일 수신 상자로 전달. 발신자·순번·중복 방지 키·본문 지문·크기 한도·확인증 결합.
- [SCOPE-02] 프로젝트 훅이 공식 호스트 사건을 Hive 사건 파일로 기록. Stop 훅은 즉시 `queued` 반환, 결과는 뒤의 훅 사건이나 호스트 `/loop` 조회로 전달.
- [SCOPE-03] 작성·검토·자문 작업의 봉투·확인증 흐름, 상태 화면에 Hive 기록만으로 역할·신·제공자·모델·단계 표시.
- [SCOPE-04] 작업자 권한 한도·`max_workers`·읽기 전용 점수표·`hive stop` 취소 사건으로 작업자 실행의 피해 범위 통제.
- [SCOPE-05] 로컬 결정 대기열과 기존 Discord 발신 경로의 결정 요청·완료 알림.
- [SCOPE-06] 내장 Skill 이름 통합, 옛 이름의 새 이름 안내.
- [SCOPE-07] `hive stop`의 새 메시지 중지, `hive route`·`hive prompt`의 `hive advanced` 하위 이동.
- [SCOPE-08] 사용량을 읽지 못해도 빠진 한도·원인·해결 명령을 알리는 경고 뒤 작업 계속. 측정한 사용량이 기준 이하이면 기존처럼 중단. 승인 뒤 `hive setup --scope user --section usage --claude-statusline preview`로 Claude Code 상태 표시줄 연결, 기존 상태 표시줄 유지, 되돌리기 가능.

### 호환성

- [COMPAT-01] 공개 0.15.3·이전 지원 버전에서 사용자 답변·지식·프로젝트 파일 보존 갱신.
- [COMPAT-02] 옛 `max_panes` 값의 `max_workers` 이전. 두 값이 충돌하면 변경 중지.
- [COMPAT-03] 내장 Skill의 `knowledge-manage`·`run`·`judge` 통합. 옛 이름은 새 이름 안내, 바꾼 파일 보존.
- [COMPAT-04] 메시지 훅·흐름은 실제 Claude·Codex 확인 전 실험 단계. Gemini 훅은 미리보기만.
- [COMPAT-05] Claude 데스크톱 앱 Code 탭의 상태 표시줄 실행은 미확인. 그곳에서 Claude 사용량이 보이지 않으면 터미널의 Claude Code 사용, 작업은 사용량 미확인 경고와 함께 계속.

### 검증

- [VERIFY-01] 가짜 호스트 실행기로 수신 상자, 중복·동시 소비, 확인증 유실, 훅 사건, 작업자 한도, 결정 대기열, Skill 이름 이전의 Rust·Python 시험.
- [VERIFY-02] 공개 0.16.0 시험판의 세 운영체제 수용과 유지관리자 PC 실제 호스트 확인의 출시 근거 기록.
