# Aigent Hive `0.9.0` 변경점

> 비교 기준: npm `0.8.0`, `develop` 시험 후보
> 현재 상태: `0.9.0-test` 독립 시험 배포 준비, 정식 `0.9.0` 미게시

## 주요 변화

| 영역 | `0.8.0` | `0.9.0` |
| --- | --- | --- |
| 실행 조정 | 신규 실행의 외부 호환 계층 우선 가능성 | 검증된 host-native capability 기본 소유 |
| 장기 실행 | 역할·run checkpoint 중심 | 검증 edge·retry budget·steering을 갖는 loop graph 추가 |
| 지식 검색 | Markdown·공유 FTS 색인 | 모든 질문 전 bounded 전역 RAG와 named-project 검색 |
| 지식 기록 | 검토된 task fact capture | durable fact·preference·workflow의 foreground mandatory memory gate |
| 지식 이식 | Markdown 직접 이동 | checksum manifest 기반 `.hivekb` export·import |
| 프로젝트 수집 | 명시적 promotion 중심 | tracked-first directory scan과 reusable candidate review 추가 |
| Skill | `0.8.0` 기본 suite | loop·Wiki·cleanup·research·scan Skill 추가 |
| Wiki backend | local Markdown 정본 | user-scope `markdown|notion` 상호 배타 backend |
| 원격 knowledge | 없음 | Notion 유일 정본 + user-root SQLite FTS5 projection |
| Prompt refine | explicit·suggestion 중심 | material ambiguity 자동 `refine-only`와 exact 승인 경계 |
| 장애 자료 | 일반 진단만 제공 | 공통 `report to developer` preview·collect·export |
| 시험 배포 | `test` 이력 channel | bare `0.9.0-test|test` 독립 publication, `latest` 불변 |

## Host-native loop engineering

- DAG node·edge·revision·evidence의 canonical Markdown graph
- Self-edge·cycle·unreachable node·orphan criterion 사전 차단
- Evidence predicate 충족 전 전이 금지
- Node별 bounded retry·backoff·failure fingerprint
- 근거·영향 edge를 남기는 dynamic steering
- 독립 verifier·judge evidence 없는 성공 처리 금지
- Fresh-session checkpoint·resume·handoff
- 신규 실행의 `tmux`·scheduler·OMX·OMC 자동 의존성 제거
- 기존 OMX·OMC 고정 run의 owner 보존과 명시적 migration 원칙
- Hive-native iterative·team·multi-goal execution의 default-off 계획과 host feasibility gate
- 신규 workflow의 OMX·OMC functional dependency 제거 결정
- Selected session pointer 비권한, exact event head·control epoch·one-time authority 기반 cancel·recovery 계약

## Wiki와 전역 knowledge RAG

- `hive wiki add|query|lint|list|read|delete|refresh|scan|export|import`
- Keyword·tag·category·`[[wikilink]]` 결합 검색
- 질문·research·knowledge task 전 1회, 최대 5개 bounded retrieval
- User-root·current project·named project·collection scope
- Citation-ready chunk·score·canonical locator
- Markdown 정본과 삭제 가능한 SQLite FTS5 projection
- Dirty journal·generation manifest·resident prepared query 경로
- 검색 결과의 instruction authority 없음
- Raw transcript·secret·credential·runtime 자동 수집 없음

## Wiki backend과 Notion mode

- user-scope `markdown|notion` 상호 배타 설정
- Markdown mode: 기존 local Markdown 정본과 SQLite projection 유지
- Notion mode: 선택한 Notion scope 유일 정본, local Wiki Markdown 생성·활성화 `0건`
- Notion page inventory·revision 기반 changed-only fetch와 다음 retrieval 전 freshness preflight
- Notion create·update 성공 뒤 SQLite write-through, local projection 실패 시 dirty 상태와 query fail-closed
- SQLite 삭제·schema 교체 뒤 complete remote inventory 기반 rebuild
- plugin/app → official hosted MCP → 명시 동의 REST 순서의 capability resolver
- capability·scope drift, partial·truncated·unknown block, remote delete·권한 상실의 fresh publication 차단
- Notion content의 instruction authority·Skill activation·권한 확대·자동 외부 전송 `0건`
- Webhook, Notion AI 이중 검색, local-to-remote push, 양방향 Markdown sync `0건`

## Prompt refine와 사용자 지원

- material ambiguity ordinary work의 `hive-prompt-refine` 자동 `refine-only` 선택
- refined prompt·digest 제시 뒤 `awaiting-approval` 정지
- exact digest 후속 승인 전 project read·tool·write·network·run·실행 `0건`
- correction 시 새 digest 발급, stale·generic approval 차단
- clear work·simple/editless question의 기존 route 유지
- `hive report preview|collect|export`의 명시적 local 문제 보고 자료 생성
- raw prompt·transcript 기본 수집, 자동 upload, 자동 원격 전송 `0건`
- usage guard `limited|unknown` 전이의 선택형 Discord outbound 알림과 bounded retry
- Claude official Discord Channel 경로 위임, Codex inbound continuation은 official capability 확인 전 `unsupported`

## Knowledge 이식과 project scan

- SQLite 파일 복사 대신 deterministic ZIP `.hivekb`
- Versioned manifest·SHA-256·canonical object만 포함
- SQLite·cache·runtime·backup·absolute path 제외
- Directory별 table 대신 stable `collection_id` normalized schema
- Git tracked file 우선 inventory와 bounded snapshot
- Project claim과 reusable candidate의 2단계 review
- 기존 knowledge promotion consent·visibility·confidentiality 경계 재사용
- Destination import 뒤 disposable SQLite 재구축

## 신규·확장 Skill

- `hive-loop-engineering`: host-native graph 준비·검증·checkpoint
- `hive-wiki`: project·user-root Wiki 통합 진입점
- `hive-knowledge-scan`: 현재 directory의 검토 가능한 claim 수집
- `hive-knowledge-capture`: durable memory foreground 기록
- `hive-knowledge-query`: bounded automatic retrieval
- `ai-slop-cleaner`: regression-first, changed-file 한정 cleanup
- `best-practice-research`: 공식 source 우선 bounded research와 인용 handoff

## 호환성과 migration

- `0.8.0 → 0.9.0` same-major non-breaking migration
- Canonical Markdown·tracked YAML/TOML·사용자 preference·foreign byte 보존
- 기존 `0.8.0` project·user base의 byte-exact historical baseline 유지
- SQLite·runtime·backup의 migration 정본 제외와 destination rebuild
- 신규 실행의 host-native 기본값 적용
- 기존 외부 owner 고정 run의 자동 owner 전환 없음
