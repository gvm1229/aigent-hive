# 프로젝트 갱신 스킬 실제 사용 검증

## 범위와 현재 상태

- 사용자 요청: 명령 입력 없는 프로젝트 갱신 스킬 제공·실제 검증 후 예시 프로젝트 적용
- `PRF-001` 스킬 개선·`PRF-004` 기준본·`PRF-005` 예약·`PRF-006` Windows 줄바꿈 표시 병합 완료. `PRF-002` 공개 검증 진행. 예시 적용 전
- Windows 11·Codex 기준 실제 사용 확인. 다른 운영체제의 파일 생성·공개 패키지 검사와 실제 AI 사용의 구분

## 스킬 접근성

- 기존 스킬 파일과 Codex 등록 모두 존재. 전역·플러그인 스킬의 자연어 선택 설정만 `false`
- 원본 스킬의 자연어 선택 허용, 한국어·영어 설명에 프로젝트 갱신 범위 명시
- 선택한 전역 스킬만 자동 선택 허용. 프로젝트 사본의 명시 호출 정책과 사용자의 스킬 선택 유지
- Codex `skills/list`로 실제 설치 경로 발견 확인. 설치 전 전역 두 사본 `false`, test.3 설치 후 두 사본 `true`, 프로젝트 사본 `false`
- test.3 전역 스킬 내용 지문: `bd732b0433f41c66a91b12a2707f862124efb734c310fc93f9796e074fa739cc`
- 사용자 설정 지문 유지, 예시 프로젝트의 기존 406개 파일·Git 상태·57개 사용자 변경 보존 확인

## test.3 공개와 실제 사용

- 소스: `2d07a9b207f005a445cb149bda6a41bb1112c29b`
- CI `35803273136`, 후보 `35803273217` 통과
- 첫 게시 `35804211338`: macOS npm 반영 지연으로 종료. 같은 후보의 복구 게시 `35804968769` 통과
- Windows 등록 패키지의 무결성·설치·갱신 검사 2개 통과. 실제 전역 설치와 `hive.user-install-valid` 확인
- 명령줄 Codex: 스킬 선택 언급 뒤 `helper_sandbox_lock_failed`·오류 5로 파일 읽기 실패. 프로세스 종료 0은 실제 갱신 검증 성공이 아닌 결과
- Codex 기본 에이전트: 스킬 이름 없는 미리보기 요청에서 설치된 스킬을 읽고 조사 실행. 과거 기준본 검증 실패로 중단, 파일 변경 0건
- 일반 앱 질문: 스킬·명령·파일 변경 없이 설명만 반환
- test.3 실제 구버전 갱신 실패로 수용 보류. 예약·줄바꿈 표시 문제 발견 후 미공개 test.4 `35806629061`·test.5 `35808307887` 후보 취소. 최종 수정은 test.6 검증

## 실제 구버전 생성 자료에서 발견한 결함

- 정식 0.10.3 CLI로 만든 합성 프로젝트 보존. 사용자 프로젝트 원문·개인 경로·Git 내부 자료 포함 없음
- 0.9부터 허용한 `available`·`host-native` 조합에 0.8 실행 주체 규칙 적용
- 0.10.1 이후에도 생성한 `.prettierignore`의 과거 기준본 목록 누락
- 사용량 검사 비활성 설정의 실제 생성 문구 변경 미반영
- 해결: 버전별 실제 규칙과 문구 재현. 기준본 인증 생략·과거 원본 변경·기존 실행 주체 변경 없음
- 공개 test.3에서 실패 재현, 수정 코드에서 조사·미리보기·적용·검사 통과. 잘못된 실행 주체와 사용자 서식 규칙·팀 메모 보존도 확인
- [PRF-004 종합 근거](../../tests/results/runs/20260923T012740-52f5a750001e.md): Windows Rust 942개 통과·기존 조건부 제외 4개, 프로젝트 갱신 15개·과거 배포 6개 통과
- 독립 검토로 0.9.0 실행 주체 경계·0.9.3 서식 파일 도입·0.10.3 문구 확인

## 전체 스킬 실행과 Windows 형식

- 실제 스킬의 사전 전체 실행: 조사·미리보기 성공 뒤 지침 경로 예약 거부. 파일 변경 없이 중단
- 예약 코드 보완 뒤 같은 합성 프로젝트의 정확한 18개 경로 예약·적용·검사·종료 성공. 팀 메모 보존. 종료 명령의 불필요한 인수는 한 번 오류 후 바로잡아 성공
- [PRF-005 종합 근거](../../tests/results/runs/20260923T014832-909b7a34c38d.md): Windows Rust 943개 통과·기존 조건부 제외 4개, 프로젝트 갱신 16개 통과. 세 호스트 예약 충돌·외부 경로 거부·지침 파일 보존 확인
- 실제 예시는 AGENTS만 CRLF, 기준본 JSON·설정·관리 지침은 LF로 관측. 같은 합성 자료에서 명령 성공 뒤 설치 선택 문구 누락 재현
- 기준본 JSON까지 CRLF로 바꾼 첫 합성 자료는 정본 검사에서 정상 거부. 이 거부를 완화하지 않고 실제 관측 형식으로 재현 범위 교정
- Hive 지침의 줄바꿈 표시 차이만 정렬에서 구분 제외. 실제 사용자 수정·혼합 줄끝·마지막 개행·단독 CR·공백·표시 밖 원본 보존, 일반 병합 정책 유지
- [PRF-006 종합 근거](../../tests/results/runs/20260923T021945-a49d732d0555.md): Windows Rust 948개 통과·기존 조건부 제외 4개, 병합 25개·프로젝트 갱신 17개 통과
- 새 Codex 에이전트도 CRLF 자료의 조사·미리보기·예약·적용·검사·종료 성공. 부모의 새 검증에서 설치 선택 문구·조건부 예약 문구·원본 보존·남은 변경 0개 확인
- 위 결과는 설치된 스킬과 로컬 검증 실행 파일의 조합. test.6 공개 파일과 설치된 스킬의 정상 미리보기·갱신 실행은 별도 확인
