- 문서 성격: 검토 제안; 제품 구현·실행 정책 변경·후속 버전 확정 승인과의 구분
- 상세: [코드 변경](changes.md) · [실행 구조](runtime.md) · [단계·작업량](rollout.md) · [공식 근거](sources.md) · [조사 계획](PLAN.md)

## 판단

- 추천 조합: **Tauri 2 + React·TypeScript·Vite + Rust 업무 처리·실행 관리**
- 현재 Hive의 강점: 지식 저장·검색, 지침 배포, 작업 상태, 승인 검증, 안전한 갱신
- 큰 빈자리: 사용자가 메시지를 보내고, AI가 도구를 사용하고, 결과를 화면에 계속 전달하는 실행 엔진
- 전환 규모: 기존 기반의 재사용과 새 앱·실행 계층의 추가. 단순 화면 추가보다 큰 제품 작업
- 첫 선택: 외부 실행 엔진을 연결하는 앱부터 검증, 자체 에이전트 실행 엔진은 같은 연결 경계 아래의 별도 후속 후보
- Codex 연결의 위치: **검증용 후보**. 공식 문서의 실험 단계·운영 지원 제한과 인증 조건 때문에 즉시 운영용 확정 제외

## 필요한 앱의 모습

| 사용자의 행동 | 필요한 기능 |
| --- | --- |
| 앱 설치·첫 실행 | 설치 프로그램, 프로젝트 선택, 실행 엔진 연결 상태, 오류 복구 안내 |
| 요청 입력 | 대화 목록, 파일 첨부, 답변의 연속 표시, 작업 중 추가 지시 |
| 진행 확인 | 실제 도구 사용·명령·파일 변경 표시, 승인 요청, 오류·재시도 표시 |
| 중지·재개 | 실제 실행 중단, 최종 중단 확인, 앱 재시작 뒤 작업 복구 |
| 코드 확인 | 파일 탐색·편집, 변경 전후 비교, Git 작업 공간, 터미널 |
| Hive 기능 사용 | 지식 검색·수정, 계획·역할·완료 조건, 스킬·정책 관리 |
| 오래 작업 | 화면을 숨겨도 작업 유지, 알림, 작업량 제한, 종료 시 실행 상태 안내 |

앱 종료 뒤의 계속 실행에는 별도 상주 실행 관리가 필요. 첫 버전의 창 닫기·앱 완전 종료·컴퓨터 절전 상태별 동작 명시 필요. 음성·컴퓨터 조작·내장 브라우저·휴대전화·클라우드 동기화는 각각 별도 확장 기능.

## 적합한 화면 기술

WebView: 앱 창 안에서 HTML 화면을 보여주는 운영체제 구성 요소. 화면의 웹 기술 사용과 브라우저 웹사이트 제품의 구분.

| 후보 | Hive와의 적합성 | 비용·주의점 | 판단 |
| --- | --- | --- | --- |
| **Tauri 2 + React + Rust** | 기존 Rust 라이브러리 연결, 운영체제 WebView, 권한 제한·설치·갱신 지원 | WebView2·WKWebView·WebKitGTK 차이, 세 운영체제의 실제 화면 시험 필요 | 기본 추천 |
| **Electron + React + Rust 보조 실행파일** | Node.js용 실행 SDK 연결, Chromium 기반 화면, 풍부한 데스크톱 구성 | Chromium·Node.js 배포, Rust와 별도 통신, 화면의 Node 권한 차단 필요 | Node.js SDK·내장 브라우저 중심이면 유력 |
| **Flutter + Rust 연결** | Windows·macOS·Linux 앱과 향후 휴대전화 화면 공유 | Dart 추가, Rust 연결 계층, 코드 편집·터미널 구성의 통합 작업 | 휴대전화가 핵심일 때 재검토 |
| **운영체제별 별도 앱** | 각 운영체제의 기본 화면·접근성 기능 활용 | 화면 구현·시험의 반복, 공통 Rust와 언어별 연결 | Windows 전용 확정 시 별도 비교 |

Tauri의 Rust·WebView 구조와 Electron의 여러 프로세스 구조는 공식 문서의 확인 사실. 크기·메모리·개발 속도의 상대 우열은 Hive 실행파일의 측정 전 미확정. [Tauri](https://v2.tauri.app/concept/architecture/), [Electron](https://www.electronjs.org/docs/latest/tutorial/process-model), [Flutter](https://docs.flutter.dev/platform-integration/desktop).

2026-09-26 발표의 Tauri `2.12`에서 최소 Rust `1.90` 확인. Hive의 `rust-toolchain.toml`은 `stable`; 실제 통합 빌드의 도구 버전 고정과 의존성 검사 별도 필요. [발표](https://v2.tauri.app/blog/tauri-2.12/).

## 추천 구성

| 역할 | 후보 기술·소유권 |
| --- | --- |
| 앱 창·설치·알림 | Tauri 2; 운영체제별 설치·서명 |
| 화면 | React·TypeScript·Vite; 대화·변경 비교·설정 화면 |
| Hive 기능 연결 | 새 `hive-app` Rust 라이브러리; 현재 CLI와 앱의 공통 업무 처리 |
| 오래 실행하는 작업 관리 | 새 `hive-runtime`; Tokio 기반 입출력·중단·복구 |
| 화면으로 진행 전달 | Tauri 명령과 Channels; 순서 보존·흐름 제한 |
| 코드 편집·비교 | Monaco Editor 후보; 전체 VS Code 확장 기능과의 구분 |
| 터미널 | xterm.js 화면 + `portable-pty` Rust 연결; 화면만으로 명령 실행 불가 |
| Git | Git 실행파일의 구조화된 결과 우선; 파일명·취소·충돌 처리 필요 |
| 지식·상태 | 현재 `hive-wiki`·`hive-core` 재사용; Markdown 정본과 재생성 가능한 SQLite 유지 |
| 실행 엔진 | 별도 연결 규약; Codex·Hermes·승인된 SDK·향후 Hive 자체 엔진의 교체 경계 |

위 새 패키지 이름은 설계 제안. 현재 저장소의 존재 항목과의 구분. 처음부터 웹 서버·원격 데몬·Node.js·Python을 모두 추가하는 구성 제외. 선택한 실행 엔진에 실제 필요한 보조 실행파일만 추가.

[Channels](https://v2.tauri.app/develop/calling-frontend/), [Monaco](https://github.com/microsoft/monaco-editor), [xterm.js](https://xtermjs.org/), [portable-pty](https://docs.rs/portable-pty/latest/portable_pty/)의 공식 문서 기준 후보. 통합 성능·접근성·한국어 입력의 미검증 상태.

- 현재 규칙: Hive의 모델 제공자 직접 호출·제공자 자격 증명 취급·모델 실행 프로세스 시작 금지
