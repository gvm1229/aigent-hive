# 반복 문맥 압축과 지침 복구 조사

> 조사일·자료 접근일: 2026-09-25
> 환경: Windows, 로컬 Codex CLI 0.155.1, Hive 소스 7539f44b
> 상태: 읽기 전용 조사 완료, 제품·호스트 설정 변경 없음
> 대상: 0.11.0의 후속 구현안. [구현 계획](../plans/directive-context-recovery-0.11.0.md)

## 결론

권고: 압축 직후 짧은 핵심 안내 재전달, 작업에 맞는 상세 지침 선택, 위험한 변경의 코드 검사 조합.
매 도구 호출에 전체 문서를 반복하는 방식보다 작은 입력과 명확한 적용 범위 우선.
외부 공급자 API·별도 판단 모델·지침의 자동 정책 변환은 권고 범위 밖.

사용자의 관측은 여러 번 압축한 뒤 일부 지침 준수 저하. 원인 전체를 압축으로 확정한 실험 근거는 아직 없음.
확인할 가설: 압축으로 사라진 파일 읽기 결과, 문서는 그대로라는 이유의 재전달 생략, 충돌하거나 너무 긴 지침, 모델의 의미 판단 편차.

## 저장소 관측

- [현재 편집 훅](../../crates/hive-cli/src/policy/native.rs): Hive 관리 경로의 직접 수정 검사. 임의 프로젝트 지침 전체의 의미 판정 기능 부재
- 같은 파일의 `CONTEXT`: 고정된 짧은 안내. 현재 지침 원문·현재 작업·압축 횟수에 따른 재구성 기능 부재
- [등록기](../../crates/hive-cli/src/policy/configure.rs): 시작·편집 전·종료 이벤트 등록. 별도 문맥 세대별 복구 상태나 예산 부재
- [보조 훅](../../crates/hive-cli/src/main.rs)의 `checkpoint_reminder`: 압축 전 기록 존재 안내. 전체 지침 복원과 구분
- [정책 목록](../architecture/policy-rule-inventory.md): 이미 규칙과 실제 검사 위치를 구분. 기존 목록·판정기를 확장하는 방향 우선
- [문맥 유효성 계획](../plans/active/refactor-context-hosts.md)의 RFK-002: 원본 지식의 최신성 검사. 모델의 현재 문맥에 지침이 남았다는 증명과 별개
- 소스 AGENTS.md와 지침 9개 합계 57,386 UTF-8 바이트. 현재 모델 입력량이나 소비 토큰의 측정값은 아닌 파일 목록 합계
- 현재 소스 폴더의 Codex 프로젝트 훅 설정·등록 영수증 부재. 이 조사는 실제 훅 활성화나 반복 압축 시험을 수행하지 않은 범위

## 외부에서 확인한 활용 방식

시장 보급률 조사가 아닌 여섯 도구 생태계의 공식 기능·유지보수자 예시 비교.

| 도구 | 공식 사용 방식 | Hive에 적용할 판단 |
| --- | --- | --- |
| Codex | 압축 뒤 `SessionStart`의 `compact` 경로로 다음 모델 요청 전에 문맥 추가. 도구별 훅 선택과 출력량 제한 제공 [S1] | 첫 구현 대상으로 적합. 현재 설치 버전의 실제 자동 압축·수동 압축 동작은 별도 검증 필요 |
| Claude Code | `SessionStart(compact)`로 중요 문맥 복원하는 공식 예시 [S2] | 같은 복구 개념 적용 가능. 호스트가 이미 복원하는 내용의 중복 전달 방지 |
| Antigravity | 모델 호출 직전 `PreInvocation`과 선택적 메시지 삽입, 도구별 검사 [S4] | 명시적 압축 이벤트·세대 식별 계약은 확인하지 못한 상태. 호출 횟수로 압축을 추정하는 보장 금지 |
| Gemini CLI | `BeforeModel`에서 요청 조정, `BeforeTool`에서 작업 거부. `PreCompress`는 관측용 비동기 이벤트 [S5] | Antigravity와 별도 제품으로 취급. 압축 전 이벤트만으로 복원 완료 판정 금지 |
| Cursor | 시작·도구별 검사·문맥 추가. `preCompact`는 압축을 막거나 바꾸지 못하는 관측 이벤트 [S7] | 동일한 이벤트 이름만으로 Codex와 같은 기능 추정 금지 |
| OpenCode | 실험적 압축 확장점에서 요약에 보존할 작업 상태·결정을 추가 [S8] | 압축 전 보존의 참고 사례. 실험 API이며 Hive 기본 방식으로 즉시 채택하는 근거는 아님 |

CLAUDE.md의 루트 규칙은 다시 주입되는 반면 경로별·하위 규칙과 과거 훅 문구는 별도 취급. 파일이 Markdown이라는 이유만으로 모두 같은 방식으로 사라진다는 가정 금지. [S3]

문서에 제시된 주된 사례는 보호 파일 접근 검사, 편집 뒤 서식 검사, 중요 문맥 복원. 넓은 매처 대신 필요한 이벤트·도구만 선택하고 비싼 계산을 캐시하는 권고. [S2][S6]

가벼운 참조와 필요한 시점의 상세 조회를 결합하는 방식은 장기 작업 문맥 설계에도 적합. 다만 참조만 전달한 사실을 실제 조회·준수의 증거로 사용 금지. [S9]

## 지침별 보장 수준

| 지침 종류 | 가능한 강제 | 문맥 처리 |
| --- | --- | --- |
| 소유 파일·허용 경로·유효 승인·버전 결합 | 실제 변경 함수·Git·원격 게시 경계에서 결정적 검사 | 핵심 조건만 안내, 매 호출 설명 반복 불필요 |
| 작업별 시험·계획·완료 기준 | 등록된 자료와 결과의 존재·현재성 검사 가능. 시험의 충분성은 별도 판단 | 현재 단계와 관련 기준만 전달 |
| 언어·톤·설명 수준·설계 원칙 | 일부 형식 검사 가능, 일반 의미의 완전 강제는 불가 | 짧은 핵심 안내와 실제 답변·행동 평가 |
| 사용자 의도·새로운 예외·우선순위 | 자연어를 자동 권한으로 변환하지 않는 경계 | 검토된 PLAN·STATUS·결정 기록에서 복원 |

전체 지침의 몇 퍼센트를 강제할 수 있다는 수치는 현재 제시 불가. 규칙별 관측 가능한 조건과 통제 가능한 실행 경로를 먼저 확정하는 순서.
확인 수준은 문서 발견 → 훅 실행 → 모델 문맥 전달 → 실제 준수 → 변경 차단으로 분리.
앞 단계의 성공만으로 뒷 단계 성공 판정 금지.

## 토큰 절약과 복구의 기준

- 조건이 맞는 파일·명령의 코드 검사는 모델 호출 없이 실행 가능. 주된 비용은 실행 지연과 출력 전달이며 지침 주입 비용과 구분
- 정상 검사에서는 새 설명 출력 0개 목표. 위반일 때만 짧은 이유와 바로잡는 방법 제공
- 압축 직후에는 지침 내용이 바뀌지 않았어도 핵심 안내 재전달. 파일 지문 캐시와 문맥 전달 상태의 별도 관리
- 호스트 자체의 지침 복원 범위를 확인한 뒤 보완할 내용만 선택. 자동 로딩은 발견 경로·파일 크기·호스트별 차이 존재 [S3][S10]
- Codex의 큰 훅 출력은 별도 파일과 일부 미리보기로 바뀔 수 있으므로, 초과 출력을 중요한 지침의 전달 방법으로 사용 금지 [S1]
- Anthropic의 문맥 설계 원칙에 따라 현재 작업에 도움이 되는 작은 문맥을 우선하며, 실제 절약량은 Hive의 비교 시험으로 측정 [S9]

## 자료 충돌·미확인 사항

- 공식 문서의 현재 지원과 저장소의 과거 실제 시험은 서로 다른 근거. 문서상 지원을 설치된 앱의 성공으로 대체 금지
- Claude의 안내 자료에는 PostCompact 활용 설명도 있지만, 상세 참조의 출력 계약은 SessionStart(compact)와 다른 계약. 복원 연결은 상세 계약·실제 전달 확인을 기준으로 선택 [S2][S3]
- Gemini의 일반 성능 안내는 동기식 훅을 설명하지만 PreCompress 상세 계약은 비동기 관측용. 이벤트별 참조를 우선 [S5][S6]
- 현재 공개 문서에 정확한 압축 식별자가 없는 호스트는 중복 이벤트와 새 압축을 안전하게 구분할 근거 부족
- 비용 수치는 아직 설계 목표. 실제 호스트의 여러 압축 후 준수율·토큰·지연 측정은 미실행
- Claude 실제 수용의 기존 0.11.0 범위 제외 유지. Cursor·Gemini CLI·OpenCode 조사로 Hive의 새 지원 호스트 추가를 승인한 것으로 해석 금지

## 조사 인계

읽기 전용 자료 조사를 완료한 뒤 요청된 구현 계획 작성으로 전환. 제품 코드·훅 등록·실제 사용자 프로젝트는 변경하지 않은 범위.
이번 결과는 구현 계획의 근거이며, 압축 누락의 원인 확정이나 새 복구 기능 수용 완료를 뜻하지 않는 상태.
