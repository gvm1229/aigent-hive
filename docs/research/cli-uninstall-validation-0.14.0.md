# 0.14.0 보존형 제거의 실제 검증

## 직접 설치 본체의 실제 제거 — 2026-10-26

- 격리 GitHub VM의 [Windows](../../tests/results/runs/20261026T105828-dcc3c9a392fa.md)·[Linux](../../tests/results/runs/20261026T105641-5751cdd476ff.md)·[macOS](../../tests/results/runs/20261026T110749-2ccf99d7a72c.md) 통과. 개발 실행 파일과 지문 결합 소유 기록을 전용 경로에 준비한 부분 설치, 앱/감시 등록 없음
- 실제 dry-run/무승인 JSON의 무변경, 확인 뒤 본체·소유 설치 기록·파생 색인 제거 확인. Windows 첫 pending 반환 뒤 지연 처리의 complete 기록 확인, 완료 작업 재개는 성공·같은 보존 자료 유지
- 설정·지식·프로젝트 목록/원문·같은 prefix의 타사 파일 지문 불변. Linux의128MiB 초과 개발본 거부는 안전 조건대로 동작, 공유 빌드 대신 시험 복사본의 디버그 정보만 제거. 원본/배치 지문 별도 기록
- `7347cde5`: 본체만 보류된 경우 완료된 파일 단계까지 incomplete로 표시하던 오류 수정. [실제 네 중단 경계 재개·승인 검사](../../tests/results/runs/20261026T111916-17c36936e522.md) 통과, 전체 pending2·본체 unverified 유지
- 현재 미완료: 실제 npm 제거, 등록 앱·감시/예약 제거, 보조 실행 파일 실패 복구와 직접 재설치·공개 배포 파일. D140-001 전체 완료 아님. 정본 계획의 초기 M14–M16 기록은 당시 상태

- 원래 전체 조건과 이전 실패는 [제거 정본 계획](../plans/active/cli-uninstall-0.14.0.md) 참조. 직접 설치 본체의 부분 수용은 등록 앱/감시·공개 후보 완료로 확대하지 않는 경계
