# 모든 공개 안정판의 프로젝트 갱신 검증

## 요구와 적용 범위

- 사용자 결정: 최초 공개 안정판 0.9.1부터 최신까지 모든 공개 안정판의 하위 호환성 보장. 향후 출시에도 적용, 번호 공개 시험판 제외
- 현재 출발 버전: 0.9.1·0.9.2·0.9.3·0.9.4·0.9.5·0.10.0·0.10.1·0.10.2·0.10.3. 목표 0.11.0
- 모든 버전 보장과 모든 설정 조합 증명의 구분. 현재 실제 표본은 공식 Windows CLI로 생성한 Codex 기본 호스트 설정

## 기존 결손과 보완

- 선언된 범위 안의 태그만 검사하던 방식에서 전체 공개 안정판 목록을 먼저 계산하는 방식으로 변경
- 0.9.1부터 목표 이전까지 각 버전에 정확히 하나의 유효한 갱신 경로 요구. 앞·중간·끝 누락, 중복, 역방향, 잘못된 목표·주 버전 종류 거부
- Rust의 고정 여섯 버전 목록을 기준본 등록 목록으로 교체. 별도 실제 배포물 표본 검사는 공개 태그 목록으로 누락 검출
- 각 공식 배포 ZIP의 공개 SHA256 대조 후 구버전 CLI로 합성 프로젝트 생성. 생성 자료의 버전·파일 수·압축 파일 지문을 표본별 manifest에 기록
- 합성 사용자 설정만 사용. 사용자 프로젝트 원문·개인 경로·실행 상태를 표본에 포함하지 않는 경계

## 버전별 검사

1. 표본 지문·파일 수·실제 시작 버전 확인
2. 사용자 지침을 Hive 표시 블록 안팎에 추가, 별도 사용자 파일과 설정 보존 기준 저장
3. 조사·미리보기 뒤 모든 활성 파일 지문 동일성 확인
4. 시험용 실행 파일에서 첫 쓰기 뒤 오류 주입, 활성 파일 전체 원복 확인
5. 첫 쓰기 뒤 프로세스 중단으로 실제 복구 기록 유지, 다음 실행의 recover와 전체 원복 확인
6. 실제 적용·목표 버전·최종 검사·사용자 내용·설정 보존 확인. 폐기 스킬 이름은 선언된 대체 규칙과 일치하는 변환만 허용
7. 재적용의 변경 경로 0개와 전체 파일 지문 동일성 확인

백업·실행 기록은 활성 파일 비교와 구분. recover는 일반 되돌리기 명령이 아니며, 이 시험은 부분 적용 뒤 원복 상황 검증.

- [실행 검사](../../scripts/qualify-project-predecessors.py): 위 전체 목록의 실제 표본으로 갱신·보존 확인. 누락된 표본은 실패

- 다섯 플랫폼 후보 실행 파일에서 전체 안정판 갱신 검사, 버전별 결과와 실행 파일 지문 보존
- 세 운영체제의 공개 패키지 수용 검사에서도 전체 안정판 갱신 실행
- 공개 실행 파일에는 실패·중단 주입 기능 제외. 시험용 복구 결과와 공개 파일 성공 결과를 별도로 기록
