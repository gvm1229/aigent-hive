# 프로젝트 지식 쓰기와 전역 지식 읽기 전용 진단

## 판정

공개 `0.14.0`의 프로젝트 지식과 전역 지식은 하나의 사용자 루트 색인으로 합류. 승격 목록 비우기와 `project-private` 선택만으로 전역 저장소 쓰기 금지 불가. 요청 기능에 필요한 프로젝트 저장소·별도 전역 출처의 분리 설정, 쓰기 권한 정책, 두 저장소 통합 조회의 부재.

색인은 문서를 빨리 찾기 위한 목록. 정본은 다시 만들 때 기준으로 삼는 원래 Markdown. 공개 제품의 프로젝트 Wiki 정본은 프로젝트 안에 있지만, 추출한 사실인 `Claims`와 검색용 자료는 사용자 루트에도 저장. 따라서 검색 공개 범위와 물리적 저장 위치의 별도 판단 필요.

확인된 별도 결함: 명시적으로 해제한 컬렉션의 재연결, 오래된 프로젝트 등록 목록을 적용한 잘못된 해제, 생성 README의 현행 명령 안내 오류. 컬렉션은 함께 검색할 지식의 묶음.

다른 운영 설정을 둔 사용자 루트를 프로젝트 안에 배치하는 경로의 실제 동작 확인. 임의의 모든 격리 저장소가 불가능하다는 결론 제외. 다만 기존 전역 저장소를 읽기 전용으로 함께 사용하는 정책과 구분.

## 최소 수정 권고와 인계

2026-11-04 정정: 읽기 전용은 명시적으로 고른 프로젝트에만 적용하는 추가 옵션. 기존 읽기·쓰기 기능·기본값·저장·승격·권한·연결 수명 동작 유지. [보존 회귀 C1–C5](../../plans/details/project-local-global-readonly/compatibility.md) 필수.

D1·D2와 기존 공유 수집의 준비 순서 수정은 [별도 작업](../../plans/backlog/knowledge-attachment-consistency.md). 새 기능에 묶거나 선행 조건으로 요구하지 않는 경계. 새 옵션은 기존 공유 경로를 유지한 채 전용 저장·읽기 경로부터 추가.

요청 기능의 최소 완성 단위: 중앙 경로·권한 검사 → 프로젝트 저장소 → 무쓰기 전역 읽기와 통합 조회 → 명시적 이전 → 설정·도움말·스킬·회귀 수용. [계획과 승인 경계](../../plans/backlog/project-local-global-readonly.md), [설계·단계](../../plans/details/project-local-global-readonly/design.md), [수용·이전](../../plans/details/project-local-global-readonly/acceptance.md) 참조.

- `agent-owned`: 조사·계획·문서 확인 완료 뒤 잔여 0건
- `awaiting-user-authority`: 제품 구현, 선택적 실제 이전, 버전 선정과 이후 출시·설치
- `awaiting-external-evidence`: 실제 소비자 사건의 정확한 명령 순서. 이번 진단 완료의 선행 조건에서 제외
- `blocked`: 없음. 새 모드 제품 수용은 구현 전 미실행 상태
