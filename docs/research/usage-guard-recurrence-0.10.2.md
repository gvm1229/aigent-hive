## 반복 원인

### 정상 재시작과 잘못된 상태 재사용의 혼동

- [저장 위치](../../crates/hive-cli/src/usage_control.rs): `control_path`가 호스트·세션 식별값으로 디렉터리 선택, 프로세스 번호는 파일 내부 비교
- 같은 세션을 다른 프로세스에서 재개할 때 기존 파일과 충돌 가능
- `load_halt`: 프로세스 번호 불일치를 `Stale`로 분류
- `enforce`: `Stale`이면 센서 호출 전 `session halt marker belongs to a different process binding` 오류
- 의미상 필요한 보호: 이전 프로세스의 허용·우회 권한 재사용 금지
- 현재 구현의 추가 차단: 새 프로세스가 새 사용량을 측정하는 복구 경로까지 거부
- 최초 작성자의 의도 추정 제외; 코드·시험에서 관찰 가능한 동작만 근거로 사용

### 실패를 정상 동작으로 고정한 시험

- [기존 적합성 시험](../../tests/conformance/contracts/test_usage_control.py)의 `test_enforce_refuses_a_process_replayed_halt_marker_without_sensor_use`: 다른 프로세스 표식 차단과 센서 미사용 요구
- `test_halt_marker_is_not_replayed_to_another_binding`: 같은 조건의 `status`는 성공과 `stale` 반환 요구
- `test_enforce_creates_a_latched_marker_and_repeat_skips_the_sensor`: 같은 정책의 중단 후 센서 재호출 금지 요구
- `test_unknown_sensor_state_is_latched_without_raw_payload`: 측정 실패도 지속 중단 상태로 저장
- [0.10.1 수용 항목](../plans/active/harness-upgrade-0.10.1.md)의 `UGR101-003`: 현재 정책 중단 결정의 즉시 재사용 유지
- 결과: 시험 통과만으로 정상 재시작·사용량 회복·일시 센서 실패 이후 복구 증명 불가

### 제어와 복구의 혼동

- `control_session`: `control.json`만 변경; `halt.json` 수정·재측정 경로 부재
- 따라서 `session enable` 성공을 실제 작업 재개 성공으로 해석 불가
- 같은 프로세스·같은 정책의 중단 표식: `enforce`가 측정 시각·사용량 회복을 확인하기 전에 이전 결정 반환
- 전역·프로젝트 기준: 큰 값 적용; 낮은 전역 기준만 변경해도 프로젝트의 높은 기준 유지 가능
- [실제 값 계산](../../crates/hive-cli/src/usage_control.rs)의 `read_effective_config`와 정책 식별값 계산을 복구 설계에 함께 포함할 필요

## 사고 근거와 이전 설명 정정

- 사용자 지정 `Discord 링크 자동 수집` 작업의 2026-09-09 Windows Codex 명령 기록에서 프로세스 결합 오류와 종료 코드 `3` 확인
- 같은 기록의 다시 활성화 안내와 현재 `control_session` 구현 대조: 활성화만으로 표식 복구 보장 불가
- 가장 최근 두 실행의 항목은 조회 결과 비어 있는 상태; 해당 실행의 세부 동작에 대한 독립 확정 제외
- 사고 당시 주간 사용량 `70%` 잔여는 사용자 보고; 이번 조사에서 사고 시점 센서 측정값의 독립 검증 제외
- 이전 답변의 새 세션 `status` 성공: 사고 세션의 복구 증거로 사용 불가
- 이전 답변의 “복구 시험 누락” 설명 보정: 관련 시험 존재, 정상 재시작도 오류로 처리하는 기대값 자체가 문제
- 이전 답변의 Skill 해석 보정: `session_override=stale`의 활성 기본값과 `halt_marker=stale` 복구를 동일 계약으로 단정 불가
- 외부 작업 원문·실제 세션 식별자·프로세스 번호·파일 내용: 문서 제외 대상

## 재발 방지 설계

1. 중단 표식을 과거 관측 기록으로 취급하고, 실행 허용에는 현재 바인딩의 새 측정 요구
2. 다른 프로세스의 정상 형식 표식은 권한으로 재사용하지 않고 현재 프로세스에서 재평가; 다른 호스트·계정의 모호성, 변조·심볼릭 링크 등은 계속 거부
3. 같은 프로세스에서도 일시 측정 실패·사용량 초기화 이후 새 검증 경로 제공; 권장 기본값은 다음 `enforce`에서 제한된 재측정
4. 측정 결과 안전 시 정확한 기존 바이트 비교 후 표식 해제, 부족·불명확 시 현재 증거로 차단 유지; 동시 변경 충돌 시 재읽기 또는 안전한 재시도
5. 이전 프로세스가 함께 살아 있는 경우까지 고려한 바인딩별 상태 분리; 단순 기존 파일 덮어쓰기만으로 복구 완료 판정 금지
6. `status`, `enforce`, `session`, `run resume`, 반복 실행 준비 경로에서 같은 복구 상태 해석; `loop_engineering`의 독립 중단 파일 판독도 검증 대상
7. 기준 변경 명령 결과에 저장된 전역·프로젝트·실제 적용 값과 재검사 이유 제공; 재시작을 해결책으로 요구하지 않는 기준 변경 흐름
8. 설치 Skill·호스트 투영·도움말과 동작 시험의 기대값 동시 변경; 단순 문구 변경만으로 완료 판정 금지

## 필수 수용 조건

| 입력 변화 | 기대 결과 |
| --- | --- |
| 같은 세션, 새 프로세스, 잔여 `70%`, 기준 `20%` | 보호 활성 상태에서 새 측정 후 허용 |
| 같은 세션·프로세스·정책, 일시 센서 실패 후 정상 회복 | 우회 승인 없이 새 측정 후 허용 |

| 기준 이하·정확히 기준값·불명확한 계정·현재 센서 실패 | 보호 차단 유지 |

| 구버전의 중단 표식이 남은 실제 설치 형식 | 보호 비활성화·수동 파일 삭제 없이 복구 |
| 파일 바꿔치기·변조·정책 변경 경쟁 | 잘못된 허용·타 세션 상태 삭제 금지 |
