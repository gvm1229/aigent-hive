# 사용자 관리 ship과 프로젝트 갱신

## 조사 계획과 범위

- 대상: WProject에서 보고된 `ship` 기준 원본 충돌, test.6의 전역 `user-setup` 명시·자연어 검증
- 허용: 명시한 프로젝트의 Hive 설정·해당 스킬·본인 지침과 계획의 읽기 전용 조사, 공식 미리보기
- 제외: 사용자 스킬 이동·삭제·덮어쓰기, 기준 원본 임의 등록, 프로젝트 적용·커밋·다른 구성원 자료 조회
- 절차: 소유권과 실제 내용 확인 → 기존 설정 유지·기본 `ship` 제외의 공식 미리보기 → 원본 불변 확인 → 사용자 선택과 제품 수정 필요성 분리
- 검증: Windows·Codex·공개 `0.11.1-test.6`, 실제 CLI 결과와 핵심 파일 지문 전후 비교; Unity 실행·모든 스킬의 모델 준수는 증명 범위 밖

## 확인된 사실

- 기존 프로젝트 버전 0.11.0, 선택 스킬 10개·`ship` 제외, 설치 기준 목록에도 해당 경로 없음
- 사용자 관리 `ship`의 프로젝트 전용 `MonoBehaviour` 검사·정상 커밋 훅 규칙, 별도 설치의 본인 계획 기록 존재
- 공식 scan의 `hive.update-conflict` 재현, 인증된 병합 기준 없는 기존 파일의 보존과 갱신 중단
- 기본 `ship` 추가가 사용자 파일과 같은 경로를 사용하므로 충돌, 사용자 파일 이동을 기본 해결책으로 권장하지 않는 판단
- 기존 스킬 보존과 Hive 기본 `ship` 제외의 선택 변경은 사용자 결정 대상, 22개 기본 선택과 사용자 `ship` 보존 질문 제출

## 선택 변경 미리보기

- 공개 test.6의 공식 `setup --dry-run` 실행, 원래 답변의 다른 설정을 유지한 개별 스킬 22개 입력
- 기존 능력 증거의 YAML 값을 임시 JSON으로 변환; 능력·권한의 추가 또는 임의 변경 제외
- `hive.setup-conflict`: 기존 활성 스킬 목록과 인증된 설치 이력의 불일치, 현재 CLI 경로의 구버전 재설정 제약
- 사용자 `ship`과 핵심 파일 6개 지문 불변, 실제 적용·파일 이동·기준 원본 추가 없음
- 사용자 선택 확인 뒤 인증된 구버전 기준을 재사용하는 Hive 경로 수정 검토; 프로젝트 보호 조건 완화와 사용자 파일의 생성 소유권 전환 제외

## 전역 스킬 검증

- 사용자가 보고한 재시작·목록 확인, 두 새 대화의 명시·자연어 요청과 실제 스킬 읽기·CLI 명령 실행 확인
- 두 대화 모두 Windows·Codex·test.6에서 `hive.user-setup-valid`, 설정·프로젝트 변경 없는 요청 범위 유지
- 자연어 대화의 `hive.user-install-dry-run-complete`, 전역 설치 미리보기 성공
- 초기 명시 호출의 도우미 상대 경로 오류 후 올바른 파일로 복구; 이 오류와 최종 검증 통과의 구분
- 전역 호출의 성공과 프로젝트의 사용자 파일 충돌 해결은 별도 증명 범위
