# 0.14.0 설정 진행 기록의 대상 확인과 쓰기 복구

## 범위

- 설정 진행 기록: 사용자가 고른 답안과 다음 질문의 저장 위치
- 처리 기록: 적용 시작·실패·완료와 전후 파일 지문의 저장 위치
- 대상 폴더 확인 `622c5006`, 중단된 기록 쓰기 복구 `1fce3d1f`
- Windows11 x64의 격리 폴더·오류 주입·실제 CLI 구성 시험. 공개0.14.0·Linux·macOS·전원 손실 시험은 별도 미검증

## 같은 경로의 다른 폴더 구분

- target_id에 정규화 경로와 운영체제의 디스크·폴더 식별자 결합. 저장값은 지문, 실제 경로와 식별자 원문은 기록 제외
- 읽기·쓰기·완료 기록 전에 현재 폴더와 열어 둔 폴더의 일치 확인
- 같은 경로에 새 폴더를 만들거나 진행 파일을 복사한 경우 이전 답안의 자동 재개 거부. 기존 답안 보존
- 일반 파일 추가는 폴더 교체와 구분하여 정상 재개 유지
- [Windows 진행18개](../../tests/results/runs/20261024T002042-3c65b3af2600.md)·[사용자244개](../../tests/results/runs/20261024T002128-14489a198d9d.md) 통과. Windows의 열린 폴더 이동 거부 확인 후, 닫고 교체한 경우의 재개 거부 검증
- 최초 시험2개 실패는 열린 폴더 이동 자체의 Windows 오류32. 해당 [실패 기록](../../tests/results/runs/20261024T001905-11f760899fea.md) 보존. Unix의 열린 폴더 교체 검사는 현재 Windows에서 미실행

## 중단된 쓰기 복구

기존 파일 교체는 원본을 별도 위치에 보관한 뒤 새 파일을 게시하는 방식. 중간 종료로 원래 경로가 비어 있더라도 새 설정 시작으로 오인하지 않는 처리.

| 위치 | 역할·수명 |
| --- | --- |
| `.hive/config/setup-progress/locks/<target-id>.lock` | 같은 범위의 짧은 쓰기 잠금. 파일 존재와 실제 잠금 구분, 질문 대기에는 잠금 없음 |
| `.hive/config/setup-progress/writes/<target-id>.json` | 대상·전후 지문·원래 권한만 보관. 답안 원문 없음, 해당 쓰기와 정리 완료 뒤 제거 |
| 기존 파일 교체의 claimed.bin·replacement.bin | 기존 검증 방식으로 원본과 게시값 대조. 불명확한 내용이나 다른 권한은 보존 후 거부 |
| `.hive/history/lifecycle/<operation-id>.json` | 기존 범위별 완료100개 보존. 미완료 기록의 자동 삭제 없음 |

- 쓰기 순서: 현재 폴더 확인 → 같은 범위의 잠금 → 이전 쓰기 복구 → 원본 대조 → 쓰기 의도 저장 → 파일 교체 → 쓰기 의도 제거
- 조회는 복구 파일을 바꾸지 않고 확인 가능한 원본 또는 게시값 사용. 실제 설정·갱신·완료 기록 경계에서만 복구 실행
- 이미 게시된 답안 유지, 게시 전 중단은 원본 복원. 명시한 진행 삭제는 답안을 다시 살리는 동작 없이 완료
- 쓰기 의도 파일 자체의 생성·삭제 중단도 복구 대상. 완료 전 임의 시간 만료나 삭제 없음
- 생존한 쓰기 작업의 잠금·다른 폴더·다른 범위·지문 또는 권한 변경은 복구 거부
- 전역 완료 처리에서 다른 프로젝트의 중단된 기록에 개입하지 않는 범위 분리
- 실행 정보의 지문 결합과 적용 승인 검사는 계속 별도 수행. 쓰기 복구 기록에서 새 실행 권한을 만드는 동작 없음

## 질문판 변경의 선택적 재개

- `aaa1d899`: 질문별 revision·저장 키·입력형·묶음을 진행에 저장. 값과 선택 출처는 보존하고, 뜻의 번호·키·입력형 또는 허용값이 달라진 답안만 재확인
- 문구 다듬기나 권장 기본값 변경만으로 유효한 기존 선택을 교체하지 않는 기준. 질문 뜻 변경 시 revision 증가 필요
- 같은 원본 설정·권한·대상의 미확정 답안에 한정. 적용 시작/실패 기록·바뀐 원본·지원하지 않는 질문은 자동 재해석 없이 보존
- [Windows 설정139개](../../tests/results/runs/20261024T012526-8e08d19a0b18.md)와 [실제 터미널 재개](../../tests/results/runs/20261024T013055-48b1535529c2.md) 통과. 합성 질문판 차이를 넣은 뒤 배경 선택만 다시 확인하고 한국어·Codex 선택을 유지하여 적용 완료
- 위 터미널 시험은 개발0.14.0·앱 대역의 조합. 공개 질문판 사이의 갱신이나 다른 OS의 수용 근거에서 제외

## 파일·AI 입력의 공통 적용과 복구

- `d07c0cfb`: 파일의 명시적 `--apply`도 확정 답안·처리 기록·동일한 파일 쓰기 복구 경로 사용. 같은 완전한 저장 초안은 확정 가능, 다른 답안으로 미완료 작업 교체는 거부
- 같은 파일의 재실행은 최초 답변 시각과 출처 보존. AI 입력의 출처는 `agent`·`external-change`, 사용자 직접 선택으로 승격 없음
- 이미 승인한 적용은 `--resume --non-interactive`로 복구 가능. 미확정 답안은 입력 보류, `--resume --dry-run` 동시 사용은 변경 없는 입력 오류
- [최종 실제 CLI](../../tests/results/runs/20261024T083117-bff53facbe26.md): 초안 저장→적용 중 종료 87→다른 답안 거부→같은 파일 복구. AI 입력의 별도 중단은 공통 재개 명령으로 완료
- 첫 파일 복구 구간의 가짜 호스트 명령은 읽기 전용 6회, 설치·모델 호출 0회. 미리보기와 검증은 진행 파일 무변경
- Windows 설정 171개는 마지막 초안 수용 보완 전 범위. 최종 파일 관련 5개·비대화형 4개·코드 검사 통과. 연결 통합 6개 중 5개 통과, Antigravity 대상의 Codex 전용 기본값 1개는 적용 대상 차이로 제외
- 최초 비대화형 복구 거부는 제품 수정 후 재검증. 자료형 추론 오류와 시험 명령 순서 오류는 수정 후 통과, 실패 기록 보존
