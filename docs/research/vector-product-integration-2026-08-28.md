- `vector-scale-100/preparation.json`, `registry-normalization.json`, `cleanup-receipt.json`: 실패 임시본은 활성 색인과 전체 해시 일치 확인 뒤 정확한 파일 하나만 정리

- 의미 후보 검색 뒤 질문·문서 쌍을 함께 읽고 관련성 점수만 계산하는 별도 모델
- [Sentence Transformers의 공식 검색·재정렬 방식](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)은 빠른 후보 탐색과 정밀 순위 계산을 분리
- 공개 후보 [다국어 mMiniLMv2 재정렬 모델](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1): Apache-2.0, ONNX 제공. 한국어 정확도·현재 CPU 지연은 미검증
- 기존 로컬 실행 예외는 임베딩 색인 계산에 한정. 재정렬 모델 실행·의존성 추가 전 유지보수자 승인 필요
- 승인 시 원본·독립 질문을 변경하지 않고, 정확한 사실 검색 무회귀·전체 지연·모델 용량을 함께 측정
- 제공자 API·글 생성·기준 완화 없음. `0.10.0` 후보이며 이후 버전으로 자동 이월하지 않음

### 현재 승인 범위

- 추가 모델 없이 가능한 비교: 순위만 더하는 RRF와 검색 점수의 정규화 결합 비교
- [혼합 검색 결합 함수 연구](https://arxiv.org/abs/2210.11934)의 점수 결합을 참고하되, 다른 자료의 우위를 Hive의 통과 근거로 사용하지 않음
- 현재 실제 FTS 점수와 벡터 거리 점수에 질문별 최소·최대 정규화 적용, 벡터 비중 0.25·0.5·0.75만 사전 지정
- 원본 120문항으로 후보를 선택한 뒤 독립 문항으로 별도 확인. 문항·정답·기준 수정 없음
- 사전 지정 비중 0.25·0.5·0.75의 원본 의미 결과: 86.7%·91.7%·95.0%, 정확 질문은 모두 100%
- 벡터 비중 0.75만 후속 독립 평가 후보로 선택. 이 탐색 뒤 위의 실제 CLI 검증으로 연결, 새 모델 실행 없음

- 초기 생성 보강 후보: 같은 ONNX 모델을 한 프로세스에서 공유하는 제한된 스레드 묶음과 기존 다중 프로세스 비교
- [ONNX Runtime의 동시 실행 계약](https://github.com/microsoft/onnxruntime/blob/main/onnxruntime/core/session/inference_session.h)과 [스레드 설정 안내](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)를 기준으로 CPU만 검사
- 모델·본문 길이·batch·질문·채택 기준 변경 없이 메모리·실제 시간·벡터 결과 동등성 검증 후 적용
- 공유 CPU 세션의 3,072개 탐색: 8개 스레드 33.99초·최대 작업 메모리 2.27GB, 12개 27.21초·2.88GB. 전체 생성 시간으로 환산해 통과 처리 금지
- 이전 다중 프로세스 결과와 일부 벡터의 최대 성분 차이 약 0.00014. 동일 입력 64개는 순차 3회·동시 24회 바이트 일치
- 서로 다른 512개 입력도 순서를 바꾼 동시 32회 실행에서 각 순차 결과와 바이트 일치
- 동시 실행의 같은 입력 반복과 실행 구성 변경의 수치 차이를 구분. 최종 검색 결과·전체 비용 검증 전 출하 방식 확정 금지

1. 고정된 최적화 빌드로 원본 120개·독립 60개 질문의 실제 CLI 재검증
2. 최종 후보의 고유 5만 청크 전체 생성·100개 변경·중단 재개·전체 재생성 동등성
3. 실제 CLI 전체 시간·범위별 디스크 사용량·승인/기밀 경계 재검증
4. Windows x64·macOS arm64·Linux musl의 고정 바이너리 수용

독립 질문 작성자는 기존 질문·모델 점수에 접근하지 않는 별도 검증 역할.
어느 후보도 통과하지 못하면 통과로 표시하거나 기준을 완화하지 않고 미달 원인 보존.
독립 60문항 고정 SHA-256: `e2de7a222f1cb9aad9c5c1f8c90c6890797c3c7b1da896a64a85bb47b8613fcb`.
기존 정답표 감사도 순위·모델 점수와 분리. 감사만으로 원본 질문·정답·기준 변경 금지.

### 평가자료 검토의 한계

- 120개 답변 근거 감사: 타당 84개·복수 정답 5개·필수 조건의 본문 근거 부족 31개
- 후속 독립 검토: 완전한 답변 근거 부족과 검색 관련성 부족의 구분 필요
- 문항을 바꾼 진단용 v2의 원래 검색 기준 대체는 미승인. 원본과 독립 60문항은 그대로 보존
- 단순 버전 문자열의 복수 정답·본문에 없는 숫자는 별도 정정 근거. 문서 간 관계 질문의 일괄 삭제·교체 금지
- 복수 정답의 하나 이상 포함률과 모든 필수 근거의 회수율 구분. 기존 미달을 새 평가셋 통과로 소급 취소 금지
