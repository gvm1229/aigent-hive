# 0.14.0 프로젝트 재설정과 역할 보존 검증

## 범위

- Windows 11 x64의 개발 0.14.0과 임시 사용자·프로젝트 폴더, 전용 앱 대역
- 실제 사용자 설치 변경 없음. 공개 0.13.1 프로젝트·다른 운영체제·실제 역할 실행 지원의 합격 근거에서 제외
- [새 프로젝트와 종료 복구의 이전 근거](cli-project-validation-0.14.0.md)와 구분

## 보존형 갱신과 설정 검증 연결

- [최초 관찰](../../tests/results/runs/20261024T053842-7eebabc1e0f9.md): 사용자 수정 후 갱신은 성공·원문 보존, 설정 검증은 AGENTS.md와 개별 지침에서 실패. 기능 파일만 통과
- 원인: 보존 기록을 기능 파일 범위로만 해석하는 검증과 별도의 공유 표시 블록 검사
- 수정 `c5f79982`: 기능·개별 지침·공유 표시 블록의 원본 및 보존 지문을 각각 대조. 알려지지 않은 경로·바뀐 원문·오래된 원본 지문 거부
- 일반 재설정의 정본 재생성으로 보존된 수정이 사라지는 경로 차단. 이후 재설정은 아래 보존형 병합 경로 사용
- [수정 후 실제 CLI](../../tests/results/runs/20261024T055052-174fc630bb75.md): 세 종류 모두 갱신·설정 검증 성공, 일반 덮어쓰기 거부, 사용자 수정 바이트 동일
- 렌더링 74개·프로젝트 갱신 49개 회귀와 코드 검사 통과. 초기 실패 기록 유지

## 기존 설정의 대화형 재설정

- 후보 렌더링 `aed9fe83`→보존형 병합 `d23d185d`→대화 연결 `f1985f63`
- 저장값의 정규화와 출처 유지. 기존 출처 불명은 `legacy-unknown`, 새 자동 보충값은 `default`, 실제 다시 답한 값만 새 선택 기록
- 같은 호스트에서는 저장된 기능 자료 재사용. 실제 실행 지원의 재검증으로 표시하지 않는 구분
- 이전 배포 원본·현재 사용자 수정·새 설정의 세 자료 비교. 병합 결과와 제품 정본 기대값을 분리한 임시 검증
- 새 요구가 누락되거나 수정된 기능 파일을 삭제해야 하는 충돌은 원문 보존 후 거부
- [실제 CLI](../../tests/results/runs/20261024T064031-5386d796051a.md): v1 답안 형식의 개발 하네스에서 이름 변경→미리보기 거부→원본 답안 불변→재개 확인→파일 1개 적용 후 종료 87→비대화형 재개 완료
- 확인 결과: v2 답안 저장, 기존 프로젝트 식별자 유지, AGENTS.md·개별 지침·기능 파일의 사용자 추가 내용 보존
- [설정 163개 회귀](../../tests/results/runs/20261024T064710-1009a2c8a511.md), 병합 단계의 렌더링 76개·프로젝트 갱신 51개 및 코드 검사 통과
- v1 답안 형식 시험과 공개 0.13.1 원본 설치 시험의 구분. 후자는 이 기록에서 미실행

## 기존 역할 정의 변경

- 구현 `ef1eca97`: 바뀌는 기존 역할 목록과 별도 확인 질문, 기본 거부
- 거부 시 원문 유지와 역할 입력부터 재검토. 같은 정의의 승인 후 재개는 확인 반복 없음
- 승인한 역할 ID·정의 지문·질문판을 진행과 결합. 승인 뒤 정의 변경은 재확인
- 역할 본문·현재 할당·인계가 동일한 정의 변경만 적용·복구 허용. 명시하지 않은 역할 변경과 실행 주체 교체 거부
- [실제 CLI](../../tests/results/runs/20261024T065626-d12669e66b2f.md): 거부→역할 재검토→승인→파일 1개 후 종료 87→비대화형 재개, 본문·할당·인계 보존
- 위 실제 CLI는 정의별 지문 추가 전 소스 범위. [지문 추가 후 실제 파일 적용 회귀](../../tests/results/runs/20261024T070140-60bf9d1ee632.md)에서 정의 변경 시 재확인 및 보존 적용 확인
- 렌더링 76개·설정 164개 전체 회귀는 지문 추가 전 범위. [최종 코드 검사](../../tests/results/runs/20261024T070254-e61a7b4e2a10.md) 통과

## 남은 수용

- 공개 0.13.1 프로젝트와 0.14.0 전역 설정의 조합, 세 운영체제 및 공개 후보 수용

## 선택 기능과 후크의 별도 동의

- `0bbfd614`→`c32a658c`: 로컬 기능 원본·요청/승인 권한·지원이 확인된 후크 입력, 별도 동의, 최종 미리보기의 순서
- 새 설정의 선택 기능·후크 기본 비활성. 검토 거부는 기존 선택 유지, 빈 목록의 명시적 승인으로 해제
- 원본 지문·승인 시각·후크 명령은 CLI에서 계산. 같은 승인 재개는 반복 질문 없이 유지, 선택 변경은 재검토, 미리보기 뒤 원본 변경은 적용 거부
- [실제 CLI](../../tests/results/runs/20261024T081650-d7b163b738ed.md): 별도 동의 거부→초안 재개→승인→파일 1개 적용 후 종료 87→비대화형 복구→기능·후크 해제. 사용자 원본 파일 보존
- Windows 설정 170개와 [최종 선택 관련 8개 회귀](../../tests/results/runs/20261024T081808-b9837f140a79.md), 코드 검사 통과. 시험의 확인 문구 불일치와 함수 길이 실패는 수정 후 통과, 최초 기록 보존
