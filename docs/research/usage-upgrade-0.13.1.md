# 사용자 연동·Windows 감시 갱신의 보존 수정

## 실제 공개 시험에서 확인한 문제

- 공개0.13.0 Windows 실행 파일로 Skill3개를 고른 합성 사용자 설치 생성.13.1-test.1의 일반 갱신에서 실행 파일 교체 성공, 사용자 연동은 `hive.user-install-conflict`로 거부. 기존 설정·지식·중단 기록 보존, 실사용자 설치 변경 없음
- 원인: 설치한 파일의 공개 지문은 정상이나 과거 인증에서 선택하지 않은 모든 Skill 파일까지 요구. 전체 선택을 바탕으로 만든 이전 합성 시험의 검증 공백

## 수정과 보존 경계

- 포함된 파일은 기존과 같이 내장 공개 원본·허용한 언어·Windows 줄바꿈의 지문과 대조. 선택한 Skill 묶음의 전체 파일·필수 플러그인 메타데이터 요구, 선택하지 않은 묶음은 필수 검사에서 제외
- 임의 경로·변조·선택 묶음의 일부 누락 거부. 설치 기록의 자체 지문만으로 파일을 신뢰하는 우회·사용자 자료 삭제·재설치 없음
- [합성 공개 기록](../../tests/fixtures/user-predecessors/0.13.0/README.md): 실제 공개 실행 파일의20개 항목. 사용자 실제 설치에서 가져온 정보 제외

## 검증 범위

- 현재 Windows의 사용자 설치·인증 회귀101개 통과, 전체 선택·부분 선택과 변조·누락 거부 포함. 엄격 검사·형식 검사 통과, 최초 함수 길이 검사 실패와 정리 뒤 재검증 기록 보존
- 공개0.13.0에서 별도로 만든 부분 설치를 새 소스 실행 파일로 미리보기·적용·검증. 설정·지식·기존 기록 보존 확인, 호스트 등록만 시험 대역. 새 공개test.2 실행 파일의 실제 갱신·감시 전환은 별도 수용
- 기존 Windows 대화·AI 하위 작업 중단·알림·재개 정본 코드 변경 없음. 새 코드 변경을 이유로 같은 중단 시험을 반복하는 처리 제외

## 첫 공개 시험의 별도 결과

- `0.13.1-test.1` 후보39550218935·게시 복구39553168664 성공, 정확 소스 `d43bb9918f8dfa9a86c0f0fb2f99c2f5cb185130`. 여섯 npm 파일의 SHA-512·주석 태그·GitHub 시험판 대조 통과, latest0.13.0 유지
- 세 운영체제 공개 수용39553674579: Windows·Linux 통과, macOS의 기존 벡터 검색 보조 프로그램에서 신호6 종료 실패. 같은 보조 프로그램의 별도 진단은 성공, 원인 해결이나 원래 수용 통과의 대체 제외
- 실패한 실제 부분 갱신과macOS 결과 보존. test.1을 수용으로 변경하지 않고 수정한test.2에서 관련 공개 검증 재실행, 벡터 제품 기능의 추가·기준 완화 없음

## 두 번째 공개 시험과 Windows 경로

- [test.2 결과](../../tests/results/release-0.13.1-test.2.json): 정확 소스23314c44·후보39560738094·게시 복구39564940601·여섯 파일 대조 통과. Windows·Linux 공개 수용 성공, macOS의 기존 벡터 보조 프로그램 신호6 실패 반복. 수용 미완료 유지
- 부분 선택 인증 수정은 실제 공개 갱신에서도 통과. 이어진 감시 전환에서 일반 경로와 `\\?\` 경로를 다른 루트로 비교해 소유권 거부. 원래 실패 자료·사용자 설정 보존
- 같은 폴더의 고정 핸들에서 장치·파일 식별자를 대조한 뒤 프로세스용 경로만 정규화. 새 실행 파일의 모든 구분자도 Windows 형식으로 통일해 실제 프로세스 식별 검사와 일치. 다른 폴더·임의 예약·상위 경로 거부 유지

## 이전 감시기의 종료 순서와 알림

- 실제 소스 갱신의 첫 실패: 이전0.13.0 감시기65568이 예약 제거 뒤에도 잔존, 새 상태 형식은 기록됐으나 사건 기록은 없음. 사용자는 앱이 유지된 채 중단·안내 창을 관찰. 이전 감시기의 새 형식 읽기 실패 경로와 부합하나 정확한 취소 영수증·감지 시각 부재로 그 창의 원인 확정 제외
- 해당 합성 시험의 경로·실행 파일 지문·보유 핸들을 확인해 Hive 감시기65568만 정리. Codex·하위 AI 프로세스·다른 앱에 운영체제 종료 신호 없음, 원래 Codex 앱 생존 확인
- 수정 순서: 이전 설정의 일시 비활성 → 기존 상태를 그대로 두고 제어부 잠금 해제 확인 → 정확한 이전 예약 제거 → 새 기록·실행 파일 전환. 종료 확인 실패 시 기존 선택·기록 형식 보존, 전환 미완료 표시. 강제 종료 기능 추가 없음
- 시작 실패의 실행 번호·버전·원인을 `startup.json`과 상태 명령에 보존. 안내 창의 읽기 실패에서도 전달한 이유·시각 유지, 실제 확인 실패를 성공이나 과거 사건으로 표시하지 않는 동작

## 긴 대화의 상태 연결

- 현재 Windows 읽기 전용 진단: 소유자만 조회하면633개 목록의 확인 대기0개까지 약4초. 전체 상태 연결은19,943,687바이트 프레임이 기존16MiB 한도를 넘어 보조 연결 종료
- 표준 JSON 해석기로 제한된64MiB 입력에서 작업 상태·순서·확인 정보만256KiB 이하로 추출. 본문·도구 결과·변경 값은 대기열 제외, 기존 중단 요청·소유권·확인 시한 유지
- 수정 후 현재 앱의19,976,860바이트 상태 자료 수신, 대화2개·실행2개·확인 대기0개로18초 연결 유지. 읽기 실패 없음, 대화 중단 요청 없음. 앱 충돌 원인의 확정이나 서버 처리 종료 증명과 구분
- Windows 알림·제어 회귀57개와 Rust 감시53개 통과, 실제 관측 시험1개는 별도 수용으로 선택 실행 제외. 첫 검사에서 시험 입력·이전 소스 추출 가정3개 실패 후 수정·재검증, 실패 원본 보존. 엄격 검사 통과
- [최종 Windows 전환](../../tests/results/usage-windows-transition-0.13.1.json): 확정한 e3de3ae3 제품 코드에서 별도의 공개0.13.0 활성·비활성 설치를 새 소스 실행 파일로 전환. 새 실행 파일 지문·정상 조회4회·대화 제어·확인 대기0개·설정/기록/앱 보존 통과, 사건 재전송 없음. 시험 감시기는 검사 뒤 해제
- 이 단계의 추가 대화 중단 요청 없음. 이전 실제 긴 추론·도구·AI 하위 작업 중단과30분 조회 근거는 해당 코드 범위로 유지, 새 공개test.3의 실제 갱신 수용은 별도. 과거 앱 충돌의 정확한 원인은 여전히 미확정
