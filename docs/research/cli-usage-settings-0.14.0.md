# 0.14.0 사용량 경고와 일반 설정의 감시 해제

## 범위와 판정

- 초기 검증은 각 절의 당시 범위, 후속 M09 결과는 마지막 절 기준. 전체 진행은 [CURRENT](../state/CURRENT.md) 참조

- 같은 경고의 반복 방지와 기존 v2 사용자가 보호를 끄는 설정 흐름의 부분 수용
- Windows 11 x64 개발 CLI·분리된 사용자 폴더·가짜 Codex와 Linux amd64 격리 컨테이너의 관련 시험
- 새 감시 활성화의 별도 동의, 갱신 결과의 상태 표시, 수동 사용량 조회 안내 연결, 공개 후보 수용은 계속 미완료
- 전체 G140-001·G140-002 또는 0.14.0 완료 판정으로 확대 금지

## 경고 표시 이력

- `d58b785f`: 기준을 20%→40%→20%로 다시 선택할 때 같은 기간의 기존 경고가 반복되던 문제 수정
- 호스트·계정 지문·사용량 구간별 파일에 현재 기간과 기준별 이력 저장. 최대 100개 기준, 저장 입력 한도 32KiB
- 경고용 추가 조회 없음. 이미 검증된 관측만 사용하며 낮은 잔여량과 실제 0%의 표시 이력 구분
- 각 기준을 초과한 정상 관측 두 번 또는 새 사용량 기간에서 다시 안내 가능. 같은 관측의 재사용을 두 번째 회복 관측으로 계산하지 않는 조건
- 이전 저장 형식의 마지막 경고 이력 보존 후 새 형식으로 이전. 프로그램 재시작·다른 기준 선택만으로 기존 표시 이력 삭제 없음
- [Windows 경고 검사](../../tests/results/runs/20261024T142617-89adc2baa125.md) 7개 통과. 기준 왕복·기간·동시 표시·회복·이전 형식·해제·오래된 관측 포함. 실제 센서 조회의 증명은 제외

## 일반 설정에서 기존 감시 해제

- `3a9c0578`: 이미 v2 설정을 쓰는 사용자의 전체 보호 또는 상시 감시 해제를 공통 적용 경로에 연결
- 미리보기에서 현재 Hive 소유 감시 설정의 지문을 진행 기록과 결합. 다른 선택으로 바뀌면 적용 거부
- 색인 읽기 범위의 지문을 먼저 검사한 뒤, 정확한 기존 감시 종료→해제 선호 저장→색인·하네스 적용 순서
- 종료 실패 시 기존 사용자 설정 보존. 종료 확인 뒤의 색인·하네스 실패에서는 해제 선호와 복구 기록 유지
- 완료 시 단순한 `enabled=false`만으로 종료 판단 금지. 해제 완료 기록·현재 설정 지문·감시 프로세스 잠금 해제 확인
- 새 설치에 감시 구성이 없으면 종료 동작이나 감시 폴더 생성 없음. 저장된 감시 선택과 실제 실행 상태의 의미 구분

- `live_monitor_sensor_sustains_four_fresh_observations`는 실제 조회 네 번과 시작 사이 15초를 요구하는 기존 별도 시험. 이번 고정 관측·분리 시험 범위 밖이므로 미실행, 제외 조건 변경 없음

- 감시 구성 부재의 검사에서 불필요한 잠금 폴더를 만들던 실패는 구성 존재 확인을 먼저 수행하도록 수정 후 통과
- 정적 검사의 중복 조건·시험 자료 선언 위치 오류는 수정 후 통과. 실패 기록 보존

## M09 실행 연결

- Windows 부분 검증 `c9399fba`: 보호 설정과 분리한 수동 조회·설정 화면 안내 연결. Linux·macOS·공개 후보 미검증

- 기존 경고 이력·재시작·기준 왕복·정상 관측2회·새 기간·quiet/해제 동작 유지. 남은 사용자 흐름은 실제 값의 수동 조회와 설정 화면 안내
- `hive usage show --host codex|claude|antigravity --user-root <dir> [--account-digest <sha256>] --output json` 추가. 선택한 앱과 저장된 보조 조회 동의 확인, Codex 기본 조회 우선. 다른 앱의 독립 기본 조회는 미지원으로 구분, 동의한 기존 보조 조회만 허용
- `usage_control/manual.rs`에서 기존 센서·정규화·관측 유효성 검사 재사용. 유효한0%도 조회 성공, `scope=manual-observation`·`authorizes_dispatch=false`. 오래된/잘못된 값은 성공 표시 금지. 설정·중단·세션·경고 이력 쓰기와 설치/활성화 없음
- `main.rs`·`usage_control.rs`의 명령/도움말 연결, `interactive.rs`의 설정 조회에 수동 명령 제공. 설정 조회의 센서 호출 없음, quiet은 선택 안내만 생략
- 검증: Windows의 구문·동의·계정·신선도·0%·무쓰기와 기존 경고 회귀, 임시 사용자/닫힌 PATH/가짜 명령의 실제 CLI. Linux는 Docker 연결 부재로 미실행 유지, 실제 계정·모델·앱 제어·공개 후보 증명과 구분
