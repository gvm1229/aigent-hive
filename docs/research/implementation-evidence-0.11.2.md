사용량 수신은 Antigravity를 기본 호스트로 설정한 소비자 프로젝트 범위. Source Workspace의 전역 수신 연결과 동일하다는 주장 제외. 원문 JSON·이메일·대화 식별자의 저장 없음.

관계 입력은 바뀐 문서 최대 10개와 같은 권한 범위의 관련 문서, 본문 합계 16KiB. 관계 대상은 실제 전달한 문서로 제한. 현재 구현의 한 모음·한 공개 범위에 한정, 여러 모음을 합친 관계 조회와 구분. 추정 관계는 정본 사실로 승격하지 않는 파생 자료.

- 고정 사실·질문과 현재 정본 바이트 불변. 위 30개 결과를 새 의미 모델의 정답률이나 소비자 모든 모음의 수용으로 확대 금지

## 갱신과 남은 배포 선택

- 0.11.1 프로젝트·사용자 기준본은 공개 태그 원본 바이트와 대조, 스킬·공개 표면 등록부에 추가. 과거 등록 내용 보존
- 다음 버전에서도 실제 과거 기준본으로 시험하도록 준비 코드 수정, 갱신 시험 44개 통과
- 기존 `classify_release`는 새 기능 배포에 두 번째 버전 숫자 증가 요구. 새 공개 스키마가 있는 0.11.2는 현재 검사에서 거부
- 선택 대기: 0.11.2에 한정한 명시적 예외 또는 사용자가 정하는 새 기능 버전. 선택 전 배포 검사 우회·새 버전 임의 변경 없음
- 전체 회귀·관련 Linux 검사·실제 호스트 수용의 증거 보완 뒤 마지막 macOS 전용 검증. Windows 성공만으로 macOS 오류 해결 판정 금지

## Windows 샌드박스 오류 5

- [같은 실행 파일의 대조](../../tests/results/windows-sandbox-0.11.2.json): 같은 PowerShell·격리 시험 폴더에서 일반 경로와 공백/한글 경로의 직접 읽기, 단일·동시 실행 4회 성공
- Codex의 실제 `sandbox -- <명령>` 실행 1회는 읽기 본문 시작 전 `SetNamedSecurityInfoW`의 오류 5. 샌드박스 실행 파일 디렉터리의 권한 설정 단계 실패, 입력 파일 바이트 보존
- 후속 샌드박스 경로·동시 실행은 시작 실패 때문에 미실행. 수집 도구의 정상 종료와 샌드박스 읽기의 실패를 별도 판정
- 원인 한계: 호스트 권한 설정 단계의 실패 확인. 특정 사용자·보안 제품·조직 정책을 근본 원인으로 단정하는 증거 없음
- 복구 소유자: 사용자 또는 Windows 관리자. [공식 절차](https://learn.chatgpt.com/docs/windows/windows-sandbox)에 따라 Codex 재시작 후 `elevated` 샌드박스 설정 재실행, 허용된 환경의 관리자 승인 필요
- 복구 뒤 동일 명령의 일반·공백/한글 경로와 동시 읽기 재검증. 자료 폴더의 읽기 권한 추가는 이번 시작 단계 실패의 해결 증명과 별도
- 에이전트의 전역 ACL·방화벽·보호 수준 변경 명령 미실행. 호스트 자체의 정상 샌드박스 시작 준비 동작과 구분

## 전체 검사 진행

- Windows 계약 검사 509개 중 495개 통과·14개 제외. POSIX 프로세스·FIFO·권한 모드 또는 현재 Windows의 연결 파일 생성 권한 부재가 제외 사유
- 제외 항목은 Linux 등의 지원 환경에서 별도 실행 필요. 실제 호스트 모델·macOS 오류 재현의 증명으로 사용 금지
- Rust: CLI 492개·과거 CLI 갱신 4개·버전 1개·core 126개·projection 44개·render 67개 통과. CLI의 별도 동의가 필요한 벡터 실행 1개 제외
- 전체 Rust 실행은 갱신 엔진의 버전 분류 충돌에서 중단. 이를 전체 통과로 표시하지 않는 상태, 이후 라이브러리·통합·보안 검사 별도 진행
