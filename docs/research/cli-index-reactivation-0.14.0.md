# 0.14.0 위키 재활성화와 색인 게시 복구

## 판정과 범위

- 위키를 끈 뒤 다시 켤 때, 다른 등록 폴더의 문서를 읽어야 하는 경우를 CLI에서 처리
- Windows 11 x64의 개발 CLI·가짜 Codex·별도 사용자 폴더로 실행. 실제 0.13.1 실행 파일과 확인한 설정 4개 지문 불변
- Linux amd64 격리 컨테이너에서는 관련 Rust 시험 4개 실행. 실제 사용자 설치 폴더 연결 없음
- 전체 전역 설정·공개 후보·세 운영체제 수용의 완료 근거로 확대 금지

## 읽을 범위와 동의

- `89b1e9da`: 미리보기는 사용자 폴더의 등록 정보만 조회. 대상 프로젝트 폴더가 없어도 목록 표시 가능
- 사용자 폴더의 실제 식별자·등록 정보·읽을 모음의 지문으로 범위 결합. 동의 뒤 바뀐 등록 목록은 적용 거부
- `f19cbea1`: 읽을 폴더를 표시한 뒤 기본값이 아니요인 별도 질문 제공. 이후 전체 설정 미리보기와 최종 확인을 거쳐 적용
- 거부·입력 종료는 답안 보관, 실제 설정과 색인은 유지. 같은 범위로 재개하면 이미 받은 동의 반복 없음
- 동의 지문은 해당 진행 기록에만 저장하고 완료 뒤 제거. 일반 사용자 선호나 다른 작업의 실행 권한으로 재사용 없음
- 답안 파일의 `--dry-run`은 필요한 폴더 목록과 범위 지문 반환. `--apply --index-rebuild-scope <digest>`로 명시한 범위만 적용
- `--apply`만으로 동의 추정 금지. 같은 승인 명령을 반복하면 설정·색인 바이트 유지
- 전역 설정이 다른 프로젝트를 자동 조사하던 경로는 계속 금지. 이미 검증된 색인은 새 외부 읽기 없이 보존

## 종료 복구와 보존 경계

- `d07504e6`: 복구 기록·등록 목록·SQLite 색인·세대 정보·복구 기록 제거·검증 정보의 각 처리 완료 뒤 종료하여 재개 확인
- 이미 승인한 등록 목록 한 건과 정확한 목표 지문·변경 순서에 맞는 미완료 기록만 이어서 처리
- 다른 지식 문서 쓰기·삭제·다른 세대·손상된 기록은 보존하고 거부. 단순한 위키 활성 선택으로 해당 기록을 지우지 않는 경계
- 원문 문서와 등록 목록 보존. 이번 실제 종료 시험 모두에서 사용자 0.13.1 실행 파일과 확인 대상 설정 4개 지문 불변
- 전원 손실, 개별 파일 교체 동작 내부의 강제 종료, 그때 남은 임시 보관 파일의 일반 복구·정리는 미검증. 소유를 증명하지 못하는 파일 자동 삭제 없음

## 실패 기록과 남은 수용

- 최초 게시 종료 시험 2건은 일반 답안 파일 분기가 범위 승인값을 버려 종료 지점 전에 실패. `01c4b1d5`로 수정하고 일반 파일 경로를 별도 검증
- 앞선 AI 입력 경로의 성공을 일반 파일 경로 성공으로 전용하지 않는 구분. 실패 보고서와 당시 소스 지문 보존
- 최초 자료 직렬화·정적 검사 오류는 수정 후 통과. 과거 실패를 삭제하거나 새로운 소스의 합격 기록으로 바꾸지 않는 원칙
- macOS, 실제 호스트 기능, 구버전 첫 갱신의 기한 종료, 공개 0.14.0 파일 수용은 별도 미완료
- 일반 감시 상태 변경·프로젝트 파일 입력·벡터 선택·전체 언어 오류·전체 설정 수용은 기존 계획대로 계속 진행
