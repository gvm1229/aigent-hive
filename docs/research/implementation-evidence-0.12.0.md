## 시험판 출처 분리의 구현 수용

- 제품 번호만 남긴 옛 기준본은 시험판과 안정판의 출처를 구분하지 못하는 상태. 공식0.11.0-test.6을 안정판 호환성 대상으로 등록하는 해결은 사용자 결정으로 제외
- 새 시험판 기준본의 `package_version`은 컴파일 시점의 정확한 패키지 번호이며 정본 지문에 포함. 현재 정확한 시험판의 자체 검사와 이전 안정판의 전체 바이트 인증 유지, 다른 시험판의 자동 갱신은 거부
- 출처가 없는 옛 기준본은 제품 번호만으로 안정판이라고 단정하지 않는 진단. Orireki의 원문·기준본·현재 전역0.11.1은 변경 없음. 기존 소비자의 안정판 재설정은 별도 검토·승인 필요
- Windows [전체 Rust·정적 검사](../../tests/results/runs/20261005T212039-c73bd7aad95c.md)와 [Python 다섯 묶음](../../tests/results/runs/20261005T214615-184e974a7e26.md) 통과. 정확한 개발 test.3 바이너리의 출처 보존·변조 거부·과거 시험판 거부·안정판 갱신 보존 검증. 운영체제 조건의 제외와 실제 소비자 갱신·호스트 활성화 미증명 구분
