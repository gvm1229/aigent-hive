- 사용자 요청: 이 대화에서 매일 오전 10시 AI_Learning 지식의 Hive 개선 가능성 검토
- 시간대: `Asia/Seoul`, 한국 시간
- 입력: 사용자가 지정한 AI_Learning 프로젝트의 공개 Knowledge·Sources·Maps
- 출력: `docs/research/ai-learning/` 전용 조사·후보·검토 기록
- 기존 구현 계획과의 관계: 연구 후보만 별도 보관, 사용자 명시 요청 전 편입·구현 제외

## 분리 경계

- 조사 계획·원자료 근거·후보 목록·일일 결과는 이 폴더 안에만 보관
- `docs/plans/PLAN.md`, `docs/plans/active/`, `docs/plans/backlog/`, `docs/state/CURRENT.md`, 출시 계획·구현 체크리스트의 자동 변경 제외
- 다른 구현 계획의 기준 ID·완료율·버전·차기 작업과 연구 후보의 별도 관리
- 후속 편입: 사용자가 지정한 후보와 대상 구현 계획에 대한 명시 요청 뒤 별도 절차
- 외부 원문·기밀 내용·원시 대화의 복사 제외, 공개 자료의 검토된 Hive 관련 요지와 안전한 논리 위치만 기록
- AI_Learning 프로젝트 읽기 전용, 수집·검토 대기 승격·외부 메시지 전송·도구 설치 제외
- 제품 코드·배포·설치·게시·새 버전 지정 제외
- 소스 사실 쌍: 이 분리 규약과 검토 결과의 위치만 안내, 연구 후보의 구현 승인 의미 제외

## 일일 절차

1. 현재 소스 지침·사용량 보호·편집 예약 확인
2. 전용 후보 목록과 최근 보고서를 기준으로 새 지식·변경된 출처 확인
3. 메타데이터부터 확인, 실제 판단에 필요한 공개 본문만 선택 조회
4. 기밀·검토 대기·출처 주장·의견·직접 검증의 구분
5. 현재 Hive 코드와 비교, 기존 기능 재사용·새 결손·검증 필요의 분류
6. 중요한 외부 기술 주장은 현재 공식 원자료와 대조, 성능 수치의 자체 보고·독립 재현 구분
7. [후보 목록](CANDIDATES.md)의 기존 ID로 증분 갱신, 중복 후보 추가 제외
8. `reviews/YYYY-MM-DD.md`에 확인 범위·변경·적용성·근거·미검증·제외 이유 기록
9. 문서 연결·문체·분리 경계 검사, 의미 있는 새 후보·판정 변경·실패·사용자 조치 필요만 대화에 보고

자료 변화 부재의 경우: 짧은 일일 확인 기록과 기존 후보 보존. 매일 전체 원문 재복사·같은 권고 반복 제외. 도구나 원자료 접근 실패 시 실패 원인·영향 범위·복구 경로 기록, 실패를 새 자료 부재로 표시하는 처리 제외.
