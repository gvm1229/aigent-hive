# Hive 작업별 점수 평가 제안

- 상태: 기존 논의와 사용자 승인된 추가 후보 3개 병합
- 보존본: [병합 전 답변 원문](baseline-original.md)
- 추가 근거: [AI_Learning 후보와 검토 한계](additional-findings.md)
- 별도 조사: Google Research Harness²의 후속 심층 조사 결과는 이 문서의 자동 병합 대상에서 제외
- 구현·모델 실행·실제 채점 시험: 미수행
- 후속 정본: [최종 구현 계획](../../../plans/score-driven-improvement-0.14.0.md). Harness² 최종 목표는 철회, 선택한 결합 흐름과 단계별 계약은 해당 계획에서 관리

**조사·계획·문서에 각각 기본 평가표를 두고, Hive 소스 개발과 배포 하네스가 같은 계산 규칙을 공유하는 방식**을 권합니다. 환경에 따라 바꿀 것은 평가 대상과 필수 조건입니다.

공통 규칙은 유지합니다.

- 배점 합계 **100점**, 최종 점수는 **획득 배점 ÷ 100**, 표시 범위는 **`0.00~1.00`**.
- 기본 완료 조건은 **총점 `0.90` 이상 + 각 항목 `0.80` 이상 + 필수 조건 충족**.
- 세부 기준·배점·평가 범위는 작업 시작 전에 확정.
- 평가할 수 없는 항목을 임의로 만점 처리하거나 합계에서 제외하지 않음.
- 결과에는 평가표 이름·버전·대상 산출물·근거를 함께 표시.
- 점수 분포·평가자 간 차이는 선택적인 보조 정보로 별도 보존. 최종 점수의 고정 배점 계산과 0.00–1.00 두 자리 표현 유지.
- 자동 완료 판단에 쓰기 전 채점표 자체의 양방향 오류 시험과 평가 정답 접근 경계 확인.

아래 수치는 모두 **논의용 제안값**이며, 실제 평가 자료로 검증된 기준은 아닙니다.

**조사 평가표는 “질문에 대해 근거 있는 판단을 내릴 수 있는가”에 무게를 둡니다.**

| 항목 | 배점 | 구체적인 세부 기준 |
|---|---:|---|
| 질문·범위 적합성 | **15** | 핵심 질문과 판단 기준 10, 적용 환경·버전·조사 시점 5 |
| 근거의 신뢰성과 연결 | **30** | 주요 주장과 실제 근거의 연결 15, 해당 질문에 적절한 원자료 10, 자료의 적용 시점·버전 확인 5 |
| 필요한 범위의 조사 | **20** | 주요 질문의 조사 10, 유효한 대안 5, 반대 증거·상충하는 결과 5 |
| 분석과 결론 | **25** | 사실·추론·불확실성 구분 10, 같은 조건에서의 비교 10, 근거가 뒷받침하는 결론 또는 다음 판단 조건 5 |
| 확인하기 쉬운 전달 | **10** | 직접 확인 가능한 출처·위치 5, 핵심 결과와 한계의 명료한 설명 5 |
| **합계** | **100** | |

여기서 ‘원자료’는 공식 웹 문서일 수도 있고, 프로젝트의 실제 코드·측정 자료·사용자가 제공한 기록일 수도 있습니다. 출처 개수가 많다는 이유만으로 높은 점수를 주지는 않습니다.

예를 들어 항목별 획득 배점이 `12 + 24 + 16 + 23 + 8`이면 **`0.83`**입니다. 다음 재시도는 부족한 주장에 직접 근거를 붙이거나, 빠진 대안을 같은 조건으로 비교하는 작업이 됩니다.

조사의 필수 조건은 **핵심 근거를 꾸며내지 않았고, 결론에 영향을 주는 불확실성과 충돌을 숨기지 않았다는 것**입니다. 합의한 범위를 충분히 조사했다면 “현재 자료로는 결정할 수 없다”도 좋은 조사 결과가 될 수 있습니다. 이 경우 조사 완료와 제품 결정 가능 여부를 별도로 표시해야 합니다.

**계획 평가표는 “다음 작업자가 중요한 결정을 다시 추측하지 않고 진행할 수 있는가”를 봅니다.**

| 항목 | 배점 | 구체적인 세부 기준 |
|---|---:|---|
| 목표와 수용 조건 | **25** | 원하는 결과 10, 관찰 가능한 완료 기준 10, 범위·제외 사항 5 |
| 접근 방법과 결정 | **25** | 선택한 방법과 이유 10, 입력·출력·책임 경계 10, 가정과 미해결 사항의 처리 5 |
| 실행 순서와 의존 관계 | **20** | 구체적인 단계 8, 선행 조건·단계 간 연결 8, 담당 역할 4 |
| 검증과 실패 대응 | **20** | 성공 확인 방법 10, 실패 시 복구·대안 6, 중단·추가 판단 조건 4 |
| 인계 가능성 | **10** | 정확한 대상과 필요한 참고 위치 6, 다음 행동을 이해할 수 있는 설명 4 |
| **합계** | **100** | |

계획의 필수 조건은 **실행에 꼭 필요한 결정을 미룬 채 실행 준비가 됐다고 주장하지 않는 것**입니다. 다만 다음 단계 자체가 조사라면, 조사 질문·허용 범위·필요 증거·결정 규칙을 구체적으로 정한 계획은 준비된 상태로 볼 수 있습니다.

이 구분은 Hive의 현재 [구현 인계 규칙](C:/Users/hojin/Documents/aigent-hive/.agents/directives/references/planning-contract.md)과도 맞습니다. 높은 계획 점수는 **해당 범위의 실행 준비가 됐다는 뜻**이며, 구현이나 검증을 완료했다는 뜻은 아닙니다.

**문서 평가표는 “대상 독자가 이 문서를 통해 원하는 일을 하거나 이해할 수 있는가”를 봅니다.**

| 항목 | 배점 | 구체적인 세부 기준 |
|---|---:|---|
| 내용의 정확성 | **30** | 사실·동작 설명 15, 명령·예시·정의의 정확성 10, 적용 조건과 한계 5 |
| 독자와 목적의 적합성 | **25** | 독자의 배경에 맞는 설명 5, 문서의 핵심 목적 달성 15, 필요한 범위 유지 5 |
| 필요한 정보의 충실도 | **20** | 필수 정보 10, 중요한 예외·실패 상황 5, 전제와 준비 사항 5 |
| 구조와 탐색성 | **15** | 읽는 순서·정보 배치 6, 연결과 참조의 정확성 6, 용어의 일관성 3 |
| 표현의 명료성 | **10** | 이해하기 쉬운 문장 6, 필요한 예시와 간결한 표현 4 |
| **합계** | **100** | |

‘핵심 목적 달성’의 채점 질문은 문서 종류에 맞게 바꿉니다.

| 문서 종류 | 확인할 질문 |
|---|---|
| 따라 배우는 문서 | 처음 접한 독자가 단계를 따라가며 중간 결과와 최종 결과를 확인할 수 있는가? |
| 작업 안내서 | 준비 사항부터 실행·성공 확인·실패 대응까지 필요한 행동을 찾을 수 있는가? |
| 참조 문서 | 필요한 항목·기본값·조건·오류 의미를 정확하고 빠르게 찾을 수 있는가? |
| 개념 설명 | 무엇이며 왜 그렇게 작동하는지, 어떤 조건과 한계가 있는지 이해할 수 있는가? |

이 구분은 [Diátaxis의 문서 유형](https://diataxis.fr/)을 참고했습니다. 독자와 범위를 먼저 정하는 원칙은 [Google의 기술 문서 지침](https://developers.google.com/tech-writing/one/documents)과도 맞습니다. 두 자료는 2026-10-23에 확인했으며, 위 배점은 별도로 제안한 것입니다.

문서의 필수 조건은 **핵심 설명이 실제 대상과 모순되지 않고, 필요한 승인·위험·적용 조건을 빠뜨리지 않는 것**입니다. 개념 설명 문서에 실행 명령이 없다는 이유로 감점하거나, 짧은 참조 문서에 긴 배경 설명을 요구해서는 안 됩니다.

두 환경에는 이 평가표를 다음처럼 적용하는 것이 좋겠습니다.

| 작업 | Hive 자체 개발에 적용 | 사용자에게 배포되는 하네스에 적용 |
|---|---|---|
| **조사** | Hive의 실제 소스·스키마·호스트 지원 범위와 외부 관행을 구분. 소스·배포물·설치된 하네스의 차이 확인 | 사용자의 질문·프로젝트·운영 환경을 기준으로 조사. 해당 프로젝트의 코드·자료도 유효한 원자료로 인정 |
| **계획** | 현재 목표 버전, 실제 파일·심벌, 소스와 배포물의 경계, 검증 절차, 버전별 승인 조건 반영 | 사용자 프로젝트의 산출물·역할·순서·자원·승인 조건 반영. 코드 작업이 아니면 파일·심벌·Git 절차를 요구하지 않음 |
| **문서** | 소스 개발자용 설명과 최종 사용자용 설명을 구분. 실제 제품 동작·명령·버전과 일치 여부 확인 | 사용자가 지정한 독자·언어·문체·문서 목적을 기준으로 평가. Hive 저장소의 문서 규칙을 일괄 강제하지 않음 |

**배포할 것은 세 가지 일반 평가표와 계산·기록 규칙이고, Hive 소스 전용 조건은 소스 개발 규칙으로 유지하는 편이 좋습니다.** 이는 현재의 [소스·하네스 분리 원칙](C:/Users/hojin/Documents/aigent-hive/.agents/directives/02-architecture.md)에도 맞습니다.

사용자 프로젝트에서 배점을 조정할 수는 있습니다. 예를 들어 API 참조 문서는 정확성 배점을 높이고 설명 배점을 줄일 수 있습니다. 다만 조정은 시작 전에 확정하고, 합계는 100으로 유지하며, 별도의 평가표 버전으로 구분해야 합니다. 실제로 해당하지 않는 세부 기준은 같은 목적의 적절한 기준으로 바꾸되, **증거가 없다는 이유로 ‘해당 없음’으로 바꾸지는 않습니다.**

재시도 방식도 작업 종류에 맞게 달라집니다.

| 평가표 | 낮은 점수에 대한 다음 행동 | 완료가 뜻하는 것 |
|---|---|---|
| 조사 | 근거 확인, 빠진 대안 조사, 상충하는 자료의 조건 비교 | 합의한 질문과 범위에 대한 근거·결론·한계 정리 완료 |
| 계획 | 빠진 결정 해소, 의존 관계 수정, 검증·복구 방법 구체화 | 지정한 다음 단계의 실행 준비 완료 |
| 문서 | 잘못된 내용 수정, 독자에게 필요한 정보 보완, 예시·연결 확인 | 지정한 독자와 목적에 맞는 문서 준비 완료 |

앞서 제안한 최대 3번의 수정과 기존 사용량 한도는 그대로 적용할 수 있습니다. 같은 산출물을 재채점해 우연히 높은 값을 얻는 방식은 피하고, **감점 근거를 해결한 변경이 있어야 개선으로 인정**합니다.

마지막으로, **같은 숫자 범위가 작업 간 동일한 품질 척도를 뜻하지는 않습니다.** ‘조사 `0.94`’와 ‘계획 `0.91`’은 각각의 기준 충족도를 나타냅니다. 조사·계획·문서가 모두 필요한 작업이라면 각 결과를 따로 표시하고, 필요한 결과가 모두 완료 조건을 만족해야 전체 완료로 판단해야 합니다.

## 승인된 보완 1: 점수와 불확실성의 별도 기록

- 유지: 최종 점수는 획득 배점 합계 ÷ 100, 소수점 이하 두 자리
- 추가: 평가 모델이 제공하는 점수 분포 또는 여러 평가자의 점수 차이를 선택적인 보조 정보로 보존
- 구분: 한 모델의 예측 분포, 여러 평가자의 불일치, 실제 정확도의 교정은 서로 다른 정보
- 산술 예시: 0.80에 확률 0.70·0.90에 확률 0.30인 분포와, 0.50에 확률 0.34·1.00에 확률 0.66인 분포의 기대값은 모두 0.83
- 적용: 같은 최종 점수라도 분포가 넓거나 평가가 갈리는 경우 해당 기준과 증거를 추가 검토하는 단서
- 경계: 교정되지 않은 확률을 정답 확률로 표시하거나 임의의 분산 기준으로 자동 통과·탈락 처리하는 변경 제외
- 자료: AI_Learning의 NanoJev·경량 구조화 판단 모델 설명. 실제 모델 설치·호출·효과 재현 없음

## 승인된 보완 2: 채점표 자체의 양방향 오류 시험

- 목적: 표현이 다른 정답의 부당한 감점과 그럴듯한 오답의 부당한 통과 탐지
- 정답 시험: 의미·요구 충족은 같고 표현·구조·구현 방식만 다른 결과의 동등한 취급 확인
- 오답 시험: 문장은 매끄럽지만 핵심 사실·필수 조건이 틀린 결과의 거부 확인
- 적용 단위: 코드·조사·계획·문서 평가표의 각 버전
- 재시도: 채점표의 오류 확인 시 해당 기준 수정·재검증과 영향받은 결과의 재평가; 작업 결과만 반복 수정하는 처리 제외
- 완료 조건: 자동 완료 판단에 사용하는 평가표의 시험 근거 확보; 미검증 평가표의 점수는 참고 상태
- 자료 한계: Ultramarine 로컬 출처는 독립 검토 대기. 설계 보완의 채택과 성능·안전성 검증 완료의 구분

## 승인된 보완 3: 평가 중 정답 자료의 접근 경계

- 목적: 평가 대상이 정답지·검증 전용 자료를 읽어 얻은 점수의 비교 증거 사용 방지
- 대상: 제품·하네스 비교를 위한 별도 평가 환경의 파일·도구·네트워크 경로
- 사전 확인: 공개 작업 요구·평가 기준과 비공개 정답·검증 전용 자료의 분리, 허용 자료·접근 경계 명시
- 실행 확인: 허용 범위 밖 정답 자료의 접근 흔적과 평가 자료 노출 여부 확인
- 오염 발견: 해당 평가 결과 무효 표시와 비교 집계 제외; 깨끗한 조건에서 다시 평가
- 경계: 일반 조사에서 필요한 공개 자료 검색의 일괄 제한, 요구 사항·평가 기준의 부당한 은폐 제외
- 자료 한계: Harness² 로컬 출처는 독립 검토 대기. 여기에는 이전에 승인된 정답 접근 경계 후보만 반영하며, 새 심층 조사 결과와 구분

## 현재 증거 범위

- 실제 수행: Codex·Windows에서 관련 규칙·자료 확인과 Markdown 제안 갱신
- 미수행: 제품 구현·설정 변경·모델 실행·채점표 시험·평가 격리 시험·효과 재현
- 미증명: 배점·합격선·재시도 정책·보완 절차의 실제 품질 개선과 비용
- 사용자 승인 의미: 세 설계 보완의 조사 문서 병합; 제품 구현·출시·설치 승인과 구분
