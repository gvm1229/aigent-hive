## 추가 후보 1: 단일 점수와 별도로 점수 분포 보존

- 자료: `AI_Learning/Knowledge/경량-구조화-판단-모델.md:18–26`, 갱신일 2026-10-09; `AI_Learning/Sources/NanoJev-0.6B-구조화-판단-모델-2100920275475042443.md:30–45`, 마지막 확인일 2026-09-19
- 자료 내용: NanoJev의 Score 유형에 2~10단계 순서형 점수의 분포와 기대값 제공이라는 설명
- 기존 논의와의 차이: 현재 제안의 단일 점수·판단 불가·사람 평가 대조에 더하여, 같은 평균값을 만드는 서로 다른 평가 분포의 보존
- Hive 적용 제안: 최종 점수 0.00–1.00과 고정 배점 계산 유지; 평가 모델이 제공하는 점수 분포 또는 여러 평가자의 분산을 별도 보조 정보로 기록
- 계산 예시: 0.80에 확률 0.70, 0.90에 확률 0.30인 경우의 기대값 0.83; 0.50에 확률 0.34, 1.00에 확률 0.66인 경우에도 기대값 0.83. 동일한 평균에도 다른 불확실성
- 예시의 지위: 이번 비교를 위한 산술 예시; 실제 NanoJev 출력이나 Hive의 측정값과 구분
- 한계: 모델의 확률 분포와 실제 정확도의 일치 미증명. 여러 평가자의 불일치와 한 모델의 예측 분포도 별개의 정보. 새 모델 설치·Hive의 직접 모델 실행 제안 없음
- 원자료 위치: [NanoJev](https://github.com/TianyuCodings/NanoJev); 이번에는 로컬 보관 자료의 설명만 확인

## 추가 후보 2: 채점표 자체에 대한 양방향 오류 시험

- 자료: `AI_Learning/Sources/Ultramarine-업무-평가와-합성-보상-설계.md:30–35`, 마지막 확인일 2026-10-20
- 자료 내용: 특정 모범 답안의 말투에 맞춘 기준과 그럴듯한 오류를 통과시키는 모호한 기준을 함께 경계하는 설명
- 기존 논의와의 차이: 기존의 고정 배점·항목별 근거·사람 평가 대조에서 한 단계 구체화한 채점표 시험 자료의 구성
- Hive 적용 제안: 사실은 맞지만 표현·구조가 다른 결과, 문장은 매끄럽지만 핵심 사실이 틀린 결과를 평가표별 시험 사례로 준비
- 확인 대상: 올바른 다른 표현의 부당한 감점, 그럴듯한 오답의 부당한 통과
- 기존 조건과의 관계: 작업 결과의 합격선 변경과 구분; 평가표를 사용하기 전 평가표 자체의 오류 확인 절차 후보
- 한계: 해당 출처의 상태는 review-pending, promotion_eligible=false. 비용·성능·금융·법률 안전성 주장 및 독립 검증 완료의 승격 제외
- 원자료 위치: [Ultramarine 기술 글](https://www.paperinstruments.com/blog/ultramarine), 로컬 기록의 원자료 날짜 2026-10-14; 이번 원문 재확인 없음

## 추가 후보 3: 평가 실행 중 정답 자료의 접근 경계

- 자료: `AI_Learning/Sources/Harness2-실행-비교-기반-하네스-개선.md:52–67`, 마지막 확인일 2026-10-22
- 자료 내용: 평가 실행기가 온라인 공개 정답·채점 자료에 접근하여 결과를 오염시킬 가능성과 별도 네트워크 제한 안내의 기록
- 기존 논의와의 차이: 개선에 쓰는 문제와 최종 평가 문제의 분리뿐 아니라, 실제 평가 실행 중 정답이 들어오는 파일·도구·네트워크 경로의 통제
- Hive 적용 제안: 제품·하네스 비교용 시험에서 정답지와 검증 전용 자료의 접근 경계를 명시하고 접근 흔적 확인; 노출된 실행의 점수는 유효한 비교 증거에서 제외

- 한계: 해당 출처의 상태는 review-pending, promotion_eligible=false. 실제 격리 효과·성능 향상·Windows 실행 재현 없음
