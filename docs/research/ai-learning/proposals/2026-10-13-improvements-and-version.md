### 현재 코드로 확인한 구체적 차이

- [rag.rs](../../../../crates/hive-wiki/src/rag.rs)의 `RetrievalRequest`: 검색어·상위 개수·바이트 예산은 존재, 선택 항목 목록의 요청 필드는 부재. 이 부재만으로 제품 결함 판정 불가, 새 선택 API의 이번 패치 편입 제외
- 같은 파일의 `RetrievalHit`: 지문·모음·범위·출처·원본 상태·신뢰 경계 존재. 간결한 표현에서도 이 의미 보존 필요
- [token_accounting.rs](../../../../crates/hive-core/src/token_accounting.rs)의 `Report`: 입력·출력·초과·계측 완전성은 존재, `hard_cap_enforced: false`의 계측·제어 구분 유지. 완료당 통계 필드 부재를 결함으로 판정하거나 합산기를 재구현하는 처리 제외
- [usage_control.rs](../../../../crates/hive-cli/src/usage_control.rs)의 중단 결과: 초기화 확인용 지문과 원인 코드가 있는 반면 `next_action: None`. 보호를 유지한 현재 작업 확인·재검사 절차를 바로 안내하는 개선 후보
- 같은 대화의 초기화 중단·명시 확인·재검사 경험은 안내 개선의 사례. 실제 초기화 감지 자체의 오류·오탐 판정 근거로 사용 제외

## 실제 자동 분담의 가치 조건

- 해결할 일: 독립적인 작업의 분할·담당·결과 합치기·취소·재개를 사람이 반복 관리하는 부담
- Hive의 추가 가치: 기존 계획·역할·진행 상태·예산·검증 기준을 호스트 소유 작업과 연결, 늦은 결과·중복 배정·불확정 실행의 구분
- 가치 부재 조건: 호스트 기본 분담으로 이미 같은 일을 같은 부담으로 처리 가능한 경우, Hive가 설정·확인 단계만 추가하는 경우
- 확인할 비교: 같은 독립 작업에서 호스트 기본 방식과 Hive 연결 방식의 사용자 조정 횟수·총 소요 시간·결과 품질·총 사용량
- 성공 조건: 수동 조정량이나 총 시간이 실제로 감소하고 품질·권한·취소 경계 유지. 여러 작업자를 쓰는 것만으로 속도·비용·정확도 개선 선언 제외
- 현재 판정: 실제 실행 확인이 부족한 HCT112-004 유지. 설치·역할 정의·검증 구조의 존재만으로 이득 증명 불가
- 범위: 기존 역할·결과·권한 계약의 완결 검토, 새 분담 엔진이나 모델 호출 계층 도입 제외
