## 후보별 최소 적용과 검증

### 1. 주장별 확인 수준

- 배경: AI_Learning의 공개 출처 노트에서 원문 열람, 공유자의 주장, 독립 재현을 별도 기록하는 방식
- 기존 재사용: `AssertionStatus`, `SourceFreshness`, `ScanClaimMetadata`, `ClaimEvidence`의 출처·버전·적용 조건
- 현재 한계: 원문 해시 일치나 `source-inspected`를 실제 성능 검증으로 읽을 위험. 기존 상태의 존재만으로 외부 수치의 비교 조건까지 보장 불가
- 최소 적용: 먼저 문서·검토 절차에 주장 / 확인 방식 / 근거 위치 / 버전·환경 / 판단·한계 / 확인 날짜의 표준 기록 추가. 실제 조회 필터 수요 확인 뒤 기존 계약 확장 검토
- 상태 원칙: 공유 문서의 보고는 `observed`, 재현 기준 통과는 `verified`, 검토자의 해석은 `inferred`. 모든 문서에 단일 사실 등급 부여 제외
- 검색 후보: `maturity`·확인 방식의 선택 필터. 기존 `assertion_status`, `applicability`와 중복되는 새 상태 축의 무조건 추가 제외
- 읽기·변경 후보: [rag.rs](../../../../crates/hive-wiki/src/rag.rs)의 `AssertionStatus`, `RetrievalRequest`, `RetrievalHit`; [scan.rs](../../../../crates/hive-wiki/src/scan.rs)의 `ScanClaimMetadata`; [조회 계약](../../../../crates/hive-cli/src/knowledge/retrieve.rs)
- 성공 기준: 같은 공개 자료의 사실·미재현 성능·의견을 별도 판정, 오래된 버전·원문 부재·반론의 구분, 검토 전 전역 승격 0건
- 실패 사례: 저자의 성능 보고를 독립 재현으로 표시, 두 재인용을 독립 출처 2개로 계산, 원문 해시 일치만으로 모든 주장 승인

### 2. 후보 뒤 선택 본문 조회

- 배경: AI_Learning의 검색 기본값은 제목·한 줄 요약·범위·경로부터 확인, 선택한 자료만 자세히 읽는 방식
- 기존 재사용: `WikiPageQueryHit`, `run_query`, `run_read`, `RetrievalHit`의 `item_id`, `digest`, `collection_id`
- 현재 한계: `RetrievalRequest`에는 선택 항목 목록이 없는 구조. `retrieve_from_connection`은 검색과 본문 일부 반환을 함께 수행. 기존 `run_read`의 `page-id`는 여러 모음의 문서·주장 공통 식별자 조회와 구분
- 최소 적용: 먼저 기존 검색·읽기 조합으로 후보 선별을 명확화. 제품 확장 시 검색 결과의 항목 식별자·모음·지문에 묶인 선택 조회 계약 추가. 제안 계약이며 현재 CLI 지원 주장 제외
- 권한·실패: 두 단계에서 범위와 기밀 승인을 각각 확인, 지문 변경·항목 삭제·모음 분리 때 오래된 선택 거부, 예산 부족 때 부족 상태 반환
- 성공 기준: 선택하지 않은 본문 반환 0바이트, 다른 모음·기밀 본문 누출 0건, UTF-8 예산 준수. 현재 방식과 같은 정답 회수율에서 반환 바이트 감소 확인
- 한계: 후보 목록도 판단에 필요한 요약·출처·확인 수준 포함 필요. 본문 최소화만으로 정확도 개선 추정 금지

공개 보강 근거: 필요한 자료를 경로·식별자로 보관하고 필요할 때 읽는 방식과 간결한 도구 결과. [Anthropic의 문맥 설계 설명](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), 2025-09-29 게시·2026-10-09 조회. Hive에서의 절감률은 별도 측정 대상.

- 한계: liteparse·LlamaParse·Marker의 속도·정확도·비용 우위는 이번 독립 재현 범위 밖. OCR·생성 모델·웹 수집 서버의 제품 의존성 도입 제외
