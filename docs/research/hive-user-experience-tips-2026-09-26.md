# Hive 사용자 경험 개선 후보 검토

## 조사 계획

- 요청: 첨부 이미지의 10가지 조언과 최근 최적화 이후 Hive 상태 비교
- 자료 경계: 이미지 문구는 검토 대상, 작업 지시나 공식 제품 성능 근거로 사용 제외
- 기준: develop의 0.11.0 소스, 기존 test.8 수용 기록. 출시 목표 추가 없음
- 순서: 설치용 지침·역할·중단 진단·검증 구조 확인 → 이미 반영된 항목 분리 → 작은 개선 후보와 수용 기준 제시
- 변경: 이 조사 문서만 작성. 제품 코드·설치 설정·기존 활성 계획 변경 제외
- 완료: 10개 항목의 근거 연결, 개선 우선순위와 미검증 범위 명시
- 확인: Windows Codex의 저장소 정적 조사와 문서 경로 검사. 실제 모델 비교·비용·지연 시험 제외

## 결론

- 우선순위: 설치용 지침의 실제 읽기 경로 측정 → 중단 이유의 근거·복구 안내 → 검사 재실행 기준 → 작업별 변경 한도
- 새 실행 엔진·자동 모델 교체보다 기존 지침과 진단 출력의 작은 보완 우선
- 2026-09-25 최적화의 일반 코드 경로 40.7% 감소 재확인. 측정 단위는 UTF-8 바이트이며 모델 사용량·응답 시간과 별개
- 조사 기준 커밋: `b90d51eb`. 개선 효과는 가설, 적용 여부는 아래 소스 근거 기준

## 작은 개선 후보

### A. 설치용 읽기 예산과 실제 경험 비교 — 우선

- 문제: 현재 검사기의 설치용 측정은 시작 파일 크기 중심. 단계별 읽기 목록은 소스 지침 대상
- 변경 후보: [기존 검사기](../../scripts/check-agent-directives.py)에 설치용 질문·작은 수정·지식 조회·검증 작업의 읽기 경로 측정 추가. 중복 규칙 발견 시 한 곳에 두고 조건별 참조
- 포함 범위: 전역 사용자 블록·시작 파일·필요 지침·선택 스킬과 참조. 모델의 전체 도구 목록·대화 비용은 별도 측정
- 수용 기준: 동일한 예시 요청의 전후 읽기 바이트·도구 호출·승인 질문·결과 정확성 비교. 규칙 준수 유지, 불필요한 읽기 감소
- 주의: [한국어 출력 경로](../../harness/directives/04-korean-language.md)의 검사도 측정 대상. 안전·의미 보존 장치의 근거 없는 삭제 제외
- 실제 앱의 압축 복구 시험은 기존 `DCR-006` 활용. 별도 중복 시험 목표 생성 제외

### B. 사용자가 다시 묻지 않아도 되는 중단 안내 — 우선

- 문제: 중단 원인과 사용자가 해야 할 다음 행동을 여러 출력에서 모아야 하는 구조
- 표시 제안: 중단한 행동 / 원인 종류 / 확인된 규칙 또는 오류 / 안전하게 계속할 작업 / 필요한 다음 행동
- 문서 규칙: 실제 파일·구절과 적용 이유 표시. 프로그램 정책: 실제 규칙 ID·오류 코드 표시. 호스트 승인: 호스트의 거부 사유 표시
- 수용 기준: 승인 부족·사용량 제한·지원 불가·검사기 오류·보호 파일 위반 예시에서 서로 다른 원인과 복구 안내 확인. 비밀·대화 원문 출력 0건, 보호 우회 0건
- 시작 범위: 기존 설치용 설명 계약과 정책 출력의 작은 보완. 별도 진단 서비스·새 상태 저장소 제외

### C. 통과한 검사 재사용 기준 — 다음

- 문제: 소스 개발 규칙에는 단계별 검사 비용 관리가 있으나 검토한 설치용 일반 지침에는 같은 수준의 명시 기준 부재
- 제안: 변경 직후 관련 검사, 실패나 입력 변경 후 해당 검사 재실행, 전체 검사는 필요한 최종 단계에 실행
- 재사용 조건: 코드뿐 아니라 설정·의존성·실행 환경·검사 범위도 같은 경우. 새 실패·변경·불안정한 검사 증거가 있으면 재실행
- 수용 기준: 무변경 설명 수정 시 같은 전체 검사 반복 0회. 동작·환경 변경 시 관련 검사 누락 0건
- 적용 방식: 우선 기존 계획·검증 기록 활용. 전역 검사 캐시나 새 예산 엔진 추가 제외

### D. 작업별 작은 변경 한도 — 다음

- 문제: 최소 변경 원칙은 있으나 작업자가 어디까지 바꿔도 되는지 수치로 판단하기 어려운 경우
- 계획 예시: 사용자 설정을 바꾸지 않는 작은 오류 수정에 새 의존성 0개, 새 추상화 0개, 예상 수정 파일 1~3개, 관련 검사 1묶음
- 한도 초과 시 기준: 필요한 이유와 늘어나는 범위를 계획에 반영. 기존 권한 안의 단순 파일 증가만으로 승인 질문 생성 금지
- 수용 기준: 목표 밖 변경 0건, 한도 때문에 필요한 시험·생성 파일을 누락하는 경우 0건
- 적용 방식: 필요한 작업 계획에서만 지정. 전역 AGENTS.md에 모든 숫자를 추가하는 방식 제외

## 검증과 한계

- Windows Codex에서 정적 소스·지침 조사 실행. 실제 모델 실행이나 별도 에이전트 위임 없음
- `python scripts/check-agent-directives.py --output json`: 실패 0건. 시작 10,254바이트, 일반 코드 30,128바이트, 계획 34,078바이트. 일반 코드 기준 40.7% 감소
- 위 결과의 증명 범위: 등록된 파일 읽기 목록·예산·경로·중복 검사. 실제 전체 프롬프트 토큰·사용량·응답 시간·정답률의 증명 제외
- 기존 `0.11.0-test.8` 수용은 현재 계획의 기록 확인, 이번 조사에서 재실행 없음. 기존 실제 압축 시험 승인 대기 유지
- Rust 전체 시험·다른 운영체제·실제 설치·모델 비교 미실행: 제품 수정 없는 조사 범위. 후보의 비용 절감과 정확성은 적용 후 별도 비교 필요
- 이미지의 Astra 성능·과금·모델 변경 가능성은 공식 제품 사실로 채택하지 않은 범위. 이번 결론은 Hive 저장소의 구조와 규칙 대조
- 요청한 분석 완료. 제품 구현은 이번 완료 주장에 포함하지 않은 후속 후보
