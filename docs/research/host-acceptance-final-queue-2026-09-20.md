# 남은 호스트 수용의 실행 순서

- 목표: `0.11.0`의 남은 다섯 항목 해결. 30/35 기준과 기존 합격 조건 유지
- 실행 경로: 소스 계획. `verified-workflow` 초기화·검증 영수증과 연결된 실행 ID가 없어 활성화 주장 제외
- 소유: 현재 Codex 작업. 별도 구현 에이전트·모델 CLI·공급자 API 실행 제외
- 사용자 승인: 기존 격리 Codex 시험 유지. 다른 호스트의 정확한 정의는 미리 보기 검토 뒤 적용

## 순서와 증거

| 단계 | 소유 항목 | 실행·독립 확인 | 제한·후속 행동 |
| --- | --- | --- | --- |
| 1 | `RB104-004` | 현재 앱의 연결 방식·공식 중단 계약 대조 | 연결되지 않은 새 서버로 현재 앱 지원을 대체하지 않는 경계 |
| 2 | `RFH-003` | Claude·Antigravity 정의·실행 파일 지문 재검사, 읽기 쉬운 검토서와 시험 요청 준비 | 정확한 적용 승인과 해당 앱 실행·신뢰 확인 뒤 실제 시험 |
| 3 | `HK-003` | Codex 추가 실패 조건·적용 도구 범위 고정, 변경 정의의 별도 검토 | 실제 실행과 직접 명령 시험을 별도 판정 |
| 4 | `HK-004` | 정상·오류 비교의 자료·입력량·측정 경계 고정 | 미노출 모델 비용을 추정 통과 처리하지 않는 경계 |
| 5 | `RFR-001` | 앞선 실제 근거 연결, 관련 회귀와 공개 시험 조건 확인 | 선행 미완료를 출시 제외로 변경하지 않는 경계 |

- 재시도: 같은 조건의 실패는 원인 수정 없이 반복하지 않는 원칙. 조건별 최초 실행과 원인을 수정한 재시험 최대 1회
- 사용량: 현재 세션의 설치된 사용량 보호 유지. 임의 하한 변경·보호 해제·예산 재설정 제외
- 검증자: 상태 조회·바이트 지문·JSON 및 문서 검사 등 결정적 검사 우선. 모델의 완료 설명만으로 통과 판정 금지
- 완료: 실제 근거로 해당 기준 충족. 권한·수동 동작이 필요한 노드가 생겨도 나머지 독립 작업 지속
- 지식 기록: 재사용 가능한 프로젝트 결론만 원자 사실로 정리, 원문 대화·훅 입력·인증 정보 수집 제외

## 자동 중단 연결의 현재 한계

- 현재 Codex 앱 프로세스의 시작 인자에는 별도 `--listen` 주소 없음. 설치본 도움말의 기본 전송은 `stdio://`, 기존 앱 연결을 위한 도구에는 직접 `turn/interrupt` 호출 없음
- [공식 중단 규약](https://learn.chatgpt.com/docs/app-server#interrupt-a-turn)은 연결된 서버의 정확한 작업·실행 ID와 결과 확인을 요구. 메서드 존재와 현재 앱에 연결 가능한 전송 경로는 별개
- 기존 기본 소켓 오류 `10050`의 원인 해결 없이 반복하지 않는 경계. 새 서버·상시 감시기·프로세스 신호로 현재 연결을 대신하는 조치 없음
- `RB104-004`의 자동 중단 연결은 계속 미검증. 앱 재시작이나 지원 전송 노출이 필요하다면 별도 구체 절차·권한 확인 후 진행
- [Claude 공식 시간 초과 규약](https://code.claude.com/docs/en/hooks#timeouts): 명령 훅의 제한 시간 초과는 `PreToolUse`를 자동 거부하지 않는 동작. 문서 버전과 로컬 `2.1.163` 실제 실행은 별도 판정
