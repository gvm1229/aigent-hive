# OV170-020 — `autonomous-workflow` 제품 Skill화와 `verified-workflow` 제거

- 기준일: 2026-11-28, 실행 장소: cloud 세션
- 결정 근거: 유지관리자 2026-11-28. `verified-workflow`는 최근 두 달간 사용 기록 없음, 0.17.0 작업 기준은 `autonomous-workflow`

## 변경

- 제품 Skill: `.agents/skills/autonomous-workflow/SKILL.md`를 `harness/skills/autonomous-workflow/SKILL.md`로 바이트 그대로 복사, Codex 메타데이터 추가. `harness/skills/verified-workflow/` 삭제
- Athena: `harness/gods.toml`의 Skill 목록과 단계 문장 교체, `scripts/generate-gods.py`로 진입 Skill·소유 문서 재생성
- 목록: catalog(`RunWork`, `project-write`, 파일 읽기·쓰기·셸), 묶음·의존성(`skill-suites.yml`·`user-setup/catalog.yml`), `copier.yml`, 활성 Skill 원장 틀, 사용자 설정 스키마 enum, 프로젝트 설정 답변 enum(옛 이름 입력 유지)
- 옛 이름: `retired-names.yml`에 `verified-workflow → autonomous-workflow`(0.17.0 이름 변경 lifecycle) 추가, `engineer-run`·`hive-loop-engineering`·`ralph-loop`·`iterative-execution` 대상도 새 이름으로. 필수 lifecycle 목록에 0.17.0 항목 추가
- 라우팅: 작업 흐름 신호 2개 이상이면 `autonomous-workflow` 선택(`workflow_route: autonomous-workflow`). 요청의 `workflow_override`는 옛 값 `verified-workflow`도 별칭으로 수용. 명시 호출한 옛 이름은 새 이름으로 route되고 결정 결과에 `renamed_from` 표시(스키마 추가)
- 다른 Skill 본문: multi-goal·team-execution·judge(반대 검토 참고 파일 포함)의 옛 Skill 참조를 새 이름 또는 저장 계획 단계로 교체
- 검사 도구: `check-agent-directives.py`가 제품 본문과 소스 사본의 바이트 동일성 검사, 수용 스크립트·경로 고정물 이름 교체
- 0.17.0 표면 목록에 새 Skill 추가(옛 이름은 퇴역 경로로 유지)
