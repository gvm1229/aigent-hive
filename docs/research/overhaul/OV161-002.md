# OV161-002 — 바뀐 검색 결과 하나의 비차단 처리

- 기준일: 2026-11-26, 실행: Claude Code local 세션(Windows 11 Pro 10.0.26300)
- 진입: 유지관리자 보고. 직접 지운 프로젝트 폴더 때문에 JLPT 세션의 지식 기록 3건 실패
- 원칙: Hive는 감독관이 아닌 도구. 항목 하나의 삭제·손상으로 인한 관계없는 작업 차단 금지
- 판정: 구현·단위 시험 통과. 공개 시험·이 PC 확인은 OV161-006

## 증상

- 원본이 바뀌었거나 사라진 검색 결과 하나 때문에 retrieve·semantic 조회 전체가 `RepairRequired`로 실패
- 프롬프트 훅은 오류를 삼켜 모든 요청의 기억 조회가 조용히 비는 상태

## 수정

- `retain_current_hits`(`crates/hive-wiki/src/store.rs`): 결과마다 원본 확인, 맞지 않는 결과만 제외
- 단계 검토 2번 반영: 후보를 3배(최대 100개)로 넓혀 거른 뒤 top-k(묶음 기준)·바이트 예산 재적용, 의미 검색은 결합 전 거르기
- 버린 수 `stale_hits_dropped`(0이면 생략, 스키마 반영)와 `next_action`의 `hive index rebuild` 안내
- 단계 검토 2차 반영: 주제 묶음 대표가 빠지면 구성원도 함께 제외, 스키마 상한 1700
- 오래된 본문은 계속 미반환. `returned_bytes`는 남은 결과 기준으로 다시 계산
- 의미 검색 게시 차단, 오염된 corpus 거부, snapshot 경합 거부는 그대로 유지

## 확인

- 기존 시험 6개를 "전체 실패" 대신 "해당 결과 제외"로 갱신, 안전 단언은 유지
- 새 시험: top-k 1에서 1위가 오래된 결과면 다음 정상 결과로 채우고 버린 수 1
- 주제 묶음 조회 시험 2개: 묶음 기준 top-k 유지 확인
- 새 시험: 오래된 주제 대표의 구성원 함께 제외, 다음 정상 묶음으로 채움
