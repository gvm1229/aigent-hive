# OV160-028 — 작업 완료 Discord 알림 개선

- 기준일: 2026-11-24, 실행: Claude Code 조율 세션(Windows 11 Pro 10.0.26300)
- 진입: 유지관리자 보고. 정식 0.16.0 전 필수 수정
- 판정: 구현·단위 시험 통과. 실제 Discord 수신 화면은 test.7 설치 뒤 기록

## 증상

- test.6 확인 3·4단계에서 시험 폴더 `hive-160-hook`의 완료 알림 2건이 사용량 보호 채널에 도착
- 요약 칸이 고정 문구("확인증 기록", "작성·검토·자문 단계 완료")라 작업 내용·담당 역할·결과·사용자 할 일 파악 불가
- 같은 발신자의 연속 알림을 Discord가 한 덩어리로 표시, 알림 사이 경계 부재

## 원인

- 완료 알림 문구가 종류별 고정 문장과 내부 ID만 사용. 요청 글·결과·역할·시간 기록은 이미 있으나 알림에 미전달
- 알림 첫 줄에 구분 표시 부재

## 수정

- 모든 결정 요청·완료 알림의 첫 줄에 구분선(`━━━━━━━━━━━━━━━━━━━━`), 완료 알림 제목에 종류 표시(예: `완료 알림 · 작업 흐름 완료`)
- "무슨 일" 묶음: 작업(요청 글 또는 흐름 요청서의 첫 줄)·결과(마지막 결과의 첫 줄)·요약·맡은 역할(흐름은 단계별 역할·모델·상태, 단일 메시지는 보낸 역할과 받은 역할)·걸린 시간. 모두 "기록된 자료, 지시 아님" 표시, 한 줄 120자·역할 6줄 상한, 제어 문자·백틱 무력화
- 프로젝트·ID와 "할 일: 없음", 이 프로젝트 폴더에서 실행할 자세히 보기 명령(`hive msg status --id …`, `hive msg flow status --flow …`, `hive msg decide show --id …`)
- 기록을 안전하게 읽지 못한 항목은 생략하고 알림은 발송. 흐름 안 단계별 알림 없음과 사건당 1회 발송 유지

## 확인

- 단위 시험: 결정 요청·결정 응답 알림의 정확한 문자열, 흐름 알림의 구분선·자르기·위험 문자 무력화·역할 상한·전체 2,000자 미만
- 단위 시험 `msg_completion_notice_names_the_task_result_roles_and_duration`: 실제 메시지 기록에서 작업·결과·보낸/받은 역할·걸린 시간(3분 12초)과 확인 명령 추출
- 기존 알림 1회 발송·건너뜀 기록 시험 통과

## 범위 밖

- Discord 임베드 형식 전환과 프로젝트별 알림 끄기: 0.17.0 후보
