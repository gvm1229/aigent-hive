# OV170-034 — 공용 결과에 신 이름과 대상 목록

- 기준일: 2026-11-29, 실행 장소: cloud

## 변경

- 결과 JSON에 선택 필드 3개: `actor`(신 이름, Hive 자체는 `null`), `items`(대상·결과 `done|skipped|failed|planned`·이유·비밀 표시), `notice`(설정 언어로 그린 안내 문장). 기존 필드 순서는 그대로 두고 끝에 붙임
- 신 배정: 명령 묶음의 담당 신을 `harness/gods.toml`의 `commands`에서 확인. 모든 명령 묶음의 배정 누락을 계약 시험으로 검출(`advanced`만 명시 예외)
- 사람용 출력: 공용 렌더러가 첫 줄 `신 호출 · 하는 일 개수`, 대상 목록, `결과:` 줄을 그림. 바뀐 것이 없으면 한 줄, 10개 넘으면 `외 N개`, 비밀 항목은 `비밀 정보라 표시 안 함`, 사용자 경로는 작업 폴더 기준 상대 경로·홈은 `~`
- 우선 적용: 지식 기록(Apollon, 사실별 종류·주제·문장), 저장 공간 정리(Hades, 삭제 예정·삭제·건너뜀과 이유), 설정·갱신·프로젝트 맞추기(Eileithyia). 나머지 쓰기 동작(지식 추가·삭제·숨김·가져오기·검사, 백업 복원, 사용자 설치·제거)은 바뀐 경로 목록으로 같은 모양
- 읽기 전용 조회는 안내 없음. 결과를 실제로 쓴 경우의 한 줄은 OV170-035 지침

## 차이

- 계획의 "전체 목록 파일 경로": 출력 중에 파일을 만들지 않고 `--output json`의 `items` 전체로 안내. 렌더러가 부수 효과 없이 동작하게 하려는 선택

## 확인

| 시험 | 결과 |
| --- | --- |
| `notice` 단위 시험 10개 | 성공·건너뜀·실패·변경 없음·10개 초과·비밀 항목·삭제 예정·버전 안내·JSON 필드 순서·배정 누락 통과 |
| 스키마 계약 | `action-result.schema.json`에 `actor`·`items`·`notice`, 동작 목록에 `SyncProjectHarness` |
| 통합 | 프로젝트 맞추기 결과의 `actor`·`items`·`notice` 스키마 검증 |
