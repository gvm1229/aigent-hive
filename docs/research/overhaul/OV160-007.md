# OV160-007 — 지식·실행·판정 Skill 통합

- 기준일: 2026-11-20, 단계 6 계획 시작 `4106bd9b` 직후. 실행 장소: cloud 세션
- 계획 항목: [0.16.0 중재 계획](../../plans/active/0.16.0-mediation.md)의 OV160-007
- 승인 범위: 지식 6개·`run-*` 3개·Judge 2개의 통합, 옛 이름 이관과 안내. 계획 밖 Skill 추가 통합 없음
- 사용량 사전 확인: cloud 세션에 실행 가능한 `hive`·사용자 루트 없음, 07의 해당 경로에 따라 생략

## 범위

- 정본 Skill `harness/skills/`, 생성 사본(플러그인·Copier 템플릿 두 곳), 신 입구 표
- 이관 원장 `retired-names.yml`, 0.16.0 표면 목록과 시험 출시 고정물
- 렌더러·투영·갱신 경로의 Skill 이름, 소유 경로 목록, 설정 스키마
- 동결 원본 `harness/project-bases/*`·`harness/user-bases/*`와 출시 기록 문서는 변경 제외

- 묶음 기준: 대상과 권한. 조회(읽기 전용)·새 지식 기록·기존 지식 관리를 분리
- 옛 본문은 각 `references/*.md`로 그대로 이동, 머리말에 사용 조건만 추가. 규칙·CLI 명령 삭제 없음
- 새 `SKILL.md` 핵심: 방식 표, 공통 규칙, 옛 이름 안내. `run` 37줄·`judge` 32줄·`knowledge-manage` 39줄
- 권한 합집합: `knowledge-capture`는 스캔의 `external-write`·`memory-read` 포함, `knowledge-manage`는 `external-write`, `run`은 `project-write`, `judge`는 `read-only`와 host Judge 요청용 `subagents`
- 의존 관계: `verified-workflow` → `judge`·`run`·`usage-guard`, `knowledge-manage` → `knowledge-recall`·`knowledge-capture`
- 신 입구: `run`은 아테나 소유(옛 `run-checkpoint`·`run-resume` 소유자), 포세이돈은 `run`의 인계 방식으로 안내
- 경로 판단: `run`은 요청의 행동(`ResumeWork` 등)을 그대로 사용, 옛 `run-resume`의 재개 행동 유지

### 이관과 갱신

- `retired-names.yml`: 옛 9개 이름과 이전 별칭 전부를 새 이름으로 직접 연결, 0.16.0 `merge` 수명 기록 9건
- 과거 선택 이관: 이름 변경 뒤 병합된 경우(`knowledge-import` → `knowledge-scan` → `knowledge-capture`)도 병합 대상의 수명 기록으로 허용
- 사용자 선택: 서로 다른 옛 이름이 병합 대상 하나로 모이는 경우만 허용. 현재 이름과 옛 이름의 동시 선택은 중복 거절 유지
- 0.16.0 표면 목록: 새 Skill 3개·투영 13개 추가, 옛 이름은 이전 갱신용으로 유지. 0.15.3 대비 `AdditiveFeature`로 선언 `feature`와 일치
- 시험 출시 고정물 `valid-0.16.0`: 같은 목록과 지문·길이 갱신
- 갱신 삭제: 소유 경로 목록에 새 참조 파일 추가, 옛 `run-checkpoint/references/policy-review.md` 소유 유지. 인증된 옛 폴더만 제거, 사용자 수정은 기존 거래의 보존·충돌 경로
- 한국어 과거 설치 인증: 0.15.3까지의 한국어 설명을 별도 표로 보존, 옛 Skill과 문구가 바뀐 `knowledge-capture`의 공개 설치 바이트도 갱신 전 인증
- 설정 스키마: 사용자 Skill 목록·의존 표 31개로 축소, 프로젝트 답변 스키마는 옛 이름을 이관 입력으로 유지
- 사본: `scripts/sync-user-plugin.py`, 신 입구 `scripts/generate-gods.py`, 설정 화면 고정물 `HIVE_UPDATE_SNAPSHOTS=1`로 재생성

### 옛 이름 호출 안내

- 새 Skill의 설명(`SKILL.md`·`openai.yaml`·한국어 표시 설명)에 `Formerly <옛 이름>` 표기, host의 이름 검색이 새 Skill로 연결
- 본문: 옛 이름별 방식 대응과 "새 이름과 방식 한 번 안내 뒤 계속" 규칙
- 시험: `hive-projection`의 `former_skill_names_resolve_and_are_announced_by_their_merged_skill`, Python `test_rename_ledger_is_stable_and_complete_for_the_last_public_inventory`

## 한계

- 다섯 앱의 새·옛 이름 표시는 local 확인
- 옛 이름 안내는 새 Skill 설명과 본문에 의존. 옛 Skill 파일이 사라진 뒤 host가 옛 이름 호출을 새 Skill로 연결하는지는 실제 호스트 대화 근거 필요
- Wiki 비활성 사용자 설정은 `knowledge-manage` 전체를 제외. 이전 `knowledge-transfer`의 Wiki 비활성 사용자 노출 없음
- 공개 HTML 안내(`docs/hive-core-features.ko.html`)는 공개 안정판 기준이라 옛 이름 유지, 정식 0.16.0 공개 문서 갱신 때 반영
- `test_trust_root_rejects_impossible_calendar_timestamp`는 단독 실행에서 이 환경의 `rfc3339_validator` 부재로 실패, 이번 변경과 무관
- 이 보고서의 홈 도달 연결은 조율자가 CURRENT에서 추가
