# OV170-025 — 위임 실행 중 사용량 급감 보호(옛 OV160-022)

- 기준일: 2026-11-28, 실행 장소: cloud 세션
- 사건(2026-11-21 local, [재계획 기록](OV160-replan.md#ov160-022-위임-실행-중-사용량-급감-보호)): Codex 작업자 4개 병렬 약 40분 만에 Codex 30일 한도 남은 양 94% → 0%. Hive 읽기는 정확, 원인은 작업 시작 때 한 번뿐인 사전 확인과 위임 중 재확인 부재

## 결정 규칙 적용

- 저장된 중간 보호(`usage_guard.midway`)는 기본 꺼짐이고 위임 작업자를 멈추는 경로가 아님 → 계획의 두 번째 경로: 위임마다 `hive usage enforce` 재호출과 급감 판정

## 변경

- `hive_core::usage_guard::evaluate_delegation`: 같은 창의 읽기 목록(시각·남은 %)과 사용자 기준, 실행 중 작업자 수로 판정. 10분 안 20%p 이상 하락이면 `stop-new-workers`, 기준 이하면 `at-threshold`, 아니면 기준 위 여유를 실행 중 작업자와 새 작업자 수로 나눈 작업자별 예산
- usage-guard Skill `references/control.md` "Delegated workers": 새 작업자마다 `enforce` 재실행, 급감·기준 도달이면 새 작업자 준비 중단과 보고, 아니면 작업자별 예산 부여

## 확인

| 항목 | 결과 |
| --- | --- |
| 판정 시험 | `delegation_stops_new_workers_on_a_sharp_drop_and_splits_headroom`: 사건 재현(94→66, 10분 28%p) 중단, 완만한 하락 허용, 작업자별 예산 계산, 기준 도달·읽기 없음 |

## 한계

- 판정을 부르는 CLI 명령은 미추가. 호스트 Skill 절차가 `enforce` 결과를 모아 판정 규칙대로 행동. 실제 위임 중 동작은 local 확인 대상
