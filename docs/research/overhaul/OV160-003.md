# OV160-003 공식 훅의 사건 알림과 결과 반환

- 기준일: 2026-11-20. 실행 장소: cloud 세션, Linux 컨테이너
- 기준 커밋: `65380ce1`(OV160-002)의 격리 작업 폴더
- 범위: cloud 부분. 훅 사건 정규화·사건 기록·비동기 결과 반환·프로젝트 한정 훅 설정 미리보기와 확인. 제품 버전 변경 없음
- 실제 호스트·제공자 호출 0회. `claude -p`·인증 파일·사용자 전역 `~/.claude`·`~/.codex`·`~/.gemini` 접근 없음
- local 잔여: Claude+Codex 실제 왕복과 공식 이벤트→사건 기록 5초 측정. 아래 한계 참조

## 선행 결정과 선택

- P2 비동기 반환 유지: 훅은 즉시 반환, 작업자 대기 0회. 진행 중 요청은 짧은 `queued` 안내, 확인된 결과는 뒤의 공식 훅 사건에서 반환
- 새 명령 대신 `hive msg` 하위 명령: 같은 수신 상자·게시 함수·역할 해석 재사용, 새 최상위 명령의 신 소속 추가 회피. `msg`는 Poseidon 소속으로 등록
- `hive policy hooks` 미확장: 그 수신 확인은 고정 정책 지문·스키마 파일에 묶인 별도 계약. 같은 부품(`hook_config::edit_entry`·`prune_empty`, `replace_host_policy_file`, 미리보기 지문 확인)만 재사용
- Claude Stop 기본 반환은 결과를 넘길 때만 `hookSpecificOutput.additionalContext`: 공식 문서상 오류가 아닌 피드백으로 대화 계속. 대기·미전달 안내만 있으면 대화를 잇지 않는 `systemMessage`([단계 6 검토 B1](stage-6-review-fixes.md)). OV150-001의 `decision: block`은 Claude가 "Stop hook error"로 표시한 형식, `--return block`으로만 선택
- 사건 ID: 호스트의 턴 ID(`prompt_id`)가 있으면 그 지문, 같은 턴 재시도만 저장된 응답 재생. 없으면 같은 입력이라도 다른 턴일 수 있어 호출마다 새 ID·응답 다시 계산([단계 6 검토 S2](stage-6-review-fixes.md)). 처음 구현의 입력 바이트 지문 방식은 같은 입력의 두 번째 턴에 낡은 응답을 재생해 새 결과를 숨기던 결함
- 결과 전달은 메시지당 한 번: 두 세션에 같은 결과를 주면 호스트가 두 번 실행할 위험. 다른 새 세션의 같은 요청은 OV160-002의 중복 보내기 반환이 기존 확인증 전달 담당

## 프로젝트 훅 설정

```text
hive msg hooks preview|apply|remove --host claude|codex|gemini --role <역할|신> [--task <id>] [--return context|block] [--confirm <승인 지문>] --target <dir> --user-root <home>
hive msg hooks status --host claude|codex|gemini --target <dir> --user-root <home>
hive msg hook --host <호스트> --event <공식 이벤트> --role <역할> [--task <id>] --binding <지문> --target <dir> --user-root <home>
```

- 미리보기: 읽기 전용, 영수증 전체와 승인 지문·허용 목록 표시. 적용 전까지 비활성
- 적용·제거: 현재 미리보기의 정확한 승인 지문 필요, 다르면 `hive.msg-hooks-refused`. 영수증 먼저, 그다음 호스트 파일의 비교 후 교체
- 다른 훅 항목·설정 바이트 보존. Hive 항목만 삽입·제거, 만든 파일은 제거 때 삭제
- `--return`: Claude만 `context`(기본)·`block`, Codex는 `block` 고정, Gemini는 없음
- `msg hook`은 호스트가 실행하는 명령. Codex·Gemini 실행·키 입력·화면 회수 없음, 봉투 소비와 작업자 호출은 호스트 처리기 담당

## 단계 6 검토 뒤 변경

[단계 6 검토 수정](stage-6-review-fixes.md)이 이 문서의 기본 동작을 아래처럼 바꿈.

- B1: Claude 기본 Stop 반환이 결과 없이 대기·미전달 ID만 있을 때도 `additionalContext`를 보내 Stop마다 모델 턴이 하나 더 생기던 문제. 공식 문서상 Stop의 `additionalContext`는 대화를 이으므로, 넘긴 결과가 없으면 `StopBlock`과 같이 `systemMessage`만 반환
- B2: 훅 전달 전에 결과 파일을 확인증의 `result_digest`·`result_bytes`와 대조. 다르면 `quarantined`, 본문 미전달
- S2: 사건 ID가 `prompt_id` 기준, 없으면 호출마다 새 사건
- S3: 미전달 메시지는 상태마다 한 번만 안내(`announcements/<메시지 ID>-<상태>.json`, 덮어쓰기 없음), 대기·미전달 ID는 10개까지 나열하고 나머지는 "and N more"
- S7: 사건이 모두 미검증인 호스트(Gemini)는 `msg hooks apply`를 `hive.msg-hooks-unverified-host`로 거부, 미리보기만 허용. 단위 미확인이라 Gemini 항목에는 `timeout` 없음, Claude·Codex는 초 단위 10
- S8: 기록 하나가 일반 파일이 아니면 그 메시지만 `quarantined`, 다른 메시지 전달은 계속
- 확인증 기록은 `msg ack --id <ID> --claim <소비권 토큰|지문> --result <file>`(S5)
