# OV160-005 피해 범위 통제

- 기준일: 2026-11-20. 실행 장소: cloud 세션, Linux 컨테이너
- 기준 커밋: `3203023d`(OV160-004 cloud 부분 기록)의 격리 작업 폴더
- 범위: 작업자 최소 권한 정책, 점수표·검사 지문 고정, `max_workers` 상한과 옛 `max_panes` 이전, `hive stop` 취소 사건과 호스트 취소 확인증. 제품 버전 변경 없음
- 실제 호스트·작업자·제공자 호출 0회. `claude -p`·인증 파일·사용자 전역 `~/.claude`·`~/.codex`·`~/.gemini` 접근 없음, 키 입력·프로세스 종료 코드 없음
- 동시 작업: OV160-006(결정 대기열)과 공유 파일 `msg.rs`·`cli_help.rs`·`human_output/codes.rs`·`main.rs`·`lib.rs`는 줄 추가 위주의 작은 변경

## 선택과 이유

- 정책 자료는 `crates/hive-core/src/containment.rs`, 입출력 없음. 명령 처리는 `crates/hive-cli/src/msg/containment.rs`·`msg/stop.rs`
- 봉투 구조 유지: 정책은 봉투 옆 `policies/<메시지 ID>.json`에 봉투보다 먼저 게시. OV160-002 봉투 지문·메시지 ID와 기존 기록 호환, 다른 작업의 봉투 생성 코드와 충돌 회피
- `hive stop`은 새 최상위 명령, Poseidon 소속(조율·취소). 계획 문구의 이름 그대로, 기존 `stop` 명령 없음. 구현은 같은 수신 상자 기록을 쓰는 `msg` 하위 모듈
- 하위 명령형(`hive stop status`·`hive stop clear`): 공용 옵션 해석이 값 없는 깃발을 받지 않음. 계획 초안의 `--clear`는 `clear` 하위 명령으로 표기
- 동작 결과 이름은 기존 `Message` 재사용: 사람용 출력 묶음·스냅숏 변경 최소화
- `max_workers` 위치는 `.hive/config/harness.toml` 최상위 키. 설정 렌더러는 이 키를 모르므로 템플릿·답변 스키마는 바꾸지 않고, 프로젝트 갱신이 기존 값을 새 렌더 결과로 옮김. 출시 표면 목록 변경 없음

## 작업자 정책

모든 메시지에 역할 정책 하나. 호스트가 작업자 실행 때 적용, Hive는 실행하지 않음(`hive_launches_worker: false`).

| 항목 | 값 | 근거 |
| --- | --- | --- |
| `sandbox` | 판정·조사 역할 `read-only`, 그 밖 `workspace-write`, Claude·Gemini `host-guidance` | 기존 Codex 프로필의 `--sandbox` 값과 같음 |
| `network` | `none` | Codex `workspace-write`의 기본 네트워크 차단과 같은 방향 |
| `git_push` | `deny` | 네트워크 차단과 아래 git 환경 |
| `writable_roots` | 쓰기 역할 `["{target}"]`, 읽기 전용 역할 `[]` | 호스트가 `-C {target}`에 묶는 작업 폴더 |
| `git_env` | `GIT_CONFIG_COUNT=1`·`protocol.allow=never`·`GIT_TERMINAL_PROMPT=0` | 모든 git 전송(file·ssh·git·http) 거부 |
| `enforced_by` | Codex `host-sandbox`, 그 밖 `host-guidance` | 실행 프로필 유무 |

- 실행 인자 상승 거부(`validate_worker_argv`): `--dangerously-bypass-approvals-and-sandbox`·`--yolo`·`--full-auto`·`--add-dir`·`danger-full-access`·`-s`·`--dangerously-skip-permissions`·`--permission-mode`, `--sandbox=` 같은 한 줄 형식, 허용 목록(`model_reasoning_effort`·`forced_login_method`) 밖의 `-c` 키, 두 번째 `--sandbox`, 역할과 다른 sandbox. Claude·Gemini 프로필은 빈 인자만
- 적용 위치: 정책 생성(메시지 보내기·흐름 단계) 전, `SummonEnvelope::validate`. 위반은 `hive.msg-policy-refused`, 파일 0개
- 역할 설정 파일로는 인자를 바꿀 수 없음(인자는 코드가 생성). 상승 거부는 변조된 소환 봉투와 앞으로의 프로필 변경에 대한 방어
- push 시도 실패 확인: 임시 폴더의 실제 `git`으로 정책 환경 적용 push 실패(`transport 'file' not allowed`), 같은 push의 정책 없는 대조군 성공. 네트워크·호스트 없음

## 점수표·검사 지문 고정

- `hive msg flow start ... --check <파일> [--worktree <작업 폴더>]`: 검사 파일 하나를 정식 경로로 바꿔 SHA-256·크기를 `flows/<흐름 ID>/checks.json`에 고정(덮어쓰기 없음)
- 작업 폴더 기본값은 대상 프로젝트. 검사 파일이 작업 폴더 안(같은 경로·하위)이면 `hive.msg-check-inside-worktree`, 파일 0개. 작업자가 쓸 수 있는 파일은 채점 입력 불가
- 자동 흐름 키에 검사 지문 포함: 검사가 다르면 다른 흐름
- 단계 생성(`ack` 뒤 진행·`advance`·`requeue`) 전마다 다시 읽어 비교. 불일치·파일 없음은 `check-drift.json` 기록, `hive.msg-flow-check-drift`, 흐름 `stopped`. 원래 바이트로 되돌려도 기록이 남아 재개 없음
- 상태 화면 `checks`: 고정 목록·`read_only_for_worker: true`·`drift`·기록. Hive는 검사 파일을 읽기만 함

## 상한과 이전

| 키 | 기본값 | 범위 | 효과 |
| --- | --- | --- | --- |
| `max_workers` | 4 | 1–64 | 기한 안의 `claimed`·`cancel-requested` 수가 상한이면 새 소비권 거부(`hive.msg-worker-limit`) |
| `max_worker_seconds` | 3600 | 1–86400 | 더 긴 `--lease` 거부(`hive.msg-worker-time-limit`), 기본 기한은 15분과 상한 중 작은 값 |

- 시간 상한 도달: 기존 상태표대로 `dispatch-uncertain`, 흐름은 `blocked`. 자동 재호출 없음, 상한 칸 반환
- 옛 키 읽기: `max_panes`만 있으면 그 값을 `max_workers`로 사용(`source: legacy-max-panes`), 두 값이 같으면 `both-same`, 다르면 `hive.msg-limit-conflict`로 소비권 거부·파일 변경 없음
- 이전 쓰기: `hive project upgrade`(설정 재구성 포함)의 미리보기·적용 경로에서만. 렌더된 `harness.toml`에 기존 `max_workers`·`max_worker_seconds`를 옮기고, `max_panes`는 같은 값의 `max_workers`로 기록. 변경 사유 `worker-limit-migration`
- 충돌 시 갱신 전체 거부(`--dry-run`·`--apply` 모두 실패, 파일 그대로). 덮어쓰기 없음
- 이전 전에는 렌더러가 손으로 넣은 키를 지웠음. 이번 변경으로 갱신 뒤에도 상한 유지

## 중지·취소 계약

```text
hive stop [--flow <흐름 ID> | --task <작업 ID>] [--reason <text>] --target <dir> --user-root <home>
hive stop status --target <dir> --user-root <home>
hive stop clear [--flow|--task] [--confirm <중지 지문>] --target <dir> --user-root <home>
hive msg cancel-ack --id <메시지 ID> --receipt <호스트 취소 확인증.json> --target <dir> --user-root <home>
```

- 중지 기록: `.hive/mediation/stops/<중지 ID>.json`, 덮어쓰기 없음. 범위는 프로젝트·흐름·작업, `forced: false` 고정. 같은 범위 반복은 `hive.stop-already-active`, 새 파일 0개
- 범위 안에서 거부(`hive.msg-stopped`, 파일 0개): `msg send`, `msg flow start`, 흐름 단계 생성(`ack` 뒤 진행·`advance`·`requeue`), `msg claim`, 프로젝트 중지 때 `hive summon` 봉투 준비. 훅은 결과를 넘기지 않고 `withheld: stopped`로 기록, 호스트 계속 요청(`decision: block`) 없음
- 읽을 수 없는 중지 기록은 프로젝트 전체 중지로 취급
- 진행 중 작업: 끊지 않고 `cancel-requested`로 표시. 중지 결과에 작업마다 `host_cancel`·이유·다음 행동, `workers_interrupted: 0`·`keystrokes_sent: 0`
- 호스트 공식 취소 지원표

| 제공자 | 표시 | 의미 |
| --- | --- | --- |
| Codex | `unverified` | `codex exec`를 실행한 호스트가 자기 공식 프로세스 제어로 끝낼 수 있음, Hive 왕복 미검증. 확인증 수락 |
| Claude | `unsupported` | 다른 프로세스가 요청할 수 있는 실행 중 턴·하위 에이전트 취소 문서 없음. 확인증 거부(`hive.msg-cancel-unsupported`) |
| Gemini | `unsupported` | 미검증 동료 작업자, 공식 취소 미확인 |

- 취소 확인증: 메시지·봉투 지문·소비권 지문·현재 중지 ID·청구 역할 제공자·`method: host-official-cancel`·`forced: false`를 모두 묶어야 `cancels/<메시지 ID>.json`에 기록, 상태 `cancelled`(종료). 강제 취소·다른 방법 이름은 거부
- 확인증 없는 `unsupported` 작업은 기한 뒤 `dispatch-uncertain`, `cancelled`로 표시하지 않음
- 늦은 결과: `cancel-requested`·`cancelled` 메시지의 `ack`는 결과를 `quarantine/`에 두고 전달·흐름 진행 없음
- 재개: `hive stop clear`는 미리보기와 지문만, `--confirm <중지 지문>`이 맞을 때만 해제 기록. 해제 뒤 자동 재발송 0회, 같은 범위의 다음 중지는 세대 +1

## 한계

- Hive는 정책을 무시하는 호스트·작업자를 막지 못함. 실제 경계는 호스트 sandbox(Codex `--sandbox`)와 그 네트워크 차단. git 환경은 작업자가 환경 변수나 `-c`로 되돌릴 수 있는 보조 장치
- Claude·Gemini는 실행 프로필이 없어 정책이 안내(`host-guidance`)일 뿐, 실제 권한은 호스트 권한 설정
- 공식 취소 미지원 호스트(Claude·Gemini)는 `unsupported` 표시만, 진행 작업은 기한까지 계속될 수 있음. Codex도 `unverified`, 실제 호스트 취소 왕복 미검증
- `max_workers`는 소비권 수를 세는 방식이라 같은 순간의 동시 소비 두 건은 상한을 하나 넘을 수 있음. 실행 슬롯 잠금 없음
- 점수표는 흐름당 파일 하나. 같은 사용자의 악의적 동시 변조(기록과 원본을 함께 바꾸기)는 증명 밖, 지문은 우발 변경 탐지
- 상한 키는 `hive project upgrade`·설정 재구성이 옮김. 다른 경로로 `harness.toml`을 새로 렌더하면 손으로 넣은 키는 다시 넣어야 함
- 실제 Claude·Codex 호스트, macOS·Windows 실행 미확인
