# OV170-023 — 공통 원본 동봉·주간 동기화 도구

- 기준일: 2026-11-28, 실행 장소: cloud 세션
- 목적: 동봉한 외부 Skill 원본은 원문 그대로 쓰고, Hive 덮어쓰기·충돌 판정·사용자 선호는 원본 폴더 밖에서 유지

## 변경

- 보관: `harness/upstream/<이름>/` 다섯 원본(바이트 그대로, `.gitattributes` `-text`). 고정 commit: {'omc-ai-slop-cleaner': 'b8fe8682ae5b', 'hallmark': '04977e15f3df', 'frontend-design': 'e4bb5d960d87', 'web-artifacts-builder': 'e4bb5d960d87', 'impeccable': '2fc5e1459efb'}
- 원본별 라이선스 파일: OMC는 저장소 루트 `LICENSE`, hallmark는 폴더 안 `LICENSE`, anthropics 두 원본은 폴더 안 `LICENSE.txt`, impeccable은 루트 `LICENSE`·`NOTICE.md`
- 고정 기록: `harness/upstream/UPSTREAM.lock`(JSON, `name, repo, ref, path, commit, license, license_files, used_by, synced_at`). 출처 표시: `THIRD_PARTY_NOTICES.md`·`docs/licensing.md`, `REUSE.toml` 파일별 라이선스, `LICENSES/MIT.txt`
- 도구: `scripts/sync-upstream.py`. 기본은 원본마다 최신 commit을 얕게 받아 폴더 교체·lock 갱신, `--check`는 비교만, `--verify`는 오프라인 라이선스 확인, `--pr-body`는 원본별 변경 수·다시 볼 충돌 판정 주제를 담은 PR 본문 작성. 닿지 않거나 사라진 원본은 그 원본만 건너뛰고 이유 표시
- 주기: `.github/workflows/upstream-sync.yml`(월요일 03:17 UTC 예약·수동 실행). 바뀐 원본이 있으면 `chore/upstream-sync` 브랜치에 유지관리자 신원으로 커밋하고 develop 대상 PR 하나 생성·갱신, 자동 병합 없음
- 판단: 계획의 `docs/upstream/sources.yml`은 lock과 같은 내용이라 미작성. 출처는 lock·THIRD_PARTY_NOTICES·licensing 세 곳
