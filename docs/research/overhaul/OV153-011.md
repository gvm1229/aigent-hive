## 변경

- `hive setup --answers <patch> --input-channel agent --apply`에서 `--capabilities` 선택. 생략 시 대화형과 같은 순서(저장된 해석, 없으면 감지)로 능력 해석. 결과의 `capabilities.source`는 `provided-document` 또는 `saved-or-detected-by-cli`, `execution_capabilities_verified:false`
- 생략한 능력 파일은 hook 승인·선택 Skill·지식 범위·역할 생성 없음. 새 프로젝트는 네 초기 선택(`setup_mode`·`project_name`·`project_kind`·`primary_host`) 여전히 필수
- `--show --summary`: 미설정 프로젝트에 `agent_setup` 제안(`project_state` empty/existing, `required_answers`, `detected_defaults`, `selected_hosts`, `requires_user_confirmation:true`)과 `next_action`. 사용자 설정이 없으면 `next_action`은 user-setup 상태 명령. 제안 실패는 `unavailable`과 이유로 낮추고 조회는 성공
- 손대지 않은 터미널 초안(질문 중·미리보기, 적용 전)은 에이전트 적용의 차단 대상에서 제외. 메모리에서만 건너뛰고 설정 잠금 안의 비교 후 교체로 대체. 실패한 적용은 초안 유지. `--show`는 이 경우 `terminal_draft:"superseded-on-apply"`
- 요약 크기 초과 시 `agent_setup.detected`, 다음 `available_sections` 순서로 덜어 냄
- Skill: `project-setup`(참고 문서 포함)과 `user-setup` 재작성, 배포 사본 동기화. 빈 폴더는 프로젝트 내용·목표·개발 방식을 한 번에 하나씩 질문, 위임 문구로도 생략 불가. 기존 프로젝트는 예시(Markdown 묶음·React TypeScript·C++과 uasset)를 단서로 한 제한 탐색, 모호하면 근거와 함께 확인. 제안 한 번, `--input-channel agent --apply`로 적용, `--show`로 확인. CLI 터미널은 요청 시에만. 역할·hook·선택 Skill·지식 범위·임계값의 임의 생성 금지, 능력 파일 생성 금지. user-setup은 인터페이스 언어와 `selected_hosts`를 항상 질문
