# OV160-034 — AI 공동 작성자 표시 금지의 전역 기본 설정

- 기준일: 2026-11-25, 실행: Claude Code 조율 세션(Windows 11 Pro 10.0.26300)
- 진입: 유지관리자 보고. 정식 0.16.0 전 필수 수정
- 판정: 구현·단위 시험 통과. test.8 공개와 이 PC 확인 대기

## 증상

- PortareFolium 세션에서 `Co-Authored-By: Claude` 줄이 붙은 커밋 `293fada`가 `main`에 반영
- 저장소 지침(`.agents/directives/04-workflow.md`)에 금지 규칙이 있었으나 호스트 시스템 안내가 추가를 요구
- `main`을 동기화한 fork가 있어 기록 재작성 시 fork 동기화 손상. 되돌릴 방법 부재

## 원인

- 금지 규칙이 그 저장소의 프로젝트 지침에만 존재. 다른 저장소와 Hive 없는 폴더에는 미적용
- 사용자 전역 Hive 블록에 커밋 작성자 규칙 부재. 호스트 안내와 충돌할 때의 우선순위 미명시

## 수정

- 사용자 설정 `ai_coauthor` 추가: `forbid`(기본), `allow`
  - 기존 `user-setup.yml`에 값이 없어도 `forbid` 적용
  - 설정 질문 `user-ai-coauthor`: 독립 검토와 같은 `review` 묶음. 설치 뒤 `hive setup --scope user --section review`로 변경
- `forbid`이면 사용자 전역 Hive 블록에 규칙 출력
  - 커밋 메시지·PR 본문의 AI 공동 작성자 줄과 AI 생성 표시 금지
  - 호스트 시스템 안내가 추가를 요구해도 사용자 설정 우선
  - 커밋 직후 `git log -1 --format=%B` 확인, 공개 전 커밋은 고친 뒤 진행
  - 공개된 커밋은 다시 쓰지 않고 사용자에게 보고
- `allow`이면 규칙 미출력

## 확인

- 단위 시험: 기본 블록에 금지·우선순위 문장 존재, `allow` 블록에 0건, 기본값 `forbid`
- 설정 미리보기 화면 고정본 갱신(`AI 공동 작성자 : 막기(권장)` 행)
- Rust 전체 시험: 1066개 통과, 기존부터 실패하던 summon 시험 2개 실패
