## 변경

기능과 질문·도움말·선택지 문구는 그대로, 배치와 꾸밈만 수정.

- 새 모듈 `setup_engine/layout.rs`: 80열 줄바꿈(한글 2열 계산), `이름 : 값` 표, 질문별 짧은 제목, 꾸밈 판정
- 질문(`terminal.rs` `ask_step`): 앞 빈 줄, 제목 줄 `[2/4] 프로젝트 이름`, 빈 줄, 들여쓴 묶음(질문 문장·도움말·선택지·여러 개 선택 안내·`Enter로 유지/선택`), 빈 줄, 입력 줄 `> `. Enter로 유지되는 선택지에 `(현재값)` 또는 `(기본값)` 표시
- 단계 번호: 프로젝트 설정(`questions::collect`)과 사용자 설정(`interactive::collect`)에서 지금까지 물은 수와 현재 답 기준 남은 질문 수로 계산. 빠른 프로젝트 설정은 `[1/4]`–`[4/4]`. 번호를 알 수 없는 질문(선택 기능 검토 등)은 `[질문]` 제목
- 프로젝트 미리보기(`questions::preview`): 제목 `프로젝트 설정 미리보기`, 구역 `일반`·`기능`·`지식 경로`·`변경 규모`. 질문 문장 대신 짧은 이름, 빈 값은 `없음`, 목록은 여러 줄, 기능 묶음은 `개별 선택 32개`와 줄바꿈한 이름 목록, 선택 기능·후크는 한 줄 JSON 대신 항목별 줄
- 사용자 설정 미리보기(`display_preview`): 제목 `적용 전 확인`, 구역 `일반`·`기능`·`지식`·`사용량`·`알림`의 같은 표
- 확인 질문 앞 구분선
- 꾸밈: 제목은 굵은 청록, 구역 이름은 굵게. 표준 오류가 터미널이고 `NO_COLOR`가 없거나 빈 값일 때만. Windows는 색 코드를 해석하는 Windows Terminal(`WT_SESSION`)·VS Code 등(`TERM_PROGRAM`)에서만, 기존 콘솔 창은 일반 문자. 그 밖에는 같은 줄의 일반 문자. 입력 줄 `> `는 항상 일반 문자(터미널 구동 스크립트의 `> ` 대기 유지)
- 구조형(JSON) 질문의 기본값 줄은 다시 붙여 넣을 수 있도록 줄바꿈 없이 유지

## 시험

- 스냅샷(색 없음·80열): `tests/fixtures/setup/screens/project-quick.ko.txt`·`.en.txt`(빠른 프로젝트 설정 전체 화면), `user-preview.ko.txt`·`.en.txt`(사용자 설정 미리보기). 모든 줄 80열 이하, 제어 문자 없음. 갱신은 `HIVE_UPDATE_SNAPSHOTS=1`
- `decoration_only_adds_colour_around_the_same_lines`: 꾸밈을 켠 화면에서 색 코드를 지우면 일반 화면과 동일
- `decoration_needs_a_terminal_and_no_no_color_value`: 터미널·`NO_COLOR` 판정
- 계약 시험 `test_readable_setup_screen_has_no_control_bytes_without_a_terminal`: 비TTY 실행과 `NO_COLOR=1` 실행 모두 제어 문자 없음, 같은 출력
- 기존 터미널 시험 2개는 줄바꿈과 표 정렬에 맞춰 비교 방식만 수정(문구 동일)
- `cargo test -p hive-cli --bin hive -- user_setup` 257개 통과, clippy `-D warnings` 통과

## 한계(후속 제안)

- 단계 번호는 기본 질문 묶음 기준. 맞춤 설정 뒤의 지식 경로 연결·역할 확인·선택 기능 검토, 사용자 설정의 변경 구역 선택·의미 검색·색인 복구 질문은 `[질문]` 제목, 재개 시 번호는 다시 1부터

- 새 프로젝트의 제안값도 초안의 현재값이라 `(현재값)` 표시
