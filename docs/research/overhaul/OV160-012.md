## 1. 시험판 설치와 갱신

- `npm install -g aigent-hive@0.16.0-test.3` → `AIgent Hive v0.16.0-test #3 · 개발 시험판`. 인계 기대 문구 `v0.16.0`과 표기 차이뿐
- `hive update --user-root $HOME --non-interactive --confirm --output json` → **exit 2** `hive.update-failed`, "installed ownership manifest does not match an authenticated Hive release: claude", `steps.core=not-started`
- `hive install --scope user --hosts codex,claude,antigravity --dry-run` → Codex 정상 인증, Claude·Antigravity는 `hive.user-install-dry-run-preserving-reinstall-planned`
- 원인(읽기 전용 진단, 0.15.3 설치 기록 사본으로 검증). 이 PC 문제 아님, 0.15.2·0.15.3 사용자 전부 해당
  - Claude: `crates/hive-cli/src/user_install.rs` `historical_09x_user_inventory`(약 4681–4688행)가 `.hive/marketplaces/claude/.claude-plugin/marketplace.json` 지문을 고정 상수 `USER_070_CLAUDE_MARKETPLACE_DIGEST`(`sha256:52681102…`)와 비교. 실제 파일은 `render_claude_marketplace()`가 `"version"`에 출시 버전을 넣으므로 버전마다 다름(0.15.3 = `sha256:1d6d0940…`, 같은 틀로 재계산해 일치 확인). 0.9.x–0.15.x 중 상수와 일치하는 버전 0개
  - Antigravity: 같은 함수 4644행이 범위 `>=1.1.7 <1.2.0`만 허용. 0.15.2부터 설치 기록은 `>=1.1.7 <2.0.0`
  - 시험 공백: `every_09_stable_user_inventory_authenticates_for_every_host`(약 10466–10560행)와 `seed_historical_09x_user_install`이 같은 상수·옛 범위로 가짜 기록을 만들어 항상 통과. CI에 공개 0.15.3 사용자 설치 → `hive update` 경로 시험 부재
- 우회: `hive install --scope user --hosts codex,claude,antigravity --apply` → `hive.user-install-multi-host-complete`(Claude·Antigravity 보존 재설치). 이후 `hive update` → `hive.update-complete`, `--validate` → `hive.user-install-multi-host-valid`
- 보존 확인: 지식 파일 702개 전후 동일, `user-setup.yml`·`user-feature-answers.yml`·`collections.yml` 바이트 동일, `~/.claude/settings.json`·`~/.codex/config.toml`·`~/.gemini/settings.json` 바이트 동일
- **데이터 손실**: `~/.hive/config/projects.yml`이 `projects: []`로 바뀜(전 `sha256:1f0b056c…` → 후 `sha256:278f6c3a…`). 보존 재설치가 쓰는 `execute_uninstall`이 `UNINSTALL_FILES`의 `.hive/config/projects.yml`을 예외 없이 지움(`user_install.rs` 약 801행). 제거 명령 경로(`user_install/uninstall.rs` `PRESERVED`·`removal.rs`)는 보존하므로 두 경로 불일치. dry-run의 `preserved` 목록에도 없음. 같은 흐름이 `.hive/runtime`·`.hive/backups`도 지움. 백업 없음, 이 PC의 등록 프로젝트 약 15개(`Documents/*`·`hive-*`에 `.hive/` 존재)는 각 프로젝트 설정 재적용 전까지 미등록
- 추가: `hive project upgrade --target .`와 `hive setup --target .`이 Windows에서 실패("project target has no directory name", "--user-root must be an absolute directory"). 절대 경로는 통과. 인계 2-1·3단계 명령이 `--target .` 사용

## 2. Claude 사용량 기록(OV160-013 local)

- 연결 전 enforce(이 Code 탭 세션) → exit 0 `hive.usage-observation-warning`, `missing_windows=["session","weekly"]`, `observation_cause=no-measurement`, `fix_command=hive setup --scope user --section usage --claude-statusline preview`, Discord `kind=observation-warning`. 차단 없음 → **통과**
