# OV161-001 — 삭제·이동된 프로젝트 폴더의 비차단 처리

- 기준일: 2026-11-26, 실행: Claude Code local 세션(Windows 11 Pro 10.0.26300)
- 진입: 유지관리자 보고. 직접 지운 프로젝트 폴더 때문에 JLPT 세션의 지식 기록 3건 실패
- 원칙: Hive는 감독관이 아닌 도구. 항목 하나의 삭제·손상으로 인한 관계없는 작업 차단 금지
- 판정: 구현·단위 시험 통과. 공개 시험·이 PC 확인은 OV161-006

## 증상

- 사용자가 등록 프로젝트 `Documentse-fortunes-weave-guide-main`을 직접 삭제
- 다른 프로젝트에서 `hive knowledge remember`·`lint`·`index rebuild` 전부 실패
- 오류: `cannot inspect registered project root <경로>: … (os error 2)`(Windows 파일 없음 오류)

## 원인

- `validate_registry`(`crates/hive-wiki/src/shared.rs`)가 등록된 모든 프로젝트 폴더의 존재를 요구
- 컬렉션 동기화(`synchronize_project_collection_metadata`)와 문서 적재가 폴더 하나의 고정 실패를 전체 실패로 전파

## 수정

- 쓸 수 없는 폴더(삭제·이동·파일로 바뀜·symlink·검사 불가): 열지 않고 건너뜀
- 해당 컬렉션: 자동 분리(`explicitly_detached` 아님), 폴더가 돌아오면 다음 동기화에서 다시 연결
- `projects.yml` 등록 항목 보존
- `collection attach`로 연결한 일반 폴더 컬렉션의 문서 적재, 지식 내보내기도 같은 처리
- 가져오기(import)는 쓸 곳이 없으므로 기존 오류 유지
- 단계 검토 1번 반영: 현재 프로젝트 판별도 같은 사용 가능 판정으로 비교. 링크로 바뀐 등록 폴더의 프로젝트 신원은 링크 대상에 미부여

## 확인

- 실제 `~/.hive` 사본(삭제된 등록 그대로) 재현: 설치된 0.16.0은 remember·lint·index rebuild 실패, 수정본은 remember·retrieve·lint·index rebuild 성공, 컬렉션 `detached`, `projects.yml` 항목 유지
- 회귀 시험: 삭제 폴더 분리·재연결·다른 프로젝트 등록 가능, 파일로 바뀐 폴더, 삭제된 연결 폴더 rebuild
