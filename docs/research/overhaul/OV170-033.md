# OV170-033 — `capability-resolution.yml` 추적 여부 판정

- 기준일: 2026-11-29, 실행 장소: cloud

## 판정: 컴퓨터별 값

- 템플릿 `harness/template/.hive/config/capability-resolution.yml.jinja`의 값은 설정을 실행한 호스트의 읽기 전용 탐지 결과
- 컴퓨터마다 달라지는 값: `host`(설정을 실행한 앱), `host_version`(그 컴퓨터의 설치 버전), `detection`, `external_runtime`(OMX·OMC 설치 여부), `evidence`의 지역 카탈로그 지문
- 고정물 비교: `tests/fixtures/setup/capabilities-codex-omx.json`과 `capabilities-claude-host-native.json`은 같은 프로젝트라도 호스트·외부 런타임·근거 지문 차이

## 옮기기: 미완

계획은 다르면 `.hive/runtime/`으로 옮기고 Git에서 빼라고 함. 이번 변경에서 하지 않은 이유:

- `harness.toml`의 `capability_resolution_file` 값을 렌더러가 정확한 옛 경로로 검증. 경로를 바꾸면 모든 기존 프로젝트의 `harness.toml`과 33개 동결 판 업그레이드 경로가 바뀜
- 갱신 거래(`hive-update`)·설정 엔진·Copier 템플릿·소유권 시험 8곳 이상이 같은 경로를 씀
- Git에서 빼면 협업자가 받은 프로젝트에서 파일 부재. 그때 `hive setup --validate`의 동작을 먼저 결정 필요
