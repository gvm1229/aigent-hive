## 실험실 파일

모든 상대 경로의 기준: `tests/work/hook-inbox-lab/`. Git 제외 확인, 커밋 대상 0개. 다른 컴퓨터로 push되는 파일은 이 근거와 소스 계획·사실뿐. 실험실은 현재 PC에 유지.

## 훅 입출력과 처리 순서

1. `UserPromptSubmit`: 표준 입력 JSON의 `cwd`·`session_id`·`hook_event_name`·`prompt` 확인. 공통 `transcript_path`·`permission_mode` 수신 가능, 대화 기록 파일 읽기 없음. 승인된 입력 원문만 인식, 끝 줄바꿈만 제외
2. `authority.json`의 정확한 요청과 작업 SHA-256 대조. 봉투 필드: 버전·작업/실행 ID·역할·제공자·모델·수준·작업 파일/지문·프로젝트·사건 머리·제어 세대·일회 권한·중복 방지 키·결과 위치·세션 ID
3. `inbox/claimed/<request_id>/` 생성으로 원자적 단일 소비권 획득. 같은 파일시스템의 임시 파일→`os.replace`로 대기 봉투 작성. 이미 소비권 존재 시 빈 JSON 반환·추가 호출 없음
4. 입력 훅 반환: `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"OV150-001 queued ..."}}`. Claude에 작업 대기·직접 호출 금지 안내
5. `Stop`: 같은 세션과 `stop_hook_active: false` 필수. 값이 `true`이거나 없으면 빈 JSON 반환, 재진입 호출 0회. 대기 봉투를 소비권 폴더로 원자적 이동, 경쟁자의 재소비 차단
6. 처리기가 공식 로그인 상태 확인 후 아래 명령 실행. 작업 본문은 표준 입력, 최종 응답은 후보 파일. 결과 정상 완료 뒤 최종 파일로 이동·확인증 작성
7. 종료 훅 반환: `{"decision":"block","reason":"OV150-001 host result: ..."}`. 결과 ID·상태·본문·확인증/결과 경로를 Claude의 다음 응답에 전달. `delivered/<request_id>.json`에 반환 내용 보관. 훅 정상 종료 코드 `0`

```text
codex exec -m gpt-6.1-sol -c model_reasoning_effort="low" -c service_tier="priority" -c forced_login_method="chatgpt" --sandbox read-only --skip-git-repo-check --ephemeral -C <lab> -o <candidate> -
```

- 호출 소유자: 실험용 호스트 처리기, Hive 제품 실행 코드 없음
- 작업 제한: 도구 호출·파일 수정 없이 `OV150-001_CODEX_OK` 한 줄 반환
- 환경: 자식 실행에서 API 키 환경 변수 2개 제거, 값 출력·인증 파일 접근 없음. 사용자 전역 설정 변경 없음
- 시간 제한: 작업자 180초, Claude 훅 설정 240초. 취소 또는 만료 시 해당 작업자 프로세스 중지·회수
- 취소: `cancel/<request_id>.json` 파일 생성. 호출 전 취소는 호출 0회, 실행 중 취소는 중지, 반환 직전 재확인으로 늦은 후보 결과 격리
- 오류·확인증 유실: 소비권 유지·자동 재호출 없음. 비정상 종료는 `dispatch-uncertain`, 새 권한 없이 재실행 금지
- 반환 유실: 반환 기록과 실제 Claude 소비는 별도. 반환 기록만 존재하는 경우 전체 왕복 성공 처리 금지
- 일회성 실험의 권한 경계: 동일 사용자의 신뢰한 로컬 파일. 악의적 동시 파일 변조·프로세스 트리 전체 회수·일반 제품의 정확히 한 번 실행 보장은 이번 증명 밖

## 처리기 실측

입력: `evidence/synthetic-submit.json`, `evidence/synthetic-stop.json`. 실제 Claude에서 수집한 사건이 아닌, 공식 형식을 따른 합성 사건. 사건 생성은 합성, Codex 작업자 호출은 실제 구독 로그인 실행.

```powershell
Get-Content -Raw tests/work/hook-inbox-lab/evidence/synthetic-submit.json | python tests/work/hook-inbox-lab/handler.py
Get-Content -Raw tests/work/hook-inbox-lab/evidence/synthetic-stop.json | python tests/work/hook-inbox-lab/handler.py
```

위 명령의 같은 사건 재실행은 재호출 없이 빈 JSON 반환. 최초 실행 기록은 `evidence/handler-smoke-launch.json`·`evidence/handler-stop-output.json`, 재생 기록은 `evidence/replay.json`.

| --- | --- | --- |
| 작업자 | 호출 1회·종료 코드 `0` | Codex·Windows 실측, Claude 사건 발생 증명 제외 |
| 결과 | `results/handler-smoke.txt`: `OV150-001_CODEX_OK` | 실제 모델 최종 응답, 일반 작업 정확성 증명 제외 |
| 확인증 | `receipts/handler-smoke.json`: `completed`, `codex_exit_code: 0` | 작업·실행·세션·지문 결합, 실제 Claude 소비 증명 제외 |
| 지문 | `d720e0a5f5ca31b23eb1dc8f1150f42cefd1266cfd44ed5e688dd0471fedf76a` | 결과 바이트 SHA-256 |
| 재생 | 입력 1회·종료 2회 재생, 추가 호출 `0` | 동일 요청의 소비권·실행 기록 불변, 분산 실행 보장 제외 |

자체 시험: 동시 입력·중복 재생, Stop 재진입, 실행 전 취소, 취소 뒤 늦은 결과 격리, 오류 뒤 재호출 금지, 작업 지문·경로 이탈 거부, 실제 로컬 대기 프로세스의 시간초과·취소 회수. 실제 제공자 작업의 시간초과·취소는 추가 호출 방지를 위해 미실행, 그 범위 성공 주장 없음.

실행 로그의 부수 경고: 기존 Codex 플러그인 `SessionEnd` 제한 보정·로컬 MCP 연결 실패. 이번 작업의 모델 응답·종료 0·결과 확인증에 영향 없음. 기존 연결·전역 설정 수정 및 경고 원인 해결은 이번 범위 밖.

## Claude 첫 입력

조율자가 `tests/work/hook-inbox-lab/`를 작업 폴더로 선택한 새 대화형 Claude Code 데스크톱 세션에서 아래 입력을 한 번 전달. 프로젝트 훅 활성 목록에서 `UserPromptSubmit`·`Stop`과 `handler.py` 경로 확인. 설정 미인식 시 미검증 유지, 전역 설정 수정이나 비대화형 Claude로 대체 금지.

```text
OV150-001 RUN claude-first
Wait for the project Stop hook to return the Codex result. Do not launch Codex yourself. After hook feedback, report the request ID, result marker, receipt status, and result/receipt paths. Do not edit files.
```

성공에 필요한 관측:

- 입력 훅 추가 문맥의 `OV150-001 queued claude-first`, 종료 훅의 `OV150-001 host result:` 반환
- `inbox/claimed/claude-first/envelope.json`의 실제 Claude `session_id`와 `request_id: claude-first`
- `evidence/claude-first-launch.json` 한 개, 해당 실행 로그와 종료 코드 `0`
- `results/claude-first.txt`의 `OV150-001_CODEX_OK`, `receipts/claude-first.json`의 `completed`·작업/실행 ID·결과 SHA-256 일치
- `delivered/claude-first.json`의 종료 훅 반환과 Claude 최종 응답의 요청 ID·표식·확인증 상태·경로 일치
- `stop_hook_active: true` 재진입의 추가 호출 0회, 같은 첫 입력 반복에도 추가 호출 0회

한 번 더 입력해도 이미 소비한 `claude-first` 권한은 재실행 불가. 실패 시 원본 근거·소비권 보존, 정확한 오류를 근거에 추가한 뒤 별도 실험 권한 결정. Claude의 실제 답변 확인 전 OV150-001 체크 금지.
