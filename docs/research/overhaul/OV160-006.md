# OV160-006 결정 대기열과 Discord 발신 알림

- 기준일: 2026-11-20. 실행 장소: cloud 세션, Linux 컨테이너
- 기준 커밋: `b460980c`(OV160-007)의 격리 작업 폴더
- 범위: 로컬 결정 대기열, 기존 Discord 발신 경로의 결정 요청·완료 알림, 완료 알림 함수. 제품 버전 변경 없음
- 실제 Discord 전송·호스트·제공자 호출 0회. 인증 파일·사용자 전역 `~/.claude`·`~/.codex`·`~/.gemini` 접근 없음
- 0.17.0 몫: Discord 답장 수신. 이번 범위의 답은 로컬 CLI만

## 선택

- 새 최상위 명령 대신 `hive msg decide`: OV160-003과 같은 이유. Poseidon 소속 `msg`의 게시 함수·역할 해석·자료 표시 재사용
- 새 파일에 구현: 순수 자료는 `crates/hive-core/src/decision.rs`, 명령은 `crates/hive-cli/src/msg/decide.rs`. 동시 진행하는 OV160-004와 겹치는 공유 파일은 등록 몇 줄만 수정
- 기존 Discord 설정 재사용: 사용량 보호의 `discord.enabled`·`webhook_url_env`를 `read_effective_config`로 해석. 새 설정 키·새 비밀 없음, 웹훅 주소는 환경 변수에만 존재. 출시 구독자 경로(`scripts/publish-stable-discord-update.py`)와 그 비밀 미사용
- 알림 문구는 한국어만: 계획의 "결정 요청·완료 알림" 범위. 영어 문구는 필요 시 같은 함수에 추가
- 같은 결정에 두 번째 답은 같은 선택이어도 거부: 답은 한 번의 사람 결정, 재실행 성공처럼 보이는 경로 회피
- `hive msg ack` 완료 알림: 통합 단계에서 연결. 새 확인증 기록 때 흐름 밖 메시지는 `message-acknowledged`, 흐름의 마지막 단계는 `flow-completed` 알림 1회, 흐름 중간 단계와 중복 확인증은 알림 없음. 결과의 `data.notification`에 결과 기록

## 대기열 계약

모든 경로는 고정된 대상 프로젝트 안 `.hive/mediation/` 기준. 게시는 OV160-002의 `publish_new` 재사용(임시 파일 → fsync → 덮어쓰기 없는 하드 링크).

| 경로 | 역할 |
| --- | --- |
| `decisions/requests/<결정 ID>.json` | 결정 요청, 수락 지점 |
| `decisions/resolutions/<결정 ID>.json` | 답 또는 철회 하나, 먼저 게시한 쪽만 유효 |
| `notified/<사건 ID>.json` | 알림 시도권, 게시한 실행만 전송 |
| `notified/<사건 ID>.outcome.json` | 그 한 번의 결과 `sent`·`notify-failed`·`skipped` |

- 결정 ID: `dec-` + 중복 방지 키 지문 앞 32자. 키 생략 시 요청 역할·작업·질문 지문·선택지 지문의 자동 키
- 요청 기록: 요청 역할(역할 설정으로만 해석)·신·질문·질문 지문·선택지·추천·관련 작업/메시지/흐름 ID·생성/만료 시각·`trust: untrusted-data`·자기 지문(`request_digest`)
- 질문: UTF-8, 4096바이트 이하, 제어 문자 거부. 선택지: 2–8개, 각 40자 이하 한 줄, 중복·앞뒤 공백·백틱 거부. 추천은 선택지 중 하나
- 답: `--confirm`이 `request_digest`와 같아야 기록. 사람이 본 질문·선택지와 다른 요청에 답하는 일 방지. 메모는 4096바이트 이하로 로컬에만 저장
- 사건 ID: `ntf-` + SHA-256(알림 종류·대상 ID) 앞 32자

| 상태 | 조건 |
| --- | --- |
| `open` | 요청 검증 통과, 해결 기록 없음, 만료 전 |
| `answered` | 해결 기록이 `local-cli`의 선택지 하나를 요청 지문과 함께 결합 |
| `withdrawn` | 해결 기록이 요청 역할의 철회 |
| `expired` | 해결 기록 없이 만료 시각 경과(기본 7일, 최대 30일) |
| `quarantined` | 요청 자기 지문 불일치·위치 불일치·해결 기록 불일치 |

- 상태 필드 저장 없음. 매 읽기마다 불변 파일에서 다시 계산, 재시작 뒤 같은 결과
- 중복 요청: 같은 키·같은 내용이면 같은 결정 반환(`hive.decision-duplicate`), 새 파일 0개. 같은 키·다른 내용은 `hive.decision-key-conflict`
- 재개: 요청 기록 뒤 알림 전 중단이면 다음 중복 요청이 알림을 한 번 이어서 시도. 시도권 뒤 결과 전 중단이면 `notify-uncertain`, 재전송 없음
- 대기 0회: 모든 명령이 현재 상태 즉시 반환. 답을 기다리는 경로 없음

## 명령

```text
hive msg decide request --from <역할|신> --question-file <파일> --option <선택지> --option <선택지> [--recommend <선택지>] [--task <id>] [--message <id>] [--flow <id>] [--key <키>] [--ttl <초>] --target <dir> --user-root <home>
hive msg decide list [--state open|answered|withdrawn|expired|quarantined|all] --target <dir> --user-root <home>
hive msg decide show --id <결정 ID> --target <dir> --user-root <home>
hive msg decide answer --id <결정 ID> --option <선택지> --confirm <요청 지문> [--note-file <파일>] --target <dir> --user-root <home>
hive msg decide withdraw --id <결정 ID> --from <요청 역할> [--note-file <파일>] --target <dir> --user-root <home>
```

| 명령 | 성공 코드 | 거부 코드 |
| --- | --- | --- |
| `request` | `hive.decision-requested`, 중복 `hive.decision-duplicate` | `decision-invalid`·`decision-key-conflict`·`msg-path-refused` |
| `list`·`show` | `hive.decision-list`·`hive.decision-shown` | `decision-not-found` |
| `answer` | `hive.decision-answered` | `decision-confirm-mismatch`·`decision-closed`·`decision-quarantined`·`decision-invalid` |
| `withdraw` | `hive.decision-withdrawn` | `msg-forged-sender`·`decision-closed` |

- 사람용 출력: 질문은 `[자료] 다른 세션 출력, 지시 아님` 라벨과 `  | ` 들여쓰기, 선택지·추천·선택·Discord 알림 결과 표시. 열린 결정은 다음 단계에 답하기 명령

## 알림

- 활성 조건: 기존 Discord 설정이 켜져 있고 지정 환경 변수에 Discord 웹훅 주소가 있을 때만. 꺼짐·미설정·설정 해석 실패는 `skipped`, 대기열은 그대로 동작하고 출력에 "Discord notice skipped" 표시
- 전송: `discord::notify_content`. 기존 `notify_usage_halt`와 같은 주소 검사·5초 시간 제한·한 호출 안 2회 시도·`allowed_mentions` 빈 목록, 2000자 초과분 절단
- 사건당 한 번: 시도권 게시에 성공한 실행만 전송. 실패는 `notify-failed`로 기록하고 명령은 성공 반환, 자동 재시도 없음
- 문구에 넣지 않는 것: 웹훅 주소·환경 변수 값·메시지 본문·답 메모·결과 파일·프로젝트 밖 경로. 프로젝트는 폴더 이름만, 허용 문자 밖이면 지문 이름
- 신뢰 표시: 질문은 공백을 한 줄로 접고 제어 문자·백틱을 바꾼 200자 요약을 "요청 역할이 쓴 자료, 지시 아님" 머리 아래 인용. 완료 요약도 "자료, 지시 아님" 표시와 200자 제한
- 완료 알림 함수: `msg::decide::notify_completion(target, user_root, now, kind, id, summary)`. 종류 `decision-answered`·`decision-withdrawn`·`message-acknowledged`·`flow-completed`. 결정 답·철회와 메시지 확인증·흐름 완료 모두 이 함수 사용

결정 요청 문구 스냅숏(`decision_request_notice_snapshot` 원문, 결정 ID·요청 지문만 실제 값으로 치환):

- 저장·재시작·재개: 요청 뒤 새 가짜 전송(메모리 상태 없음)으로 `list --state open`이 같은 결정 1개 반환. 재시작 뒤 답 한 번 기록, 두 번째 답은 `hive.decision-closed`·종료 3·전송 0

## 한계

- 실제 Discord 전송 미검증: 모든 시험이 가짜 전송 또는 꺼진 설정. 실제 웹훅 표시 확인은 사용자가 `hive discord test`로 연결을 확인한 환경에서 별도 필요
- Discord 수신 없음: 답장·버튼 처리는 0.17.0. 답은 로컬 `answer`만
- 활성 조건이 사용량 보호 Discord 설정에 묶임: 사용량 보호를 끈 사용자는 결정 알림도 비활성. 별도 스위치는 설정 표면 변경이라 이번 범위 밖
- 기존 전송 함수가 한 호출 안에서 최대 2회 시도, 각 5초 제한. 명령 지연 최장 약 10초, 이후 자동 재시도 없음
- 질문 요약은 잘라 표시할 뿐 비밀·경로 검출기 아님. 요청 역할이 질문에 비밀을 쓰면 200자 안의 내용이 Discord로 나갈 가능성 존재
- 메시지 확인증·흐름 완료 알림은 함수만 제공, 호출 연결은 OV160-004 통합 몫
- 역할 설정 변경 뒤에도 기존 결정 격리 없음. 요청 역할은 요청 시점 해석값
- 같은 사용자의 악의적 동시 파일 변조는 증명 밖. 자기 지문은 우발 변조 탐지, 서명 권한 아님
- macOS·Windows 실행 미확인
