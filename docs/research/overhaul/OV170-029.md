# OV170-029 — `project.toml`·`project.lock` 형식과 이전

- 기준일: 2026-11-29, 실행 장소: cloud. 브랜치 `feature/overhaul-7-0.17.0-project-sync`
- 요청: 유지관리자 2026-11-29 "새로 갱신한 0.17.0 계획대로 구현". 계획의 "미정" 첫 항목은 전부 0.17.0으로 판정

## 결정

- `.hive/project.toml`: 사람이 고치는 파일. `schema_version`, `[hive] range`, `[sections.<이름>]`마다 옛 설정 파일 경로와 보호 등급. Hive는 처음 한 번만 작성, 이후 재작성 없음
- `.hive/project.lock`: Hive만 쓰는 파일. Hive 버전, 범위, 인증된 프로젝트 기준 장부(`project-base.json`)의 지문, Hive 관리 파일마다 경로·지문
- 스키마: `schemas/project-settings.schema.json`, `schemas/project-lock.schema.json`. 출시 표면 목록에 등록
- 옛 파일 내용의 물리 합치기는 이번 변경에서 제외. 근거:
  - `copier.yml`의 `_answers_file`이 `.hive/setup-answers.yml`. Copier는 이 경로의 YAML 답 파일로 `copier update` 실행. TOML 구역으로 옮기면 Copier 경로 손상
  - 동의 보호 파일(`approved-skills.yml`·`approved-hooks.yml`)과 생성 파일은 0.9.1부터 0.16.1까지 33개 동결 판의 업그레이드 경로가 읽는 위치. 계획도 과거 출시 기준 수정을 제외
  - 그래서 0.17.0의 `project.toml`은 범위를 담고, 옛 파일은 구역 표로 경로·보호 등급만 표시. 동의 보호 파일의 승인 없는 변경 0건
  - 내용 합치기는 [OV170-036](../../plans/active/0.17.0-project-sync.md)으로 분리, 유지관리자 결정 대기

## 이전

- `.hive/`와 기준 장부가 있는 프로젝트에서 `hive project sync`가 없는 파일을 만듦. 범위 기본값은 장부 버전의 `MAJOR.MINOR`
- 쓰기는 임시 파일에 쓴 뒤 이름 바꾸기. 옛 파일은 지우지 않으므로 실패해도 원래 상태 그대로
- 기준 장부가 없는 옛 프로젝트는 건드리지 않고 "한 번 설정 필요"만 알림
