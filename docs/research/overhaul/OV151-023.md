# OV151-023 Discord 순서 보장과 불확실 전송 기록

- 근거: [재검토](stage-4-review-2.md)의 D1·D3, 0.15.0 안내의 개발자 표현
- 정정 대기 목록: `docs/releases/discord-pending-corrections.txt`에 `0.15.0`
- 정식 게시: 목록이 비어 있지 않으면 `send_subscriber_update=true`를 npm 게시 전 단계에서 거부. 안내는 정정 뒤 `recover`로 전송
- recover: 게시 소스의 목록에 있는 이전 버전마다 `stable-discord-correction-<이전 버전>-<이 버전 소스>` 수신 기록 필수. 없으면 종료 3
- 불확실 전송: 수정·삭제·전송 요청 뒤 응답 없음·리디렉션·검증 불가 성공이면 `status: unknown` 수신 기록 작성. 워크플로가 기록을 올려 맹목적 재실행 거부. 429·500 같은 명확한 거부는 기록 없이 재시도 허용
- 0.15.0 안내 마지막 항목: "작업자 자동 실행은 꺼져 있으며 이번 버전에서 켜는 경로 없음. 미리보기와 전달 준비까지만 사용 가능". 1,274자, 승인 지문 갱신
- 시험: Discord 묶음 42개 통과·제외 1. 새 시험 3개: 불확실 전송의 unknown 기록과 비밀 부재, 명확한 거부의 기록 부재, 두 워크플로의 순서 차단
- 한계: 실제 GitHub 환경과 Discord 실행 미검증. unknown 기록도 recover 허용 조건에 포함, 유지관리자의 Discord 확인 필요
