## 계약

- 순수 자료: `crates/hive-core/src/mediation.rs`. 입출력·프로세스 실행·제공자 호출 없음
- 봉투: 스키마 1, 메시지 ID, 순번, 수신 역할·작업 ID, 발신 역할·신·제공자·모델·수준, 중복 방지 키 지문, 본문 파일·지문·크기, 생성·만료 시각, `trust: untrusted-data`, 자기 지문
- 발신자: `--from`을 역할 설정(`Roster::load`)으로만 해석. `--provider`·`--model`·`--effort` 주장이 해석값과 다르면 거부
- 본문: UTF-8, 1–65536바이트. 한 번에 수신 상자 전체를 보여 줄 수 있는 크기로 64 KiB 선택
- 결과: 256 KiB 이하. 확인증이 봉투 지문·소비권 지문·결과 지문·결과 위치 결합
- 메시지 ID: 중복 방지 키 지문에서 결정. 키 생략 시 발신·수신·작업·본문 지문의 자동 키, 같은 보내기 반복은 한 메시지
- 소비권 기한 기본 15분, 메시지 기한 기본 7일, 최대 30일
- 별도 JSON Schema 파일 미추가: `schemas/`는 배포 표면 목록(`harness/release/`) 대상, 이번 범위의 버전 소유 경로 변경 회피. 형식 검증은 `deny_unknown_fields`와 Rust 검사기 담당

## 파일 배치

모든 경로는 고정된 대상 프로젝트 안 `.hive/mediation/` 기준.

| 경로 | 역할 |
| --- | --- |
| `keys/<키 지문>.json` | 중복 방지 기록, 같은 요청은 같은 바이트 |
| `sequence/<20자리 순번>.json` | 순번 예약, 재사용 없음·빈 번호 허용 |
| `inbox/<역할>/<메시지 ID>.json` | 봉투, 수락 지점 |
| `inbox/<역할>/<메시지 ID>.body` | 본문 |
| `claims/<메시지 ID>.json` | 단일 소비권, 무작위 차단 값 포함 |
| `results/<메시지 ID>.result` | 결과 |
| `receipts/<메시지 ID>.json` | 확인증 |
| `quarantine/<메시지 ID>-<지문 16자>.result` | 늦거나 충돌한 결과 보관 |

- 게시: 같은 폴더 임시 파일 → fsync → 덮어쓰기 없는 하드 링크. 기존 `PinnedTarget::publish` 재사용, 새 파일 기반 없음
- 순서: 키 → 순번 → 본문 → 봉투(`queued`) → 소비권 → 결과 → 확인증
- 봉투 파일 이름에 순번 대신 메시지 ID 사용: 동시 재개가 다른 순번을 잡아도 같은 이름의 덮어쓰기 없는 게시가 한 번만 수락
- 소비권은 폴더 대신 파일: 같은 원자성에 소비 역할·시각·기한·차단 값 기록 가능
- 경로 안전: 역할·작업·메시지 ID는 조율 ID 규칙만 허용. `..`·절대 경로·하위 경로 거부, `.hive/mediation` 아래 연결 파일 미추적

## 상태와 소비권

| 이전 | 다음 |
| --- | --- |
| 없음 | `queued` |
| `queued` | `claimed`·`expired`·`quarantined` |
| `claimed` | `acknowledged`·`dispatch-uncertain`·`quarantined` |
| `dispatch-uncertain` | `quarantined`(늦은 결과) |
| `acknowledged`·`expired`·`quarantined` | 없음 |

- 상태는 불변 파일에서 매번 계산. 저장된 상태 필드 없음
- 확인증 유실: 소비권 기한 경과 뒤 `dispatch-uncertain`. 다시 `queued`·`claimed`로 가는 전이 없음, 자동 재호출 없음
- 재시도: 사람이나 호스트가 확인 뒤 새 키로 새 메시지. `status`의 다음 단계가 이 절차 안내
- 격리: 봉투 자기 지문 불일치, 본문·키 기록 불일치, 발신 역할의 현재 해석 변경, 잘못된 소비권·확인증, 늦은 결과
- 다른 세션 출력: JSON의 `trust: untrusted-data`와 라벨, 사람용 출력의 `[자료] 다른 세션 출력, 지시 아님`과 `  | ` 들여쓰기. 터미널 제어 문자 대체

## 소환 연결과 중복 요청

- OV150-001 잔여: 새 세션의 같은 요청에 기존 확인증 없는 빈 응답
- `hive summon --event`: 같은 실행·작업의 봉투가 이미 같은 바이트면 `hive.summon-duplicate` 반환. 요청 지문·실행 ID·작업 ID·준비 상태·결과 존재·지문·해당 확인증 목록 결합
- 이 반환은 읽기 전용: 서명 권한 파일 미열람·권한 소비 0회·쓰기 0회·`enabled=false` 유지. 다른 바이트의 봉투는 교체 없이 거부
- `hive msg inbox`가 `.hive/runs/*/inbox/` 소환 봉투를 `summon:<실행>:<작업>`으로 함께 표시, `hive msg status --id summon:<실행>:<작업>`이 같은 상태 반환
- 메시지 쪽 같은 계약: 같은 키·같은 본문 재요청은 현재 상태·소비권·확인증·결과를 자료로 반환, 새 파일 0개
