## 판정

- Hive는 agy·Antigravity 구독 로그인과 옛 Gemini CLI를 자동 작업자, 하위 에이전트, 위임 대상, 판정자, 반복 실행 대상으로 사용 금지
- 유지: 사람이 직접 쓰는 agy, agy 자체 설정 폴더로의 Skill·지침 투영, `agy --version`·`agy plugin` 설치 관리 명령, agy가 스스로 부르는 사용량 콜백, agy 세션 안의 편집 잠금
- 사람이 Antigravity 모델을 다른 도구에서 쓰려면 Google이 권장하는 API 키 경로를 직접 사용. Hive의 공급자 API 키 취급 없음

## 조사 결과(2026-11-28)

- agy나 Gemini를 모델 작업자로 실행하는 코드는 없음. Hive가 실행하는 agy 명령은 버전 확인과 플러그인 관리뿐
- 하지만 다음 검증 경로가 `gemini`·`antigravity`를 작업자·판정자·위임 대상으로 받아들이고, 지금은 "미검증" 표시로만 닫혀 있음. 표시가 바뀌면 열리는 구조라 약관 사유의 영구 거부로 교체
  - 위임 확인증과 소환 봉투: `HostReceipt::validate`, `SummonEnvelope::validate`, 확인증 스키마
  - 역할 배정: `Roster::validate`, `check_resolved`, `worker_profile_resolved`, 기본 역할 파일의 `[providers.gemini]`
  - 야간 반복: `overnight::Provider::Gemini`와 작업자·비평자 기록
  - 메시지 흐름: `StepProfile::validate`, `--reviewer-provider`, 교차 검토 후보, Gemini 중재 훅
  - 자동 위임과 이어 하기: `run.rs`의 Antigravity 자동 위임, `continuation_adapter`
  - 자동 재호출 훅: Antigravity용 `continue-active-run`·`AfterAgent` 재시도
  - 독립 판정: Host Judge 확인증과 봉투 스키마의 `antigravity`
- 사용자 기존 `roster.toml`에 `[providers.gemini]`가 남아 있어도 나머지 Hive 작업은 멈추지 않게, 그 항목만 쓰지 않고 안내
- 경계 판정: Antigravity 세션의 지식 추출 엔진(`--host antigravity`)과 CodexBar의 Antigravity 사용량 읽기도 제3자 접근 위험으로 보고 제외. agy가 스스로 보내는 사용량 콜백은 유지

## 구현(2026-11-28 local)

- 공통 거부 사유: `crates/hive-core/src/automation_terms.rs`(영어·한국어 문구, `is_terms_restricted`, `refuse_automated`)
- 거부 위치: 위임 확인증·소환 봉투, 역할 배정, 야간 반복 작업자·비평자, 메시지 흐름 단계·교차 검토·중재 훅, Antigravity 자동 위임·이어 하기, 자동 재호출 훅, Host Judge 확인증, 지식 추출 엔진(`disable`·`status`만 허용), CodexBar의 Antigravity 사용량 읽기. 관련 스키마 열거값에서 `gemini`·`antigravity` 제거
- 기존 사용자 `roster.toml`의 `[providers.gemini]`는 불러올 때 버리고 `notices`로 안내, 나머지 역할 배정은 계속 동작. 역할을 gemini로 보내는 설정은 사유와 함께 거부
- 유지: 사람이 읽는 Antigravity용 수동 위임 안내(`dispatch-brief`), 편집 잠금, 파일 정책 훅, agy 사용량 콜백
- 읽기 호환 한계: `gemini` 비평자가 든 옛 야간 반복 기록과 gemini 단계가 든 옛 흐름 기록은 해석 불가. 이 PC에는 해당 기록 없음(OV170-008 미실행)
- 안내 문구: `team-execution` 중재 참고, `04-korean-language` 지침, `usage-guard` 센서 참고와 생성 사본
