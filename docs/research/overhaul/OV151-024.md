## P1 공유 Skill 사본

- 문제: 플러그인이 검증된 PC에서 기존 전체 구성 프로젝트를 갱신하면 플러그인이 제공하는 Skill 사본 삭제, 플러그인 없는 PC는 복원. PC마다 공유 구성이 바뀌는 문제
- 수정: 플러그인 검증 결과는 임시 사본에서 구성 판단에만 사용. 압축 구성(저장된 선택, 또는 새 프로젝트에서 플러그인이 전부 제공)일 때만 플러그인 기록과 사본 삭제. 전체 구성은 모든 Skill을 로컬로 기록
- 시험: 플러그인 있는 PC·없는 PC의 갱신 모두 변경 0개, 두 호스트의 사본 유지, 사용자 수정본 보존. hive-render 90개·project upgrade 55개 통과
- 남은 범위: Claude 압축 구성에서 이식용 `.agents` 사본도 함께 지우는 기존 동작 유지. 공급 기록 의미 변경이 필요해 별도 후속

## P2 분류 오류

- 빈 workspace: `Cargo.toml`의 `[workspace]` 구성원 없음, `package.json`의 빈 `workspaces`는 모노레포 아님
- 문서 우선순위: Python·Rust 등 구체적 코드 종류가 있으면 docs 제외. `package.json`만의 일반 coding은 docs보다 낮은 순위
- 하위 폴더 탐색: `public`·`dist`·`build`·`out`·`site`·`_site`·`static` 제외
- 추정 언어: `CMakeLists.txt`·`build.gradle(.kts)`만으로 정한 언어는 낮은 확신, AGENTS.md 제외. 빌드 도구 사실은 높은 확신 유지
- 고정 30종 입력 정리: `rust-workspace`의 `members=[]`를 `members=["crates/*"]`로 변경. 정답 monorepo 유지, 사례 의도와 입력 일치
- 시험: 감지 단위 시험 8개 통과
