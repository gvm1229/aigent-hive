# OV161-003 — 시작도 못 한 쓰기 기록의 비차단 복구

- 기준일: 2026-11-26, 실행: Claude Code local 세션(Windows 11 Pro 10.0.26300)
- 진입: 유지관리자 보고. 직접 지운 프로젝트 폴더 때문에 JLPT 세션의 지식 기록 3건 실패
- 원칙: Hive는 감독관이 아닌 도구. 항목 하나의 삭제·손상으로 인한 관계없는 작업 차단 금지
- 판정: 구현·단위 시험 통과. 공개 시험·이 PC 확인은 OV161-006

## 증상

- 잠금 대기 시간 초과·동시 수정 확인 실패·Ctrl+C로 실제 쓰기 전에 멈추면 dirty journal이 남아 모든 변경과 조회 차단
- 복구 명령 `hive index rebuild --user-root`도 dirty 상태의 등록 동기화 거부로 실패. 수동으로 `.hive/index/rag-dirty.json` 삭제 외 해결 없음

## 수정

- `crates/hive-wiki/src/lib.rs`: 쓰기 전 단계 실패 시 journal 즉시 정리(`abort_external_on_error`)
- `hive index rebuild --user-root`: dirty면 먼저 복구한 뒤 등록 동기화
- rebuild 복구: 아무 대상도 쓰이지 않은 journal은 디스크의 현재 정본으로 복구
- 단계 검토 4번 반영: 그런 journal은 1분 이상 지난 경우에만 버려진 것으로 판단(잠금 대기 최대 5초). 더 새 journal은 진행 중인 쓰기로 보고 재시도 안내
- 유지한 차단: 일부만 쓰인 write set, 손상된 journal, 다른 세대의 journal

## 확인

- 시험: 새 journal 차단과 1분 지난 쓰이지 않은 삭제 journal 복구, 쓰기 하나와 삭제 대기가 섞인 부분 write set 차단, CLI 중단 시험 갱신

## 공통 확인

- Rust 시험(단계 검토 반영 뒤): `hive-wiki` 215개 통과, `hive-cli` 1068개 통과. 실패 2개(`summon_signed_prepare_writes_once_and_never_launches`·`summon_commit_crash_then_head_advance_does_not_wedge_action`)는 변경 없는 기준 브랜치에서도 같은 실패
