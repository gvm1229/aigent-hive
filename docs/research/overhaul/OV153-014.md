- 요청: [요청 원문](OV153-014-request.md) U1–U8, 진행 중 추가 범위: Codex 기본 측정의 창 형식 거부

## 변경

### 설정 질문(U1–U3, U7)

- `harness/setup/questions.yml`: 사용량 구역에 앱별 질문 틀 4개 추가. 키의 `{host}` 자리를 선택한 앱으로 바꿔 앱 순서대로 한 묶음씩 반복
  1. `usage-host-five-hour-limit-<host>`: 5시간 한도 여부(예/아니요)
  2. `usage-host-guard-<host>`: 예일 때만, 보호할 한도 1 5시간만(A) · 2 주간만(B) · 3 둘 다(C)
  3. `usage-host-five-hour-threshold-<host>`: A·C일 때 5시간 기준(0~99)
  4. `usage-host-weekly-threshold-<host>`: B·C·5시간 한도 없음일 때 주간 기준(0~99)
- 사용량 보호(`enforcement_enabled`)를 켰을 때만 질문. 앱 1개면 1묶음, 3개면 3묶음
- 질문 조건에 `any_of` 추가(`hive-core` `setup::Condition`). 기존 `equals` 조건의 직렬화 결과는 그대로
- `setup_engine/host_windows.rs`: 틀 확장, 답 저장 위치 준비, 5시간 한도 없음 → `guard: weekly` 자동 설정, 보호하지 않는 한도의 기준과 확인 기록 제거
- 대화형 질문·미리보기·`--show`·답 파일 확인 기록·`--describe`가 같은 확장 목록 사용. 저장된 앱이 없는 `--describe`는 `{host}` 틀 그대로 표시
- 제목: OV153-012 형식 `[6/9] Claude Code · 보호할 한도`. 스냅샷 `tests/fixtures/setup/screens/host-guard.ko.txt`·`.en.txt`(80열 이하)
- 안내: `usage-guard` Skill과 `control.md`, `user-setup` Skill의 `questions.md`, 사람용 [설치본 usage guard](../../guides/installed-usage-guard.md)에 같은 질문 순서와 뜻 기록. `aither`는 `usage-guard`로만 연결하므로 변경 없음

### 저장(U4)

- `usage_guard.host_windows.<host>`: `five_hour_limit`, `guard`(`five-hour`·`weekly`·`both`), 보호하는 한도의 `*_stop_remaining_percent`만 저장
- 선택 항목이라 스키마 판 번호 유지. v1·v2 이전 설정의 읽기 호환 유지. 앱 항목이 없으면 단일 `stop_remaining_percent`의 기존 동작(5시간 우선, 없으면 주간)
- 검증: `HostUsageWindows::validate`(5시간 한도 없음은 주간만, 보호하는 한도에만 0~99 기준), JSON 스키마 v1·v2 모두 허용. 선택 해제한 앱의 항목은 보존하되 평가에는 미사용

### 평가(U4·U5)

- `hive-core` `select_guarded_snapshots`·`evaluate_guarded_usage`: 고른 한도만 남기고 각 기준으로 확인. 우선순위 없음, 둘 다면 어느 한쪽이라도 기준 이하일 때 차단
- 0%·초기화 보호도 고른 한도의 측정에만 적용. 고르지 않은 한도의 소진·측정 없음은 차단 사유 아님
- 프로젝트별 기준은 각 한도의 하한을 올림(`max`). 정책 지문에 `guarded_windows` 포함(앱 항목이 있을 때만)
- 측정 없음: `hive.usage-unknown` 유지. `data.missing_windows`와 문구에 빠진 한도 표시, `next_action`에 세션 기록 설정(`hive usage capture --host claude` 등)·세션 해제·동의한 대체 조회·설정 재선택 안내. 이전 설정은 `session, weekly` 표시
- 실행 중 감시(Codex): `MonitorPolicy.guarded_windows`로 시작 전 검사와 같은 평가(`evaluate_host_decision`) 사용. 중단 기록의 기준과 같은 대화 재개 판정도 한도별 기준(`window_threshold`) 사용
- 자동 실행 직전 재확인(`verify_dispatch_preflight`)도 같은 앱별 평가 사용(이전에는 단일 기준으로 다시 판정)
- 표시: `hive setup --scope user --show`의 `usage_windows`(선택한 앱마다)와 `hive usage monitor status`·`--show`의 `actual_monitor_state.usage_windows`(Codex)가 같은 요약(`per-window` 또는 `legacy`) 사용

### 세션 해제 반영(U6)

- 원인: 일반 보호 세션 해제 뒤에도 독립 0% 보호가 측정을 요구하고, 측정 없음 → `usage-unknown` 차단 기록
- 수정: 설치 정책의 일반 보호가 켜진 상태에서 같은 연결이 명시적으로 해제했으면, 측정 없음은 `hive.usage-session-bypassed`(종료 코드 0, 차단 기록 쓰기 없음). 이 경우 `status`의 이전 `usage-unknown` 기록도 차단 판단에서 제외
- 유지: 측정된 0%는 0% 보호를 따로 해제하기 전까지 `hive.usage-quota-exhausted`. 설치 정책 자체가 일반 보호를 끈 경우의 측정 없음 차단도 기존대로
- 결과: 이전 `usage-unknown` 기록이 남지 않으므로 다시 켠 뒤 첫 측정이 직전 기준보다 늘면 초기화 보호가 한 번 `hive.usage-reset` 반환(계약 시험에 반영)

### Codex 기본 측정의 30일 창(추가 범위)

- 관찰(이 PC, codex-cli 0.167.2, 2026-11-19, `account/rateLimits/read`만 읽기 전용 재현, 계정 식별자 미기록): `rateLimits`와 `rateLimitsByLimitId.codex` 동일, `planType: free`, `primary.windowDurationMins: 43200`, `secondary: null`. 그 밖의 키 `credits`·`individualLimit`·`limitName`·`normalModelSlug`·`rateLimitReachedType`·`spendControlReached`
- 원인: 감지기가 300분·10,080분만 허용해 `usage sensor returned unexpected quota windows`로 차단
- 수정: 43,200분 창을 주간 자리의 긴 한도로 해석, 실제 길이는 `window_minutes: 43200`으로 보존. 10,080분과 43,200분이 함께 오거나 다른 길이면 계속 차단
