# 0.11.0 실제 호스트 수용 재개

대상: 기존 미완료 6개 항목. 환경: Windows Codex. 기존 수용 기준·제품 버전·안정판 승인 경계 유지.

## 실행 순서

- 사용자 확인: Hive 정의의 검토·신뢰 완료. 기존 동결 실행 파일·정의를 유지한 새 Codex 작업에서 일반 파일 허용·보호 파일 거부 재시험. 결과 지문과 실제 도구 응답 확인 후 후속 수용 진행
- 추가 절차: 고정 `HO-001–006`의 파일 사례를 같은 요청으로 지침 단독·신뢰된 훅에서 각각 실행. 격리 폴더의 Hive 전용 정의 파일만 잠시 보관 후 원래 바이트 복원, 새 작업끼리 비교
- 실패 조건: 격리 실행 파일의 일시적 부재를 별도로 시험하고 즉시 원위치 복원. 전역 설정·정의별 신뢰 기록·실제 사용자 자료 변경 제외. 실패를 확인한 뒤 같은 경로로 우회·재시도 금지

1. `RFH-002`: 기존 격리 폴더의 정확한 훅 정의 신뢰 확인과 실제 차단 재시험. 독립적인 지식 저장·새 작업 조회는 먼저 검증
2. `HK-003–004`: 실제 호출·파일 지문·고정 사례로 판단. 보호 편집 성공과 미지원 사례의 실패 기록 보존
3. `RFH-003`: Codex 수용 이후 같은 자료로 다른 호스트 확대. 접근 불가 시 정확한 사용자 실행 절차 준비
4. `RB104-004`: 설치된 호스트의 작업 조회·중단 연결부터 확인. 연결 없는 감시기와 추론 중단의 성공 추정 제외
5. `RFR-001`: 위 증거와 전체 검증 확인 후 번호 시험판 절차 진행. 미완료 항목의 임의 제외 금지

## 증거 기준

- 합성 지식과 격리 사용자 루트만 사용. 실제 사용자 지식·전역 설정 변경 제외
- 새 작업의 요청에는 질문·도구·경로만 전달, 정답과 기존 대화 전달 제외
- 실제 앱의 도구 결과와 정본·색인·결과 파일 지문을 함께 확인
- 제품 지문·호스트·버전·운영체제·실행 여부·증명 한계 기록
- 모사 시험·설정 존재·명령 성공을 실제 앱 차단 성공의 대체 근거로 사용 금지

## 연결 조사

### 검사 실행 실패의 보완

- 신뢰된 원래 정의: 일반 파일 허용·보호 파일 거부 확인. 같은 여섯 사례에서 지침 단독은 보호 편집 3건 성공, 훅 적용은 보호 3건 차단·정상 3건 성공
- 실제 검사기 부재 시험: 보호 편집 성공, 모델에 훅 단계 오류 표시 없음. 실행 파일·정의·보호 파일의 원래 바이트 복원
- `PreToolUse` 등록 명령에 실행 실패·빈 출력의 명시적 거부 추가. 부분 출력·원본 오류의 전달 제외, 정상 호스트별 응답 유지
- 적용 범위: 셸 명령이 실행돼 검사기 실패를 처리한 경우. 호스트 미로드·셸 자체 실행 실패·외부 시간 초과까지 차단한다는 주장 제외
- 검증 순서: 생성 명령의 정상·검사기 부재·실패 종료·빈 출력 시험 → 정확한 새 정의 미리 보기 → 사용자 신뢰 갱신 → 같은 실제 실패 조건 재시험
- 등록 기록 이관: 명령 형식 1의 기존 승인 지문 보존, 신규 형식 2와 이전 형식의 명시적 구분. 형식 변경을 완료된 동일 요청으로 처리하는 잘못된 재실행 판정 수정
- 기존 실행 파일 위치의 결합 유지. 다른 위치의 프로그램으로 기존 기록을 임의 인정하는 우회 제외. 새 미리 보기는 기존 위치에서 생성한 뒤 원래 실행 파일로 복원
- 형식 2 실제 재시험: 시작 안내 관찰과 별개로 보호 편집 성공. [실제 실패](../../tests/results/runs/20260919T192807-b64643c8d3ab.md)와 [바깥 셸 비교](../../tests/results/runs/20260919T191241-b78544199943.md) 보존. `cmd`는 거부, PowerShell은 구문 해석 실패 재현; 호스트 내부의 정확한 실패 단계는 미노출
- 형식 3: Windows의 `EncodedCommand`로 바깥 셸의 변수 해석 방지. 인코딩 전 명령을 적용 검토 자료에 함께 제시, 형식 1·2의 승인 지문·위치 결합 보존
- [현재 회귀](../../tests/results/runs/20260919T192041-e2bc1eb319ea.md): Windows 14개 통과. 세 호스트 응답 형식, `cmd`·PowerShell의 정상·실패·빈 출력·부분 출력, 이전 형식 이관·변조 거부 검증. 실제 형식 3 앱 수용은 별도 대기
- 진행 중이던 이전 전체 실행은 수정 중 소스·실행 파일 변경으로 실패. Windows 실행 파일 잠금과 이전 기대값의 실패를 보존하고, 코드 고정 뒤 전체 검증 재실행

- Codex 동봉 CLI의 기본 제어 소켓 조회 실패: Windows 소켓 오류 `10050`. 현재 앱은 `app-server`로 실행 중이나, 이 결과만으로 별도 클라이언트 연결 가능 판정 불가
- [Codex 비동기 훅](https://learn.chatgpt.com/docs/hooks#run-hooks-in-the-background): 다음 안전한 시점의 안내 전달, 진행 중 작업 차단 권한과 구분
- [Codex 작업 중단](https://learn.chatgpt.com/docs/app-server#interrupt-a-turn): 정확한 작업·턴 식별자와 연결된 전송 경로 필요. 성공 응답 뒤 실제 중단 결과의 별도 확인
- 새 서버 시작·앱 재시작·신뢰 우회·프로세스 강제 종료 제외
- 현재 작업 도구에 직접 작업 중단 명령 없음. 작업 이동 도구의 부수적 중단을 감시 기능으로 전용하는 방식 제외
