# 0.11.0 실제 호스트 수용 재개

대상: 기존 미완료 6개 항목. 환경: Windows Codex. 기존 수용 기준·제품 버전·안정판 승인 경계 유지.

## 실행 순서

1. `RFH-002`: 기존 격리 폴더의 정확한 훅 정의 신뢰 확인과 실제 차단 재시험. 독립적인 지식 저장·새 작업 조회는 먼저 검증
2. `HK-003–004`: 실제 호출·파일 지문·고정 사례로 판단. 보호 편집 성공과 미지원 사례의 실패 기록 보존
3. `RFH-003`: Codex 수용 이후 같은 자료로 다른 호스트 확대. 접근 불가 시 정확한 사용자 실행 절차 준비
4. `RB104-004`: 설치된 호스트의 작업 조회·중단 연결부터 확인. 연결 없는 감시기와 추론 중단의 성공 추정 제외
5. `RFR-001`: 위 증거와 전체 검증 확인 후 번호 시험판 절차 진행. 미완료 항목의 임의 제외 금지

## 증거 기준

- 합성 지식과 격리 사용자 루트만 사용. 실제 사용자 지식·전역 설정 변경 제외
- 새 작업의 요청에는 질문·도구·경로만 전달, 정답과 기존 대화 전달 제외
- 실제 앱의 도구 결과와 정본·색인·결과 파일 지문을 함께 확인
- 제품 지문·호스트·버전·운영체제·실행 여부·증명 한계 기록
- 모사 시험·설정 존재·명령 성공을 실제 앱 차단 성공의 대체 근거로 사용 금지

## 연결 조사

- Codex 동봉 CLI의 기본 제어 소켓 조회 실패: Windows 소켓 오류 `10050`. 현재 앱은 `app-server`로 실행 중이나, 이 결과만으로 별도 클라이언트 연결 가능 판정 불가
- [Codex 비동기 훅](https://learn.chatgpt.com/docs/hooks#run-hooks-in-the-background): 다음 안전한 시점의 안내 전달, 진행 중 작업 차단 권한과 구분
- [Codex 작업 중단](https://learn.chatgpt.com/docs/app-server#interrupt-a-turn): 정확한 작업·턴 식별자와 연결된 전송 경로 필요. 성공 응답 뒤 실제 중단 결과의 별도 확인
- 새 서버 시작·앱 재시작·신뢰 우회·프로세스 강제 종료 제외
