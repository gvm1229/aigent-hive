# 첫 갱신 시험의 격리 실수와 복구

## 발생과 원인

- 발생일: 2026-10-24 한국 시각. Windows 11 x64·Codex의 격리 첫 질문 시험 준비 중 사용자 승인 없는 전역 CLI 변경
- 의도: 공개0.13.1 원본에서 시험용 설치 프로그램을 호출해 개발0.14 실행 파일의 질문 연결만 확인
- 실수: PATH 앞에 `npm.exe` 대역만 준비. 공개0.13.1의 `install_with_npm`은 Windows에서 정확히 `npm.cmd`를 찾아 호출하므로 실제 npm으로 진행
- 결과: 실제 전역 `aigent-hive`와 Windows 실행 파일이0.13.2-test.2로 변경. 시험 폴더는 교체되지 않아 옛 부모의 설치 소유자 재검증에서 실패, 새 질문 진입 전 종료
- 책임: 정확한 실행 파일 이름과 설치 대상 경로를 확인하지 않은 시험 구성 오류. 제품의 성공 근거에서 제외
- [준비 기록](../../tests/results/runs/20261023T161731-5a73c6549015.md)·[실패 기록](../../tests/results/runs/20261023T161843-4362096b96db.md). 준비 성공은 설치 대역의 실제 선택이나 격리 성공을 증명하지 않는 구분

## 복구와 확인

1. 이후 시험 중단, 실제 `hive --version`의0.13.2-test.2 확인
2. 기존 npm 설치 위치에서 정확한0.13.1 재설치. 복구 명령의 설치 스크립트 실행 비활성화, 사용자 하네스 갱신 명령 실행 없음
3. 복구된 실행 파일이 공개0.13.1의 SHA256 `e34e5b7486feb6adc52f5b0ca59c01da303a14af2ecd397b1c8e60c9ecab7824`와 일치, `hive --version`의0.13.1 확인
4. `user-setup.yml`, `user-projection.json`, Codex 설치 기록, 감시 설정의 복구 전후 지문 동일. 네 파일의 수정 시각 모두2026-10-22로 이번 시험 이전
5. 감시 저장 버전0.13.1·활성 선택 유지, 감시 전용 실행 파일과 저장 지문 일치. 예약 작업 조회는Ready, 이번 복구의 감시 시작·정지 명령0건

## 증거의 한계

- 사고 전 사용자 루트 전체의 지문 없음. 모든 사용자 자료의 사고 전후 동일성까지 증명하는 전수 검사로 해석 금지
- 네 설정 파일의 수정 시각·복구 전후 지문, 복구된 공개 실행 파일, 감시 저장값·실행 파일에 한정한 확인
- 감시가 실제 실행 중이라는 증명 없음. npm 캐시·로그의 원상 복구나 삭제도 수행하지 않은 범위
- 이 복구는 실수로 바꾼 기존0.13.1 상태의 복원. 새0.14.0 설치·게시 승인으로 전용 금지

## 재발 방지와 다음 시험 조건

- 공개 원본의 실제 실행 파일 해석을 먼저 확인. Windows `npm.cmd` 대역의 정확한 선택을 실행 전에 검증
- 자식 환경에 `NPM_CONFIG_PREFIX`, 사용자/전역 npm 설정 파일, 캐시 경로를 모두 시험 폴더로 고정. 설치 대역 누락 시에도 실제 전역 설치 위치 접근 방지
- 설치 스크립트 실행 비활성화. 같은 환경의 실제 npm `prefix -g` 결과가 시험 폴더인지 사전 대조
- 대역 호출 기록·시험 폴더 변경·실제 전역 실행 파일 지문을 사후 확인. 하나라도 불일치하면 실패와 복구 대상으로 분류
- 위 격리 조건을 먼저 확인한 뒤 첫 질문 시험 재개. 실제 공개0.14 갱신·설정 이전·기한 복구·다른 운영체제 수용은 여전히 별도 미완료 항목
