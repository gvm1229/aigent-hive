# 호스트 정책 훅의 가능성과 설계

- 기준일: 2026-09-18
- 대상: `0.11.0` 정책 훅 설계, 기존 `0.10.4` 변경 계승
- 실행 환경: Windows Codex; 다른 호스트는 설치본 버전·도움말 확인
- 결론: 세 호스트의 실행 전 훅은 활용 가능 후보. 실제 변경 지점의 강제 검사를 보완하는 역할

## 설계 판단

규칙 전달·규칙 이해·행동 준수는 서로 다른 결과. 문서가 대화에 들어갔다는 사실만으로 이후 행동의 준수 보장 불가.

처음부터 설계할 경우의 책임 분리:

| 단계 | 책임 | 성공 근거 |
| --- | --- | --- |
| 짧은 지침 | 목적·작업 선택·예외 설명 | 필요한 현재 규칙의 전달 |
| 호스트 훅 | 도구 호출을 정규화하고 정책 판정 연결 | 해당 이벤트의 로드·허용·거부 관측 |
| 정책 함수 | 구체적 입력과 권한에 대한 결정적 판정 | 고정 자료의 동일 결과와 위반 거부 |
| 변경 경계 | Git 참조·Hive 파일 변경·원격 게시의 최종 검사 | 잘못된 상태의 생성·게시 방지 |

- 지침을 매 도구 호출마다 전부 다시 읽는 구조 제외; 필요한 규칙 ID·요약·현재 지문만 전달
- 임의 자연어를 자동으로 실행 가능한 정책으로 바꾸는 기능 제외
- 모델이 올바른 검사를 선택한다는 가정 축소; 실제 쓰기 함수와 서버에서 검증
- 정책 함수의 제안 입력: 작업 종류·정확한 대상·변경 내용·현재 상태·검증된 권한
- 제안 결과: `allow|deny|unsupported|error`, 규칙 ID·이유·정책 지문·증명 범위
- 승인과 설정은 기존 명시적 동의 계약 재사용. 호출자가 보낸 문자열을 승인 증거로 취급 금지
- 위협 범위: 실수·누락·잘못된 명령의 방지. 로컬 관리자가 훅과 정책을 모두 변경하는 경우까지 완전 통제한다는 주장 제외

## 호스트별 가능성과 한계

| 호스트 | 공식 계약에서 확인한 후보 | 로컬 증거 | 판단 |
| --- | --- | --- | --- |
| Codex | `SessionStart`, `UserPromptSubmit`, `PreToolUse`; 실행 전 `permissionDecision: deny` 또는 종료 `2` | 앱 동봉 CLI `0.155.0-alpha.2.6`, `hooks stable true` | 기능 존재 확인, 이 대화의 실제 훅 로드·거부는 미검증 |
| Claude Code | `SessionStart`, `InstructionsLoaded`, `PreToolUse`; 실행 전 거부 응답 또는 종료 `2` | CLI `2.1.163` 버전·설정 인자 확인 | 문서상 실행 전 강제 가능, 최신 이벤트의 설치 버전별 수용 필요 |
| Antigravity | `PreInvocation`, `PreToolUse`; `decision: deny` | CLI `1.1.18` 버전·도움말 확인 | 공식 후보 확인, CLI·IDE와 버전별 설정 위치·실행 의미 별도 검증 필요 |

### Codex

- 공식 문서의 프로젝트 훅은 신뢰된 설정 계층에서 로드, 새롭거나 변경된 훅 정의는 검토·신뢰 전 건너뜀
- `exec_command`는 `Bash`로 매칭, `apply_patch`와 MCP도 적용 대상 후보. 이미 열린 명령의 `write_stdin`에는 실행 전 훅 재호출 없음
- 일부 도구 경로는 공통 훅 경로에서 제외 가능. 전체 명령 실행의 완전한 통제 경계로 사용 불가
- 시작·문맥 압축 뒤 필요한 규칙 재전달에 적합; 전달과 준수의 별도 평가 필요
- 실제 승인 UI·현재 호스트의 이벤트 연결은 이번 조사에서 변경·실행 없음

근거: [OpenAI 공식 훅 문서](https://learn.chatgpt.com/docs/hooks).

### Claude Code

- `InstructionsLoaded`는 지침의 문맥 로드를 관측하는 비동기 이벤트, 행동을 차단하는 기능 없음
- `PreToolUse`의 명시적 거부와 종료 `2`는 차단 계약. 일반 실패 종료 `1`과 오류를 같은 차단 의미로 해석 금지
- 사후 이벤트의 성공은 이미 발생한 쓰기를 되돌리는 증거가 아닌 진단
- 셸 외 파일 편집·MCP·자식 실행 경로와 훅 미로드·오류·시간 초과의 실제 결과를 별도 시험

근거: [Claude Code 공식 훅 문서](https://code.claude.com/docs/en/hooks).

### Antigravity

- 입력은 `toolCall.name`·`toolCall.args`, 출력은 `decision`과 이유의 호스트 고유 형식
- `deny`는 즉시 차단, `ask`는 기존 허용 설정의 영향 가능. 필수 거부를 질문으로 대체하는 설계 제외
- `PreInvocation`의 일시적 메시지 주입은 규칙 전달용 후보
- 공식 문서만으로 오류·시간 초과의 거부 보장 확정 불가; CLI와 IDE 수용을 별도로 유지

근거: [Antigravity 공식 훅 문서](https://www.antigravity.google/docs/hooks).

## 기존 Hive 구현과의 차이

[현재 훅 계약](../architecture/hook-consent.md)과 `crates/hive-cli/src/main.rs`의 `run_hook` 확인 결과:

- 전용 `HookInput`은 `schema_version`·`event`와 Hive 작업 자료를 요구, 호스트의 원본 입력과 상이
- 현재 `block`은 종료 코드 `3`과 Hive 결과 형식 출력. 호스트의 종료 `2`·거부 JSON과 자동 동치가 아닌 계약
- 자료·승인·이벤트 검증 실패 시 `allow`, `active: false`의 보조 장치 동작
- 배포 훅 템플릿은 설명 자료이며, 생성만으로 호스트가 실제 등록·호출한다는 증명 불가
- 따라서 현재 명령을 그대로 `PreToolUse`에 연결하는 방식 제외; 입력·출력 변환과 호스트별 실제 수용 필요
- 오류 시 허용을 유지하는 기존 보조 훅과 필수 쓰기 경계의 오류 시 거부를 별도 책임으로 설계

## `0.11.0` 구현 순서

1. `HK-001`: 사람이 작성한 정책 목록과 공통 판정 함수. 우선 사례는 이번 브랜치 규칙
2. `HK-002`: 검증된 이벤트마다 얇은 변환기, 소유 범위와 승인된 위치에 한정한 설치·갱신·철회
3. `HK-003`: 실제 호스트에서 정책 지문·설치·로드·허용·거부·미실행 증거 결합
4. `HK-004`: 지침만 사용한 기준선과 비교, 누락·오탐·지연·문맥량 측정

공통 수용 자료:

- 지침 누락·오래된 지침·문맥 압축·하위 디렉터리 진입에도 현재 규칙의 위반 거부
- 도구 이름 별칭·파일 쓰기·셸 스크립트·기존 터미널 입력·MCP·자식 실행의 적용 범위 명시
- 훅 미설치·미신뢰·비활성·파싱 오류·종료 `1/2/3`·시간 초과를 각각 주입
- 잘못된 보호 대상 변경의 성공 0건, 정상 고정 사례의 거부 0건
- 잠금·복구·상태 조회는 유지; 실패 때문에 일반 대화 전체를 막는 동작 제외
- 호스트 훅이 건너뛰어져도 실제 변경 경계의 보호 유지. 없는 강제 경계는 미지원으로 보고
- 정책 적용 기록은 제한된 ID·지문·판정만 보존; 대화 원문·자격 증명·전체 명령 기록 제외
- 성능 기준은 `HK-001`에서 실행 환경과 기준선 측정 후 고정, 효과 확인 전 임의 최적화 제외

상세 완료 항목: [호스트 정책 훅 계획](../plans/active/host-policy-hooks-0.11.0.md). 이 조사로 `HK-*` 구현·실제 호스트 수용을 완료 처리하지 않는 경계.

## 이번 브랜치 수정의 실행 근거

- `refactor/hive-foundations`로 이름 교정, 기존 커밋 보존
- `scripts/branch-policy.py`: 이름·문법·생성·이름 변경·참조·커밋·게시·PR 방향 검사
- Windows Git `2.45.1`의 기본 생성·변경·게시 회귀와 관련 지침·검사 목록 시험 33개 성공
- 실제 소스 저장소의 금지 브랜치 생성 거부, 전후 참조 불변
- GitHub ruleset `23612617`: 허용 목록 밖 이름의 생성·갱신 금지, 우회 대상 없음
- 정규식 규칙 생성은 서버 422 거부; 지원되는 생성·갱신 제한으로 대체 후 성공
- GitHub API의 금지 브랜치 생성 422 거부와 해당 ref 부재 확인. 올바른 이름·중첩 이름은 이름 제한 대상에서 제외
- 기존 `main`·`develop` 규칙의 내용과 우회 목록 보존
- CI 정의는 로컬 커밋에 포함; 원격 브랜치 push·CI 실행은 이번 요청에서 미수행

## 알려진 한계와 미실행 범위

- Git `2.45.1`의 직접 `branch -m`은 참조 훅 우회 가능. 사전 `rename` 도구와 커밋·게시 검사로 보완; 모든 로컬 명령의 무조건 사전 차단 주장 제외
- 첫 시험의 이름 변경 거부 가정 실패와 Windows 임시 자료 정리 오류는 이후 수정·재시험으로 해소, 실패 기록 보존
- 전체 정적 계약 검사의 기존 사용량 보호 Skill 투영 불일치는 이번 소스 도구 변경 밖의 `RF-B02` 정리 대상
- macOS·Linux Git 훅 수용, 세 호스트의 실제 훅 실행, 새 제품 설치·공개 시험은 미실행
- 이번 결과는 소스 Git 정책의 실제 일부 경로와 호스트 공식 계약 조사에 한정, 모든 지침 준수의 보장으로 확대 금지
