## 실행 순서

1. 시험 의도·양언어 출시 설명·현재 수용 근거 검증과 커밋
2. PR #60의 정확한 커밋·필수 검사 확인, develop 통합
3. Release candidate를 develop에서 실행, 다섯 대상·npm 후보·서명/출처 결과 확인
4. 성공한 정확한 후보 실행 ID로 test 채널 게시
5. npm 정확한 버전·test 태그·GitHub prerelease 확인, latest=0.10.3 불변 확인
6. 같은 공개 패키지로 세 운영체제 설치·이전·복구 수용, 레지스트리와 최종 근거 정합화

후보 생성과 실제 게시·공개 수용은 별도 단계. 실패·미실행·필수 수동 조작은 해당 단계에 남기고 성공으로 합산하지 않는 판정.

### 제한된 추가 진단

1. Windows 시험 도구의 이미지 조회 실패에 Win32 오류 번호 추가, 같은 공개 실행 파일로 원인 재현
2. macOS 소스 생성 실패 시 동결 합성 자료의 동일 81개 항목을 원래 보조 프로그램에 한 번 전달, 새 격리 검색 파일만 사용
3. 종료 코드·고정 오류 종류·프로그램 지문만 보존, 원문 입력·표준 오류 원문 제외. 진단 성공도 원래 공개 수용 실패를 바꾸지 않는 판정
4. 원인에 따른 최소 수정·회귀 검사. 시험 도구만 변경하면 공개 제품 바이트 유지; 제품 수정 시 다음 번호 시험판과 영향 범위 재검증

## 최종 판정

- Windows 종료 직전의 조회 경합 재현: 같은 컴퓨터의 자식 40개씩 비교에서 수정 전 오류 2건·수정 후 0건. [실제 비교](../../tests/results/runs/20260920T205130-e7a95052dc21.md)
- 같은 관측 핸들에서 최대 100ms 대기 후 확인된 종료만 건너뛰는 시험 도구 수정. 살아 있는 자식의 조회 실패는 계속 거부, 검증되지 않은 자식 종료 권한 추가 없음
- [최종 공개 수용](../../tests/results/runs/20260920T210047-e5db157f28b6.md): Windows Server 2025 x64·macOS 15.7.9 arm64·Linux x64의 정확한 공개 제품 지문 확인. 검색·원본 보존·복구 통과; Linux 실행 환경은 glibc 호스트 위 musl 실행 파일
- [RFR-001 완료 검사](../../tests/results/runs/20260920T210828-a7f59de22f8d.md): 선행 34개 근거·현재 제품 불변·필수 CI·develop 통합·시험 정의 복원 확인
- 현재 수용 범위 35개 완료. Claude 실제 앱과 15초 상시 감시·진행 중 자동 중단은 기존 승인대로 후속 범위 유지
- macOS 최초 오류는 원인 미확정으로 보존. 두 후속 실행에서 각 첫 생성·전체 재생성 두 번 통과, 오류가 영원히 재발하지 않는다는 보장 제외
- 안정판 main·태그·게시·전역 설치 제외. 현재 수동 해결이 필요한 장애 없음
