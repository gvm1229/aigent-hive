# 사용자 관점의 패치 노트 작성

## 요청과 작업 순서

- 독자: Hive 내부 구조를 모르는 사용자. 개발 경험과 Hive 구현 지식의 구분
- 공통 문서 지침과 update-summary 스킬에 사용자 경험 중심 작성 기준 반영
- 0.11.0 안내의 내부 용어·검사 절차를 실제 사용 이점으로 바꾸고 지원 범위 보존
- 두 언어의 의미 일치·문서 형식·스킬 형식·지식 출처 검사 후 결과 기록

## 판단 기준

- 제목과 첫 설명만으로 업데이트 뒤 더 쉬워지는 일이나 줄어드는 불편 파악 가능
- 예: 오래 사용한 버전에서도 설정과 직접 작성한 지침을 지키며 프로젝트 지침 업데이트
- 지원 범위: 0.9.1 이후 모든 공개 안정판. 번호 시험판·모든 설정 조합·무조건 성공으로 범위 확대 금지
- 내부 검사 수·기준 자료·파일 형식·개발 절차는 개선점 대신 근거 문서에 유지
- 기존 승인된 안내문과 발송 승인 지문은 이번 변경 범위에서 제외

## 반영 결과

- 공통 작성 지침과 update-summary에 독자·표현 전환 예시·지원 범위·최종 독자 관점 점검 기준 반영
- 0.11.0의 한국어·영어 안내를 같은 사용자 경험으로 정리, 내부 구조 정리 항목은 사용자용 개선점에서 제외
- Windows에서 스킬 형식·릴리스 안내 형식·문서 문체·지식 정본과 검색 색인 검사 통과
- 편집·문서 검사 범위의 확인이며 제품 동작 재시험은 이번 문구 변경의 검증 대상에서 제외

## Discord 안내 초안 작업

- 비교 기준: 현재 공개 안정판 0.10.3과 정식 출시 예정 0.11.0, 검증 완료한 공개 시험판 test.7
- 사용자 이점이 있는 변경만 선택, 승인된 0.10.0 안내의 쉬운 문장과 기능별 예시 참고
- 0.11.0 구독자 안내 경로에 발송 전 검토 초안 작성, 문자 수·출처·지원 범위 확인
- 문구 승인·발송과 정식판 출시는 별도 결정

## Discord 검토 초안 결과

- [0.11.0 구독자 안내 초안](../releases/0.11.0.subscriber.ko.md): 현재 초안 1,054자
- 현재 안정판 0.10.3과 예정 버전 0.11.0의 사용자 체감 변경 일곱 가지 정리
- Windows에서 Markdown 링크·문서 문체와 다섯 문서 연결 검사 통과
- 초안 문구 승인·외부 등록·Discord 발송은 아직 수행하지 않은 상태

## 0.11.0 후속 문구 수정 계획

- 사용자 요청: 릴리스 안내·Discord 초안의 실패 기록 제거, 훅을 0.11.0의 대표 기능으로 소개
- 훅 첫 설명: AI의 파일 편집 직전에 자동으로 실행되는 검사. 이전 버전의 지침 안내와 현재의 실제 편집 검사 차이를 쉬운 예시로 설명
- 수정 경로: 소스 작성 지침, 소스 전용 update-summary 스킬, 두 언어 릴리스 안내, Discord 검토 초안
- 제품 코드·호환성 기준·내부 검증 자료 보존. 검증 뒤 공개 test.7의 기존 GitHub Release 설명도 같은 문구로 갱신
- 두 언어 사실 대응, 사용 범위, Discord 2,000자 한도, 문서·스킬 형식과 출처 검사
- 훅의 비중과 작동 설명은 0.11.0 문안에만 반영. 공통 지침·스킬에 훅 전용 규칙 추가 없음

## 후속 수정 결과

- 0.11.0 안내와 Discord 초안의 첫 기능에 훅의 뜻·기존 지침 안내와의 차이·사용 이점 배치
- 사용자용 두 문서에서 검사 실패·재시도 기록 제거, 지원 호스트·선택 설정 등 사용에 필요한 범위 유지
- 실제 실행 결과와 첫 macOS 검사 기록은 내부 [검증 자료](all-public-project-refresh-0.11.0.md)에 보존
- 소스 지침과 update-summary에는 실패 기록의 공개 제외 기준만 반영, 훅 전용 일반 규칙 제외
- 공개 test.7 GitHub Release 설명과 현재 릴리스 안내의 전체 문구 일치 확인, 시험판 상태·대상 소스 유지
- 한국어·영어 사실 대응, Discord 1,054자 한도, 스킬 형식·문서 문체·링크·지식 정본 검사 통과
