# ADR-0026: 공식 CLI 확장점을 통한 작업 전달

- 상태: accepted
- 날짜: 2026-11-12
- 범위: 재정비 OVX-009, 단계 3·6·7의 실행 연결 방식
- 근거: [OVX-008 부록 A](../research/overhaul/OVX-008.md), [Fable 권고 (b)](../research/overhaul/stage-2-review.md), [반영 계획·결과](../research/overhaul/OVX-009.md)

## 배경

- 기존 제안: tmux·psmux·cmux 창에서 제공자 CLI 실행, 키 입력 주입과 화면 회수로 작업 전달·상태 확인
- OVX-008 판정: Anthropic·OpenAI·Google 모두 이 외부 창 제어 방식의 약관 허용 불명확. 계정 제재 위험을 감수할 명시 근거 부족
- 공식 문서 근거: 훅(정해진 사건의 알림), 하위 에이전트, 비대화형 작업 실행, Claude 반복·예약 기능. Codex·Gemini 비대화형의 기존 구독 로그인 사용 근거는 부록 A

## 결정

- Hive와 제공자 CLI의 연결은 공식 문서의 확장점으로 한정
- 제공자 CLI 세션에 키 입력 주입·화면 캡처 금지. tmux·psmux `send-keys`·`capture-pane` 제어와 cmux 경로 제외
- Claude Code: 사람이 직접 앉아 쓰는 대화형 호스트. Claude 자체 훅·하위 에이전트·`/loop`·예약 작업 사용. Claude 비대화형 호출 전면 금지, `claude -p` 금지 유지
- Codex·Gemini: 구독 로그인으로 공식 비대화형 작업자 사용. Codex `codex exec`, Gemini 공식 비대화형 모드. Claude+Codex 먼저 검증, Gemini도 같은 지위의 작업자
- Hive: 파일 수신 상자의 실행 봉투(대상·작업·권한·결과 위치를 적은 파일)와 훅으로 조율. 호스트 소유 처리기가 봉투 검증 후 작업자 CLI 호출, 결과·확인증 반환
- 모델·하위 에이전트 프로세스와 모델 호출 소유권은 호스트에 유지. Hive 자체 모델 호출·제공자 API·자격 증명 요청·읽기·중개 없음
- 훅은 알림·봉투 전달 수단. 알림·현재 경로·대화 내용으로 새 권한 추론 금지. 정확한 대상·일회 권한·확인증·취소·안전한 재점유 검증 유지
- 제공자의 창 제어 서면 확인은 주 작업을 막지 않는 별도 조사. 서면 확인만으로 금지 해제·창 경로 복구 불가, 새 구조 결정 필요

## 영향과 검증

- OVX-005–007 창 실험: 성공 처리 없이 재범위화로 대체 종료, 원래 근거 파일 보존
- 대체 검증: 단계 3 첫 항목에서 `tests/work/` 일회성 프로젝트의 Claude→훅→봉투→`codex exec`→결과 왕복. 사람이 Claude에 한 번 입력, 프로젝트 한정 훅 설정만 허용
- 사용자 전역 `~/.claude`·`~/.codex`·`~/.gemini` 설정·훅·인증 변경 금지
- 단계 6: 메시지 상자와 훅 신호 중심 중재. 단계 7: 호스트 공식 반복·예약과 비대화형 작업자 호출
- 문서상 가능성과 실제 실행 성공 구분. 이번 요청에서 제공자 CLI·모델 실행 없음. 호스트별 실제 동작은 후속 실험 전 미검증
- 출시 권한·기존 활성화 기본값·정확한 확인증과 취소 기준 유지. 이번 요청의 develop 병합·OVX-010 제외

## ADR-0019와의 관계

- [ADR-0019](ADR-0019-hive-native-iterative-execution.md)의 수정·대체 없음. 결정적 조율은 Hive, 모델·프로세스 실행은 호스트라는 소유권 유지
