# ADR-0023: 기존 기능을 유지하는 기반 구조 리팩터링

- 상태: 방향 확정, 구현 계획 검토 중
- 날짜: 2026-09-17
- 요청 범위: 별도 브랜치와 구현 계획
- 목표 제품 버전: `0.11.0`; 첫 공개 시험: `0.11.0-test.1`

## 배경

- 지식·호스트 실행·안전 지침·설치·상태 집계의 넓은 책임과 변경 부담
- 사용자 설치와 프로젝트 생성의 파일 처리 분산
- `hive-update → hive-render` 의존 관계로 인한 공통 처리의 위치 제약
- 현재 계획 집계와 후속 사용량 보호 항목의 범위 불일치

## 결정

- 기존 기능·CLI·기본값 유지, 핵심 지식 흐름부터 단계적으로 개선
- 미출시 `0.10.4` 변경을 기준으로 `0.11.0` 구현; 별도 `0.10.4` 출시 제외
- Windows Codex 실제 수용 우선, 이후 Claude Code·Antigravity 확대
- 코드로 판단 가능한 안전 규칙의 직접 CLI 검사, 지침의 중복 절차 축소
- 사용자·프로젝트 정책과 파일 교체 기능 분리, 두 실제 호출 경로 확인 후 최소 공통 기능 추출
- 기존 Markdown 체크리스트를 유일한 상태 원본으로 유지, 요약만 생성
- Rust·Markdown·파생 SQLite·호스트 소유 모델 실행·외부 파일 보존 원칙 유지
- 소비자 공개 명령·저장 형식·기능 제거, 안정판 게시·실제 설치는 이번 계획 작성 범위에서 제외

## 대안과 선택 이유

| 대안 | 판단 |
| --- | --- |
| 전체 재작성 | 기존 동작과 이관 증거 보존 비용 때문에 제외 |
| 공통 처리를 `hive-update`에 집중 | `hive-render`의 역방향 의존 필요 가능성 때문에 제외 |
| 모든 규칙을 코드로 이동 | 사용자 의도·자연어 승인·설명 품질의 코드 판정 한계 때문에 제외 |
| 새 상태 데이터베이스 도입 | Markdown과 별도 원본의 불일치 위험 때문에 제외 |
| 호스트 공통 계층 선행 구현 | 실제 취소·재개·완료 확인 가능성 검증 뒤 공통 부분 추출로 대체 |

## 권한과 검증

- 현재 브랜치의 목적: 검토 가능한 계획. 구현 성공·실제 호스트 수용을 의미하지 않는 계획 상태
- 제품 파일의 번호 변경은 후속 `RF-B01`에서 수행; 공개된 `0.10.3`에 새 시험판 추가 금지
- 기존 `RB104-*` 작업 보존, 미지원 동작의 완료 추정 제외
- 합격 기준·선행 관계·시험·되돌리기: [총괄 계획](../plans/active/refactor-foundations.md)
- 현재 실행 환경: Windows Codex의 문서·코드 조사. 다른 호스트와 운영체제 제품 수용 미실행

## 2026-09-18 범위 보완

- 브랜치 규칙의 소스 개발 도구·Git 훅·원격 제한 구현 승인
- 세 호스트 훅의 가능성 조사와 `0.11.0` 계획 편입
- 지침 전달과 준수의 구분, 최종 변경 지점의 결정적 검사 우선
- 소스 브랜치 도구는 비출하 범위, 제품 훅 구현·실제 호스트 설치는 후속 수용 단계
- 세 호스트의 실행 전 훅은 공식 지원 후보, 실제 로드·거부 수용은 별도 기준
- 기존 Hive 전용 입력·종료 `3`의 직접 연결 제외, 호스트별 변환과 최종 쓰기 검사의 분리
- 결정 근거: [호스트 정책 훅 조사](../research/host-policy-hooks-2026-09-18.md)
