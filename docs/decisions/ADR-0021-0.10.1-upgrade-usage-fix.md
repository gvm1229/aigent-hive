# ADR-0021: `0.10.1` 갱신·사용량 정책 전이

- 상태: accepted
- 날짜: 2026-09-06
- 기준 stable: `0.10.0`
- 첫 공개 시험: `0.10.1-test.1`

## 문제

- Project upgrade의 current render 선행으로 historical support state의 정상 migration 차단
- Hand-maintained historical registry와 release coverage의 불일치
- Current binary로 만든 fixture의 version 문자열 교체로 실제 predecessor 상태 미검증
- Threshold 변경 뒤 old-policy halt marker 영구 우선과 guard disable 요구

## 결정

- Historical source 인증 뒤 typed state migration, current projection render 순서
- User install과 project upgrade transaction 분리 유지, release compatibility registry·gate 공유
- Declared many-to-one Skill merge만 deduplicate, raw duplicate·undeclared collision 거부
- Effective usage policy digest와 halt marker 결합
- Threshold 변경 직후 same session fresh enforce, guard 활성 유지
- Fresh allow의 exact-byte halt 제거와 fresh limited·unknown의 marker 교체
- 설정·runtime 사이 경쟁의 digest 재검사·bounded retry

## 제외

- User install·project upgrade transaction 단일화
- Stable `0.10.1` 자동 승인
- 실제 DuckSoul `.hive` 수정
- Provider API·provider credential·외부 orchestrator

## 결과

### 2026-09-10 후속 계획

- 기존 결정의 한계: 같은 정책 중단 재사용과 다른 프로세스 표식 차단 유지
- [후속 복구 계획](../plans/active/usage-recovery-0.10.2.md): 모든 Hive 대상의 옛 파일을 같은 위치에서 현재 관측으로 교체·제거. 별도 저장소·영구 옛 파일 보존 제안 폐기
- 상태: 제안 계획 기록, 구현·공개 수용 미완료; 아래 기존 결과는 `0.10.1` 범위

- 새 release의 migration source 선언과 full base·state fixture·실행 coverage 자동 대응
- 새 session이나 disable 없는 threshold 적용
- `0.10.1-test.1` 공개 artifact의 세 운영체제 수용 뒤 stable 별도 결정
