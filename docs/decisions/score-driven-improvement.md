# 점수 기반 작업·하네스 개선 설계 결정

- 기준일: 2026-10-24
- 상태: 최종 구현 계획의 설계 기준; 제품 구현 미착수
- 사용자 정정: Harness²를 최종 목표로 삼는 방향 철회
- 채택 방향: Hive의 실행 통제 + 작업별 점수 평가 + 제한된 하네스 후보 시험 + 독립 검증 + 조건부 경험 재사용
- 구현 정본: [최종 계획](../plans/score-driven-improvement-0.14.0.md)

## 고정 결정

1. 최종 점수0.00–1.00, 소수점 이하 두 자리. 내부 정수 단위0–100과 외부 숫자 표현의 분리
2. 코드·조사·계획·문서의 네 평가표. 세부 기준의 이진 충족 결과로 부분 점수 계산, 평가 중 배점 변경 금지
3. 산출물 수정과 하네스 개선의 별도 상태, 공통 상위 예산·취소·권한·증거·최종 검증
4. 합격선0.90·항목별0.80은 검증 전 초기 제안값. 평가표·평가자 교정이 없는 결과는 참고 상태
5. 필수 조건 실패·판단 불가·오염·만료·변조를 높은 평균으로 상쇄하지 않는 완료 조건
6. 기준 하네스의 후보 유지. 제약 위반 또는 회귀가 있는 후보의 자동 채택 제외
7. 하네스 개선 대상은 승인된 실행 구성의 격리 사본. 승인·검증 기준·보안 경계·서명 신뢰·예산·실사용 설정의 자동 수정 금지
8. 모델·하위 에이전트 실행은 호스트 소유. 공급자 API·자격 증명·Hive의 모델 프로세스 실행 없음
9. 채택·프로젝트 적용·전역 공유·제품 출하의 별도 권한. 기존 유효한 정확 범위 승인의 중복 질문 없음
10. 소스·소비자 저장 경계 유지. 소스 루트의 소비자 .hive 생성 금지, 공통 순수 로직과 별도 저장 어댑터
11. 자동 제어는 기본 비활성. 교정·호스트 수용·범위 승인이 있는 실행에만 활성, 기능 미지원은 해당 경로에 명시
12. 작업 결과의 개선 여부와 하네스의 다른 작업 전이 여부를 별도 검증

## 취사선택

- Hive에서 유지: 대상·지문·역할·승인·예산·복구·독립 검증의 기존 계약
- 점수 논의에서 채택: 고정 배점·항목별 근거·평가표 자체 시험·보조 불확실성·정답 접근 경계
- Harness²에서 참고: 일반/분야 후보 분리, 같은 조건의 시험, 근거 기반 합성, 실행 구성과 적용 경험의 결합
- 그대로 이식하지 않는 항목: 기존 결과를 제외한 선택, 격리·승인 해제, 최종 점수의 개선자 노출, 모든 작업의 고비용 반복, 채택 경험의 무조건 승격

## 범위·버전·기존 작업

- 현재 버전 기준0.14.0과 다음 공개 시험0.14.0-test.1 재사용; 별도 후속 버전 임의 지정 없음
- 기존 CLI 구현15개 항목의 수정·완료율 변경 없음. 활성 계획 편입은 실행 개시 시 소유권 확인 뒤 직렬 처리
- 현재 요청은 계획 작성. 구현·출시·설치 시작 승인으로 확대하지 않는 구분
- 정식 버전 확정 뒤 새 제품 변경은 해당 시점의 사용자 버전 결정 필요
