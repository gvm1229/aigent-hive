### 5. Upgrade·검증·출시

- 새 version의 유지보수자 명시가 없는 개발 요청: 활성 `PLAN.md` product version과 다음 번호 시험판에 귀속
- 현재 활성 범위에서 임의의 미래 version 제안·이전 금지
- Pre-`0.10.0` canonical Markdown·project 설정·collection registry byte 보존
- 기존 SQLite 직접 사실 결과 무회귀
- Graphify disable·손상·build 실패 rollback
- Windows x64·macOS arm64·Linux musl 공개 시험 수용
- Accepted test와 같은 product bytes의 protected `main`·stable publication
- 구현·시험 권한과 별도인 유지보수자 명시 안정판 승인
- Host-neutral Goal·closure gate와 지원 host 한정 선택형 Stop hook: 조사·안전 gate 통과 뒤 조건부 채택
- 기존 `checkpoint-reminder / Stop` neutral allow 유지. Continuation은 별도 `continue-active-run` capability·명시 승인·bounded block gate 필요
- `ralph-loop` canonical Skill을 `verified-workflow`로 rename하고 자연어 continuation의 설명 가능한 complexity routing 대상에 포함
- `adversarial-judge` explicit Skill 추가. Existing `package-review`·Judge package/quorum·Ed25519 trust 재사용, 실제 Judge launch는 active host 소유
- `package-review` → `judge-evidence`; `iterative-execution` protocol은 `verified-workflow`에 병합
- 모든 지원 predecessor의 authenticated retired Skill·host projection은 direct `0.10.0` upgrade에서 제거. Modified·foreign bytes는 삭제 대신 conflict, 성공 activation 금지
- Historical Skill registry는 npm·GitHub에 게시된 모든 stable을 영구 포함. 현재 stable `0.8.0`, `0.9.0–0.9.5`; 향후 stable publication은 current snapshot append와 prior entry 불변 검증 전 차단
- Registry는 lifecycle event의 effective version과 stable compatibility epoch를 기록. Exact no-change stable은 epoch 공유 가능하나 stable-to-epoch coverage entry 필수
- `0.10.0-test.1` 뒤 한국어 product behavior가 추가됐으므로 새 범위는 `0.10.0-test.2` 이상에서 다시 수용

Checklist: [`REL10-001–007`](../plans/active/release-0.10.0.md)
