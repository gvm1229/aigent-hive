# ADR-0013: `0.8.0` 시험 배포 범위

- 상태: accepted
- 날짜: 2026-07-31
- Target: `0.8.0`
- 관련 결정: ADR-0008 verifier-only TUF, ADR-0010 native usage sensor,
  ADR-0012 global onboarding

## 결정

### Distribution identity

- `0.8.0`: 설치·업데이트·onboarding 검증용 product candidate
- npm 시험 배포판: `0.8.0-test.N`; 첫 배포판 `0.8.0-test.1`
- GitHub Release·prerelease·release tag 생성 금지
- npm `0.8.0-test.N`과 `test` dist-tag로만 publication
- npm `latest` 이동과 안정 릴리스 표기 금지
- 실제 안정 릴리스는 사용자 별도 승인 뒤 `0.8.x` exact version으로 수행

`preview` 성숙도 label: 사용 중단. `test` dist-tag: 시험 배포를 기본 install
channel과 분리하는 배포 제어값. `test.N`: immutable npm package version의 시험
반복 번호. 안정 `0.8.0` npm version은 사용자 승인 전 미사용.

### Artifact와 설치

- 명시적으로 선택된 protected branch의 exact candidate commit
- macOS arm64·x86_64, Linux musl x86_64·arm64, Windows MSVC x86_64 native build
- SHA-256과 GitHub artifact attestation
- Candidate archive와 npm-installed native binary byte identity
- Public umbrella `aigent-hive`와 exact `@aigent-hive/*` platform package
- Umbrella tarball에 exact version·digest가 렌더된 `install.sh`·`install.ps1`·
  `install.cmd` 포함
- npm 설치는 `npm install -g aigent-hive@0.8.0-test.1` 또는 `@test`
- curl·PowerShell·CMD bootstrap은 exact umbrella installer를 받은 뒤 npm registry의
  같은 scoped native package tarball을 digest 검증
- Direct path는 Node.js·npm runtime dependency 없음

GitHub Actions artifact 용도: candidate 검증. 일반 사용자 download channel과
GitHub Release asset 생성 대상에서 제외.

### Candidate branch authority

- 사용자 지정 순서: npm 시험 배포 성공 뒤 `develop` → `main` 병합
- Workflow authority: protected `develop` candidate
- Current GitHub ruleset: `main`만 보호, `develop`은 unprotected
- Current blocker: `develop` ruleset 부재
- Silent ruleset mutation 금지
- 사용자 작업: `develop` PR·필수 상태 검사·강제 push 차단 ruleset 적용
- 시험 배포 성공 뒤 exact commit의 `main` PR 병합
- 보호 확인 전 candidate activation·npm publication 중단

### Update discovery와 activation

- Global setup에서 일 1회 자동 확인을 별도 opt-in
- 확인 경로: fixed npm registry metadata endpoint read-only, 설치 0건
- 마지막 성공 확인으로부터 24시간 throttle
- Offline·timeout·malformed response는 성공으로 기록하지 않고 다음 host session 재시도
- 전역 host 지침이 각 session의 첫 Hive 작업 전에 check를 호출
- Bare `hive update`는 즉시 확인하고 새 버전이 있을 때 설치 전 질문
- 수락 뒤 authenticated install owner의 exact-version adapter만 실행
- 거절·EOF·noninteractive 상태는 mutation 0건
- Provider API·credential·host runtime state 접근 금지

기존 offline signed harness update command: explicit option 유지. Bare command의
binary update와 consumer project harness activation: hidden transaction 결합 금지.

### Language-first onboarding

- 초기 setup 첫 질문은 `English|한국어`
- Setup mode와 모든 후속 질문은 선택 언어
- `interface_language=en|ko`가 user config와 global host guidance의 정본
- Codex·Claude Code·Antigravity 전역 marker를 같은 의미로 localized projection
- Reconfiguration은 현재 언어를 보존하며 language 변경 요청 때만 전환

### README

- Root English README와 `docs/readme/README.ko.md`
- 상호 `Languages` 링크
- Root README는 설치·빠른 시작·지원·update·안전 경계 중심으로 축소
- 두 문서에 빈 `QA Contributors` 표
- 추가 언어는 번역 owner와 review evidence가 생긴 뒤 같은 구조로 확장

## Deferred

- npm `latest`와 기본 `npm install -g aigent-hive`
- GitHub normal release
- macOS Developer ID signing·notarization
- Windows Authenticode 또는 Azure Artifact Signing
- External TUF 2-of-3 production authorization
- 실제 Claude Code subscription session qualification

## 결과

- 안정 npm `0.8.0`을 선점하지 않는 `0.8.0-test.N` 설치 시험
- npm과 curl이 같은 native bytes를 사용하는 단일 계보
- Offline 뒤 다음 session 재시도를 갖는 opt-in update 알림
- 사용자 동의 없는 background install 0건
- English·Korean setup과 global harness의 실제 동작 일치
