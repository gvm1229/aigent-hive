# ADR-0017: `0.9.0` 시험·정식 릴리스 범위

- 상태: accepted
- 날짜: 2026-08-01
- Target: `0.9.0`
- 관련 결정: ADR-0006 version lifecycle, ADR-0008 verifier-only TUF,
  ADR-0013 `0.8.0` test distribution, ADR-0018 Notion Wiki backend

## 결정

### Release identity

- Product version `0.9.0`과 package publication version의 분리
- 기본 시험 package `0.9.0-test`, 추가 시험 필요 시에만 `0.9.0-test.N`
- `0.9.0`: 첫 GitHub normal Release와 annotated release tag 대상
- 시험·정식 artifact의 기능·명령·기본값·진단 계약 완전 일치
- Protected `main` final candidate commit을 tag·Release·npm의 단일 identity로 사용
- Remote `develop` candidate는 main 통합 전 qualification 전용
- `0.8.0-test.1|test`와 `0.8.0|latest`의 immutable publication history 보존

### Distribution

- 시험: 독립 GitHub prerelease와 npm `test`; 기존 npm `latest` 변경 0건
- 정식: 시험 수용 뒤 별도 GitHub normal Release와 npm `latest`; 시험과 동시 게시 금지
- GitHub Actions `workflow_dispatch`: test publication workflow의 default-branch 등록 선행,
  registration-only `main` PR은 product artifact·tag·`latest` mutation 제외
- Bare 시험 version 재게시 금지, 추가 수정은 numbered suffix로만 게시
- GitHub: annotated `v0.9.0` tag와 normal Release
- Native: macOS arm64·x86_64, Linux musl arm64·x86_64, Windows MSVC x86_64
- npm: 5개 `@aigent-hive/*` platform package와 `aigent-hive` umbrella
- Direct: `install.sh`, Windows PowerShell 5.1 `install.ps1`, `install.cmd`
- 모든 channel의 native binary byte identity와 SHA-256·GitHub attestation

### Final candidate authority

- `develop` 사전 후보 통과 뒤 `develop → main` PR
- Required CI·review 뒤 protected `main` exact commit 고정
- 같은 main commit에서 final candidate 재빌드
- Final candidate run·branch·SHA·workflow SHA·artifact attestation 재검증 뒤 publication
- Develop artifact를 main publication에 재사용 금지

### Branch policy

- `develop`: 일반 fast-forward direct push 허용, deletion·non-fast-forward 차단만 적용
- `main`: production branch, Pull Request·required checks·deletion·non-fast-forward 차단
- `staging`: 별도 pre-production branch가 필요한 release plan에서만 생성,
  생성 시 `main` 수준의 엄격한 ruleset 적용
- 현재 `0.9.0` final-main candidate 계보의 `staging` dependency 0건

### Production trust

- macOS Developer ID signing·notarization evidence 필수
- Windows Authenticode 또는 Azure Artifact Signing evidence 필수
- External TUF production root·targets·snapshot·timestamp threshold authorization 필수
- Private key·certificate·2FA material의 Hive·agent custody 금지
- Protected environment의 human approval 뒤에만 publication mutation 허용

### Compatibility

- `0.8.0 → 0.9.0`: same-major non-breaking upgrade
- Markdown mode canonical Markdown·typed YAML/TOML·사용자 preference·foreign byte 보존
- Notion mode canonical remote content·selected scope·SQLite rebuild receipt 보존
- SQLite·runtime·backup 제외 후 selected backend에서 destination rebuild
- 신규 run의 host-native 기본 owner 적용
- 기존 OMX·OMC 고정 run의 자동 owner 변경 없음
- 공통 소비자 문제 보고: 명시적 preview·collect·export, raw prompt 기본 제외,
  자동 업로드·Markdown knowledge 자동 수집 0건
- 시험·정식 공통 `markdown|notion` backend와 optional Discord guard outbound

### 사용자 승인 범위

- 2026-08-01 요청으로 full `0.9.0` 릴리스 계획과 원격 `develop` push 승인
- Tag·GitHub Release·npm publication의 실행 authority: 모든 `REL9-*` 선행 gate와
  외부 protected approval 충족 뒤 exact `0.9.0`에 한정
- 다른 version·force-push·branch deletion·credential 접근 권한 포함 없음

### `0.9.0` 한정 예외

- 실제 Codex·Antigravity host 수용과 Claude fixture 공개: 유지보수자 요청으로 `REL9-011` 제외. `0.9.0`의 해당 host end-to-end 호환성 주장 없음
- `develop → main` CI: 유지보수자 요청으로 병합 gate 일시 면제. 실패·미실행 CI 결과의 통과 처리 금지, 정확한 범위 공개 유지

## 결과

- Bare 시험·선택형 numbered 시험·정식 채널의 분리된 publication 계약
- 시험판 전용 기능 없이 동일 artifact capability의 선행 수용
- Release identity와 공개 artifact의 protected `main` exact commit 결합
- OS signing·TUF·public install evidence 없는 정식 완료 표시 금지
- `REL9-011` 제외와 CI 병합 gate 면제는 OS signing·TUF·public install·upgrade 보존 증거를 대체하지 않음
