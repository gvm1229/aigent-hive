# ADR-0017: `0.9.0` 시험·정식 릴리스 범위

- 상태: accepted
- 날짜: 2026-08-01, 2026-08-12 최소 정책 개정
- Target: `0.9.x`
- 관련 결정: ADR-0006 version lifecycle, ADR-0008의 release 적용 폐기,
  ADR-0013 `0.8.0` test distribution, ADR-0018 Notion Wiki backend

## 결정

### 최소 배포 신뢰 경계

- 빠르고 반복 가능한 publication 우선
- GitHub·npm 이중 승인 없음. Human approval: protected GitHub stable environment 한 곳
- 필수: protected `main`·exact annotated tag, same-candidate GitHub Release, SHA-256 sidecar,
  GitHub artifact attestation, npm Trusted Publishing OIDC·registry provenance
- macOS: explicit ad-hoc seal과 검증. Publisher identity·notarization 제공 없음 공개
- Windows: unsigned 상태 공개
- Developer ID·notarization, Authenticode·SignPath: optional enhancement, stable gate 아님
- Release TUF·offline threshold signer·external authorization ceremony·platform certificate evidence gate 폐기
- Repository·workflow의 private key·certificate·2FA material 입력 금지

### Release identity

- Product version `0.9.0`과 package publication version의 분리
- 기본 시험 package `0.9.0-test`, 추가 시험 필요 시에만 `0.9.0-test.N`
- `0.9.0`: 첫 GitHub normal Release와 annotated release tag 대상
- 시험·정식 artifact의 기능·명령·기본값·진단 계약 완전 일치
- Protected `main` final candidate commit을 tag·Release·npm의 단일 identity로 사용
- Remote `develop` candidate는 main 통합 전 qualification 전용
- `0.8.0-test.1|test`와 `0.8.0|latest`의 immutable publication history 보존

### `0.9.2` 완료 기능 범위

- 공개 `v0.9.1` exact source: `1e5e7b39c17545f8b997f71cdee39e4cd77d2ef2`
- `0.9.2` 기능 기준: `2cec0377748874748d126b6b55e59975a3f20a02`
- 포함: 설치 product usage guard 단일 정본 전환·non-Hive 경계·CI 보정
- 허용 후속 변경: version·build date·release note·historical base·package와 plugin metadata·시험·게시 계약
- 필수 공개 문서: root·번역 README, 설치 안내, 공개 HTML, npm README, plugin metadata,
  문서 색인·명령·version 예시의 release artifact 동기화
- `0.9.3` 이관: `NAT-002–024`·`MRA-001–032`와 Native orchestration·workflow·custom subagent 구현
- `0.10.0-test` 유지: `N10-002–011`
- Release branch: `codex/release-0.9.2`; 기존 `develop` history rewrite 없음
- `0.9.3` 재개 authority: QA contributor 추가 지시 완료 뒤 유지보수자의 별도 명시적 승인 필요
- 승인 전 Native·custom subagent 구현·검증·출시 mutation `0건`

### 시험판 선행 불변 조건

- 정식판은 탐색·회귀·성능·설치·최종 수용 시험 경로가 아닌 최종 배포 채널
- active plan의 미래 version 후보로 명시한 checklist ID 외 미완료 `0건` 뒤 stable candidate 생성
- exact `develop`의 고유 numbered public test를 GitHub prerelease·npm `test`로 먼저 게시
- 필수 host에서 공개 시험판 clean install·upgrade·rollback·recovery·fresh-session·성능 수용
- 시험판 뒤 제품·package·installer·metadata 변경 시 기존 수용 무효화와 다음 번호 시험판 재수용
- 최신 numbered test 결함 `0건`과 exact source 결합 뒤에만 protected `main` stable candidate 허용

### Distribution

- 시험: 독립 GitHub prerelease와 npm `test`; 기존 npm `latest` 변경 0건
- 정식: 시험 수용 뒤 별도 GitHub normal Release와 npm `latest`; 시험과 동시 게시 금지
- 시험·정식 publication은 하나의 `release-publish.yml`에서 `channel=test|stable` 입력으로 분기. 각 channel은 exact `develop|main` candidate, npm `test|latest`, prerelease·normal Release를 각각 검증
- npm package별 Trusted Publisher는 하나만 연결. 여섯 package 모두 `release-publish.yml`·`release-publication`·GitHub OIDC를 사용하며 게시용 장기 token 경로 없음
- GitHub Actions `workflow_dispatch`: test publication workflow의 default-branch 등록 선행,
  registration-only `main` PR은 product artifact·tag·`latest` mutation 제외
- Bare 시험 version 재게시 금지, 추가 수정은 numbered suffix로만 게시
- GitHub: annotated `v0.9.0` tag와 normal Release
- Native: macOS arm64·x86_64, Linux musl arm64·x86_64, Windows MSVC x86_64
- npm: 5개 `@aigent-hive/*` platform package와 `aigent-hive` umbrella
- Direct: `install.sh`, Windows PowerShell 5.1 `install.ps1`, `install.cmd`
- 모든 channel의 native binary byte identity와 SHA-256·GitHub attestation

### Final candidate authority

- `develop` 사전 후보 통과 뒤 `develop → main` PR
- Required CI·review 뒤 protected `main` exact commit 고정
- 같은 main commit에서 final candidate 재빌드
- Final candidate run·branch·SHA·workflow SHA·artifact attestation 재검증 뒤 publication
- Develop artifact를 main publication에 재사용 금지

### Branch policy

- `develop`: 일반 fast-forward direct push 허용, deletion·non-fast-forward 차단만 적용
- `main`: production branch, Pull Request·required checks·deletion·non-fast-forward 차단
- `staging`: 별도 pre-production branch가 필요한 release plan에서만 생성,
  생성 시 `main` 수준의 엄격한 ruleset 적용
- 현재 `0.9.0` final-main candidate 계보의 `staging` dependency 0건

### Production trust

- Protected `main` exact candidate와 annotated tag
- Candidate build의 SHA-256·GitHub artifact attestation
- Rebuild 없는 GitHub Release·npm package 승격
- npm Trusted Publishing OIDC와 provenance
- Protected environment의 한 번의 human approval 뒤 publication mutation 허용
- Direct installer·update의 transactional backup·atomic activation·failure rollback·crash recovery 유지

### Compatibility

- `0.8.0 → 0.9.0`: same-major non-breaking upgrade
- Product-only 22-Skill catalog, authenticated source Skill retirement, global·project threshold를
  사용하는 single `usage-guard`: numbered 시험판과 stable 공통 gate
- 현재 Codex CLI의 marketplace 등록·plugin 활성화·구조화 상태 검증·global setup을
  numbered 시험판과 stable 공통 출시 gate로 적용
- Windows setup acceptance: maintainer의 실제 Windows 11 clean install·fresh Codex session만
  authority 보유. macOS install·setup 또는 cross-compile 결과의 대체 판정 금지
- Windows `test.13` 수용: maintainer의 새 Codex session 자동 `hive` 탐색·Discord 실제 전달,
  global npm preserving uninstall·재설치·`dry-run → apply → validate`·install validate와 saved preference·knowledge
  digest 보존 포함 완료
- stable 전 내부 qualification: contributor preference·setup Skill 대화 없이 authenticated catalog와
  `hive setup --describe`에서 유도한 product-owned 신속 기본 profile로 disposable user root의
  `install → dry-run → apply → validate → install validate` 자동 실행. user home·수동 schema·`where` 의존 금지
- release test corpus: contract coverage 대장·replacement evidence·named lane을 정본으로 사용.
  추정된 노후 test 삭제 금지. disposable consumer fixture는 `tests/work/` ignore 작업 영역만 사용
- Codex adapter·parser는 공개 구조화 JSON 계약만 사용. 임시 command bridge와
  호스트 전역 설정 수동 쓰기 금지
- Markdown mode canonical Markdown·typed YAML/TOML·사용자 preference·foreign byte 보존
- Notion mode canonical remote content·selected scope·SQLite rebuild receipt 보존
- SQLite·runtime·backup 제외 후 selected backend에서 destination rebuild
- 신규 run의 host-native 기본 owner 적용
- 기존 OMX·OMC 고정 run의 자동 owner 변경 없음
- 공통 소비자 문제 보고: 명시적 preview·collect·export, raw prompt 기본 제외,
  자동 업로드·Markdown knowledge 자동 수집 0건
- 시험·정식 공통 `markdown|notion` backend와 optional Discord guard outbound

### 사용자 승인 범위

- 2026-08-01 요청으로 full `0.9.0` 릴리스 계획과 원격 `develop` push 승인
- Tag·GitHub Release·npm publication의 실행 authority: 모든 `REL9-*` 선행 gate와
  protected stable environment approval 충족 뒤 exact `0.9.0`에 한정
- 다른 version·force-push·branch deletion·credential 접근 권한 포함 없음

### `0.9.0` 한정 예외

- Codex 실제 plugin 활성화·global setup: `REL9-011` 필수 gate로 복원. 격리 Windows
  user root·fresh session·실패 rollback 증거 없는 `0.9.0` 정식 완료 금지
- 실제 Antigravity host 수용과 Claude fixture 공개: 유지보수자 요청에 따른 제외 유지.
  해당 host end-to-end 호환성 주장 없음
- `develop → main` CI: 유지보수자 요청으로 병합 gate 일시 면제. 실패·미실행 CI 결과의 통과 처리 금지, 정확한 범위 공개 유지

## 결과

- Bare 시험·선택형 numbered 시험·정식 채널의 분리된 publication 계약
- 시험판 전용 기능 없이 동일 artifact capability의 선행 수용
- Release identity와 공개 artifact의 protected `main` exact commit 결합
- 최소 trust·same-byte promotion·public install evidence 없는 정식 완료 표시 금지
- Codex 활성화 차단 문제 해결과 numbered 시험판 수용 전 stable publication 금지
- 기본 신속 설정 무인 설치 수용·테스트 coverage 정리 증거 전 stable publication 금지
- Antigravity·Claude 제외와 CI 병합 gate 면제: public install·upgrade·data 보존 증거의 대체 수단 아님
