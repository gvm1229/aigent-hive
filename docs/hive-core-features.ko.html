01

한눈에 보기

Hive의 역할: 서로 다른 agent host에 흩어진 설정·지식·작업 상태를 하나의 검증 가능한 로컬 계약으로 연결

3개하나의 설정으로 연결하는 host
0개요청하거나 저장하는 provider API key
Markdown지식·계획·상태의 사람이 읽는 정본
Local외부 model runtime을 대체하지 않는 제어 계층

핵심 가치: 새 대화에서도 다시 설명할 내용을 줄이고, project별 규칙과 사용자 전역 선호를 섞지 않으며, 모든 변경에 소유권·미리 보기·검증 경계 적용

02

핵심 기능

ONE SETUP

Host 공통 설정

언어, Wiki, persona, Skill, update 선호를 사용자 범위에서 한 번 관리하고 각 host에는 얇은 projection만 제공

CLEAR SCOPE

전역·project 분리

사용자 전역 선호와 repository별 규칙을 별도 승인·소유권 경계로 분리해 홈 폴더 오염과 범위 혼동 방지

DURABLE WIKI

지속 가능한 지식

재사용 지식을 Markdown 정본으로 보존하고, 검색용 SQLite는 언제든 같은 원문에서 재생성

SKILL ROUTING

필요한 Skill만 선택

요청 의미에 맞는 최소 Hive workflow를 자동 선택하고, 선택형 third-party Skill은 명시적 승인 뒤에만 활성화

CONTINUITY

계획·role·run 상태 유지

작업 계획, 역할, 실행 상태와 검증 증거를 사람이 검토 가능한 파일로 남겨 새 session에서도 이어서 작업

USAGE SAFETY

자동 실행 사용량 보호

새 automatic dispatch 직전에 session 사용량과 설정된 중지선을 확인하고, 제한 도달 시 다음 실행 차단

SAFE CHANGE

안전한 설치·update

Hive 소유 경로만 대상으로 dry-run, exact write preview, digest, backup, atomic activation과 recovery 적용

OPTIONAL SIGNAL

선택형 Discord 알림

사용량 중단·재개 정보처럼 안전하게 요약된 상태만 전송하고 webhook 값과 confidential data는 메시지에서 제외

03

안전 경계

Hive가 소유하는 것

  • Hive marker block과 manifest에 등록된 파일
  • Provider-neutral Skill과 host projection
  • Markdown·YAML·TOML 정본 상태
  • 정본에서 재생성 가능한 SQLite 색인
  • 검증된 설치·update 소유권 receipt

Hive가 소유하지 않는 것

  • Model-provider 자격 증명과 host session
  • Provider의 model runtime과 API 호출
  • 사용자·third-party가 작성한 foreign guidance
  • 명시적 승인 없는 선택형 third-party Skill
  • OMX·OMC와 다른 도구의 runtime state
