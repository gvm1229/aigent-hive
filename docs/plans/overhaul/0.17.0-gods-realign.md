## 제외

- Hive는 Aphrodite 추천 Skill 묶음의 본문을 제품에 넣어 재배포 제외. 사용자가 설정에서 고르면 각 원본 저장소에서 그대로 설치하고 고정 commit으로 추적. 이유: 원본 문구를 그대로 쓰면서도 Hive가 재배포 조건(Apache-2.0의 LICENSE·NOTICE·변경 표시) 부담이 없는 방식. 2026-11-28 확인 라이선스: frontend-design·web-artifacts-builder·impeccable·DESIGN.md는 Apache-2.0, hallmark·shadcn/ui·Tailwind CSS·Magic UI는 MIT, Lucide는 ISC
- 과거 버전 산출물(`harness/project-bases/<old>`, `harness/user-bases/<old>`, `harness/release/<old>`, `historical-*.yml`)은 수정 제외
- 사용자 전역 Skill 폴더(`~/.claude/skills` 등)는 대상 아님

## 현재 구조 (2026-11-28 확인)

- 정본 표: `harness/gods.toml`. 역할마다 `name, korean, purpose_*, summary_*, ownership_ko, role, aliases, commands, skills, steps` 보유
- 생성기: `python scripts/generate-gods.py` (`--check`로 생성물 불일치 검사). 생성물은 `crates/hive-core/src/gods_generated.rs`, 각 역할 진입 `SKILL.md`·`agents/openai.yaml`, `docs/architecture/god-ownership.md`, `docs/skills.md`, `harness/template/.hive/config/active-skills.yml.jinja`.
- 손으로 관리하는 목록: `crates/hive-core/src/gods.rs`(표시 문구 시험), `crates/hive-cli/src/gods.rs`(별칭 명령 시험), `crates/hive-projection/src/lib.rs`(역할별 `include_bytes!`와 이름 목록), `crates/hive-render/src/lib.rs`(이름 목록 여러 곳), `copier.yml`, `harness/project-setup/skill-suites.yml`, `harness/user-setup/catalog.yml`, `harness/skills/catalog.yml`, `schemas/setup-answers.schema.json`·`schemas/user-setup*.schema.json`, `tests/conformance/contracts/test_hive_skills.py`·`test_skill_inventory.py`·`test_static_contracts.py`.
- 명령 소유: apollon `prompt, korean`; demeter `knowledge, source-wiki, index`. 시험 `gods_commands_have_one_owner_from_the_same_table`이 명령별 단일 소유자 확인

- [ ] [OV170-018] 매주 원본 확인 명령 `hive design sync`
  - depends: OV170-017; 장소: local
  - 진입 조사(먼저 수행, 범위 제한): `crates/hive-cli/src/update_discovery.rs`의 하루 한 번 확인 구조(설정 켜기·끄기, 마지막 확인 시각 저장)를 읽고 같은 방식의 재사용 가능 여부 판단. 불가능하면 이 항목 설계 수정 뒤 진행
  - 인터페이스:
    - `hive design sync --check --user-root <dir> [--output json]`: 읽기 전용. 원본마다 `git ls-remote <url> HEAD`로 최신 commit을 얻어 `pinned_commit`과 비교. 바뀐 원본은 `git fetch --depth 1`로 두 commit을 `~/.hive/cache/design/<name>`에 받아 `path` 아래 차이만 요약. 결과: 원본별 `unchanged|changed|skipped(이유)`와 다시 정리할 충돌 후보.
    - `hive design sync --apply --user-root <dir> --name <name>...`: 미리 보기를 본 사용자가 고른 원본만 `pinned_commit`·`last_checked` 갱신. `DESIGN.md` 결정 갱신은 Skill이 사용자 확인 뒤 별도 수행
  - 주기: 사용자 설정 `design_sync: enabled|disabled`(기본 disabled, user-setup에서 켬). 켜져 있으면 호스트 세션의 첫 Hive 작업에서 마지막 확인이 7일 이상 지났을 때만 `--check` 실행. 확인만 수행, 자동 적용 없음
  - 실패 처리: 원본 하나가 지워졌거나 닿지 않거나 `git`이 없으면 그 원본만 `skipped`로 표시하고 나머지 계속. 네트워크 부재도 다른 Hive 작업 비차단(종료 코드 0, 결과에 이유 표시)
  - 저장 공간: `~/.hive/cache/design`을 Hades의 저장 공간 측정·정리 후보에 포함
  - 확인: 로컬 bare 저장소 두 개로 `unchanged`·`changed`·사라진 저장소(`skipped`) 시험; 네트워크 차단 상태에서 종료 코드 0. 실제 GitHub 저장소 확인은 단계 7의 OV170-009.
