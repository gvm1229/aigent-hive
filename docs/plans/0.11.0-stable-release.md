1. **마지막 기준 확인** — 계획 57/57 완료, `develop` CI·브랜치 정책 통과, 공개 `test.9` 소스·npm·GitHub 태그·세 운영체제 수용 재확인. `test.9` 이후 제품 파일 변동이 있으면 게시 중단 후 새 번호 시험
2. **공개 문서 준비** — `docs/public-stable-release.json`, README 두 언어, 설치 안내, 제품 개요, 색인의 현재 안정판을 0.11.0·2026-09-27로 맞춤. 변경점은 0.10.3 대비 사용자 체감 범위로 기술. `check-public-stable-docs.py`·출시 안내·문서·링크·문체 검사 통과
3. **안내문 고정** — 검토된 `docs/releases/0.11.0.subscriber.ko.md`의 실제 바이트 SHA-256을 승인 파일에 기록. 같은 지문을 공식 등록 도구로 게시 환경에 등록하고 Discord 검증 전용 검사 통과. 이 단계는 메시지 발송과 구분
4. **정본 통합** — 문서 준비 커밋을 `develop`에 게시하고 필요한 CI 통과 확인. `develop`을 head, `main`을 base로 하는 PR을 열고 보호 규칙·필수 검사 통과 뒤 병합. `main`의 최종 커밋과 제품 바이트를 재확인
5. **안정판 후보** — `main`에서 Release candidate에 제품/패키지 버전 0.11.0, 날짜 2026-09-27, 승격 시험판 test.9, 수용 실행 36241227506을 지정. 후보 성공, 다섯 네이티브 배포 파일·여섯 npm 파일·무결성·과거 안정판 복구 확인

7. **종료 기록** — 출처 커밋·후보/게시 실행·태그·레지스트리·운영체제 검증 범위를 기록하고 계획·현재 상태·지식 정본 갱신. 로컬/원격 `main`·`develop` 외 브랜치 생성 없음
