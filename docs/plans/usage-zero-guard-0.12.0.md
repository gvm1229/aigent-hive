# 0.12.0 사용량 소진 보호 구현

- 사용자 승인: 기존 범위의 0.12.0 전환·추가 소진 보호 구현·검증, 이정표별 ship
- 목적: 구독 잔여 0%에서 Hive 경유 새 자동 작업 차단. 기본 활성, 일반 보호 해제와 독립
- 제외: 계정 유료 설정 변경·호스트 프로세스 종료·미검증 현재 실행 중단의 성공 주장
- 기존 HCT112-003의 독립 구현 단계. 기존 13개 기준 ID와 실제 호스트 수용 상태 보존

## ZERO120-1: 핵심 판단

- 소유자: 현재 Codex, 선행 조건: 기존 보호의 최신 관측·계정·모음 검증
- 변경: `crates/hive-core/src/usage_guard.rs`의 별도 `evaluate_zero_quota` 함수. 기존 1–99 하한 계약 보존
- 절차: 기존 관측 구조 검증 뒤 전달된 모든 창·모음의 최신성·계정·중복 검증, 하나라도 0이면 차단. 양수 창으로 다른 창의 0 덮기 금지
- 실패: 누락·손상·만료는 불확정 차단. 일반 하한 적용 없이 양수 허용, 0 보호와 별도
- 검증: 핵심 Rust 시험에서 양수 세션·0 주간, 여러 모음, 손상·만료·중복·빈 입력·양수 확인

## ZERO120-2: 현재 대화 제어·집행

- 변경: `crates/hive-cli/src/usage_control.rs`의 `SessionControl`, `parse_session`, `set_session`, `enforce_captured`, `verify_dispatch_preflight`, 상태 출력
- 데이터: 선택적 `zero_quota_guard_disabled`, 누락 기본 false. 기존 기록 호환·정확한 호스트/대화/프로세스 결합·원자적 교체·개정 번호 재사용
- 명령: `enable-zero-quota-guard`, `disable-zero-quota-guard`. 해제에 `--confirm-zero-quota-guard-disable` 필수, 다른 해제 확인으로 대체 금지
- 범위: 현재 대화만 제외, 새 대화 기본 활성. 기존 enable/disable/toggle·초기화 보호 조작은 소진 보호 상태 보존
- 절차: 일반 보호 해제 시에도 소진 보호의 새 관측 검사. 둘 다 명시적 해제일 때만 기존 우회. 실행 허가 직전 관측 만료·제어 변경 재검사
- 검증: 일반 보호 해제·전역 보호 해제에서 0 차단, 별도 제외·재활성, 오래된 제외 결합 무효, 센서 실패 차단과 정상 양수 허용
- 실제 한계: 지원 중단 연결 없는 현재 실행은 멈춤 증명 불가. Hive 검사 밖 호출·이미 시작한 호출의 크레딧 사용 방지 보장 제외

## VERSION120: 버전·검증·안내

- 발견한 연결 보완: `run.rs::publish_usage_history`에서 일반 구독의 두 창을 형식2·`default` 모음으로 정규화, 단일 창의 형식1 바이트 보존. 기존 정렬·지문·계정·중복 검사 재사용
- 재개 진단: 소진 코드를 기존 제한 상태로 분류, 실패·불확정 실행의 허가 금지. 이력 왕복·한 번의 실행 허가·중복 거부·초기화 확인·역순 반례 검증
- 시험 자료: 고정된 과거 초기화 시각을 같은 시험 동안 유지되는 미래 시각으로 대체. 오래된 자료의 허용으로 최신성 검사 완화 금지

- 제품 버전·후보 표면·마이그레이션 표·합성 시험 후보를 0.12.0으로 전환, 실재 이전 안정판 0.11.1 유지
- 과거 0.11.2 실행 보고·계획 경로·기준본 바이트 보존, 새 목표와 이전 증거의 구분
- 변경 영역 Rust·관련 Python 계약 검사부터 실행, 기존 버전 분류 실패 재검증
- 소비자 스킬·안내에 별도 명시적 제외·기본 활성·실행 한계 반영. 설치 자체는 현재 버전 승인 전 제외
- 로컬 검증 뒤 정확한 후보 준비·Linux 검사, 마지막 macOS 순서 보존
