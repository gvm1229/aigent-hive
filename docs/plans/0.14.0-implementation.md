# 0.14.0 대화형 CLI·설정 이력 구현 계획

## 목표와 확정 범위

- 기준일2026-10-23. 사용자의 후속 선택으로 대상0.13.2→0.14.0 변경, 첫 공개 시험0.14.0-test.1
- 공개0.13.1의 수정 없는 실행 파일에서 시작한 `hive update` 과정에 새 설정 질문·답변·적용까지 제공. 다음 버전이나 AI 설정 대화에 의존하지 않는 완료 기준
- 전역 초기 설정·재설정·프로젝트 설정·갱신·제거의 대화형 CLI 제공. 언어 미선택 시 한국어/영어부터 질문, 이후 모든 안내에 선택 언어 적용
- 새 설치의 자동 중단·새 작업 차단 기본 비활성. 기존 사용자 선택은 출처를 구분하고 CLI 질문으로 변경, 무조건 일괄 해제안 교체
- 비대화형 갱신: 기존 선택 보존·새 선택형 기능 비활성·미응답 질문 보류. 제거: 미리보기·확인·감시 종료·사용자 자료 보존만, 전체 자료 삭제 기능 제외
- 2026-10-23 최종 계획의 사용자 구현 승인 수신. 아래 구현·검증·공개 번호 시험 수행, 정식0.14.0 게시·실사용 설치·공지 전송 제외

## 설계 기준

- [조사 근거](../research/interactive-cli-0.14.0.md)·[결정](../decisions/interactive-cli-0.14.0.md). Hermes의 필요한 질문만 표시·설정 이전·상세 결과·복구 방식 참고, 소스 갱신·프로세스 관리 코드의 그대로 복사 제외
- 새 CLI가 질문·기본값·검증·저장을 소유. AI와 터미널은 같은 설정 엔진의 입력 경로. 모델 제공자 호출·API 자격 증명·호스트 모델 설정의 자동 변경 없음
- 설치 소유자npm/직접 설치 유지. 사용자 전역 갱신만으로 등록 프로젝트 전체의 파일 일괄 수정 금지. 실제 사용량 정책은 전역 선택을 즉시 적용하고 프로젝트 투영은 명시한 프로젝트의 갱신 때 반영
- 기존0.13.2의 통신 호환·0~99% 입력·자료 보존 구현은0.14.0에 통합. 기존test.2 근거는 해당 옛 제품만 증명, 새 최종 수용으로 전용 금지
- 데이터 변경 전후를 묶는 기존 설치 transaction과 journal 재사용. 한 질문마다 적용하지 않고 답안 임시 저장→전체 변경 미리보기→확인→적용→검증 순서

## 외부 인터페이스의 최종 형태

| 명령 | 동작 |
| --- | --- |
| `hive setup --scope user` | 터미널의 전역 초기 설정/재설정. 기존 설정 존재 시 변경 항목 선택 |
| `hive setup --target <dir>` | 명시한 프로젝트의 초기 설정/재설정, 전역 언어·선호 상속 |
| 위 명령의 `--resume` | 저장한 답안과 다음 질문 재개, 변경된 입력·권한 재확인 |
| 위 명령의 `--show --output json` | 저장값·유효값·출처·보류 질문의 읽기 전용 결과 |
| 위 명령의 `--describe --section <id> --output json` | 필요한 질문 묶음만 반환. 기존 전체 describe도 호환 유지 |
| `hive update` | 변경점과 새 질문 처리, 보존 갱신과 검증 뒤 요약 |
| `hive update --confirm` | 소프트웨어 갱신 확인만 생략. 실제 터미널이면 설정 질문 유지, 새 기능 동의로 해석 금지 |
| `hive update --output json` | 새 상위 구조화 결과. 비대화형 기본, --confirm 없이 설치 승인 추정 금지 |
| `hive update --non-interactive` | 입력 대기 없음. 기존 선택 보존·보류 결과 제공, 설치 승인 없으면 기존 갱신 승인 오류 유지 |
| `hive uninstall --dry-run` | 제거/보존/감시 종료 대상의 미리보기, 변경 없음 |
| `hive uninstall` | 미리보기 후 기본 거부인 확인 질문, 자료 보존 제거 |
| `hive uninstall --confirm --output json` | 명시한 비대화형 제거. 사용자 자료 보존 동일 |

기존 `--answers|--quick-answers`, `--capabilities`, `--dry-run|--apply|--validate`, 역할 재설정과 기능 질문 명령은 호환 유지. `--interactive`와 `--non-interactive` 동시 지정 거부. JSON 요청은 기본 비대화형, 구버전 인계에 한해서만 검증된 전용 터미널 경로 허용.
