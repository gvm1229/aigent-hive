## 확정 경계

- 시험판은 이전 안정판 호환성 대상 아님. 0.11.0-test.6 호환 예외 등록·기준본 조작·검증 생략 금지
- 기존 안정판 기준본·사용자 코드·정본 지식·외부 파일 보존. Orireki 세 저장소는 읽기만, 현재 전역 안정판0.11.1 유지
- 제품 변경은0.12.0의 다음 공개 시험test.3으로 검증. 안정판 게시·설치·다른 소비자 버전 전환은 별도 승인

## 변경과 검사

1. `crates/hive-render/build.rs`와 프로젝트 기준본 생성에서 CLI와 같은 컴파일 시점 패키지 식별 사용. 제품 번호와 시험 패키지 번호를 구분, 실행 환경 변수로 출처 변경 금지
2. `crates/hive-render/src/lib.rs`의 기준본 JSON에 선택적 `package_version` 추가. 시험판·개발판만 정확한 번호 기록, 기존 안정판·누락 필드의 정본 바이트 호환 유지. 새 필드를 기준본 지문에 포함
3. `crates/hive-cli/src/project_upgrade.rs`의 기준본 읽기·쓰기에서 출처 보존·검증. 현재 정확한 시험판 상태의 자체 검사는 가능, 다른 시험판을 과거 안정판으로 인증·자동 이식하는 경로 금지
4. 기존 `historical_published_project_snapshots`의 과거 시험판 인증 예외를 안정판 이식 허가로 사용하지 않는 방향으로 조정. 보존된 과거 자료는 삭제·변조 없이 실패 진단에만 사용
5. 출처가 없는 옛 상태는 제품 번호만으로 안정판 출처를 단정하지 않는 진단. 정본 안정판 전체 바이트 인증 유지, Orireki의 알려진 시험판 출처는 조사 근거와 별도로 명시
6. 새 시험판 번호 보존·지문 변조 거부·다른 시험판 이식 거부·이전 안정판 정상 이식·외부 바이트 보존 검사. 정확한 공개 바이너리에서도 시험판 출처와 안정판만의 이전 버전 검사 확인

## 완료와 복구

- 구현 기준은 정제한 재현과 Rust/Python 회귀 통과로 완료. 번호 공개 시험의 게시·수용은 QLF112-004에서 별도 기록하며, 이 구현 완료만으로 공개 수용 성공을 표시하지 않는 기준
- Windows의 전체 Rust·정적 검사와 Python 다섯 검사 묶음 통과. 시험판 출처·지문 변조 거부·안정판 갱신 보존을 합성 표본으로 검증, 실제 Orireki 갱신·현재 사용자 설치·호스트 활성화의 증명 제외
- 기존 Orireki 상태의 자동 이식 성공을 이 구현의 완료 조건으로 삼지 않는 기준. 지원되는 안정판 재설정 경로는 별도 검토·승인 후 처리, 기준본만 덮어써 성공시키는 방식 제외
