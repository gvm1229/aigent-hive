## 고정 설계 조건

- 지침 전달 성공을 읽기·이해·준수의 증거로 사용 금지
- 브랜치는 Git 참조와 원격 서버, Hive 소유 파일은 Hive의 쓰기 경계에서 검사
- 호스트 훅은 빠른 설명·거부 연결·유효 정책 전달을 담당, 셸 문자열만으로 모든 명령 효과 판정 금지
- 기존 보조 훅의 오류 시 허용 정책과 새 필수 변경 검사의 오류 시 거부 정책 구분
- 훅 미지원·미로드는 해당 어댑터 미지원으로 표시, 모든 호스트의 공통 기능으로 추정 금지
- 상태·취소·복구의 읽기 경로 유지, 오류 시 일반 대화 전체를 차단하는 설계 제외
- 모델 호출·새 에이전트 실행·전체 대화 저장 없이 정책 ID·지문·결과·제한된 근거만 사용
- 호스트 설정의 정확한 변경 위치·이벤트·명령·지문을 보여 주는 승인과 기존 설정 보존
- 현재 작업: 승인된 제안의 계획 반영. 실제 사용자 전역 호스트 훅 설치는 별도 적용 단계

## 구현 경계와 순서

1. 공통 판정: `allow|deny|unsupported|error`, 규칙 ID·이유·정책 지문. 현재 권한·대상·상태를 명시 입력
2. Codex: 신뢰된 훅 정의·실행 전 JSON 거부·시작 및 압축 후 짧은 규칙 전달
3. Claude Code: 실행 전 JSON 거부 또는 종료 `2`, 지침 로드 관측은 준수 증거와 분리
4. Antigravity: `toolCall` 입력과 `decision: deny` 변환, CLI·IDE의 지원 범위 분리
5. 실제 쓰기: Hive 쓰기 함수·Git·원격 게시의 검사, 호스트 훅 누락 시에도 해당 보호 유지

현재 `hive hook`의 Hive 전용 입력·종료 `3`을 호스트 입력·종료 코드에 그대로 연결하는 방식 제외. `HK-002`는 입력·출력 변환과 실제 등록을 함께 검증.

## 승인 제안의 구체적 수용 기준

### HK-001: 실패 분류와 결과 합산

- 규칙 부재·기존 규칙 미준수·준수했지만 해로운 규칙·도구 및 환경 오류·근거 부족을 구분
- 분류마다 확인 근거·확실성·수정 담당 영역 표시. 의미 판단은 검토자가 확정, 근거 없는 원인 자동 단정 제외
- 규칙 부재에는 추가 후보, 미준수에는 강제 경계, 해로운 규칙에는 수정·삭제 검토, 환경 오류에는 도구 복구 연결
- 필수 검사 집합을 작업별로 먼저 확정. 결과는 규칙 ID·작업 ID·정책 지문에 결합, 배열 위치로 연결 금지
- 필수 결과 누락·중복·시간 초과·다른 작업 또는 정책 결과를 전체 성공으로 합산 금지
- 명시적 거부가 있으면 보호 동작 거부. 필수 검사 오류·미지원도 보호 동작의 허가로 사용 금지, 비필수 안내 실패와 구분
- 검사 함수의 부수적 쓰기 제외. 여러 훅의 등록 순서를 보안 검사와 실제 쓰기의 선후 보장으로 사용 금지
- 시험: 결과 순서 교환에도 판정 동일, 누락·중복·거부와 허용 혼합·이전 결과 재사용 시 잘못된 허용 0건

### HK-002: 실제 작동 진단과 전달 비용

- 설정 존재·호스트 로드·이벤트 일치·검사 수행·거부 응답·실제 효과 검증을 별도 상태로 표시
- 각 상태에 호스트·버전·정책·대상 범위와 근거 연결. 관측 없는 상태는 미확인, 설정만으로 보호 활성 표시 금지
- 진단은 실제 적용값과 변경점 중심, 오류는 원인·위치·복구 행동 제공. 기계용 JSON에 설명 문구 혼입 금지
- 고정된 규칙 요약과 동적인 대상·승인·사용량·파일 상태 분리. 시작 시 최소 규칙, 작업 중 관련 규칙만 전달
- 정책 내용 지문 기준의 해석 결과 재사용 허용, 동적 권한·사용량·변경 상태의 오래된 허가 재사용 금지
- 정책 변경·문맥 압축·대상 변경 시 재확인. 실제 호스트의 단계별 효과 검증은 HK-003에서 수행
