# 0.17.0 전역 업데이트만으로 프로젝트 Hive 맞추기

> Plan version: 0.17.0
> Scope: product
> State: 2026-11-29 활성 계획 등록. 유지관리자 토론(수정 금지 세션)에서 정한 범위. 같은 날 cloud 구현(브랜치 `feature/overhaul-7-0.17.0-project-sync`)

진입: 유지관리자 요청·결정(2026-11-29). 프로젝트마다 Hive를 손으로 갱신하지 않고, 전역 Hive만 업데이트하면 Hive가 있는 프로젝트가 따라오게 함. Hive가 없는 협업자도 그대로 쓸 수 있도록 Hive 파일은 프로젝트 안에 실제 파일로 남김

## 결정

- **전역만 업데이트:** 사용자는 전역 Hive만 업데이트. `.hive/`가 있는 프로젝트를 열면, 범위 안 버전일 때 Hive 파일 자동 맞추기. 자동 커밋 없음. 결과는 평범한 Git 변경
- **Hive 없는 프로젝트는 영원히 수동:** `.hive/`가 없는 프로젝트에는 자동 설치·질문·설치 권유 금지. 사용자가 지운 `.hive/`도 재생성 금지. 처음 설정은 사용자가 직접 `project-setup`을 실행할 때만. 이 규칙은 앞으로도 고정
- **실제 파일 유지:** Hive 파일은 지금처럼 프로젝트 안 실제 파일로 Git에 커밋. 심볼릭 링크나 전역 경로 참조로 대체 금지. Hive 없는 협업자는 커밋된 파일을 그대로 사용
- **npm은 생각만 빌림:** 사람이 정하는 범위 파일과 기계가 남기는 영수증 파일을 나누는 방식만 차용. 용어(범위·lock) 겹침 허용. `package.json` 형식·파일 생성 금지
- **새 파일 짝:** `.hive/project.toml`(사람이 고침)과 `.hive/project.lock`(기계만 고침). 둘 다 TOML, `.hive/` 바로 아래, 둘 다 Git 추적. `.hive/.gitignore` 템플릿은 지금 `config/`를 무시하지 않으므로 추적 조건은 이미 충족(2026-11-29 `harness/template/.hive/.gitignore` 확인)
- **안전한 것만 합침:** 아래 표의 범위만 합치고 나머지는 그대로 둠

| 새 파일 | 합쳐 들어갈 옛 파일 | 지금 보호 등급(`harness/manifest.toml`) |
| --- | --- | --- |
| `project.toml` | `.hive/setup-answers.yml` | `hive-managed-config` |
| `project.toml` | `.hive/config/role-seeds.yml`, `.hive/config/knowledge-scope.yml` | `user-answer-protected` |
| `project.toml` | `.hive/config/approved-skills.yml`, `.hive/config/approved-hooks.yml` | `user-consent-protected` |
| `project.toml` | 새 항목: Hive 버전 범위 | 새로 정함 |
| `project.lock` | `.hive/config/project-base.json`, `.hive/config/update-state.json`, `.hive/config/active-skills.yml`, `.hive/config/skill-providers.json`, `.hive/config/project-overrides.json` | `hive-generated-config` |
| 그대로 | `.hive/config/rag-trust.json`(지식 영수증), `.hive/config/harness.toml`(directives가 정본으로 읽음), `.hive/config/capability-resolution.yml`(컴퓨터별 결과 가능성) | 변경 없음 |

- **보호 등급은 구역마다 유지:** 파일이 합쳐져도 `project.toml`의 각 구역(TOML 표)은 옛 파일의 보호 등급 유지. 동의 보호 구역은 지금처럼 사용자 동의 없이 변경 불가

`project.toml` 모양 예시(확정 아님):

```toml
[hive]
range = "0.17"          # 0.17.x 안에서만 자동으로 맞춤

[setup]                 # 옛 setup-answers.yml

[roles]                 # 옛 role-seeds.yml

[knowledge]             # 옛 knowledge-scope.yml

[skills]                # 옛 approved-skills.yml
approved = []

[hooks]                 # 옛 approved-hooks.yml
approved = []
```

## 버전·충돌 규칙

- **범위:** `project.toml`의 `[hive] range`가 자동으로 맞춰도 되는 버전을 정함. 범위 안의 작은 갱신은 자동 적용. 범위를 넘는 큰 갱신은 사람이 범위를 직접 올린 뒤에만
- **앞으로만:** `project.lock`의 기록 버전보다 오래된 전역 Hive는 파일을 다시 쓰지 않고 경고만. 팀원끼리 버전이 달라 서로 되돌리는 일 방지
- **범위 밖 전역 Hive:** 자동으로 맞추지 않고 경고만
- **lock 충돌:** Git 충돌이 난 `project.lock`은 손으로 고치지 않고 실제 파일에서 다시 계산
- **파일과 lock은 같은 커밋:** 바뀐 Hive 파일과 `project.lock`은 항상 함께 바뀜. 한쪽만 커밋된 상태는 검사에서 실패로 표시
- **사용자 수정 보존:** 지금의 인증된 기준 3자 비교를 그대로 사용. 사용자가 고치지 않은 Hive 파일만 자동으로 바꾸고, 고친 부분은 보존
- **검사 전용 모드:** CI용으로 파일이 `project.lock`과 같은지만 검사하고 쓰지 않는 명령
