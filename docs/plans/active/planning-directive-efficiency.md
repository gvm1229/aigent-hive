## 구현자가 따를 순서

1. `.agents/directives/04-documentation-state.md`에 계획 작성 시 전용 계약 연결. `references/planning-contract.md`에 목표·범위·파일/함수·설계 결정·순서·자료 형태·오류 처리·검증 명령/판정·복구·중단 조건 양식 작성. 구현자는 설계 변경 대신 근거 있는 차이만 보고
2. `.agents/directives/03-workflow.md`의 작업 복제본·커밋·검증·CI·출시 절차를 해당 조건별 참조로 이동. 기존 본문과 새 참조의 내용 지문 대조. 상위 파일은 적용 조건과 필요한 경계만 유지
3. `04`의 지식 정리·실행 영수증·출시 기준과 `08`의 상세 문체 예시를 별도 참조로 이동. 공통 완료 조건의 정본은 `01` 유지. 링크를 따라 모든 참조를 미리 읽는 동작 금지
4. `AGENTS.md`에 단계별 읽기 규칙과 예산 연결. 현재 단계에 필요한 구절만 읽고, 내용이 그대로면 다시 읽거나 답변에 복제하지 않는 기준. 기존 경로·안전 의미 보존
5. `scripts/check-agent-directives.py`와 소스 전용 읽기 목록으로 시작·계획·코드 편집·문서 변경·출시의 실제 읽기 집합 측정. 참조까지 포함한 크기로 계산하고 전체 규칙 저장량도 별도 표시. 파일 이동을 전체 토큰 절감으로 오인하는 집계 금지
6. 기존 정적 계약 검사의 소유 경로를 새 정본에 맞게 연결. 누락·범위 밖 경로·예산 초과·예외 절차의 무조건 로드에 대한 회귀 검사. 문체 예외는 같은 문구 지문을 가진 위치만 이전

## 확인과 복구

- 문서 링크, 규칙 이동 대조, 계획 상태, 소스 위키, 문체, 관련 정적 계약 검사 통과
- 주요 일반 작업의 지침 읽기량 40% 이상 감소 목표. 수치는 UTF-8 바이트로 보고, 실제 모델 토큰·전체 대기 시간과 구분
- 제품 파일 차이 0건, 새 시험판 발행 없음. 무관한 Rust·배포 검사를 반복하지 않는 범위
- 규칙 누락·상충·깨진 경로 발견 시 해당 부분 수정 후 관련 검사만 재실행. 새 기능이나 공개 승인 경계 변경은 이번 범위 밖
- 기존 훅 미리보기의 원문 지문은 변경 시 무효 표시. 새 활성화 승인 없이 적용 금지
