## Loop engineering 구조

| 계층 | 소유 범위 |
| --- | --- |
| `hive-loop-engineering` | Graph 작성·검증·steering과 host-native dispatch 조합 |
| Host | Model 실행, subagent 생성, goal 유지, 지원되는 hook event 전달 |
| `.hive/runs/<run-id>/` | PLAN·STATUS·graph revision·evidence의 Markdown 정본 |
| 기존 run Skill | `hive-run-checkpoint`, `hive-run-resume`, `hive-role-handoff` |
| Usage gate | Node·retry·steering dispatch 직전 허용 여부 판정 |
| Judge | 실행 주체와 분리된 criterion·edge evidence 검증 |

Graph 기본 흐름:

1. Host capability를 `supported|best-effort|unsupported|unverified`로 정규화
2. Node·edge·acceptance·retry budget·terminal outcome의 DAG 검증
3. 준비된 node를 host-native subagent 또는 현재 host goal로 dispatch
4. Evidence locator와 독립 verification 결과가 edge 조건을 만족할 때만 전이
5. 실패 시 남은 budget 안에서만 retry, 동일 실패 fingerprint 반복 시 조기 차단
6. Steering 변경을 새 graph revision·근거·영향받은 edge와 함께 checkpoint
7. 전체 criterion 충족 시 `complete`, 회복 불가 오류는 `failed`, 외부 조건은 `blocked`

## 통합 Wiki UX

`hive-wiki`: 사용자·프로젝트 knowledge와 source Wiki의 범위만 판별하는 얇은 진입점.
기존 capture·query·maintenance·source-wiki의 정본 구현 재사용.

| 동사 | 계약 |
| --- | --- |
| `add` | 선택 source 또는 agent-reviewed draft 추가, `--quick` 최소 질문 경로 |
| `query` | Keyword·tag·category 결합 검색 |
| `lint` | Metadata·secret·link·current-truth·stale index 검사 |
| `list` | Category·tag·상태별 page 목록 |
| `read` | Page ID와 reciprocal `[[wikilink]]` 확인 |
| `delete` | Backlink·suppression·replacement 검증 뒤 명시적 삭제 |
| `refresh` | Canonical Markdown에서 SQLite 파생 색인 재구축 |

Category taxonomy: `source|entity|concept|comparison|synthesis|question|decision|workflow`.
기존 `kind`와의 versioned mapping, 정렬된 tag·category, `[[page-id]]` link를 색인 계약에
포함. Quick-add도 secret 검사·source provenance·agent review·current-truth gate 필수.
