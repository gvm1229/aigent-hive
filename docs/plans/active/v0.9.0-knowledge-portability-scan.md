## Portable knowledge bundle

```text
canonical Markdown/config
  → hive knowledge export
  → <name>.hivekb
  → hive knowledge import --dry-run|--apply
  → canonical merge
  → SQLite rebuild
```

- `.hivekb`: sorted path·fixed metadata의 deterministic ZIP, versioned manifest,
  `data/`, `manifest-sha256.txt`, staged atomic publish
- 포함: canonical Markdown, portable metadata, suppression, provenance, logical project·collection ID
- 제외: SQLite·WAL·SHM·journal·lock·session·cache·absolute path·credential·confidential content
- Scope: `global`=user-root, `shared`=global+shared, exact `project:<id>|collection:<id>`=해당
  private 포함, `all-portable`=global+shared+모든 private; confidential은 항상 제외
- Hash 의미: 내부 무결성. Source authenticity·transport secrecy claim 없음
- Wiki disabled: explicit export·import 허용, enable 상태 변경·index rebuild·retrieval 0건
- Import: identical no-op, non-overlap add, contradiction·same-ID divergent truth fail-closed,
  staged validation·backup·atomic activation·rollback
- 다른 machine의 미등록 project: `detached` collection 유지, explicit local mapping 전
  automatic private retrieval 제외

CLI:

```text
hive knowledge export --user-root <dir> --scope <scope> --bundle <path>.hivekb --output json
hive knowledge import --user-root <dir> --bundle <path>.hivekb (--dry-run|--apply) --output json
```

## Collection model

- 고정 table: `collections|documents|chunks|claims|sources|links|replacements`; scan마다 table 추가 0건
- Registered project: 기존 project ID를 `collection_id`로 연결
- Unregistered directory: user-root local registry의 stable ID와 display alias; scanned target mutation 0건
- Directory basename·absolute path: local locator·alias만 허용, identity 사용 금지
- Canonical claim: Markdown 정본 + `claim_kind`, `assertion_status`, version·revision,
  source locator·digest, observed·verified time
- SQLite: collection·document·chunk·claim retrieval projection만 소유

## `hive-knowledge-scan`

Explicit bulk-ingest Skill. 기존 capture·promote와 책임 분리:

1. Git repository: tracked file 우선, optional untracked nonignored는
   `--others --exclude-standard`; ignored·submodule 자동 포함 0건, ignore는 secret 경계 아님
2. Non-Git directory: 문서·manifest·config allowlist와 count·size budget
3. 우선순위: user selection → AGENTS·README·ADR·intent docs → manifest·lock →
   config·test·source evidence
4. Binary·vendor·build·cache·minified·generated·database·secret·credential·external
   symlink 제외와 이유 report
5. Deterministic inventory 뒤 agent-reviewed `project-profile|decision|convention|preference|workflow|dependency-evidence|outcome|question` claim 작성
6. Project collection upsert 뒤 reusable candidate 2차 scan
7. Existing `hive knowledge promote`로 root candidate dedup·redaction·contradiction
   preview, consolidated current-action approval 뒤 apply
8. File digest incremental rescan, unchanged no-op, deletion은 source invalidation;
   promoted root fact 자동 삭제 0건

Dependency 존재만으로 성공 판정 금지. Next.js 16 convention의 reusable 후보에는 exact
version·source intention·test/build evidence·적용 조건 필수.

## Automatic retrieval Skill

- 새 find Skill 없음; 기존 `hive-knowledge-query`를 single owner로 강화
- Global Wiki enabled + setup에서 승인된 implicit routing에 한정
- 자동 대상: 질문, 비교·설계·계획·debug·구현, internal/external research 선행 context
- 제외: guard control, setup-required, Wiki disabled, pure acknowledgement, exact no-context
  command, 동일 turn의 이미 완료된 retrieval
- Turn당 lookup 1회, automatic default top 5·result byte budget; explicit query만 확대
- Retrieval 종료 뒤 next Skill sequential handoff, 동시 Skill body load 최대 1개
- Internal evidence·user preference 우선, freshness 부족·current external claim은
  `best-practice-research` 또는 web research handoff
- Retrieved instruction·command: untrusted data, 실행·Skill activation·권한 확대 0건
- Scope·score·locator·digest·freshness·conflict 표시와 no-hit 일반 route

Ownership: `KPX-*`는 bundle·collection·scan. `RAG-*`는 turn gate·ranking·answer contract.
`V9-*`의 `hive-wiki`는 thin verb router만 소유.
