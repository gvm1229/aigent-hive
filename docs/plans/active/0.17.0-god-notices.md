# 0.17.0 신 호출 안내

> Plan version: 0.17.0
> Scope: product
> State: 2026-11-29 활성 계획 등록

진입: 유지관리자 요청(2026-11-29). 세션이 "지식 3개를 기록함"이라고만 말하고, 어떤 지식인지와 어떤 신(Hive 하위 기능)이 일했는지를 밝히지 않음. 사용자는 Hive가 무엇을 바꿨는지 항상 정확히 알아야 함

## 결정

- **안내 모양:** 첫 줄에 신 이름, 하는 일, 개수. 그 아래에 정확한 대상 목록. 마지막 줄에 결과. 신 이름은 고유명사라 영어 그대로, 나머지는 설정 언어

```text
Hades 호출 · 오래된 파일 삭제 2개
- docs/plan/00.md
- docs/plan/02.md
결과: 삭제 2, 건너뜀 0
```

```text
Apollon 호출 · 지식 기록 3개
- [결정] hive/setup: Hive가 없는 프로젝트에는 .hive/를 만들지 않음
- [선호] hive/update: 전역 Hive만 업데이트하면 프로젝트가 따라옴
- [결정] hive/update: .hive/project.toml·.hive/project.lock 형식
결과: 새로 기록 3, 같은 내용 있음 0
```

- **안내는 Hive가 만들고 세션은 그대로 전달:** 세션(모델)이 기억에 의존해 요약하면 빠뜨리거나 바꿔 말할 수 있음. 그래서 Hive CLI의 공용 결과(ActionResult)에 `actor`(신 이름)와 `items`(대상 목록)를 넣고, 사람용 출력이 위 모양을 그림. 세션은 이 안내를 최종 응답에 고치지 않고 옮김
- **신 배정:** 각 CLI 동작이 어느 신의 일인지 `harness/gods.toml`의 Skill 묶음에서 정함. 예: 지식 기록·조회·정리는 Apollon, 저장 공간 정리는 Hades, 설정·업데이트·프로젝트 맞추기는 Eileithyia, 계획 저장은 Athena, 사용량 기준은 Aither. 어느 신에도 속하지 않는 동작은 `Hive 호출`로 표시
- **자동 동작도 안내:** 사용자가 신 이름을 부르지 않은 자동 동작(지식 자동 기록, [OV170-031](0.17.0-project-sync.md) 프로젝트 자동 맞추기 등)도 같은 모양으로 안내. 예: `Eileithyia 호출 · 프로젝트 Hive 0.17.1 → 0.17.2, 파일 4개`
- **결과마다 구분:** 성공·건너뜀·실패를 항목마다 표시하고, 건너뜀과 실패에는 짧은 이유. 바뀐 것이 없으면 한 줄만. 예: `Apollon 호출 · 기록할 새 지식 없음(같은 내용 3개 이미 있음)`
- **긴 목록:** 10개까지 보여 주고 나머지는 `외 N개`와 전체 목록 파일 경로
- **지우기 전에는 미리 보기:** 삭제·덮어쓰기처럼 되돌리기 어려운 일은 먼저 `삭제 예정` 안내로 보여 주고 승인 뒤 `삭제함` 안내. Hades의 기존 미리 보기와 같은 흐름
- **안전:** 비밀값·자격 증명으로 막힌 항목은 내용 대신 `비밀 정보라 표시 안 함`. 사용자 경로는 프로젝트 기준 상대 경로로 표시
- **조회(읽기 전용)는 짧게:** 지식 조회처럼 아무것도 바꾸지 않는 동작은, 결과를 실제로 쓸 때만 한 줄 표시. 예: `Apollon 호출 · 관련 지식 2개 사용`. 쓰지 않은 조회는 표시하지 않음(매 요청마다 뜨면 시끄러움)
