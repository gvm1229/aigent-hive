> Plan version: 0.11.0
> Scope: product

> 소유 항목: `PDC-001–003`
> 다음 공개 시험: `0.11.0-test.2`

## 목적과 현재 근거

- 협업자의 Hive 설치를 선택 사항으로 유지하면서 일반 코드 작업·프로젝트 규칙 준수 보장
- Windows Codex에서 사용자 지정 예시 프로젝트의 `AGENTS.md`와 Hive 관리 지침을 읽기 전용 확인
- 확인된 문제: 실행 가능 여부 분기 없이 Wiki 조회·저장과 `hive usage enforce`·`hive run resume` 요구
- 사용자 작성 규칙·Next.js 생성 블록·Hive 표시 블록의 공존 확인. 프로젝트 전용 규칙과 외부 블록의 보존 필수
- 근거 한계: 지침 파일 검사만 실행. 미설치 협업자의 실제 AI 실행·다른 운영체제 동작은 미검증
- 외부 프로젝트 원문·개인 경로는 소스 자료로 복제 제외. 회귀 시험에는 독립 합성 자료 사용

## 실행 순서와 예시 프로젝트 후속 작업

1. `PDC-001` 생성기 개선 → `PDC-002` 행동 검증 → `PDC-003` 기존 설치 갱신 검증
2. `RFR-001`에서 새 제품 지문·전체 회귀·필수 CI·`0.11.0-test.2` 공개 수용 연결. 이전 `test.1` 증거의 새 변경 수용 대체 금지
3. 위 검증 완료 후 수정된 Hive 버전을 기준으로 예시 프로젝트의 실제 수정 계획 수립. 대상 경로·설치 버전·소유 파일·사용자 변경을 다시 읽기 전용 확인
4. 후속 계획에 변경 미리보기·백업·충돌 처리·복구·미설치 협업자 수용 포함. 예시 프로젝트 수정 필요성 유지, 영구 제외 아님
5. 실제 적용은 후속 계획과 해당 대상·버전의 설치 권한 경계에 따라 진행. 현재 요청에서는 예시 프로젝트 읽기 전용 유지

- 예시 프로젝트 수정은 제품 검증 뒤 별도 작업. `PDC-*` 제품 완료 개수에 실제 프로젝트 수정 중복 집계 제외
- 현재 완료 기준: 사용자 승인 1~5단계의 구현·검증·예시 프로젝트 수정 계획 완료. 6단계 실제 적용 금지
- 소스 계획 경로로 검증형 스킬 적용. 연결된 실행 그래프 부재로 활성화 주장 제외. 항목별 결정적 시험과 독립 검토, 같은 실패의 자동 재시도 최대 2회 후 원인 조사·수정
- 사용량 예산: 설치된 현재 세션 정책 유지. 승인 없는 제한 변경·보호 우회 제외
