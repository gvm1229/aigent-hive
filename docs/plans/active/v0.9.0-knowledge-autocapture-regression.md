## 보정 계약

Wiki 활성 user turn의 final response 전 foreground 순서:

1. 현재 승인된 user statement·완료 outcome의 reusable fact·preference·workflow 판정
2. `user-root|current-project|named-project` exact scope 결정
3. Secret·credential·confidential·ephemeral·ambiguous·raw-session 제외
4. Bounded normalized current-truth claim 1개 작성
5. `hive knowledge remember --user-root <user-root> --request <request.json> --output json` 1회
6. Canonical Markdown·derived-index receipt 확인 뒤 final response

Project setup·Hive harness·project marker 유무와 무관하게 선택 host의 모든 folder에서
user-global fact를 `user-root`에 기록. 미등록 target의 `auto` 조회는 `user-root`와 공유
collection으로 폴백. Project-specific fact는 자동 project 등록·private scope 추론 없이
명시적 scope 미확정 결과. 안전한 global claim과 project-specific claim의 결합 저장 금지.
