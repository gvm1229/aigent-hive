## 구현 순서와 세부 계약

1. `usage/codex_native.rs`의 계정·한도 응답을 정규화한 뒤 동치 비교. 측정 시각 역행·예정 시각 보정 구분. 구간 구성 변화·독립 재조회로 확인한 예정 시각 보정은 유효 자료로 처리, 손상·다른 계정·늦은 응답으로 시한 갱신 금지
2. `usage_monitor/` 내부 조회 프로세스에 지속 연결 유지. 요청마다 식별자·마감 전달,5초 뒤 부모는 대기에서 독립. 보조 프로세스도5초 한정, 소유 조회 자식만 정리. 단조 경과 시간으로60초 판단, 기본 경로만 실패해 보조 경로가 성공하면 정상 관측
3. `usage_control.rs` 기존 정책·세션 기록을 읽는 한정 인터페이스를 공유. 앱 대화 메타데이터의 작업 위치·부모 연결을 정책에 결합. 확인 불가 대화는 적용 불가로 보고하며 다른 프로젝트 정책 확대 금지
4. 대화·계정·구간·정책의 하한 사건을 기록, 정상 관측이 하한 이하인 첫 경우 포함. 기존 native user-stop 경로에 대상 대화 목록 전달. 중단된 대화의 명시적 재개에는 같은 사건의 사전 하한 차단도 억제, 자동·새 대화·0%에는 허용 승계 금지
5. 알림에 잔량·하한·구간·정확한 중단 확인 결과 표시. 공개 명령 추가 없이 기존 상태에 경로·진단·실제 감시 버전 표시. 구버전 상태는 기록으로 이관하되 과거 사건 재전송 금지
6. updater가 기존 활성 감시를 새 검증 실행 파일·예약 작업으로 전환하고 정상 관측 확인. 실패는 복구 또는 명시적 미완료, 성공 표시 금지. 꺼진 감시는 꺼진 상태 유지
   - 명시적 다시 켜기만 새60초 관측 대기 시작. 예전 단조 시각·오래된 정상 조회로 즉시 중단하거나 정상 감시로 표시하는 동작 방지. 예기치 않은 재시작·갱신은 기존 공백 유지, 실행 버전에 시험판·개발판 구분 포함
   - 공개 준비: `harness/release/0.13.1/`의 갱신 경로·출시 분류·기능 목록 정본 생성. 기존 정본0.13.0에서 대상13.1·이전 범위 상한13.0·오류 수정 분류·순번23 적용, 시험 자료를 배포 권위로 사용하는 처리 금지. 현재 버전 정본 존재·전체 이전 공개판 경로를 자동 검사에 포함, 후보·실패 복구 재검증

## 검증과 복구

- 변경 Rust 모듈·가까운 Python 회귀 → 엄격 Clippy·형식·전체 관련 검증. 한도 위/동일/아래·처음부터 낮음·프로젝트 차이·하위 작업·세션 제외·0%·동일 사건 재개·새 대화 차단 포함
- 조회 경로별 실패·프로세스 정지·늦은 응답·시각 변경·계정/구간 변경·60초 경계·상태 이관. 실제 API의 일정 보정으로60초 오류가 되는 회귀 재현
- 독립 Windows 검사기가 긴 추론·도구 호출의 정확한 실행 식별자·중단 사건·앱 생존·창 이유 확인. 일반 셸 자식의5초 종료는 승인한 예외로 별도 관측, 과거 실패 원본 보존. 별도 AI 대화·하위 에이전트는 정확한 실행 중단 필수. 자연 종료·도구 대기를 추론 중단으로 계산 금지
- 최소30분·여러4분 연결 교체·기본 경로 장애 후 보조 회복, 정상 자료가 있는 상태의 허위60초 중단0건. 실제 제공자 초기화·과금 종료·다른 OS 직접 중단은 증명 제외
- `0.13.0 → 0.13.1` 활성/비활성 감시의 갱신·실패 복구·데이터 보존과 일반 `hive update` 확인. 실사용자 설치는 승인 전 격리 환경으로 검증
- 공개0.13.0 실행 파일로 만든 합성 프로젝트를 이전 버전 갱신 회귀 자료에 추가. 실제 사용자 폴더·설정의 복제나 개발판으로 만든 과거 자료 대체 금지
- 실패는 증거 보존 뒤 입력·코드 수정으로 재검증. 지식·설정·실행 기록 삭제나 앱 종료를 복구 수단으로 사용 금지
- 앱 종료 조사: Windows 11의 앱 기록·Crashpad·예약 실행 시각을 읽기 전용으로 대조. 소유 조회 작업 정리의 부모·형제 보존과 직전 화면 조작의 관계 확인. 재현을 위한 앱 종료·재시작·설정 변경 없이 근거·한계 기록
