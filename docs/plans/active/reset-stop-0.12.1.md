## 실행 순서

1. **연결 조사, 현재 작업 소유**: 설치된 앱의 정적 코드에서 확인한 `codex-ipc` named pipe의 길이 머리글·초기화·소유 대화 조회 규약 확인. 현재 사용자·공식 Codex 패키지 서버 신원 고정 뒤 `initialize`, 현재 대화의 `thread-owner-discovery`만 실행. 출력은 제어 연결·소유자 일치 여부, 대화 원문 저장 금지. 실패 시 다른 실제 앱 연결 조사 지속, 새 모델 서버로 대체 금지
2. **중단 구현, 연결 확인 후**: `usage_monitor/desktop.rs`에 검증한 앱 연결·요청별 제한시간·대상 실행 식별·중단 응답 검증 추가. 앱의 `thread-follower-interrupt-turn`이 호출하는 공식 `turn/interrupt` 경로 사용. `user-stop`의 목표 일시중지·하위 작업 정리 확인. 앱 종료·내부 파일 수정·상태 위조 금지. 제어 실패는 실패로 표시, 앱 전체 종료로 대체 금지
3. **제어부 통합**: `usage_monitor.rs`, `state.rs`, `platform.rs`, `windows.ps1`의 앱 종료 경로 제거. 공유 잠금 뒤 대상 대화에 중단, 완료 확인까지 보호 상태 유지. 재실행·새 대화·예약 재개도 다시 중단. 초기화·30초 공백 이유, 세션 중단 확인·실패와 앱 생존을 구분해 보존
4. **조회와 표시**: 기존 `usage/codex_native.rs` 조회의 제한시간 소비 지점 측정, 원인 수정. 5초·30초 기준 완화 금지. 마지막 오류 분류·정상 관측 시각 공개, 상태 표시의 사건 잠금 반영. 중단 이유가 사라지지 않는 Windows 표시 창과 CLI 상태 연결, 알림은 중단 처리와 분리
5. **회귀와 설치 검증**: `test_usage_monitor.py`와 Rust 시험의 실제 연결·부분 프레임·잘못된 소유자·재시작·확인 경합·실패·제한시간 반례. 앱 전체 종료 호출 부재 검사. 관리된 설치의 기존 원복·지식 지문 보존, 단순 생존 대신 여러 실제 15초 관측 통과 요구
6. **현재 앱 실제 수용**: `scripts/qualify-usage-monitor.ps1`의 독립 검사기로 시험 대화 두 개와 하위 작업·긴 셸·도구 없는 추론 중단 확인. 앱 프로세스 동일 신원 생존·중단 응답·원인 표시·자동 재개 방지 별도 기록. 합성 초기화와 실제 제공자 초기화 구분. 실제 시험을 지원하는 호스트 기능만 사용

## 앱 종료 경로 제거 우선

- 사용자 반복 지시: 앱 종료 가능 경로 제거 뒤 작업 진행. 모든 실제 앱 제어·상시 감시·시험 예약·자동 설치 중지
- 설치된 앱 종료 감시기 포함 0.12.1-dev를 관리된 원복으로 0.12.0 실행 파일에 복구. 지식·선호·작업 파일의 삭제·앱 재시작 없음
- 현재 Windows 앱의 안전한 제어 미검증. `usage_monitor.rs`에서 enable·run·정상 감시 표시 차단, 직접 PowerShell 제어도 시작 전 거부. 읽기 시험의 현재 앱 연결 경로 제거, 모의 검증만 유지
- 남은 비활성 실행 파일·임시 제어 도우미의 삭제는 자동 승인 정책 차단. 삭제 성공 주장 금지, 정확한 목록·비활성 확인·수동 해결 경로 제공. 차단 우회 금지
- 원래 목표인 세션 중단·이유 표시의 실제 수용 미완료. 앱 종료와의 인과관계 미확정, 실제 앱 제어·설치 재활성화 없음
