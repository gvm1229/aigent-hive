- 현재 Windows 앱의 안전한 제어 미검증. `usage_monitor.rs`에서 enable·run·정상 감시 표시 차단, 직접 PowerShell 제어도 시작 전 거부. 읽기 시험의 현재 앱 연결 경로 제거, 모의 검증만 유지
- 남은 비활성 실행 파일·임시 제어 도우미의 삭제는 자동 승인 정책 차단. 삭제 성공 주장 금지, 정확한 목록·비활성 확인·수동 해결 경로 제공. 차단 우회 금지
- 원래 목표인 세션 중단·이유 표시의 실제 수용 미완료. 앱 종료와의 인과관계 미확정, 실제 앱 제어·설치 재활성화 없음

- 제거 뒤의 [제한된 사건별 제어 설계](../../research/session-stop-0.12.1.md): 평상시 기록 구독 제거, 사건 때만 기존 작업 중지·한정된 사후 확인·5초 안 구독 해제. 활성화 차단 유지와 모의 시험 우선

## 첫 차수의 오프라인 수정 순서

1. **범위 분리**: `dcc0d242`의 제품 지침·설치 회귀 변경만 후속 차수로 이관. `user_directives.rs`, `user_install.rs`, 두 `00-project-harness.md`의 해당 부분 제거, 소스 `01-behavior.md`의 사용자 지시 보존 규칙 유지. 버전 0.12.1 유지
2. **관측 시한**: `state.rs::BLIND_SECONDS=60`, 경계 59.999초/60초·성공 후 시한 갱신·조회 멈춤의 독립 시한 회귀 추가. `platform.rs`, `windows.ps1`, 사용량 Skill의 정확한 투영·설치 안내를 같은 기준으로 갱신. 과거 30초 사건 기록 보존
3. **평상시 최소 제어**: `desktop.ps1::Track`은 식별자만 등록, 기록 구독 0회. `desktop.rs::catalog_worker`의 식별자 목록 조회는 15초, 사건 때 즉시 갱신 요청. 소유자 부재 확인의 유효기간 20초. 기록 내용·추론 문장 저장 금지
4. **사건별 중단**: 모든 확인된 소유 대화에 먼저 `user-stop` 전송. 응답의 실제 실행 식별자만 새 대상으로 기록, 사후 snapshot의 interrupted와 목표 비활성 확인. 응답 유실 때 관측한 실행은 확인 가능, 유휴 대화만으로 중단 성공 주장 금지. 구독은 사건별 5초 창 안에서 최대 1초 간격, 성공·시간 초과·확인 해제 때 following=false. 잠금 중 반복 중단은 가벼운 요청만 사용, 새 실행은 새 한정 확인 창
5. **검증·경계**: `test_usage_monitor.py`의 모의 전송으로 평상시 구독 없음·요청 우선·응답 유실·시간 초과 해제·새 실행·확인 경합 검사. Rust 시한·잠금 회귀와 Clippy 실행. `require_app_safe_control`·PowerShell 시작 거부 유지, 현재 앱 접근·실제 중단·설치 금지
6. **기록·인계**: 근거·계획·현재 상태·양언어 사실 갱신, 관심사별 커밋. 비활성 파일 14개 수동 제거는 별도 정리 항목, 오프라인 구현의 선행 조건 제외. 현재 앱 수용은 안전한 연결의 별도 실측 전 미완료
