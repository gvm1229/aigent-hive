## 구현 결정

- 참조 파일: tests/fixtures/host-handler/handler.py·fake_codex.py. 배포·호스트 설정 연결 없음, 호출은 적합성 시험의 명시적 가짜 실행 경로만 허용
- 단일 봉투 계약: hive summon의 제품 SummonEnvelope JSON, profile.argv 원문과 자리표시자 사용. 실험실 request_id·execution_id·task_sha256 등의 별도 봉투 제거
- 승인 문맥: 시험 호스트가 제품 request_digest·정확한 대상·기능 보고서 원본·사건 머리·제어 세대·권한·중복 키·fencing_token 제공. 봉투 전체 지문 대조 뒤 작업 지문·상대 경로 검증
- 소비: 원자적 claim 파일 배타 생성 → 가짜 codex 실행 → 결과/격리 → 기존 HostReceipt 스키마의 확인증. 소비권 이후 실패·확인증 유실은 dispatch-uncertain, 자동 재호출 없음. 중복은 기존 확인증 조회
- 시험: tests/conformance/contracts/test_host_reference.py, contract 묶음 등록. 실제 제품 CLI가 만든 봉투 파일 입력, 가짜 실행 파일의 인수·표준 입력·결과 확인, 변조·취소·늦은 결과·중복·불명확 실행 거부
- 서명 Prepare 연결: crates/hive-cli/src/orchestration.rs의 기존 assert_summon_signed_prepare 끝에서 실제 게시 봉투를 consume_fixture.py에 전달, 제품 HostReceipt::parse_json으로 반환 검증. 시험 전용, 제품 실행 경로 불변
- 공개 수용: HIVE_PUBLIC_CONFORMANCE_BIN 지정 시 같은 서명 Prepare 시험의 최종 게시를 공개 hive summon 명령으로 실행. 세 OS 워크플로에서 제품 Rust 계약과 공개 Python 적합성·역할/별칭 시험 실행
- 검증: Python 적합성·제품 SummonEnvelope Rust 시험·문서 묶음, 실제 모델·타 OS 증명과 구분
