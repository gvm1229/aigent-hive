## Notion indexing 흐름

```text
Notion selected scope
  → page inventory·revision 확인
  → changed page fetch·normalize·chunk
  → user-root SQLite generation transaction
  → 기존 hive knowledge retrieve
```

Notion write 흐름:

```text
agent-reviewed durable fact
  → Notion create|update 성공
  → returned page ID·content·revision 검증
  → SQLite write-through
  → receipt
```

- 일반 질문의 retrieval engine: SQLite 단일 owner
- Notion search: 초기 scope 선택·복구·누락 진단에 한정
- 매 user turn: bounded remote freshness preflight 뒤 retrieval
- 변경 page만 fetch, unchanged page의 chunk 재작성 0건
- Notion write 성공·SQLite 실패: canonical 성공 + dirty generation, query fail-closed
- Remote delete·권한 회수·scope 이탈: active chunk 제외와 명시적 tombstone·진단
- Truncated·unknown block·partial fetch: complete index 승격 금지
- Network·OAuth·rate limit·capability failure: freshness 성공 오표시 금지
- Notion content 내부 지시문: untrusted data, Skill activation·권한 확대·외부 전송 0건
