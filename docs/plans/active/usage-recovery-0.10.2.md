## 목표와 핵심 계약

- 모든 설정된 Hive 프로젝트와 Hive 소스 작업에 공통 적용; `AI_Learning`·Discord 전용 수정 금지
- 프로젝트 로컬 상태와 사용자 루트의 소스별 상태 모두 포함; 미설정 폴더에 보호 상태 생성 금지
- 옛 파일은 같은 위치에서 교체·제거; 별도 디렉터리·대체 상태 파일·영구 옛 파일 보관 금지

- 기존 설치의 옛 `halt.json` 존재·옛 형식·이전 프로세스 번호만으로 새 버전 차단 금지
- 현재 세션의 새 사용량 측정으로 실행 여부 결정; 보호 비활성화·수동 삭제·새 대화 생성 불필요
- 전역·프로젝트 설정과 명시적 사용자 기준 보존; 실제 잔여량이 기준 이하이거나 현재 측정이 불명확하면 차단 유지
- 기존 공개 버전의 수용 결과와 이번 복구 수용 결과 분리; 이번 요청의 완료 범위는 계획 작성

## 저장 형식과 기존 설치 처리

1. 기존 `halt.json` 위치를 유일한 정본으로 유지. 지원 구버전 형식을 먼저 분류하고 현재 형식 파싱을 이관의 선행 조건으로 요구하지 않는 공통 판독기 구현
2. 프로세스 번호 재사용에 대비한 검증 가능한 수명 정보를 기존 파일 내부에 결합. 세 운영체제에서 취득 방법 검증; 임의 값·추가 상태 파일 금지
3. `policy_digest` 부재·존재, 옛 `usage-unknown`, 이전 프로세스 표식은 재측정 대상으로 처리. 새 관측이 안전하면 제거, 부족·불명확하면 같은 `halt.json`을 현재 형식과 증거로 교체
4. 손상된 옛 일반 파일도 새 관측으로 재생성. 경로 탈출·심볼릭 링크·소유권 불명확·미지원 미래 형식은 별도 안전 오류; 쓰기 권한 부족 시 구체적 원인 보고, 다른 파일로 우회 금지
5. 기존 바이트·소유권 재확인 후 원자적 교체. 교체용 임시 파일만 허용, 성공 후 잔존 0건. 중간 종료·동시 변경 시 같은 위치에서 제한된 재시도
6. `control.json`은 기존 위치에서 정합화. 현재 바인딩의 명시적 설정 보존, 이전 프로세스의 우회 권한 이전 금지
7. `hive update`의 기존 승인 범위 내 사용자 루트 상태와 각 프로젝트 갱신·첫 보호 검사에 동일 이관 적용. 전역 업데이트의 무단 프로젝트 순회·설정 변경 금지
8. 해당 대상의 비활성 세션 옛 표식도 소유권·수명 확인 뒤 정리. 활성 상태는 새 관측으로 교체, 판별 불가·접근 불가 대상은 미이관으로 보고. 대상별 옛 형식 0건 확인 전 전체 이관 완료 주장 금지
9. 실행 파일만 갱신한 첫 실행도 자동 이관. 구버전의 옛 형식 재기록은 다시 이관하고 지속 충돌은 호환성 오류로 보고; 구버전의 새 형식 지원 가정 금지

## 실행 경로

- `enforce`: 유효 설정 확인 → 현재 바인딩 결정 → 새 사용량 측정 → 정책·파일 경쟁 재확인 → 현재 결과 기록
- 허용: 현재 기준 초과의 유효 측정 후에만 허용. 현재 중단 기록은 정확한 바이트 비교로 교체·해제
- 차단: 부족·불명확 결과 저장. 다음 명시적 `enforce`에서 다시 측정 가능; 무한 재시도·감시기 추가 금지
- `status`: 읽기 전용. 마지막 관측 결과·재확인 필요·이관 필요를 구분; 실행 허가로 사용 금지
- `session enable`: 활성 설정과 복구 완료 구분. 후속 `enforce` 결과까지 보고; 활성화 성공만으로 작업 재개 성공 주장 금지
- `threshold`: 전역·프로젝트·실제 적용 기준 표시, 같은 대화의 새 기준 재검사 유지
- `run resume`·반복 실행 준비: 공통 판독·이관 사용. 옛 형식을 먼저 거부하는 개별 경로 제거, 일회성·소유권 확인 유지
- 동시 실행: 다른 프로세스 상태 덮어쓰기 금지, 설정 변경·파일 충돌은 제한된 재시도 후 구체적인 오류
