# 0.14.0 제거 미리보기·확인·자료 보존

> Plan version: 0.14.0
> Scope: product

## 항목

- [ ] [D140-001] 대화형 안전 제거와 비대화형 계약
  - state: agent-owned; depends: U140-002,G140-002

## 범위와 인터페이스

- 사용자 선택: 미리보기·확인·감시 종료·자료 보존만. `--full`, `--purge` 등 사용자 설정·지식 전체 삭제 기능 추가 없음
- `hive uninstall --dry-run`: 소유 검사와 제거/보존/감시 대상 표시, 변경 없음
- `hive uninstall`: 같은 계획 표시 뒤 기본 거부 확인. 저장 언어 사용, 미설정이면 먼저 한국어/영어 선택
- `hive uninstall --confirm --output json`: 명시한 비대화형 제거. --confirm 없는 비대화형 호출 거부, --output json만으로 제거 승인 추정 금지
- 기존 내부 복구의 직접 함수 호출과 사용자 CLI 승인 구분. 인증된 설치 복구가 질문 대기나 자료 삭제로 변하지 않는 호환

## 구현 순서

1. `user_install.rs::parse_uninstall/execute_uninstall`의 소유 인벤토리 계산과 삭제 분리. preview와 apply가 같은 목록·지문·사용자 루트 결합 사용
2. 현재 활성 감시 존재 시 동일 제거 계획에 정확한 Hive 예약 해제·감시 종료 포함. 사용자가 별도 AI에게 먼저 해제를 요청해야 하는 현재 경로 제거
3. 확인 뒤 인벤토리 재대조, 타사 변경·심볼릭링크·소유 불명 파일은 삭제 거부. 감시 종료 실패 시 실행 파일 삭제 전 중단과 정확한 남은 단계 표시
4. 기존 호스트 활성 해제·Hive 소유 투영 제거·파생 색인/실행 상태 정리. 설정·선호 출처·지식·프로젝트 원문 보존, 사용자 프로젝트 전체 재귀 삭제 없음
5. 사용자 범위 하네스와 CLI 본체 제거를 같은 preview에 포함. npm 설치는 정확한 패키지 제거 명령으로 위임, 직접 설치는 인증된 소유 파일만 제거. Windows에서 실행 파일 잠금이 있으면 기존 직접 갱신의 소유 helper 방식을 재사용해 본체 종료 뒤 제거·검증. 소유자 확인 실패는 본체 보존과 부분 완료 표시, 다른 패키지/프로세스 전체 삭제 금지
6. 제거 결과를 설정 엔진과 같은 형식의 단계별 receipt로 저장. 완료/일부 실패/보존/남은 패키지 구분, 재실행은 남은 소유 항목만 처리

## 검증과 완료

- 실제 질문 거부·EOF·Ctrl-C·dry-run에서 파일/감시 변경0건
- 합성 사용자 루트의 활성/비활성 감시·부분 설치·기존 실패 복구·타사 수정·소유 불명·시점 간 변경 시험
- 제거 뒤 사용자 설정/출처/지식 지문 일치, 호스트 활성·소유 예약 잔존 여부 별도 확인. 재설치 시 보존 설정과 명시적 거부 선택 복구
- `python scripts/dev-check.py rust -- test -p hive-cli uninstall --locked`와 사용자 설치·갱신 복구·Python 설정 보안 회귀. Windows 감시 실제 시험과 다른 OS의 비해당 결과 구분
- 모든 자료 삭제 요청으로 확장 금지. 현재 제품에서 미지원인 전체 삭제는 help에도 지원 기능으로 표시 금지

- Windows 지연제거 helper는삭제범위밖의검증된임시위치. 본체종료뒤제거는removal-pending과보존처리기록위치반환, 실제제거검증후완료기록. 기록은 .hive/history/lifecycle/에유지, .hive/runtime/.hive/install 아래저장금지
