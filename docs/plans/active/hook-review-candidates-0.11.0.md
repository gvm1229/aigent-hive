## 목적과 범위

- 실제 작업 수행과 장기 규칙·기억의 개선 검토 분리
- 종료 이벤트는 전체 작업 성공의 증거가 아닌 후보 확인 시점
- 훅은 후보 존재·검토 필요성을 알리는 제한된 결과만 반환, AGENTS.md·정책·Skill·장기 기억의 직접 자동 변경 제외
- 기존 지식 기록은 검토된 사실 저장, 이 항목은 규칙·절차 개선 제안의 검토. 별도 지식 저장소나 중복 기록 경로 도입 제외
- 호스트 소유 검토 과정 활용, Hive의 공급자 API·모델 실행·에이전트 생성 제외

## 구현 순서와 책임

1. 기존 실행·검사 결과에서 규칙 ID·실패 종류·정책 지문·재현 근거의 제한된 후보 추출
2. 보존 가능한 범위·개인정보·비밀 여부 검토 후 기존 작업 자료의 승인된 경로에 후보 등록
3. 같은 규칙·정책·실패의 중복 제안 병합, 반복 근거와 반례·적용 범위 표시
4. 사람이 채택·수정·기각 판단. 검토 결과와 적용 권한을 구분하고, 채택 뒤에도 해당 파일 변경의 기존 권한 검사 유지
5. 변경이 승인된 별도 작업에서 최소 수정과 회귀 검증, 기존 버전으로 되돌릴 근거 보존

구현 대상: `crates/hive-cli/src/run.rs`의 기존 결과 연결, 검토 경로와 출하 Skill·설명 자료. 입력은 검증된 제한 자료, 전체 대화·원시 도구 출력·숨은 지침·비공개 외부 노트의 자동 수집 제외.

## 수용 조건

- 반복된 종료 이벤트·재개·같은 결과 재전달에도 동일 후보의 중복 생성 0건
- 종료 이벤트만으로 완료 판정·승인·정책 수정 발생 0건
- 검토되지 않은 후보의 정본 지식·AGENTS.md·정책·Skill 변경 0건
- 근거 부족·상충 자료에는 미확인 상태 유지, 규칙 추가를 기본 처방으로 선택 금지
- 후보 등록·검토·수정 승인·실제 적용의 상태 구분, 기각·오류·취소 경로 포함
- 기밀·비밀·대화 원문 차단 자료와 다른 프로젝트 범위 혼입 거부 시험
- 변경 코드·정책·자료의 지문과 실행 호스트·운영체제·실제 실행 여부를 증거에 포함
