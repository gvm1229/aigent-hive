> 소유 항목: `RF-B01`, `RF-B02`, `RF-R01`
> 기준 코드: `87b84f42`; 제품 버전: `0.11.0`; 첫 공개 시험: `0.11.0-test.1`
> 결정: [ADR-0023](../../decisions/ADR-0023-foundation-refactor.md)

## 요청과 범위

- 현재 요청: 새 브랜치 생성과 구현 계획 작성. 제품 구현·설치·공개는 후속 작업
- 확정 방향: 기존 기능·명령 유지, 지식 저장·조회·새 대화에서 이어 가기부터 개선
- 실제 앱 검증: Codex 우선, 이후 Claude Code·Antigravity 확대
- 목표: 같은 설명의 반복 감소, 필요한 지식의 정확한 회수, 안전 규칙과 파일 변경 처리의 단일 책임
- 브랜치: `codex/refactor-hive-foundations`; 기존 `develop` 변경과 과거 출시 기록 보존
- 버전 결정: 미출시 `0.10.4` 변경을 그대로 계승하는 `0.11.0`, 별도 `0.10.4` 출시 제외
- 기존 사용량 보호: [RB104 계획](quota-reset-guard-0.11.0.md)의 식별자·구현·증거 유지

## 유지 조건

- Rust·Markdown 정본·재생성 가능한 SQLite·호스트 소유 모델 실행 유지
- 공개 CLI 인자·JSON 결과·종료 코드·저장 형식·사용자 설정·기능 기본값 보존
- 기존 작업 조율·Judge·사용량 보호·선택형 검색의 삭제나 자동 비활성화 제외
- 승인 경계·원본 지식·외부 파일·과거 `harness/project-bases/`와 `harness/user-bases/` 보존
- 기본 검색의 모델·네트워크 독립성 유지; 미설치 선택형 검색의 자동 설치 제외
- 순수 파일 분리와 행동 변경은 별도 커밋. 신규 추상화는 실제 복수 호출 경로 확인 후 도입

## 측정과 판정

- `RF-B02`: 지원 명령별 정상·거부·재실행 결과와 대표 설치의 변경 전후 파일 지문 비교
- 계승 코드의 사전 정리: `installed-usage-guard.md`의 기존 문체 오류와 Source Wiki 원본 지문 불일치 검토. 사실의 현재 의미 확인 없이 지문만 일괄 교체 금지
- 기준 측정: 동일 기기·빌드 방식·자료에서 먼저 5회 준비 실행 후 30회 측정; 중앙값·p95·분산·실행 환경 기록
- 지식 정확도·질문 횟수·지침 크기·명령 호출 수를 별도 보고; 더 짧은 지침만으로 품질 개선 주장 금지
- 초기 성능 기준안: 같은 조건의 p95 악화 10% 이내. 기존 절대 수용 기준도 동시 유지; 불안정 측정은 원인 분리 후 재측정
- 평가 자료와 판정 기준은 구현 전 고정; 결과에 맞춘 기준 완화 제외

## 검증과 커밋 경계

- 각 항목: 담당 Rust 모듈 시험과 직접 관련 Python 계약 먼저 실행
- `RF-T*`: 파일 보호·복구의 기존 보안 시험 유지, Windows·macOS·Linux 실제 파일 동작 확인
- 통합: `python scripts/dev-check.py pre-push`; 현재 요청의 문서 작업에는 제품 전체 시험 제외
- 시험 산출물: 기존 `scripts/test-artifacts.py`로 등록, 검토 전 삭제 제외
- 첫 커밋: 문서 계획. 후속 구현: 상태 규약 → 상태 도구 → 지식 → 정책 → 지침 → 설치 분리 → 공통 처리 → 복구 순서의 독립 커밋
- `RF-R01`: 구현 승인 후 전체 제품 검증. 번호 공개 시험은 목표 버전·새 제품 바이트·실제 수용 준비를 갖춘 뒤 `develop` 통합 기준으로 진행
- `0.11.0` 전체 개발 범위: 새 리팩터링 21개와 기존 `RB104-*` 4개. `RB104-004` 미완료 상태에서 전체 완료·안정판 수용 주장 금지
- 안정판 `main` 통합·태그·게시·실제 설치: 해당 버전의 별도 명시 승인 필요

## 위험과 되돌리기

- 지침 축소: 코드 검사 이전에 문장 삭제 금지; 동일 행동 시험 실패 시 해당 지침 변경만 복원
- 공통 파일 처리: 사용자·프로젝트의 다른 승인 범위를 합치지 않고, 호출 경로별 전환과 되돌리기 가능 구조
- 저장 형식: 이번 내부 리팩터링에서 불필요한 이관 금지. 불가피한 형식 변경은 호환성 결정과 별도 이관 계획 선행
- 상태 자동화: 기존 문서와 계산 결과 대조 후 생성 구간만 교체, 유효한 근거·과거 출시 기록 보존
- 호스트 미지원: 해당 기능의 근거만 미지원으로 분리; 독립 구현 항목의 진행 유지
