## 최종 동작

1. 작업 범위·평가표·필수 조건·전체 예산·권한 고정
2. 결과물 작성 → 독립 항목 평가 → 결정적 점수 계산
3. 부족한 결과물만 제한적으로 수정; 같은 실패·무효 평가·예산 소진의 별도 처리
4. 반복되는 실행 구성 문제 또는 명시한 하네스 개선 요청에 한해 승인된 격리 사본으로 후보 시험
5. 기준 구성과 후보를 같은 조건에서 비교, 필요한 경우 한 번 합성
6. 회귀·필수 조건·독립 검증을 통과한 변경만 허용 범위에 채택
7. 실행 구성과 적용 조건·효과·반례를 프로젝트 범위에 보관; 전역·출하 승격은 별도 판단

두 반복은 하나의 상위 예산과 취소 세대 사용. 새 실행 생성으로 재시도·사용량 한도 초기화 금지.

## 설계의 확정 경계

- 숫자 점수0.00–1.00, 두 자리. 내부 정수·유리수 계산, 점수는 정답 확률과 구분
- 네 기본 평가표의 배점 합계100. 기준별 통과·실패·판단 불가와 실제 근거
- 참고 모드 기본. 자동 완료 판단은 평가표 교정과 호스트 실행·검증 지원 증거 이후에만 허용
- 초기 합격선0.90·항목별0.80, 최초 결과 후 수정 최대3회. 교정에서 부적절하면 새 평가표 버전으로 변경
- 하네스 실험 기본 비활성. 명시한 실행 범위에서 최대1회, 일반 후보1·분야 후보1·합성 후보 최대1
- 기준 구성 항상 후보 유지. 동점·불확실·회귀는 기존 구성 유지
- 모델 실행·판단은 호스트, Hive는 자료 검증·계산·제어·준비·기록
- 새로운 독립 스케줄러·백그라운드 모델 실행·공급자 API 없음
- 실제 효과가 있는 외부 작업의 반복 시험 금지; 승인된 시험 환경에서만 후보 비교

## 실행·검증 공통 규칙

- 상세 문서의 신규 파일·명령·기호: 구현 예정 계약이며 현재 제공 기능으로 표시 금지
- 각 단계: 범위 예약 → 입력·현재 코드 재확인 → 구현 → 가장 가까운 동작·실패 시험 → 근거 보존 → 다음 단계
- target 또는 tests/work 생성 시험은 기존 test-artifacts 실행기로 감싸 실행. 예시:
  `python scripts/test-artifacts.py run --purpose "점수 계산 검증" --path target --command "cargo test -p hive-core evaluation::tests"`
- 실패와 미실행·미지원 구분, 실행 OS·호스트·정확 버전·대상 지문 기록
- 새 모델 기능은 실제 호스트의 전달·결과·취소·복구 수용 전 비활성. 모의 시험을 실제 수용으로 대체하지 않는 경계
- 제품 단계별 전체 검사1회: `python scripts/dev-check.py rust`, `python scripts/dev-check.py python`
- 정식 통합·게시·실사용 설치는 현재 버전별 사용자 승인. 이번 계획으로 승인 추정 금지

## 기존 활성 작업과의 통합

- 기존0.14.0 CLI 계획·15개 수용 기준 유지. PLAN.md·CURRENT.md는 다른 실시간 구현 세션 예약 중
- 이번 최종 계획은 독립 정본 묶음. 활성 제품 집계의 자동 편입·기존 목표의 숨은 확대 없음
- 실행 개시 담당: 해당 세션의 공용 파일 예약 해제 확인 후 PLAN.md·CURRENT.md에 이 묶음의 QSI 항목을 한 번만 연결
- 공통 main.rs·Cargo.toml·투영 파일은 기존 CLI 변경 위에 직렬 반영, 덮어쓰기·되돌림 금지
- 그때0.14.0 정식 출시가 끝났다면 새로운 제품 버전 선택이 필요. 임의0.15.0 지정 금지
- 위 통합 절차는 계획 작성의 미완료 항목이 아닌 제품 실행 진입 조건

## 최종 수용 기준

- 네 평가표의 계산·교정·필수 조건이 소스와 소비자에서 같은 결과
- 알려지지 않은 결과·허위 영수증·기준 변조·오염·예산 재설정·취소 뒤 늦은 결과의 완료 승격0건
- 비교 계약상 회귀·검증 실패 후보의 자동 적용0건, 검증되지 않은 경험의 전역·제품 자동 승격0건
- 사용자·타사 바이트 보존과 실패 시 원상 복구
- 실제 Codex·Windows의 소스와 소비자 흐름 수용. 다른 호스트는 입증된 기능만 활성
- 공개 시험 파일의 별도 수용과 자료 보존. 계획·문서 검사의 성공은 제품 성공과 구분
