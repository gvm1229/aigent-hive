- 원래 진행 또는 정확히 같은 새 진행만 허용. 같은 인계 재실행의 새 작업 생성 없음, 다른 진행·다른 새 후보·다른 폴더는 보존 후 충돌. 새 설정의 base 지문은 현재 사용자 설정에 결합

- 실행 연결: 전역 설정이 미완료 인계 파일을 발견하면 사용자 설정 잠금 안에서 인계부터 마무리. 일반 적용/질문보다 먼저 처리, 조회 전용 실행에서는 변경 없음

- 인계 생성의 사용자 동의와 실제 감시 정지는 C2에서 연결. C1만으로 전체 M02 완료 표시 금지

## C2. 질문·철회·설정 적용 연결

- 현재 상태: 구현 전 설계 초안. 정지 잠금의 인계·철회 확인의 중단 기록·기존 하네스 적용 검증을 코드와 대조한 뒤 확정 필요. 아래 흐름의 구현/검증 완료 주장 없음

### 입력과 실행 계약

- `hive setup --scope user --resume --review`: 적용 중인 감시 동의의 철회 질문. 한국어/영어, 기본 아니요. 아니요는 원래 확인한 적용의 재개, EOF는 미완료 보존
- `--resume --review --dry-run --output json`: 읽기 전용 미리보기·질문·`preview_digest`. 이 조합에서만 기존 resume/dry-run 상충의 예외, 실제 설정/진행 변경 없음
- `--review-answers <json>`: `question_id`, `question_revision:1`, `answer:true`, `confirmed:true`, `preview_digest`, 선택적 `input_channel:answers-file|agent`. 4KiB 한도·알 수 없는 필드 거부, 파일에서 terminal 주장 거부. 답안 부재의 JSON/무입력 실행은 질문 대기 없음
- 철회 질문 뒤 기존 감시 범위·나머지 확인한 설정의 적용·보존을 표시하고 최종 확인. `--confirm`의 답변 보충 없음

### 구현 순서와 중단 재개

1. 사용자 설정 잠금 아래 원래 진행/설정과 현재 감시 범위 재검사. 미리보기는 CONFIG·활성화 작업 ID/승인·옛 쓰기 보관·최근 해제의 범위에 결합, 변하는 실시간 관측 원문은 결합/수집 제외
2. 실제 정지의 기존 disable 기록에 확인된 철회 질문·원래 설정 작업/의도 지문·당시 설정 지문·답변 시각/경로를 함께 저장. 정지 효과 전 stopping 기록 선행, 같은 표식을 가진 미완료 철회는 질문 재수집 없이 재개
3. 실제 감시 종료·철회 복구 뒤 반환하는 `StoppedReader`를 유지. 다른 사용자 폴더의 정지 잠금을 정책 갱신에 쓰지 못하도록 폴더 식별 검사
4. 나머지 원래 설정/하네스는 기존 적용·검증으로 마무리하되 옛 감시 시작 호출 제외. 기존 `legacy`의 설정 적용과 `finish_monitor`를 분리해 재사용
5. C1의 새 Applying 작업 생성·옛 작업 취소·인계 완료. 새 값은 midway=false와 그 출처만 변경
6. 정지 잠금을 보유한 동안 기존 정책 checkpoint로 비활성 선택부터 저장. 그 뒤 정지 잠금 해제와 새 설정의 공통 적용/검증. 후속 하네스 실패에도 비활성 선택 유지
7. 정지 기록의 철회 표식과 C1 취소→새 작업 연결로 중단 위치 확인. 설정 변경·새 감시 동의·다른 진행이 발견되면 보존 후 충돌, 옛 동의 자동 재활성 없음
8. 일반 setup/update 복구는 같은 철회 표식/인계를 먼저 확인. 같은 버전에서 남은 단계만 재개, 새 본체 설치 없음. 완료된 새 작업에는 철회 질문 반복 없음

### 검증

- 두 언어·기본 거부/EOF·미리보기 무쓰기·파일 답안 지문/출처·상태 변경 거부·정지 실패·각 인계 경계·비활성 선택 선행 저장·새 설정 적용 실패 재개
- 실제 Linux CLI는 가짜 앱·합성 미완료 진행의 사용자 흐름 수용, 실제 Windows 감시 제어와 구분. 모델·센서 호출 없음, 실제 0.13.1 설치 미연결

- C1의 저장 계약을 먼저 검증. 이어서 기존 `recovery`/`legacy`/`monitor_start`의 잠금·검증 순서를 기준으로 질문과 실제 정지 연결
- 원래 확인한 나머지 설정은 유지, 감시만 철회. 기본 거부·EOF 보류·현재 상태 미리보기와 최종 확인 필요
- 터미널/답안 파일의 같은 질문 의미와 지문 사용. `--confirm`만으로 새 답변 추정 금지. 정확한 옵션·답안 형식과 중단 재개 순서는 해당 코드 확인 뒤 실행 전 보완
- 기존 설정/하네스의 미완료 적용은 검증된 공통 복구로 처리, 옛 감시 동의 재활성 금지. 명시 해제는 후속 하네스 실패에도 유지
- Windows/Linux 대역과 실제 Linux CLI의 설정/인계 흐름 검증. 개인 감시/설치 변경 제외, 실제 Windows 활성화는 격리 운영체제에서 별도 수용
