# M06 설정의 언어와 입력 방식

- 목표: 저장된 한국어/영어를 질문·오류·재개·완료 안내에 일관되게 사용. 터미널·JSON·명시적 무입력·입력 리다이렉션의 기존 계약 검증
- 소유: `setup_engine/{interactive,project,terminal,mod}.rs`, 필요한 공통 오류 출력 모듈, 인접 시험·격리 Linux 수용 자료
- 제외: 모델 호출·번역 서비스·실제 사용자 설치 변경. 기존 오류 코드·종료 코드·상태 보존, 기술 진단 원문은 별도 구조화된 필드로 보존

## 순서와 결정

1. 기존 전역/프로젝트 엔진의 언어 복원·빠른/맞춤·일부 변경·진행 재개·질문판 변경 검증 재사용. 프로젝트 전역 미설정 연결은 기존 `project::execute`의 공통 `interactive::execute_update` 경로 유지
2. 먼저 격리 Linux 실제 CLI에서 한국어 저장 후 잘못된 설정 묶음·상충 옵션의 오류 언어 검사. JSON·무입력·리다이렉션·터미널 필수 옵션에 짧은 제한을 두고 숨은 입력 대기 거부
3. 확인한 언어 누락만 수정. 정상 질문에서 사용한 언어를 오류까지 전달하고, 질문 전 구문 오류에는 명시한 사용자 루트의 저장된 언어를 읽기 전용으로 확인. 미선택 언어는 기존 첫 질문 계약 유지
   - 미완료 답안에서 고른 언어를 기존 전역 언어보다 먼저 사용. 한국어만 처리하던 기존 분기를 한국어/영어와 기존 설정 유무 전체로 교체, 완료 기록의 빈 답안은 기존 저장값으로 대체
4. 공통 오류의 사용자 설명은 선택 언어, 현재 코드·종료 상태 유지. 알려진 입력 오류는 구체적인 두 언어 설명. 하위 검사·운영체제의 진단 원문은 별도 필드로 보존, 생성형 번역 없음
5. 실제 한국어→영어 변경 뒤 오류·재개·완료·프로젝트 설정의 언어 재사용 검사. EOF·Ctrl-C·잘못된 입력·질문판 변경은 가까운 단위 검사와 실제 CLI 취소/재개로 구분 검증
