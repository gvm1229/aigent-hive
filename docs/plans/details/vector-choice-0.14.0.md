# M04 벡터 검색 선택의 CLI 연결

- 목표: 전역 CLI에서 의미 검색의 희망 여부 확인. 답변과 실제 검색 환경 설치·활성화의 분리, 기존 선택 보존
- 범위: `setup_engine/vector_choice.rs`, `interactive.rs`, `legacy.rs`, `recovery.rs`, `mod.rs`, `progress_store.rs`, `user_setup.rs`의 기존 기능 답안 저장, `harness/setup/questions.yml`, 격리 Linux 수용 자료
- 제외: Python·모델·검색 환경 설치, 다운로드, 색인 생성, 실제 사용자 설치 변경. 기존 `setup feature status|claim|answer|prompt` 명령 호환 유지

## 구현 순서

1. 전역 선택 목록에 의미 검색 추가. 별도 질문 `user-vector-search`, 기본 거부, 답변은 희망 여부만 저장하고 실제 준비에는 별도 미리보기·동의가 필요하다는 두 언어 설명
2. 새 설정의 빠른/맞춤 절차와 명시한 해당 항목 검토에서 질문. 기존 답변은 전체 재설정·갱신에서 보존, 해당 항목을 직접 고른 경우만 변경. 무응답은 미완료 진행으로 보존
3. 별도 `SetupProgress.vector_choice`에 기존 기능 답안 지문·원하는 답안·실제 출처·질문판·답변 시각 저장. 전역 제품 설정에 임시 질문 키 혼입 금지
4. 최종 변경 미리보기와 확인 뒤 공통 적용 기록 안에서 기존 기능 답안에 비교 교체. 이미 같은 처리에서 저장한 정확한 답안이면 재개 허용, 다른 선택·외부 수정은 보존 후 충돌. 적용 전 질문 취소의 기능 답안 쓰기 없음
5. 기존 답안 파일에 선택 출처와 처리 식별자 추가. 구형 필드 호환 읽기 유지. 이후 호스트 지침 투영에서 이미 답한 질문의 재질문 제거. 실제 검색 환경 상태는 별도 표시
6. 무입력 이전·일반 답안 파일은 새 선택을 자동 생성하지 않는 처리. 선택 보류는 일반 작업 차단 조건으로 사용하지 않는 원칙 유지
