# M02 감시 동의 철회와 새 검토

G140-002의 남은 하위 작업. M02 핵심 동의·M01 처리 기록 재사용, 전체 완료 집계와 구분.

## A. 명시 해제 뒤 옛 활성화 폐기

- 부분 완료 `5f02ca62`: Windows의 기존 활성화10·새 동의1·해제10·clippy, Linux 컨테이너의 [새 동의1](../../../tests/results/runs/20261025T003629-261bc8b5e271.md)·[해제10](../../../tests/results/runs/20261025T003927-0a5c51a402ab.md) 통과
- 운영체제 대역·합성 설정의 흐름 검증. 실제 앱/예약/센서·공개 후보·Windows 격리 긍정 수용 미실행. 현재 B의 보관 복구와 C의 공통 설정 연결 미완료, 전체 M02 완료와 구분
- 최초 새 시험의 실패는 반환 필드 오인(`activation_verified` 대신 실제 `activation: verified`), 시험만 수정 후 전용 재실행 통과. 기존 활성화10의 중단/재개 반복 검사 재실행 없음

- 소유: `usage_monitor/activation/{journal,runner}.rs`, `activation.rs`, `transition.rs`, 인접 시험
- 기존 `disable`의 감시 정지 확인·잠금 보유 안에서 미완료 활성화 기록을 `cancelled`로 교체. 실제 구성 비활성/부재·완료한 새 해제 기록·원래와 다른 해제 지문·같은 사용자 폴더 확인
- 기존 승인으로 재개는 항상 거부. 이후 다른 새 미리보기 지문에 명시 동의하면 새 활성화 처리 허용. 단순 재실행·현재 설정만으로 새 동의 보충 금지
- 활성화 완료 기록은 보존. 새 해제의 고유 지문과 사용자 구성·관측 기록 보존, 센서·예약 등록/시작 호출 없음
- 옛 파일 쓰기 보관 때문에 기록 폐기가 불가능하면 실제 해제 결과와 `activation_retirement: pending` 구분. 감시 해제를 실패로 바꾸거나 남은 쓰기를 자동 적용하는 처리 금지
- 검사: 준비 단계 중단→해제→옛 승인 거부→새 동의 성공, 해제 전 새 동의 거부, 재실행 안정성, 구성/해제 기록 변경 보존. Windows/Linux 운영체제 대역 범위, 개인 감시 변경 없음
- 합격 뒤 작은 제품 커밋. A만으로 전체 M02 완료 표시 금지

## B. 남은 쓰기 보관의 취소 복구 조사

- 범위: `activation/journal.rs`의 `WRITE`·`CONFIG`·`STATE`와 `user_install.rs`의 고정 경로 쓰기 보관 도구
- 질문: 새 해제 후 옛 쓰기 보관을 현재 비활성 구성에 적용하지 않고 보존·폐기할 안전한 기존 도구의 존재 여부
- 관찰: 기존 `a_later_disable_never_rolls_a_retained_active_configuration_forward` 재사용. CONFIG 활성 바이트 자동 적용 0건·관측 원문 보존·새 동의 가능 여부
- 기존 도구로 불가능하면 현재 상태/보관 전후 지문·권한을 검사한 보존 이관의 정확한 자료·순서를 먼저 기록한 뒤 구현. 다른 파일·다른 사용자 자료·모르는 보관은 변경 전 거부

### B1. 게시된 구성의 남은 쓰기 보관

- 부분 완료 `d303f57a`: Windows 기록5·clippy, [Linux 기록5](../../../tests/results/runs/20261025T005941-05f5d51ed81f.md) 통과. 임시 폴더·운영체제 대역, 실제 앱/예약/센서/공개 후보 수용과 구분
- 보관의 지문·권한 확인과 전체 폴더 이관, 비활성 구성 바이트 보존·새 동의 성공·반복 해제 안정성 확인. 손상된 보관/다른 보관 원문은 pending으로 보존
- 최초 컴파일의 시험용 `u64`/`usize` 한도 형식 오류 수정 뒤 통과. B2/C와 전체 M02 완료 근거로 확대 없음

- 확인: 기존 `finish_setup_claim`은 현재 파일이 옛 적용 후 지문과 같을 때만 정리. 새 해제로 비활성화한 구성에는 적용 불가, 옛 활성 바이트의 일반 복구 금지 유지
- 변경: `activation/journal.rs`의 해제 전용 열기와 보관 이관, 새 `user_install/monitor_claim_retirement.rs`의 고정 CONFIG 보관 처리. 기존 일반 복구는 변경 없음
- 해제 전용 열기에서 WRITE 자체·활성화 기록의 기계적 복구만 허용. CONFIG/STATE 적용은 실행하지 않는 경로
- 같은 폴더·완료한 새 해제·비활성 현재 구성·옛 WRITE/기록의 같은 해제 지문 확인. CONFIG 보관의 정확한 전후 바이트/권한과 알려진 객체만 검증
- `.hive/config/setup-progress/cancelled-monitor/<activation-operation-id>/write.json`에 원래 WRITE 바이트 보존. 같은 위치의 `config-claim/`에 검증한 보관 폴더 전체를 한 번 이관. 원래 구성 파일은 변경 없음, 알 수 없는 대상과 기존 다른 보관은 보존 후 충돌
- 보존 이관 확인 뒤 옛 WRITE만 비교 제거, 원래 활성화 기록은 A의 cancelled 처리. 중단 뒤 같은 보관/기록 재사용, 현재 비활성 구성과 관측 원문 덮어쓰기 없음
- 검사: 기존 일반 복구의 활성 바이트 거부 유지, 명시 해제의 폐기 완료·보관 보존·다시 실행·새 동의. 보관 손상/권한 변경/다른 대상의 거부
- 현재 CONFIG가 사라진 중간 지점과 STATE 쓰기는 B2의 별도 조사·복구. B1만으로 전체 B/M02 완료 표시 금지

### B2. 아직 게시하지 않은 구성의 명시 해제

- 부분 완료 `ded2e9ff`: Windows 미게시 구성3·해제10·clippy, Linux [미게시 구성3](../../../tests/results/runs/20261025T011253-540cf9fee28a.md)·[해제10](../../../tests/results/runs/20261025T011431-317fd799907b.md) 통과. 임시 폴더·운영체제 대역, 실제 앱/센서/예약 미실행
- 원본 보관·첫 생성·손상 거부·관측 바이트 보존 확인. 최초 시험의 명시 해제 이전 일반 복구 거부 예상은 기존 승인된 동작과 달라 수정, 해제 이후 옛 활성 쓰기 거부 검사는 유지
- 관측 상태 쓰기 보관과 공통 설정 철회/재검토는 미완료. 전체 M02·공개 후보·격리 Windows 긍정 수용 완료와 구분

- 확인: 구성 교체가 원본을 보관한 뒤 멈추면 CONFIG 부재와 관측 원문이 함께 남는 상태. 일반 조회는 계속 오류로 처리, 명시 해제만 검증한 옛 쓰기 의도에서 비활성 구성을 읽는 경로 필요
- 변경: `activation/journal.rs`의 읽기 전용 후보 확인, `activation.rs` 연결, `transition.rs::quiesce_operation`의 명시 해제 전용 선택. 일반 조회·일반 복구의 규칙 변경 없음
- CONFIG가 실제로 없고 명시 해제에 원래 선택 지문/설정 처리 ID가 없는 경우에만 후보 확인. 같은 폴더의 미완료 활성화·CONFIG 쓰기 의도·같은 옛 해제 지문·보관 전후 지문/권한/소유권 전부 확인
- 검증한 보관 원본 우선, 생성 도중이면 검증한 대기 구성 또는 활성화 목표 사용. 후보의 enabled만 false로 설정, 활성 후보를 그대로 게시하는 경로 없음
- 기존 해제 절차가 이 비활성 후보를 저장하고 정확한 예약 해제·감시 종료 확인. 이후 B1 보관 이관·cancelled 처리. 관측 원문은 읽거나 바꾸지 않는 경로
- 검사: 기존 구성 교체/첫 생성의 미게시 지점, 관측 원문 보존, 손상·다른 소유 보관의 무변경 거부, 일반 조회/일반 복구는 이전대로 거부. Windows/Linux 대역, 실제 감시 미실행
- STATE 쓰기 보관은 후속 B3. B2만으로 전체 B/M02 완료 표시 금지

### B3. 관측 상태 쓰기 보관

- 부분 완료 `ee22ae57`: Windows 관측3·전체 기록11·해제10·clippy, Linux [전체 기록11](../../../tests/results/runs/20261025T012820-c16a20b27d42.md)·[해제10](../../../tests/results/runs/20261025T013113-49b3e234059d.md) 통과. 실제 앱/예약/센서 미실행, 임시 폴더·운영체제 대역 범위
- 게시 전후 교체·첫 생성의 네 조합, 복원된 원문과 남은 보관의 재실행, 손상된 관측 보관 보존 확인. CONFIG 회귀 유지. 최초 컴파일의 대상 종류/보관 이름 변수 충돌 수정 후 통과
- 구성/관측의 실제 취소 복구는 완료, C의 공통 설정 화면·진행/종료 기록 연결과 격리 Windows 긍정 수용 미완료. 전체 M02 완료와 구분

- 변경: `user_install/monitor_claim_retirement.rs`의 두 고정 대상(CONFIG/STATE) 처리와 `activation/journal.rs`의 상태 취소. 임의 경로 입력은 추가하지 않는 구조
- 실제 감시 종료·비활성 구성 확인은 기존 해제 절차에서 완료. 현재 STATE가 있으면 바이트를 바꾸지 않고, 검증한 남은 보관만 `state-claim/`으로 이관
- 현재 STATE가 없으면 보관 원본/대기 바이트를 같은 취소 보관의 `state-before.bin`/`state-after.bin`으로 먼저 보존. 기존 `recover_user_setup_record`로 원래 상태만 복원, 새 상태의 첫 생성은 게시 없이 취소
- 복원 전후의 중단은 기존 쓰기 보관 도구로 재개. 복원된 현재 상태가 있으면 남은 보관만 이관, 다시 초기화하지 않는 처리. CONFIG 비활성 값과 관측 원문·권한 보존
- 그 뒤 옛 WRITE 비교 제거와 cancelled 처리. 보관의 모르는 객체/지문/권한 변경은 보존 후 pending, 새 활성화로 자동 우회 없음
- 검사: 게시 전/후 STATE 교체·첫 생성·복원 뒤 남은 보관 재시도·손상 거부, 현재 관측 원문·실패 구간 보존. CONFIG 회귀 함께 확인. 운영체제 대역·개인 설치/센서/실제 예약 미변경
- C의 공통 설정 재검토와 격리 Windows 실제 활성화는 계속 별도 미완료

## C. 공통 설정의 철회·새 검토 연결

- C1 `d787b4e0`: [취소/인계 기록 계약과 근거](monitor-setup-review-0.14.0.md). Windows 설정212·Linux214·clippy 통과, CLI 질문/실제 감시 정지 연결은 C2 미완료

- 네이티브 활성화는 설정/하네스 검증 뒤 시작하는 기존 순서 유지. 별도 기본 거부 질문에서 감시 해제·이미 적용한 선택의 보존·새 검토 범위를 표시
- 코드 진입 전 B의 복구 결과와 `progress_store/history`의 종료·답안 삭제 규칙 확인, 정확한 취소 기록 형식·입력 옵션·실패/재개 순서 확정
- 실제 개인 Windows 예약/앱 제어 제외. 격리 Windows 긍정 수용은 환경 확보 뒤 별도, 나머지 독립 구현 지속
