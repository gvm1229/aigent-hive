## QSI-012 — 실제 작동과 효과의 수용

- 선행: QSI-004–011
- 신규 scripts/accept-score-improvement.py: 자료·영수증·결과·원본 지문 검사 담당, 모델/API/하위 에이전트 실행 없음
- 실제 작업 실행·위임·평가 모델은 현재 구독 호스트가 소유
- 신규 tests/conformance/contracts/test_quality_acceptance.py로 수용 검사기의 거짓 성공·빈 실행·다른 대상 거부 시험

### 구분된 수용표

| 범위 | 실제 확인과 합격 조건 |
| --- | --- |
| 결정적 core/CLI | Windows x64·Linux x64·macOS arm64에서 같은 입력·점수·거부 결과 |
| Codex·Windows 소스 | 실제 source adapter의 준비·호스트 소비·평가·독립 검증·재개. 소스 루트 .hive 생성0건 |
| Codex·Windows 소비자 | 새 시험 프로젝트의 같은 흐름, 등록되지 않은 사용자 자료와 실사용 설치 변경0건 |
| 평가자 교정 | 네 종류의 고정 자료와 실제 호스트 평가, QSI-004 기준 충족 또는 해당 조합 참고 모드 유지 |
| 산출물 수정 | 고정 실패가 수정되고 실제 산출물 지문 변경, 가짜 재채점·필수 실패 평균 상쇄0건 |
| 후보 격리 | 허용 경로·네트워크·쓰기 경계 실제 증거. 미입증 환경의 자동 시험 활성0건 |
| 후보 비교 | 기준 포함·동일 조건·보류 사례·필수 조건·회귀 검사. 단순 선택 성공과 개선 입증 구분 |
| 예산·취소 | 두 반복의 하나의 예약 장부, 응답 유실·늦은 결과·이중 환불·중간 취소 반례 |
| 경험 | 조건 일치 재사용, 다른 프로젝트 유출·미검증 전역 승격0건, 회귀 비활성·사용자 편집 보존 |
| 다른 호스트 | Codex·Claude·Antigravity 각각 전달·결과·취소·격리·역할의 실제 지원 표. 미검증 조합 비활성 유지 |

- 호스트 없는 OS에서 모델 실행 성공을 추정하지 않는 구분. 운영체제별 CLI 검사와 실제 호스트 수용을 별도 기록
- 필수 Codex·Windows의 소스/소비자 준비·평가·검증 수용이 없으면 QSI-012 완료 불가
- 격리·인증·교정이 입증되지 않은 자동 경로는 제품 기능 상태에 명시. 실제 효과 완료를 정적 검사만으로 선언 금지
- 사람 검토·외부 환경이 필요한 부분은 담당과 필요한 증거를 명시, 독립 구현·검사는 계속 진행
- 성능 비교: 같은 작업·자료·모델·예산의 기준과 변경안을 비교, 점수·완료율·전체 호출/시간/관측 사용량·미채점 모두 보고
- 성공에 유리한 사후 정책 변경 금지

### 실행 순서·증거·공개

1. 가까운 단위·스키마·보안·복구 시험
2. python scripts/dev-check.py rust 및 python scripts/dev-check.py python
3. 실제 호스트 수용과 교정 기록, 실패·미지원 결과 보존
4. 현재 PLAN.md의 정확 버전·다음 번호 재확인, 정확 소스 CI와 공개 번호 시험
5. 공개 파일로 새 설치·이전 설치 갱신·선택 기능 기본 비활성·자료 보존 재수용

- test-artifacts로 생성 자료의 소유권·목적·결과 보존. 실패 증거의 자동 삭제 없음
- 실행 기록: OS·호스트·제품/모델/평가표 버전·소스 SHA·입력/산출물 지문·통과/실패/미실행 이유·증명 한계
- 모델 사용량 미관측은 unavailable, 임의 비용0 또는 추정 토큰을 실측으로 보고 금지
- 정식 main 통합·태그·게시·실사용 설치는 해당 버전의 별도 승인. 번호 시험 수용을 정식 완료로 표시 금지
- 완료: 12개 항목의 해당 증거, 필수 실제 수용, 사용자 자료 보존. 남은 자동 경로의 지원 한계 명시
