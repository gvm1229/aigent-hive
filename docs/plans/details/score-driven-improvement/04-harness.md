# 04 — 제한된 하네스 개선과 경험 재사용

- 상위: [최종 계획](../../score-driven-improvement-0.14.0.md)
- 소유 항목: QSI-007·008
- Harness²는 참고 방법. 제품·실행기·모델/API 코드의 이식 없음

## QSI-007 — 후보 범위와 격리

- 선행: QSI-005·006
- 신규: crates/hive-core/src/harness_improvement.rs의 CandidateManifest·TrialContract·validate_candidate
- 신규: crates/hive-cli/src/quality/candidates.rs
- 신규 스키마: schemas/harness-candidate.schema.json, harness-trial.schema.json
- 기존 재사용: 소유 파일 목록, 대상 고정 읽기, 예상 바이트 비교, prepare-only 호스트 전달

### 진입과 권한

- 기본 비활성. 현재 실행의 명시적 하네스 개선 승인과 고정 예산 필요
- 진입 사유: 독립 근거2건 이상의 같은 구성 결함 또는 사용자의 명시적 하네스 개선 요청
- 환경 장애·권한 부족·불충분한 근거를 규칙 결함으로 자동 해석 금지
- run-only 시험, 프로젝트 지속 적용, 전역 공유, 출하를 각각 별도 권한 범위로 관리
- 이미 승인된 정확한 범위는 재질문 없이 처리. 범위 밖 변경은 후보 준비까지만 수행

### 첫 구현의 편집 대상

- 허용: 명시한 Hive 소유 스킬의 절차 본문·새 스킬, 해당 스킬의 결정적 보조 스크립트, 비권한성 도구 사용 안내
- 금지: 승인·보안·소유권·예산·취소·평가 기준·정답·신뢰 루트·모델 설정·호스트 설정·기밀 처리 규칙
- 권한과 절차가 섞인 파일은 원본 편집 금지, 비권한성 절차의 별도 후보 파일로 분리
- 사용자/타사 파일은 후보 원본으로 읽을 수 있는 범위와 수정 권한을 구분. 자동 쓰기 허용 없음
- 새 훅·플러그인·모델/하위 에이전트 정의의 자동 생성·설치는 첫 구현 범위 밖
- CandidateManifest: 기준 구성·부모 후보·프로필·허용 목록 지문, component_kind, 상대 경로, 변경 전/후 지문, 이유·관련 실패 ID, 요청 적용 범위

### 시험 격리

- 시험 작업·초기 파일 상태·모델/설정·도구·시간/사용량·네트워크 허용 범위를 TrialContract에 고정
- 매 시험의 새 사본과 원본 무변경 확인. 쓰기·네트워크 격리 기능의 실제 호스트 증거 요구
- 보호 경계가 입증되지 않으면 자동 시험 unsupported/unverified, 기존 작업은 유지
- 최종 정답·보류 평가 자료는 시험 실행자·후보 작성자·합성자에게 전달하지 않는 입력 분리
- 외부 메시지·실제 거래·설치·원본 사용자 자료 수정의 반복 실행 금지
- 형식·구문·스킬 참조 검사 뒤에만 호스트 시험 준비. 검사 성공을 동작 안전성으로 표시 금지
- 잘못된 후보는 같은 예산에서1회 수정, 재실패 시 폐기 기록과 기준 구성 유지

### 검증·완료

- 신규 tests/conformance/security/test_quality_candidate_boundary.py를 security lane 등록
- cargo test -p hive-core harness_improvement::tests
- python -m unittest tests.conformance.security.test_quality_candidate_boundary
- 악성 경로·재분석 지점·권한 규칙 변경·정답 접근·외부 부작용·기준 교체 반례
- 완료: 허용된 후보만 격리 시험 준비, 금지 후보의 실제 적용0건. 실패·미지원은 기준 구성 보존

## QSI-008 — 비교·합성·채택

- 선행: QSI-004·007
- 담당 기호: compare_trials, select_candidate, prepare_composition
- 수정: harness_improvement.rs, quality/candidates.rs, quality/run.rs
- 후보: 기준1개를 항상 유지, 일반 결함 수정1개·분야 결함 수정1개, 합성 최대1개
- 근거가 한 종류에만 있으면 해당 후보만 준비. 모든 경우에 두 후보 강제 없음

### 같은 조건에서 비교

1. 후보 작성 전에 해당 작업 종류의 보류 시나리오3개와 입력 지문 고정
2. 각 시나리오에서 기준·각 후보를 같은 조건으로2회씩 실행·평가
3. 개선자에는 작업 자료·실행 관찰·공개 요구만 제공, 최종 검증용 점수·정답은 비공개
4. 평가 완료 뒤 독립 비교자가 채택 판단; 필요한 경우 근거 있는 변경을 한 번 합성
5. 합성 결과도 같은 전체 시험 묶음 수행. 남은 예산 부족 시 합성 생략

- 새 보류 시나리오는 QSI-004의 교정 자료와 분리. 후보 작성에 사용한 작업은 전이 증명의 보류 사례로 사용 금지
- 전체 시험 묶음과 마지막 검증 예산을 예약할 수 없으면 시작하지 않는 처리
- 관측 누락·오염·환경 불일치가 있는 비교는 무효, 유효한 부분만 골라 채택 금지
- 기준과 후보의 실제 표본·모델·채점표·평가자·관측 비용 함께 보존

### 첫 채택 규칙

- 모든 필수 조건과 각 평가의 완료 기준 통과
- 각 시나리오의 후보 평균이 기준 평균 이상, 3개 중2개 이상에서 개선
- 전체 평균 개선 단위 >= max(3, 해당 교정의 반복 변동 단위+1)
- 평균 비교는 정수 합과 분모로 수행, 표시 반올림을 채택 근거로 사용 금지
- 예산·시간·권한·자료 보존의 악화 없음. 비용 단축만을 이유로 품질 열화를 허용하지 않는 규칙
- 동점·작은 차이·판단 불가·회귀는 기준 유지
- 초기 정책 수치의 일반 효과 미증명. 변경은 명시한 새 정책 버전과 재교정으로만 처리
- trial_selected는 시험 후보 선택, accepted는 독립 검증된 해당 범위의 채택. 둘 모두 일반 작업 전체 완료·출하 권한과 구분
- 현재 작업의 최종 산출물에는 기존 Judge·완료 계약 유지

- 완료: 동일 계약에서 재현된 이점만 채택, 실패 시 사용자 파일과 기준 구성 불변
