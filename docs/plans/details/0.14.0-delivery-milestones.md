# 0.14.0 남은 구현의 검증·커밋 단위

기준일: 2026-10-25. 사용자 요청: 구현 재개 전 작은 완료 단위 제시, 반복 검토 축소, 단위별 `ship`, 실제 0.13.1 설치 보존.

## 범위·진척의 의미

- [승인된 제품 계획](../0.14.0-implementation.md)의 기능·완료 조건·승인 경계 유지. 이번 변경은 실행 순서와 하위 작업의 구체화
- 공식 완료는 P140-001, 전체 1/15. M00–M24는 미완료 항목의 하위 작업이며 별도 제품 완료 항목과 구분. 단순 개수 비율을 코드 완성률로 환산 금지
- 기존 부분 구현·검증은 [현재 상태](../../state/CURRENT.md)의 근거 재사용. 이미 검증한 기능의 재작성·처음부터 재검토 제외
- 2026-10-25 실행 재개 승인. M00부터 남은 구현·검증·번호 공개 시험 진행, 실제 사용자 설치 변경 제외
- 소유자: 현재 구현 작업자. 별도 에이전트·채팅 생성이나 다른 채팅 지시는 이 계획으로 자동 승인하지 않는 경계

## 반복을 줄이는 실행 규칙

1. 한 번에 구현 단위 하나. 진입 시 변경 경로·관찰할 결과·가까운 검사·커밋 목적 고정
2. 해당 코드·기존 근거 확인 → 변경 → 가까운 검사 → 격리 CLI 확인 → `ship` → 상태 갱신. 구체적 실패나 변경 입력이 없으면 추가 검토 종료
3. 재검사 조건은 관련 코드·의존 코드·입력·환경 변경 또는 재현할 실패. 문서 수정만으로 제품 재빌드·전체 회귀 금지
4. 전체 Rust/Python 검사는 M21에서 한 번. 이후 관련 변경만 재검사. 정확한 소스 CI와 공개 파일 수용은 별도 필수 증거
5. 소유권·동의·복구·자료 보존 검사는 유지. 주변 정리·새 범용 추상화·같은 내용을 담은 여러 보고서 제외
6. 같은 원인 가설로 두 번 실패하면 재현 근거와 다음 확인 하나를 기록. 같은 명령의 무조건 반복 금지
7. 능동 작업 60분마다 실행 결과 또는 구체적 실패 근거 확보 여부 점검. 없으면 범위 축소나 단일 진단 단계로 분리. 시간은 완료 약속·검사 생략 근거와 구분
8. 시험·커밋 직렬 수행, 검사 중 소스 변경 금지. 공용 빌드 경로·`CARGO_INCREMENTAL=0`·기존 산출물 수명 규칙 유지

## 실제 0.13.1 설치 보호

- 사용자 루트·프로젝트·설치 prefix·npm 캐시·호스트 설정·PATH를 시험 경로로 명시. 개인 설치 경로·링크 탈출·격리 변수 누락은 실행 전 거부
- 개인 계정의 전역 npm 설치/제거, 실제 `hive update`, 실제 하네스·감시·예약·호스트 설정 변경 금지. 시험 준비를 위한 실제 설치 복원·재설치도 제외
- 공개 0.13.1 원본은 시험 폴더의 고정 지문 파일 사용. `.exe`뿐 아니라 `.cmd`와 구버전의 실제 호출 형태 확인. 시험 대역 누락 시 실제 명령으로 폴백 금지
- PATH·환경 변수만으로 OS 격리 주장 금지. 본체 설치/제거·실제 예약 활성화·앱 제어는 개인 환경과 설정/파일/예약을 공유하지 않는 VM·Sandbox 등에서만 실행
- 호스트에서 실행하는 시험은 대역과 시험 폴더 쓰기로 제한. M00에서 Windows 격리 OS·Linux PTY·macOS arm64·호스트 소형 모델 평가 경로의 가용성 확인. 환경 부재는 해당 증거의 미실행으로 기록, 독립 작업 지속
- 실제 실행 파일·기존 네 설정 파일의 전후 지문은 보조 확인. 사용자 폴더 전체 무변경의 증명으로 확대 금지. 하위 명령·쓰기 경로·격리 설정 함께 기록
- 위반 시 해당 시험 중단·영향 경로 보존·보고. 실제 설치 자동 수정으로 실패를 숨기는 처리 금지

## 검증·ship·진척 기록

- 부분 Rust: `python scripts/dev-check.py rust -- test -p hive-cli <실제 모듈 필터> --locked`. 단위 진입 시 존재하는 시험 이름으로 필터 고정, 변경 crate·관련 Python 회귀·격리 CLI 절차 추가
- 전체 M21: `python scripts/dev-check.py rust`, `python scripts/dev-check.py python`. 산출물 생성 명령은 기존 `scripts/test-artifacts.py run` 기록 사용
- 증거: 단위 ID·소스/파일 지문·명령/결과 위치·OS/호스트/격리 방식·통과/실패/미실행 이유·증명 범위와 한계
- `ship`: 한 목적의 diff 확인 → 해당 파일/부분 stage → 가까운 검증 → 로컬 커밋 → 본문·남은 변경 확인. 별개 목적은 별개 커밋, 문서/제품 기본 분리. 다른 채팅 문서·미완료 코드 stage 금지
- 완료 단위의 커밋을 다음 구현 뒤로 미루는 처리 금지. 단위마다 사용자에게 동작 변화·검증 범위·커밋·다음 단위·막힌 이유 간단 보고
- 이 표는 세부 작업 정본. [CURRENT](../../state/CURRENT.md)는 현재 단위·예외만 연결, [PLAN](../PLAN.md)은 기존 공식 집계 유지. 같은 근거의 장문 보고서 반복 생성 제외
- 이번 계획 작성은 제품 완료율 변화 없음. 재개 후 각 단위 통과 시 상태 칸에 증거·커밋 링크 추가
