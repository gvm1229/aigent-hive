# 프로젝트 저장 경계 설계 후보

[상위 계획](../../backlog/project-local-global-readonly.md) · [순서](steps.md) · [수용·이전](acceptance.md)

## 기존 기능 보존 계약

- 명시적으로 새 모드를 선택한 프로젝트에만 적용. 기존 읽기·쓰기의 기본값·저장 위치·승격·검색·권한·자동 복구·연결 수명 동작 유지
- 필드 생략·기존 답안·기존 프로젝트는 기존 경로로 실행. 업그레이드의 강제 선택·자동 전환·자동 이전·새 필수 질문 금지
- 새 프로젝트에서도 기존 읽기·쓰기 선택 유지. 같은 전역 저장소를 사용하는 두 방식의 공존 지원
- 공통 연결 상태 수정은 [별도 작업](../../backlog/knowledge-attachment-consistency.md). 이번 기능의 선행 조건·묶음 수정에서 제외
- 완료 기준: 새 기능 수용과 [기존 동작 보존 회귀](compatibility.md)의 동시 통과. 단순 기존 시험 재실행만으로 모든 보존 주장 금지

## 선택한 최소 설정

아래 이름·형식은 전부 제안. 공개0.14.0의 기능·필드와 구분.

```yaml
schema_version: 3
knowledge_store_mode: project-local-global-readonly
```

- 기존 schema 1·2 답안과 필드 생략: `shared-user-root`로 해석, 현재 사용자 동작 유지
- 새 모드: 정본·추출 사실·색인·벡터·그래프·캐시·잠금·처리 기록 전부 프로젝트 아래. 기존 `--user-root`는 결합된 전역 읽기 출처 선택에만 사용
- `knowledge-scope.yml` 새 판과 `harness.toml`·프로젝트 원본 기록에 같은 유효 정책·지문 투영. 저장 위치·권한을 승격 범주나 검색 공개 범위에서 추론 금지
- `project-private` 등 공개 범위와 페이지 승격 범주 유지. 새 모드의 전역 쓰기 금지가 모든 승격·자동 승격보다 우선
- 새 `.hive/config/knowledge-store.yml` 제안: 형식 판, 저장소·프로젝트·collection의 안정된 ID, 모드, 정책 지문, 선택한 전역 출처의 결합 정보. 경로를 ID 재생성의 근거로 사용 금지
- 새 로컬 저장소의 `store_id`·`project_id`: 각각 난수16바이트의 32자리 16진수와 고정 접두어. collection ID는 기존 `derive_collection_id("project", project_id)` 사용. 이전 때는 기존 프로젝트·collection ID 보존, 저장소 ID만 새 생성
- 초기 프로젝트 설정에 별도 전역 설치 요구 없음. 기존 전역 설정은 읽기만 수행. 전역 설정 부재 시 명시한 한국어·위키 선택과 현행 공통 기본값으로 로컬 설정 가능

단일 모드 선택의 이유: 별도 저장 위치·쓰기 권한 조합의 모순 방지. 지침 수정, 승격 해제, 가짜 구버전 인증, 두 사용자 루트의 수동 교대는 요청 기능의 대체에서 제외.

## 중앙 경로와 권한

제안 자료형: `KnowledgeRoute`, `WriteAuthority`, `ProjectLocalStore`, `GlobalReadSnapshot`. 기존 API 이름과 구분.

1. CLI 진입에서 현재 작업 폴더와 명시 `--target`의 검증된 프로젝트 정책 확인. 두 정책 충돌·모호한 대상은 쓰기 전 거부
2. 모드·대상·정책 지문·저장소 ID에 결합한 권한 생성. `--user-root`, 요청의 `collection_id=user-root`, 인자 생략, 경로 별칭으로 목적지 변경 금지
3. 새 모드의 쓰기에 결합 권한 전달. 전역 읽기 객체에는 생성·잠금 게시·동기화·재구축·복구·승격 함수 부재. 기존 공유 모드는 기존 `RagStore` API·쓰기·잠금 경로 유지
4. 권한 확인을 디렉터리 생성, 설정 진행 기록, 오래된 형식 변환, 잠금·승인 소비보다 먼저 수행. 로컬 모드에서 금지된 전역 작업은 부분 변경 없이 명시 오류
5. 사용자가 승인한 정책 재설정만 모드 변경 가능. 임의 입력 파일의 새 값만으로 기존 보호 경계 교체 금지. 재개 시 정책·파일 식별자·지문 재확인

대상 없는 `remember/refresh/index/transfer`도 새 모드를 선택한 현재 프로젝트에서는 같은 검사 적용. 기존 모드에는 새 쓰기 제한 부과 금지. Hive 명령 경계의 보장으로 한정; 다른 프로그램·직접 파일 편집·다른 실행 문맥의 쓰기 차단은 운영체제 권한 격리의 별도 역할.

## 프로젝트 저장소

- `.hive/knowledge/{Raw,Wiki,Schema,Claims}` 정본. `Claims`는 추출한 사실과 출처·교체 관계의 Markdown
- `.hive/index/` 아래 SQLite, 세대 정보, 변경 중 표시, 벡터·그래프·임시 파일·처리 기록. 정본 식별·검증 정보는 프로젝트 `.hive/config/` 아래
- 설정 진행·재개·복구·수명 기록도 프로젝트 내부. 전역 `projects.yml`·`collections.yml` 등록과 전역 설정 진행 기록의 생성 생략
- 현재 `RagSnapshot`, 청크 생성, 출처·민감 정보 검사, 정본 게시·되돌림·파일 식별자 검사를 재사용. 청크는 검색할 작은 문서 조각
- 현행 사용자 루트 전용 기본 collection 가정의 분리. 로컬 등록부에는 자체 프로젝트 collection만 허용, 외부 프로젝트를 읽는 등록 행의 자동 추가 금지
- `remember --target`·`ingest --target`·`scan --apply`의 목적지는 같은 로컬 저장소. 디렉터리 검토의 자동 전역 승격도 금지, 로컬 검토 사실 저장은 유지
- 일반 scan의 재사용 후보 표시는 보존하되 전역 게시 단계 제외와 정책 사유 출력. 명시적인 전역 게시 요청은 배치 전체의 첫 쓰기 전 거부
- 로컬 lint·refresh·재구축·삭제·억제·이전·그래프·벡터는 기존 동의·검증을 유지하며 로컬 경로 사용. 선택 기능 미설치 시 기존의 명시적 제한 표시

## 전역 무쓰기 조회

- 기존 게시 SQLite 바이트를 읽어 메모리에서 검색. 전역 읽기 경로에서 쓰기 파일 열기·잠금 생성·측정 기록·캐시·자동 수리 금지
- 등록부·세대 정보·검증 정보·SQLite와 정본 출처의 일관성 검사. 읽기 전후 지문·파일 식별자·변경 중 표시 재검사, 변경 시 최대 3회 다시 읽은 뒤 명시 오류
- 전역 `-wal/-shm/-journal`, 미완료 기록, 손상·미지원 형식 발견 시 자동 checkpoint·복구 금지. 정상 게시 스냅샷으로 확인하지 못한 상태의 사용 거부
- `auto`: 로컬 결과와 전역의 기존 전역·공유 결과를 메모리에서 합산. 프로젝트 결과 우선, 저장소 ID와 collection·문서·조각 ID로 출처 표시·중복 제거, 총 건수·바이트 예산 유지
- 전역 출처 부재·오래됨·손상 시 로컬 결과와 명시적인 전역 사용 불가 진단. 전역 범위만 요청한 경우 실패. 자동 초기화·이전·재구축 없음
- 검색어·로컬 결과·로컬 ID를 전역 색인·그래프·벡터·로그에 기록 금지. 첫 구현의 전역 결과 영구 캐시 생략
- 전역 의미 검색은 이미 검증된 벡터 읽기만 허용. 없거나 오래된 경우 이유와 일반 검색 사용 표시. 로컬 의미 검색·관계 그래프 생성은 프로젝트 안에서 계속 지원
- 전역 승인 토큰 소비가 쓰기를 요구하는 비밀 조회는 쓰기 전에 거부. 일반 전역·공유 읽기와 로컬 비밀 지식 기능의 해제 금지. 별도 무쓰기 승인 계약 전 지원 주장 제외

## 해제와 동시 실행

- 새 로컬 저장소의 해제 상태는 명시 attach 전까지 보존. 전역 등록 동기화를 호출하지 않는 구조로 무단 재연결 방지
- 새 모드의 자동 복구·업그레이드·재개도 같은 계약. 전역 읽기 출처의 등록·연결·해제·수리 수행 금지
- 기존 공유 모드의 `sync_project_registry`·재활성화 의미·오래된 목록 처리 수정은 별도 승인 전 제외
- 기존 공유 사용자의 명시 attach/map/detach 승인·공유 잠금·세대 게시 경로 유지. 새 모드 사용 때문에 기존 collection이 해제되거나 변경되는 결과 금지
