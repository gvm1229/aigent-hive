## 시험 설계

새 회귀 파일 제안: `crates/hive-cli/tests/project_knowledge_boundary.rs`, `tests/conformance/integration/test_project_knowledge_boundary.py`. 저장소 내부 시험은 기존 `store/rag/knowledge_lock` 묶음 확장. 새 이름은 제안이며 기존 파일로 오인 금지.

가짜 G·프로젝트 A·무관한 B 세 영역, 고유한 가짜 검색 표식, 모든 사용자·캐시·임시 경로 격리. 전역 정본뿐 아니라 전체 지식 경로의 파일 목록·내용 지문·권한·수정 시각·디렉터리 사건 검사. SQLite `-wal/-shm/-journal`, 잠금, Claims, 벡터·그래프, 세대·검증 정보, 캐시·복구·처리 기록 포함.

각 명령 앞뒤 독립 비교, 감시 시작 확인과 넘침·실패의 즉시 시험 실패. 쓰기 권한을 제거한 환경의 실행을 추가하되, 쓰기를 시도했다가 OS가 막은 결과를 Hive 무쓰기 통과로 계산 금지. Windows는 파일 접근 계측, Linux/macOS는 적절한 파일 접근 추적. 읽은 파일의 접근 시각처럼 OS가 바꾸는 속성과 Hive의 쓰기 요청 구분.

## 선택적 이전

새 프로젝트 지원과 기존 shared 사용자 유지가 선행. 실제 이전은 이번 조사에서 제외. 추후에도 별도 현재 작업 승인 필요.

1. **읽기 미리보기:** 프로젝트 소유 Wiki·Raw·Claims와 교체 관계·ID·전역 등록·파생 자료 목록의 지문 수집. 무관한 공유 사실·여러 프로젝트 출처가 섞인 사실은 별도 검토 대상으로 표시. 미리보기의 쓰기 0건
2. **로컬 준비:** 프로젝트 내부 임시 위치에 검증한 사실·이력 복사, 원래 ID·출처·교체 관계 보존, 로컬 색인 새 생성. 기존 Wiki·Raw의 내용·기존 파일 경로 유지. 중단 시 이전 모드 유지
3. **별도 전역 유지보수 승인:** 기존 전역 등록이 프로젝트를 계속 읽으면 이후 타 명령의 재구축이 새 프로젝트 자료를 다시 가져올 위험. 정확한 이전 지문에 결합한 일회용 승인으로 기존 전역 source 등록 해제·collection 해제·소유 사실과 파생 자료 정리. 일반 읽기 전용 명령의 예외로 조용히 허용 금지
4. **검증과 전환:** 전역에 남은 해당 source 경로·활성 색인 행·파생 자료의 부재, 로컬 ID·출처·이력 대조 뒤 새 정책 원자 게시. 이 시점부터 일반 프로젝트 작업의 전역 쓰기 0건
5. **중단·복구:** 두 저장소를 한 번에 바꾸는 원자성 주장 금지. 프로젝트 안의 이전 처리 기록으로 단계·예상 지문·승인 범위 보존. 전역 정리 후 로컬 전환 전 중단은 복구 필요 상태로 표시, 자동 재연결·자동 전역 되돌림 금지

정리 승인 부재·지문 변경·소유 불명 상태에서 성공 전환 금지. 전역 정리가 필요한 기존 사용자의 경우 명시적인 대기 사유와 정확한 예정 변경 제시. 이미 읽기 전용 정책인 프로젝트의 유지보수는 별도 승인 경로로만 수행.

예전에 승격된 공유 사실, 공동 출처, 백업·과거 기록의 삭제는 소유 확인과 별도 삭제 승인 없이는 금지. 따라서 “새 전역 유입 0건”과 “과거 사본까지 전부 제거”를 구분. 후자의 조건은 검토·승인·전역 그래프·벡터·캐시·보관 자료 확인 전 미완료 표시. 보존이 필요한 과거 이력은 로컬 검증본에서 유지.

## 위험과 최종 종료

- 가장 큰 위험: 권한 검사 전의 느린 초기화·수리·진행 기록, 자동 승격, 저장소 밖의 벡터·관계 기록
- 동시 실행 위험: 오래된 등록 목록, 여러 파일을 게시하는 전역 스냅샷 읽기, Windows 잠금 경합의 접근 거부
- 성능 위험: 전역 바이트 재검사 비용. 성능 개선이 무쓰기·최신성 검사를 약하게 하는 근거가 되지 않는 경계
- 최종 통합: KB-A1–A9, 문서·스키마·정본 스킬 투영·소스 사실 검사, 새 버전의 공개 시험·지원 운영체제별 실제 수용
- 제품 모드 완료와 실제 사용자 이전 완료의 별도 보고. 현재 계획 문서 완료율을 제품 구현 완료율로 사용 금지
