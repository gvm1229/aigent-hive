# M11 Linux 적용 작업자의 수명 연결

- 발견: [적용 중 부모 종료 실패](../../../tests/results/runs/20261024T203436-c23f0275d3b6.md). 원본 갱신 부모 종료 뒤 조정 프로그램과 분리된 적용 작업자·호스트 명령 잔존. 실제 개인 설치와 분리한 Linux 컨테이너의 합성 입력
- 범위: M11의 부모 종료 복구. Windows의 기존 JobObject 유지, macOS·사용량 감시·호스트 앱 종료로 확대 금지
- 소유: `crates/hive-cli/src/user_setup/setup_engine/worker.rs`, 새 `worker/lifetime.rs`, `crates/hive-cli/Cargo.toml`, `Cargo.lock`, 정본 Linux 시험 도구

## 구현 순서

1. 요청에 `parent_process_id` 추가. 생성 시 조정 프로그램의 실제 PID, 구형 입력의 기본값 0. 선호·동의·새 실행 권한과 구분
2. Linux 작업자 진입에서만 수명 연결. 현재 프로세스가 별도 그룹의 리더인지, 현재 직접 부모가 요청의 PID인지 확인. 실패 시 파일 적용·신호 없이 오류
3. 이미 잠긴 `nix=0.31.3`의 안전한 `getpgrp/getppid/killpg` 사용. Linux 전용 직접 의존성과 process/signal 기능만 추가. 새 버전·unsafe 코드·OS 도구 설치 없음
4. 작업자 내부의 짧은 수명 확인: 부모 변경 시 자신의 현재 그룹이 여전히 자신의 PID와 같은 경우에만 그 그룹 종료. 다른 그룹이나 앱을 이름으로 조사·종료하는 처리 금지
5. 정상 적용 종료 때 확인 중지. 부모가 작업자를 기다리는 기존 시간 제한·진행 기록·완료 후 응답 순서 유지

## 합격 조건

- 실제 Linux 원본 0.13.1 갱신의 적용 중 부모 종료: 작업자·시험용 호스트 명령 잔존 0건, 자료 보존, 같은 0.14.0 update 재개·설치 반복 0건
- 별도 그룹 없이 내부 작업자 호출: 신호·설정 쓰기 없이 거부, 호출한 시험 도구 생존
- 기존 90초 느린 적용 제한의 종료·재개 유지. Windows 작업자 회귀·코드 검사, Linux 작업자 회귀·정본 실제 사례
- 실제 앱 제어·Windows/macOS의 부모 종료·공개 0.14.0 파일 수용과 구분. Linux 증거로 다른 환경의 합격 대체 금지
