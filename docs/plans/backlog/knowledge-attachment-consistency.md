# 공통 지식 연결 상태의 별도 수정 후보

> 검토일: 2026-11-10

## 범위와 승인

- 근거: [공개0.14.0 진단 D1·D2](../../research/project-local-global-readonly-0.14.0/README.md), 직렬 재연결과 오래된 등록 목록의 결정적 교차 실행
- 읽기 전용 추가 옵션과 별도 작업. 그 기능의 선행 조건·구현 묶음·수용 집계에서 제외
- 현재 승인: 조사와 계획만. 제품 수정·기존 공유 동작 변경·버전 선정·출시 미승인

## 별도 판단이 필요한 동작

- 명시 detach를 공유 등록 동기화에서 유지하는 의미
- 위키 비활성화로 해제된 기존 collection의 재활성화 때 명시 attach를 요구할지 여부
- 오래된 호출자 목록을 잠금 안의 최신 등록부 읽기·예상 지문 검사로 대체하는 방법
- 기존 수집의 입력 검사와 공유 준비 순서 변경. 기존 실패 부수 효과의 변경이므로 새 옵션과 별도 검토

## 변경 후보와 검증

1. `synchronize_project_collection_metadata`, `sync_project_registry`, `shared::rebuild_shared_index`, CLI `ensure_rag_registry`의 현행 동작·호환 영향 확인
2. 명시 해제·자동 비활성화의 상태 전이와 재연결 승인 계약 확정. 기존 사용자에게 바뀌는 절차 미리 표시
3. 오래된 목록의 최신성 검사를 같은 잠금·세대 경계에 결합, 무관한 새 프로젝트·collection 보존
4. 해제 후 setup·refresh·rebuild·동일 remember·실패한 ingest, 다른 새 프로젝트 등록, 명시 attach, 순서를 강제한 동시 실행의 회귀
5. 입력 형식·민감 정보 검사를 준비 변경보다 앞에 둘 경우 검증한 바이트 재사용, 상태 의존 검사는 잠금 안에서 재확인

완료 기준: 승인한 상태 전이·경합·복구의 독립 수용. 기존 동작 변화의 고지와 회귀 필요. 별도 승인 전에는 기존 공유 사용자 경로 변경 금지.
