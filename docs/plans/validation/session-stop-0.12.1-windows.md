# 0.12.1 Windows 세션 중단 수용·설치

> 종료한 실제 시험 절차의 보존본. 추가 실제 중단 시험 없음. 최종 계약은 [한 차례 중단 계획](../active/reset-stop-0.12.1.md)·[알림과 직접 재개](../../research/usage-stop-notice-0.12.1.md)·[설치 완료 근거](../../research/session-stop-installation-0.12.1.md), 아래 잠금·확인 절차는 최종 적용에서 제외

- 승인: 2026-10-18 현재 앱을 닫지 않는 실제 검증, 이유 표시, 통과 후 설치·상시 감시. 다른 기능·정식 게시 제외
- 현재 패키지: OpenAI.Codex 26.1013.4894.0. 이전 26.1007.9446.0의 수용 결과 자동 확대 금지
- 소유: Codex. 기준 RST121-002·003, 새 완료 항목 중복 생성 없음
- 앱 종료·강제 종료·프로세스 일시정지·내부 상태 변조 금지. 모형 서버나 별도 추론 서버를 실제 앱 검증으로 계산 금지

## 1. 규약 재확인과 단일 세션 시험 — RST121-002

- 읽기: `usage_monitor/desktop.ps1`·`desktop.rs`, 설치 앱의 정적 asar. 공식 `turn/interrupt`와 완료 상태 interrupted 확인 계약
- 조사 결과: codex-ipc의 길이 머리글 메시지, 소유자 조회 1, expectedTurnId 생략 중단의 호환 버전 3, 상태 전달 11 유지
- 변경: `desktop.ps1`의 전체 시작 거부를 현재 사용자·공식 패키지·생성 시각·핸들·정확한 새 버전 검사로 교체. Rust의 전역 활성화 차단은 아래 시험 전 유지
- 시험 도구: 새 `scripts/qualify-session-adapter.py`. 제품 PowerShell 파일을 그대로 숨긴 도우미로 실행, stdin의 discover·stop·clear만 사용. 프로토콜 구현 복제 금지
- 입력: 정확한 시험 대화 식별자, 현재 앱 PID·생성 시각, 결과 경로. Windows Codex 호스트가 만드는 작은 시험 작업 하나, 원문·인증 자료 저장 금지
- 순서: metadata-only 연결·소유자 확인 → 정확한 시험 대화에만 중단 → 새 interrupted와 앱 동일 핸들 생존 → 구독 해제·도우미 종료. 시험 도우미의 자식만 정리
- 통과: 실제 실행 1개 이상 중단, 요청 2초·확인 5초 이내, 앱 동일 신원·창 유지. 실패 때 전역 차단 유지·오류 보정 후 변경 입력 재검증
- 증명 한계: 이 단계는 전역 감시·다른 대화·긴 셸·표시·사용자 설치 증명 제외

## 2. 전체 감시기 연결과 행동 회귀 — RST121-002

- 진입: 1의 실제 앱 보존 근거. 변경 `usage_monitor.rs::require_app_safe_control`, `preview`, `desktop.ps1`의 버전 고정. 검증하지 않은 버전은 거부
- 현재 인터페이스 preview·enable·disable·status·acknowledge 유지. 앱 종료 대체 없음, 감지·오류 시한 60초 유지
- 회귀: `test_usage_monitor.py`의 분할·대형 프레임·막힌 쓰기·요청 우선·5초 구독 해제·실행 선택·응답 유실·이유 표시. Rust 상태·중복 제어부·잠금·새 실행 차단·정확한 확인 검사
- 잠금 중 새 실행: 앞선 전체 중단이 확인된 경우만 새 시도의 2초/5초 시한 시작. 첫 확인 실패의 시각 재작성 금지, 최초 성공 영수증 보존. 단일 대상의 의도적 재실행 반례 뒤 전체 시험 진행
- 관측 시한 복원: 활성 관측 시작과 마지막 정상 시각을 공유 상태에 보존. 제어부 재시작으로 60초를 연장하는 처리 금지, 앱 비실행과 명시적 감시 활성화만 새 관측 구간 시작
- 명령: 산출물 수명 도구로 `cargo test -p hive-cli usage_monitor`, Windows 모의 시험, `cargo clippy -p hive-cli --all-targets --no-deps -- -D warnings`, `cargo build -p hive-cli`. 변경한 지침·투영·문서 검사
- 근거: 고정 바이너리 SHA-256·현재 패키지·앱 신원과 정제한 결과. 모의 통과로 전체 현재 앱 지원 주장 금지

## 3. 독립된 실제 감시 시험 — RST121-003

- 소유 변경: `scripts/qualify-usage-monitor.ps1`, 필요한 모의 회귀. 첫 실패 루트 보존, 수정 수용은 `tests/work/usage-monitor-acceptance/20261018-session-stop-v2/`
- 별도 사용자 루트에서 실제 비추론 사용량 관측 네 번 이상, 15초 시작 간격·계정·구간 비교. 전역 사용자 감시는 계속 비활성
- Windows 작업 스케줄러의 독립 검사기가 동작·기록. 새 시험 대화 둘과 하위 작업, 도구 없는 긴 추론·긴 셸의 실제 실행 상태 확인
- 정확한 격리 상태 파일의 과거 기준값만 합성 변경, 실제 센서의 다음 측정으로 제품 초기화 감지. 실제 제공자 초기화와 구분
- 통과: 전체 요청 2초·확인 5초, 실제 실행·셸 종료, 동일 앱 PID·생성 시각·창 생존, 보호 상태 창에 이유·확인 결과 지속, 잠금 중 자동 재개 없음
- 독립 실행 근거: 새 `qualify-session-events.py`에서 정확한 시험 대화만 현재 Codex의 읽기 전용 상태 DB로 찾고, 해당 실행 기록의 task_started·turn_aborted만 확인. 원문·도구 출력 저장 금지, 공개 결과는 식별자 지문·상태·시각만 기록
- 재실행 방지·정확한 사건 확인·새 정상 조회 후 해제와 이전 작업 자동 실행 없음 별도 확인. 관측 공백 60초의 실제 보호 시험은 실제 초기화 이유와 별도 기록
- 60초 시험: 실제 중단 시험 뒤 모델이 멈춘 상태에서 격리 감시기 자식에만 실패 프록시 환경 적용. 공개 disable 뒤 같은 승인 시험 설정만 복원, 실제 사용자 설정 변경 없음. 로컬 대화 목록·제어 연결 유지, 실제 사용량 조회 실패·60초 시한·지정 이유 표시 확인. 실행 중 중단의 증명은 앞선 초기화 시험과 구분. 정상 환경·정확한 사건 확인·새 관측 후 설치
- 현재 작업도 중단 대상일 수 있는 경계. 중단 전 독립 검사·조건부 설치를 모두 준비, 모델에게 정리·최종 답변 요구 없이 중단. 중단 뒤 모델 자동 재개 금지
- 실패 때 격리 감시 예약 제거, 앱·저장 작업 유지, 최종 실패 기록과 실제 설치 금지. 중단 이유 창은 완료 기록으로 보존
- 2026-10-18 실제 중단 뒤 전체 확인 실패: 현재 부모·셸·추론의 중단 사건과 앱 생존을 별도 보존. 설치 차단 유지, 제품 연결 코드를 재사용한 최대 12초 읽기 전용 진단으로 정확한 대화의 응답 크기·상태 처리 오류만 확인. 중단 요청·원문 저장 금지, 원인 재현 뒤 해당 회귀·고정 빌드·새 격리 수용
- 확인 보정: 중단 요청 전부 발송 후 첫 응답을 우선 처리, 최대 1.8초 뒤 상태 확인 진행. 전체 상태 요청은 한 번에 하나만 대기, 미수신 상태의 반복 요청 금지. 2초/5초 기준 유지, 실제 중단 식별자는 목표 일시정지 오류와 별도 보존
