# 0.12.0 승인 뒤 실제 호스트 검증

- 요청: 남은 기준의 자동 작업, 앞서 설명한 필요한 수동 승인 허용
- 승인 적용: Antigravity 상태 표시 연결의 검토·변경·복원, Windows 샌드박스의 공식 복구 시도. 관리자 확인 창·앱 재시작은 실제 사용자 조작이 필요하면 별도 안내
- 환경: Windows·현재 Codex, 설치 Antigravity CLI1.2.16·Codex CLI0.159.0. 기존 증명1.1.18의 지원 범위를 새 버전에 자동 확대 금지
- 제품: 공개0.12.0-test.2를 격리 사용, 현재 사용자 설치0.11.1 보존. 제품 수정이 필요하면 다음 번호test.3
- 경계: 소스 루트에 소비자 설정 없음, 모델 제공자 API·자격 증명 요청 없음. 현재 호스트 제어 연결·서명이 없으면 해당 자동 실행 비활성

## A: 승인과 준비

- 소유 기준: HCT112-001·QLF112-002, 현재 Codex
- 변경: 활성 계획·해당 기준·현재 상태·ADR에 이번 승인 기록, 원래 기준·ID·실제 증거 요구 유지
- 정확한 공개 패키지를 `tests/work/host-acceptance-0120`에 설치, 버전·배포 지문 확인. 기존 합성 소비자 초기화 경로로 하위 시험 프로젝트 준비
- 검증: 계획·문체·링크 검사, Source Wiki 출처 갱신. 연결·호스트 실행의 성공으로 집계 제외

## B: Antigravity 실제 전달

- 변경 대상: 공식 `~/.gemini/antigravity-cli/settings.json`의 `statusLine`, 소유한 격리 연결 스크립트. 나머지 설정 바이트 보존
- 현재 항목 부재 확인. 기존 사용자 명령이 생기면 자동 교체 금지, 정확한 새 상태 확인 뒤 보존 방식 결정
- 연결: `type=command`, `stack_with_default=true`; 입력은 메모리에서 공개 Hive의 `usage capture --host antigravity --target-from-stdin --stdin-json`으로 전달
- 시험 폴더의 콜백만 처리, 다른 프로젝트·소스 루트에 대한 기록 없음. 버전·입력 지문·수신 결과·모음·초기화만 정제한 증거에 보존, 이메일·원문 JSON·대화 원문·개인 경로 저장 제외
- 현재 CLI의 실제 콜백·두 모음·수신 최신성·계정/대화 결합·실제 사용량 표시 대조. 새 버전의 미지원 계약은 차단·대기로 보존
- 종료: 입력이 변경된 실패만 제한 재시도, 설정을 직전 상태로 복원·기존 표시 확인. 콜백 없이 설정 생성만으로 HCT112-001 완료 금지

## C: Windows 공식 복구

- 재사용: 기존 `sandbox_probe112.py`의 동일 실행 파일·격리 파일·일반/공백/한글 경로·단일/동시 읽기. 출력 폴더·보고는 이번 버전으로 분리, 원래 실패 증거 보존
- 현재0.159.0에서 직접 읽기와 기본 샌드박스 읽기부터 비교, 명령 실행 전 권한·잠금·시작 실패와 본문 실패 구분
- 실패 시 공식 진단과 설치한 도구의 지원 명령만 확인. 승인된 관리자 설정 실행이 가능한 경우 수행, UAC 사용자 조작·Codex 재시작이 필요하면 정확한 수동 단계로 보존
- 전역 권한·방화벽을 임의로 완화하지 않는 공식 설치 절차. 복구 뒤 같은 제한 조건 재검증, 더 약한 방식의 성공을 원래 조건 통과로 대체 금지

## D: 독립 검증과 종료

- 현재 실행의 호스트 소유 제어 연결·모델/역할 확인·누적 사건을 실제로 제공하는지 조사. 별도 사용량 서버를 현재 앱의 제어 서버로 사용 금지
- 정제한 결과·실패·정확한 바이너리 지문 커밋, 각 기준의 상태 갱신. 지원 연결 없이 Hive 검증형 작업 흐름이 활성이라고 표시 금지
- source의 기존 계획이 실행 정본. 지원되는 runner 결합이 확인된 경우에만 loop initialize/validate의 정확한 영수증으로 활성화 판정
- 남은 안전한 독립 작업 완료 뒤 사용자 조작 또는 외부 연결·증명 대기만 인계. 실제 macOS는 마지막 QLF112-005 유지
