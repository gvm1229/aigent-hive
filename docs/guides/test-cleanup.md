# 시험 파일의 매일 정리

## 목적

시험 결과는 작은 문서로 보존하고, 다시 만들 수 있는 큰 빌드 파일·시험 복제본의 누적 방지.
관리 대상은 `tests/work`의 개별 경로와 `target/debug`·`target/release`·`target/x86_64-pc-windows-gnu`.
소스·Git·동결 원본·사용자 프로젝트는 삭제 대상 밖.

## 실행

```powershell
python scripts/test-artifacts.py daily
python scripts/test-artifacts.py daily --apply
```

- 첫 명령: 삭제 없는 미리보기, 두 번째 명령: 검토 완료 경로만 실제 정리
- 기본 용량 상한: 관리 영역의 중복 없는 합계 20GiB
- 결과 `ok`·종료 코드 0: 현재 관리 범위의 조치 필요 항목 없음
- 결과 `attention-required`·종료 코드 1: 용량 초과·측정 불가·정리 실패·미검토 또는 만료 항목 존재
- 종료 코드 2: 명령·파일·프로세스 검사 오류, 성공으로 처리 금지
- 보존 예약도 용량 계산에 포함, 상한 초과가 삭제 권한으로 전환되는 동작 없음
- 매일 한국 시간 09시 Codex 대화 자동화 실행, 등록 상태와 실제 예약 실행 결과 구분

## 검토 순서

1. 현재 실행 중인 시험과 재사용할 정확 경로 확인
2. 완료 결과의 작은 Markdown·필요한 JSON만 `tests/results/`에 보존·검토·커밋
3. 소유자·근거·현재 미사용을 확인한 정확 경로만 `review`의 `completed`로 등록
4. `daily` 미리보기와 `daily --apply` 실행, 제거 경로·논리적 바이트·드라이브 여유 공간 확인
5. 오류·미확인 소유권은 원인 조사, 단순 보존 기한 연장으로 완료 처리 금지

실행 중·지문 변경·Git 추적 파일·연결 경로·미커밋 근거의 삭제 거절.
실패 자료는 작은 재현 입력과 결과 보존 뒤 명시 검토. 큰 환경 복사본의 무기한 보존 제외.
필요한 재사용 예약은 작업명·정확 경로·최대 72시간 기한 명시. 검사 종료 뒤 같은 작업에서 해제·정리.

## 재발 방지와 복구

- 기존 실행기의 `CARGO_INCREMENTAL=0` 기본값으로 Rust 증분 캐시 억제, 명시 재사용 설정만 예외
- 시험·재시도마다 새 Cargo 빌드 폴더 생성 제외
- 빌드 폴더의 종료 검토는 관련 검사 완료·활성 설치의 별도 경로 확인 뒤 수행, 임의 `target` 하위 폴더 삭제 제외
- 삭제 기록: `tests/results/cleanup/`, 변화 없는 반복 실행의 새 정리 기록 생성 없음
- 결과 문서는 Git 복구 가능, 삭제된 원시 빌드·시험 환경의 직접 복구 보장 없음
- 재생성에는 해당 소스·입력·도구 필요, 과거 통과 결과로 현재 소스 통과를 대신 증명하는 방식 제외
