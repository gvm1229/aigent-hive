# 압축 뒤에도 프로젝트 지침 이어 가기

긴 대화를 줄인 뒤에도 중요한 약속을 다시 전달하는 선택 기능. 필요한 지침만 짧게 복원하여 전체 문서를 반복하는 비용 감소가 목적.

## 사용 흐름

1. 프로젝트를 지정해 “이 프로젝트의 지침을 압축 뒤에도 유지하도록 설정해 줘”라고 요청
2. project-setup 스킬이 핵심 문구·작업별 문구·보호할 경로를 선택하고 미리보기 제시
3. 선택 문구·경로·훅 등록 내용 검토 뒤 정확한 미리보기 승인
4. 설정 확인 뒤 실제 호스트에서 전달 여부와 반복 압축 후 행동 확인

기존 Hive 갱신만으로 자동 활성화하지 않는 선택 기능. Hive 없는 협업자의 일반 작업은 그대로 유지.

## 작동 범위

| 시점 | 동작 |
| --- | --- |
| 시작·재개·압축 뒤·Codex 하위 작업 시작 | 승인된 핵심 구절 복원. 파일 내용이 같아도 다시 전달 |
| 지정 경로 편집 전 | 관련 상세 구절만 전달 |
| 관계없는 정상 편집 | 추가 안내 없음 |
| 명시적 보호 경로 편집 | 해당 파일 변경 거부. 기존 Hive 관리 상태 검사 유지 |
| 원문 구절 변경·누락 | 새 내용을 자동 주입하지 않고 원문 확인 안내. 무관한 편집은 유지 |
| 승인 설정 변경·손상 | 보호 범위를 믿을 수 없어 등록 범위의 파일 편집 거부. 조회·철회·복구 유지 |

부모 세션이나 같은 턴을 기준으로 전달 완료를 공유하지 않는 방식. 압축 사건의 신뢰할 ID가 없으므로 동일 경로의 다음 편집에서도 관련 안내가 반복될 수 있는 경계.
현재 파일 편집 훅 밖의 셸·터미널 이어 실행·MCP 변경까지 보호한다는 보장은 없음.

## 구성과 비용

- 사용자 소유 프로젝트 루트 `.hive-context.toml`: 승인할 Markdown 구절과 경로 선택
- 각 구절: 규칙 ID·원문 상대 경로·첫째/마지막 줄·선택한 정확한 바이트의 SHA-256 지문·복원/편집 시점
- `restore`: 핵심·현재 계획 구절, `edit`: 지정 파일 또는 디렉터리 아래의 상세 구절
- `protected_paths`: 직접 편집을 거부할 파일 또는 디렉터리. 와일드카드가 아닌 경로 단위 비교
- 등록 미리보기: 실제 문구와 보호 경로, 바이트 수, 승인 지문 표시
- 출력 전체 4,096 UTF-8 바이트 상한과 원문 변경 안내 여유 공간. 넘는 내용은 잘라서 통과시키지 않는 기준
- 별도 모델 호출·대화 원문 수집·지속 감시 없음. 토큰은 미측정, 바이트와 과금량은 별도 수치

구절은 기존 Markdown이 정본. 줄 이동·내용 변경 뒤에는 다시 검토하여 지문과 등록 갱신. 과거 요약을 새 요약으로 이어 붙이는 방식 제외.
새 원문을 읽을 때도 원래 지침 우선순위 유지. 훅으로 전달됐다는 이유만으로 사용자 요청보다 높은 권한 부여 금지.

## 확인과 철회

- `project-refresh`가 지침을 갱신한 뒤 기존 복원 설정의 현재성 확인. 바뀐 문구의 무단 재승인 금지
- `user-setup`은 프로젝트 훅을 대신 설치·재승인하지 않는 범위
- 철회 요청 시 스킬이 기존 훅 제거 미리보기·적용 수행. 사용자 문서·선택 파일 보존
- 설정의 `context_current`는 승인된 원문 일치만 증명. 호스트의 실제 로드·모델 준수는 별도 검증
- Codex 우선 구현. Claude 실제 수용은 기존 제외 범위 유지. Antigravity는 기존 파일 보호만 유지하며 압축 복구 미지원 표시
