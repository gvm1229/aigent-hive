# 업데이트 전후 대화 비교와 소개 사이트

## 목적

- 릴리스 노트의 기능 목록만으로는 전달되지 않는 실제 효과의 시각화
- 같은 요청에 대한 이전 버전과 새 버전의 AI 에이전트 대화를 나란히 배치
- 첫 적용: 정식 `0.16.0`, 소개 사이트 시제품 [`website/`](../../website/README.md)

## 전달 방식

| 방식 | 용도 | 현재 상태 |
| --- | --- | --- |
| 소개 사이트 비교 구역 | 장면별 탭, 좌우 대화 재생, 결과 한 줄과 주의 사항 | `website/src/index.html` 시제품 |
| 장면 고정 이미지 | Discord·GitHub Release 첨부용 장면별 캡처 | 사이트 장면의 Playwright 캡처로 생성 가능 |
| 짧은 화면 녹화 | 대화 재생 애니메이션의 GIF·영상 | 후속 후보 |
| 실제 녹화 | 실제 호스트 대화 기록 | 실제 앱 확인이 끝난 기능에 한정한 후속 후보 |

## 장면 구성 규칙

- 한 장면에 한 기능과 한 질문: 같은 사용자 요청으로 양쪽 시작
- 시작 조건 명시: 저장된 지식처럼 결과를 바꾸는 전제는 두 화면 위 공통 띠로 표시
- 결과 한 줄: 이전은 사용자가 떠안던 수고, 새 버전은 사용자가 얻는 결과
- 기능 이름보다 사용자 경험 우선: [릴리스 노트 독자 규칙](../../.agents/directives/references/release-notes.md) 그대로 적용
- 제한·미검증·실험 표시는 해당 장면 안의 "알아 둘 점"에 함께 배치, 별도 구석으로 분리 금지

## 정확성 규칙

- 근거 문서: 해당 버전의 `docs/releases/<version>.md`와 `README.md`의 변경 요약. 근거 없는 효과 금지
- 이전 화면은 해당 릴리스가 실제로 고친 문제만 묘사. 이전 버전에 없던 기능의 손실 묘사 금지
- 명령·옵션은 현재 CLI 계약과 일치. 예: `hive msg flow start`, `hive usage threshold ... --stop-used-percent`
- 출력 문구는 요약 표시로 취급하고, 코드에 고정된 문구가 있으면 그 형식 사용. 예: Discord 완료 알림의 구분선·`무슨 일`·`맡은 역할`·`걸린 시간` 순서
- 모델 표시는 제품의 표시 이름 목록에 있는 이름만 사용
- 페이지 하단 고지: 연출 예시라는 점과 환경별 실제 문구·모델·시간 차이
- 비교 장면 제외 대상: 실패한 시험, 재시도, 내부 조사 내용

## 언어

- 장면 문구: 한국어·영어·일본어 세 벌, 같은 `id`와 같은 순서
- 번역 범위: 대화·설명·결과 한 줄·주의 사항. 명령·경로·옵션 이름은 원문 유지
- 제품 고정 문구: 제품 출력 언어 그대로 표시. 예: Discord 완료 알림은 한국어 원문과 언어별 안내 한 줄
- 예시 선호는 언어별 독자에 맞게 조정 가능. 단, 이전·새 버전의 차이와 근거 기능은 세 언어 동일

## 글꼴

- 기본 글꼴: Pretendard Variable, 모든 HTML 결과물에 적용하는 유지관리자 선호. 일본어는 Pretendard JP Variable 우선
- 불러오기: Pretendard 공식 안내의 jsDelivr 동적 부분 집합 링크(`pretendard@v1.3.9`), 이후 시스템 글꼴 대체 순서
- 확인: 화면 확인 때 본문 계산 글꼴이 `Pretendard Variable`인지 점검

## 새 버전 반영 절차

1. 새 릴리스 노트에서 사용자 경험이 달라진 항목 선택
2. 항목마다 위 규칙으로 장면 작성: `website/src/index.html`의 `SCENES` 언어별 배열 세 곳
3. 명령과 고정 문구를 코드에서 확인
4. `python3 website/build.py` 실행 뒤 desktop `1280px`·mobile `390px` 화면 확인
5. 이전 버전 장면은 버전 표기만 바꿔 보관할지, 새 장면으로 교체할지 결정
